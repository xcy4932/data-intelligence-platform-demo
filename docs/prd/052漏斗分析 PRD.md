**漏斗分析 PRD**

**1. 功能定位**

漏斗分析用于分析用户在一个多步骤业务流程中的转化与流失情况。用户可以把一个完整业务流程拆成多个步骤，例如“浏览商品 → 加入购物车 → 提交订单 → 支付成功”，系统按配置的时间范围、窗口期、步骤顺序、统计口径和筛选条件计算每一步的到达人数、到达次数、上一步转化率、整体转化率、流失人数、流失率和转化时长。通过拆分流程步骤并用转化率衡量每一步表现，从而定位异常环节并优化整体转化率。

本功能主要回答：

用户从第 1 步到第 N 步的整体转化率是多少？

每一步相比上一步的转化率是多少？

哪个步骤流失最多？

不同渠道、版本、地区、人群的转化差异是什么？

用户完成整个流程通常需要多久？

某个活动、渠道或产品改版前后的转化是否提升？

某个转化路径是否值得长期保存和监控？

**3. 核心概念**

**3.1 漏斗步骤**

漏斗步骤是业务流程中的一个关键节点，由一个事件和该事件上的过滤条件组成。

数据结构：

type FunnelStep = {

id: string;

order: number;

eventName: string;

eventDisplayName: string;

alias?: string;

filters?: FilterGroup;

simultaneousMetric?: StepMetric;

};

示例：

{

"id": "step\_1",

"order": 1,

"eventName": "view\_product",

"eventDisplayName": "浏览商品",

"alias": "浏览商品详情页",

"filters": {

"relation": "AND",

"conditions": [

{

"fieldType": "event\_property",

"fieldName": "category",

"operator": "eq",

"value": "女装"

}

]

}

}

交互规则：

1. 一个漏斗至少包含 2 个步骤。

2. 步骤可增加、删除、复制、拖拽排序。

3. 每个步骤必须选择一个事件或者虚拟事件。

4. 每个步骤可以配置事件过滤条件。

5. 每个步骤可以配置别名。

6. 删除中间步骤后，后续步骤序号自动重排。

7. 拖拽步骤顺序后，前端重新生成 order。

**3.2 时间范围**

时间范围指第一个漏斗步骤发生的时间范围。

例如用户选择：

2026-05-01 00:00:00 至 2026-05-07 23:59:59

则系统先找出在该时间范围内发生第 1 步的用户或次数，然后再根据窗口期向后寻找后续步骤。

实际查询后续事件的最大时间范围为：

第 1 步时间范围结束时间 + 窗口期

例如：

时间范围：2026-05-01 至 2026-05-07

窗口期：7 天

后续事件最大查询至：2026-05-14 23:59:59

如果开启“限制窗口期在时间区间内”，则所有步骤都必须发生在用户选择的时间范围内，不允许后续步骤超出该时间范围。

**3.3 窗口期**

窗口期是用户完成漏斗的时间限制。

例如：

窗口期 = 10 分钟

漏斗 = 点击视频 → 视频加载 → 视频播放 → 视频播放完成

只有用户在点击视频后的 10 分钟内按规则完成后续步骤，才算完成转化。DataFinder 文档中给出了类似视频场景：窗口期设为 10 分钟时，只有在点击视频后 10 分钟内按顺序完成视频加载、播放、播放完成的用户才算完整转化。

窗口期配置结构：

type ConversionWindow = {

mode: "preset" | "custom" | "same\_day";

value?: number;

unit?: "second" | "minute" | "hour" | "day";

restrictWithinSelectedTimeRange: boolean;

};

默认值：

{

"mode": "preset",

"value": 7,

"unit": "day",

"restrictWithinSelectedTimeRange": false

}

前端选项：

10 分钟

30 分钟

1 小时

1 天

7 天

30 天

当天

自定义

自定义规则：

| **字段** | **规则** |
| --- | --- |
| value | 必须为正整数 |
| unit | 秒、分钟、小时、天 |
| 最短窗口期 | 1 分钟 |
| 最长窗口期 | 3650 天，可由系统配置 |
| 当天 | 以第 1 步发生日期的自然日结束时间为窗口结束 |

转化窗口期选择自定义时可选秒、分、小时、天，默认 10 分钟，也支持选择“当天”；有序漏斗和无序漏斗都需配置窗口期。

建议：无序漏斗保留窗口期配置，但默认折叠为高级项。

**4. 漏斗类型**

**4.1 有序漏斗**

有序漏斗要求用户按步骤顺序完成事件。

例如：

A → B → C

用户行为：

A, X, B, Y, C

仍然算完成转化，因为漏斗步骤之间允许穿插其他事件。

用户行为：

B, A, C

不算完成第 2 步转化，因为 B 发生在 A 之前。

有序漏斗在周期内严格限定每个步骤之间的发生顺序；步骤之间穿插其他事件，仍视作完成漏斗转化。

有序漏斗匹配规则：

1. 先找到用户在时间范围内的第 1 步事件。

2. 从第 1 步事件时间开始，在窗口期内查找第 2 步。

3. 第 2 步必须晚于第 1 步。

4. 第 3 步必须晚于第 2 步。

5. 依次类推。

6. 若某一步找不到，则用户停留在上一完成步骤。

按人数时，一个用户在一个时间粒度周期内只计入一次，取其“首次最长转化路径”。

按次数时，一个用户每触发一次第 1 步，就开始一次独立转化尝试。

**4.2 无序漏斗**

无序漏斗不要求步骤之间的发生顺序，只要求用户在时间范围或窗口期内完成这些步骤。

例如漏斗：

A, B, C

用户行为：

B, A, C

也算完成 A、B、C 三步。

无序漏斗在周期内不限定多个步骤事件的发生顺序，A 可以发生在 B 之前，也可以发生在 B 之后；只要发生过 A、B、C 的组合，就算完成转化。

无序漏斗匹配规则：

1. 以第 1 步事件作为进入漏斗的人群入口。

2. 判断用户在指定范围内是否发生过第 2 步、第 3 步……第 N 步。

3. 不校验后续步骤之间的先后顺序。

4. 每一步到达人数是“发生过前面所有步骤集合”的人数。

限制：

1. 无序漏斗默认不支持转化时长图。

2. 无序漏斗默认不支持步骤间耗时。

3. 无序漏斗支持转化步骤图、基础漏斗图、柱状图、趋势图和明细表。

**5. 计算方式：按人数与按次数**

**5.1 按人数 UV**

按人数是默认统计方式。

定义：

统计独立用户数。

同一用户在一个统计周期内多次完成漏斗，也只计为 1 个用户。

适用场景：

注册转化

新用户激活

付费用户转化

会员开通

广告触达后激活

数据结构：

calculationType: "UV";

计算逻辑：

第 1 步人数 = 在时间范围内触发第 1 步的去重用户数

第 K 步人数 = 在窗口期内完成第 1 步到第 K 步的去重用户数

**5.2 按次数 PV**

按次数是高级能力。

定义：

一个用户每触发一次第 1 步，就产生一次转化尝试。

同一用户可以贡献多次漏斗转化。

适用场景：

推荐商品曝光 → 商品点击

视频点击 → 视频播放

广告触发 → 广告观看完成

游戏入口点击 → 开始游戏

数据结构：

calculationType: "PV";

按次数匹配规则：

1. 每一个第 1 步事件实例生成一个 funnelAttemptId。

2. 后续步骤按该 attempt 的起始时间和窗口期匹配。

3. 同一个用户可以生成多个 attempt。

4. 同一个后续事件默认只能被一个 attempt 消费，避免重复计数。

5. 如果允许复用事件，需要在系统配置中开启 allowEventReuse。

配置项：

type FunnelCountingConfig = {

calculationType: "UV" | "PV";

allowEventReuse?: boolean;

attributionStrategy: "first\_match" | "closest\_match";

};

默认：

{

"calculationType": "UV",

"allowEventReuse": false,

"attributionStrategy": "first\_match"

}

支持切换人数 UV 或次数 PV；整体转化率和上一步转化率分别按人数或次数计算。

**6. 核心指标计算**

**6.1 到达人数/次数**

StepReachedCount[k] = 到达第 k 步的人数或次数

按人数：

StepReachedCount[k] = 完成第 1 步到第 k 步的去重用户数

按次数：

StepReachedCount[k] = 完成第 1 步到第 k 步的转化尝试次数

**6.2 整体转化率**

整体转化率表示从第 1 步到当前步骤的转化情况。

整体转化率[k] = 第 k 步到达人数或次数 / 第 1 步到达人数或次数

整体转化率等于到达当前漏斗事件的人数或次数除以第一步漏斗事件的人数或次数。

前端展示：

整体转化率：84.51%

**6.3 上一步转化率**

上一步转化率表示从上一步到当前步骤的转化情况。

上一步转化率[k] = 第 k 步到达人数或次数 / 第 k-1 步到达人数或次数

上一步转化率等于到达当前漏斗事件的人数或次数除以上一步漏斗事件的人数或次数。

前端展示：

上一步转化率：89.13%

**6.4 整体流失率**

整体流失率[k] = 1 - 整体转化率[k]

或：

整体流失率[k] = (第 1 步到达数 - 第 k 步到达数) / 第 1 步到达数

**6.5 上一步流失率**

上一步流失率[k] = 1 - 上一步转化率[k]

或：

上一步流失率[k] = (第 k-1 步到达数 - 第 k 步到达数) / 第 k-1 步到达数

**7.2.1 添加步骤**

事件选择器支持：

**7.3 关联属性**

**7.3.1 功能说明**

关联属性用于保证不同漏斗步骤之间的某个属性值一致。

典型场景：

浏览商品详情页 → 提交订单 → 支付订单

如果要分析“同一个商品”的转化，需要关联：

浏览商品详情页.product\_id = 提交订单.product\_id = 支付订单.product\_id

如果不设置关联属性，用户浏览 A 商品、提交 B 商品订单、支付 C 商品订单，也可能被算作完成转化。

关联属性用于让任意两个或多个漏斗步骤间的某个属性值保持一致，常用于活动名称、页面标题或商品名称，且所有配置的关联属性必须有值、类型一致。

**7.3.2 数据结构**

type FunnelRelationProperty = {

id: string;

stepMappings: Array<{

stepId: string;

propertyName: string;

propertyType: "string" | "number" | "boolean" | "datetime";

}>;

relationMode: "all\_equal";

};

示例：

{

"id": "relation\_product",

"relationMode": "all\_equal",

"stepMappings": [

{

"stepId": "step\_1",

"propertyName": "product\_id",

"propertyType": "string"

},

{

"stepId": "step\_2",

"propertyName": "sku\_id",

"propertyType": "string"

},

{

"stepId": "step\_3",

"propertyName": "product\_id",

"propertyType": "string"

}

]

}

**7.3.3 校验规则**

| **校验项** | **规则** |
| --- | --- |
| 步骤数量 | 至少关联 2 个步骤 |
| 属性类型 | 所有关联属性类型必须一致 |
| 空值 | 任一步骤属性为空，则该次路径不满足关联 |
| 多组关联属性 | 多组之间为 AND |
| 按次数 | 每次转化尝试独立校验关联属性 |
| 无序漏斗 | 允许关联，但只校验事件集合中对应属性是否一致 |

**8. 同时显示指标**

**8.1 功能说明**

同时显示指标用于在查看转化人数/次数之外，分析某个步骤上的其他业务指标。

例如：

支付步骤同时显示支付金额 SUM

详情页步骤同时显示浏览时长 AVG

广告观看步骤同时显示广告收益 SUM

订单步骤同时显示客单价 AVG

漏斗分析过程中可以在分析转化人数的同时分析其他指标，例如在购买转化漏斗中同时看详情页浏览时长或支付订单金额；每个步骤仅支持添加一个同时显示指标，并且只针对当前步骤事件配置指标。

**8.2 数据结构**

type StepMetric = {

id: string;

stepId: string;

metricName: string;

aggregator:

| "PV"

| "UV"

| "SUM"

| "AVG"

| "MAX"

| "MIN"

| "MEDIAN"

| "PERCENTILE";

propertyName?: string;

percentile?: number;

filters?: FilterGroup;

};

**8.3 交互规则**

1. 每个步骤右侧提供“同时显示”按钮。

2. 点击后打开指标配置弹窗。

3. 用户选择指标类型。

4. 如果选择 SUM/AVG/MAX/MIN/MEDIAN/PERCENTILE，必须选择数值属性。

5. 每个步骤最多配置 1 个同时显示指标。

6. 图表 tooltip 和明细表中展示该指标。

**10. 属性分组**

**10.1 功能说明**

属性分组用于按照某个维度拆分漏斗结果。

例如：

按渠道查看转化

按 App 版本查看转化

按城市查看转化

按商品品类查看转化

属性分组可设定事件属性、用户属性、用户标签，最多支持 10 个属性；分组默认应用到第一个漏斗事件，也可以手动配置分组应用的事件范围。

**10.2 数据结构**

**10.3 单分组统计**

单分组统计下，一个用户或一次转化只能进入一个分组。

规则：

按人数：

取用户首次最长转化状态中指定步骤的属性值分组。

按次数：

取每次转化中指定步骤的属性值分组。

未到达指定步骤：

进入 unknown 或 unreach 分组。

如果属性分组应用到事件 2，而部分发生过步骤 1 的用户没有发生步骤 2，则这些用户会统一进入 unreach 分组。

**10.4 多分组统计**

多分组统计下，一个用户可以进入多个分组。

适用场景：

用户浏览多个商品品类

用户参与多个活动

用户触达多个广告渠道

限制：

1. 默认最多 10 个分组。

2. string 属性必须配置具体分组值，默认最多 5 个。

3. number 属性必须配置自定义区间，默认最多 5 个。

4. datetime、list 类型不支持多分组。

5. 按次数分析暂不支持多分组。

6. 开启多路径对比时不支持属性分组。

7. 配置多个属性分组后，不支持转化时长图。

多路径对比时无法分组；有序漏斗中计算方式为“次数”时暂不支持多属性分组；多个属性分组后不支持查看转化时长图表。

**11. 多路径对比**

**11.1 功能说明**

多路径对比用于比较多个相似转化路径之间的转化差异。

例如：

路径 A：商品曝光 → 商品点击 → 商品详情 → 加购 → 支付

路径 B：商品曝光 → 商品点击 → 商品详情 → 立即购买 → 支付

或者：

路径 A：点击首页 banner → 进入落地页 → 支付

路径 B：点击弹窗广告 → 进入落地页 → 支付

多路径对比是改变原有转化路径中的任意一个事件环节，包括起点事件和终点事件，从而形成多条路径分支。约束是事件顺序和事件数完全相同，并且有且仅有一个相同环节的事件彼此不同；最多支持 5 条路径对比，进行多路径对比时不能分组。

**11.2 数据结构**

type FunnelPath = {

id: string;

name: string;

steps: FunnelStep[];

};

type MultiPathConfig = {

enabled: boolean;

paths: FunnelPath[];

diffStepOrder: number;

};

**11.3 校验规则**

1. 最多支持 5 条路径。

2. 每条路径步骤数必须相同。

3. 每条路径步骤顺序必须一致。

4. 只能有一个步骤位置的事件不同。

5. 不同路径在同一个差异步骤上不能选择相同事件。

6. 开启多路径对比后禁用属性分组。

7. 开启多路径对比后，对照组默认禁用。

**21. 异常状态**

**21.1 未配置完整**

请至少配置 2 个漏斗步骤

**21.2 窗口期不合法**

窗口期必须大于 0，且不能超过系统允许的最大范围

**21.3 查询范围过大**

当前查询范围较大，建议缩短时间范围、减少分组或减少漏斗步骤

**21.4 无数据**

当前条件下暂无漏斗数据

辅助说明：

可能原因：

1. 第一步事件在所选时间范围内无人触发

2. 步骤过滤条件过窄

3. 窗口期过短

4. 关联属性导致匹配失败

5. 用户筛选条件过窄

**21.5 unreach 分组**

当分组应用到第 2 步或后续步骤，且部分用户没有到达该步骤时，系统将其归入 unreach 分组。

提示：

unreach 表示用户未到达当前分组所应用的步骤，因此无法获取该步骤属性值。

如果分组应用到事件 2，而发生过步骤 1 的用户中有人没有发生事件 2，则这些用户会统一进入 unreach 分组。

**22. 验收标准**

**22.1 配置验收**

| **编号** | **验收项** | **通过标准** |
| --- | --- | --- |
| F-001 | 添加漏斗步骤 | 可添加、删除、复制、拖拽排序步骤 |
| F-002 | 步骤数量 | 少于 2 步禁止查询 |
| F-003 | 步骤过滤 | 每个步骤支持事件属性过滤和 AND/OR |
| F-004 | 漏斗类型 | 支持有序、无序切换 |
| F-005 | 计算方式 | 支持按人数、按次数 |
| F-006 | 窗口期 | 支持预设、当天、自定义 |
| F-007 | 关联属性 | 支持多步骤属性一致性校验 |

| F-009 | 全局筛选 | 支持用户属性、分群、标签、行为圈选 |
| F-010 | 分组 | 支持单分组、多分组、数值区间 |

| C-007 | 流失率 | 1 - 对应转化率 |
| C-008 | 关联属性 | 属性值一致才计入转化 |
| C-009 | 窗口期 | 后续步骤必须在窗口期内 |
| C-010 | 限制时间范围 | 开启后所有步骤都必须在所选时间内 |
| C-011 | 转化时长 | 只统计完成对应步骤的用户或次数 |
| C-012 | 对比时间 | 当前周期和对比周期独立计算 |
