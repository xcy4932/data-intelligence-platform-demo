**营销配置PRD**

**1. 产品定位与范围**

「营销配置」是增长营销平台中面向管理员、运营负责人、技术配置人员的后台配置中心，负责管理触达任务运行前所需的基础能力，包括通道接入、通道频控、防打扰策略、审批流程、任务分组、任务指标、短信签名等。

本 PRD 覆盖以下功能模块：

1. 通道配置
   Webhook 通道、短信通道、微信公众号、微信小程序、Telegram、WhatsApp。
2. 短信签名管理
   火山云短信签名、阿里云/腾讯云/极光签名、梦网/云片签名说明。
3. 审批管理
   审批流程管理、审批策略管理、审批通知配置。
4. 指标管理
   任务指标策略组、指标创建、指标复用、组合指标、通道关联。
5. 任务分组管理
   多级任务分组、分组对象、分组在任务和分析中的使用。
6. 防打扰策略
   跨通道频控、主体维度频控、通道组合频控。

**3.1 权限模型**

所有页面均需要基于当前登录用户权限控制入口、按钮、接口操作。

权限对象建议设计如下：

**3.2 页面级权限规则**

1. 用户没有页面 view 权限时：
   * 不展示对应菜单；
   * 直接访问 URL 时返回无权限页；
   * 无权限页展示文案：暂无访问权限，请联系项目管理员开通权限。
2. 用户有 view 权限但没有操作权限时：
   * 页面可查看；
   * 新增、编辑、删除、启停、保存类按钮隐藏或置灰；
   * 鼠标 hover 置灰按钮时展示：暂无操作权限，请联系管理员。
3. 所有写操作接口必须二次校验权限，不能只依赖前端控制。

**4.3 通道状态与操作限制**

| **操作** | **ENABLED** | **DISABLED** | **DELETED** |
| --- | --- | --- | --- |
| 查看 | 支持 | 支持 | 不展示 |
| 开启 | 不支持 | 支持 | 不支持 |
| 关闭 | 支持 | 不支持 | 不支持 |
| 编辑配置 | 不支持 | 支持 | 不支持 |
| 配置频控 | 支持 | 支持 | 不支持 |
| 配置黑白名单 | 支持 | 支持 | 不支持 |
| 删除 | 不支持 | 支持 | 不支持 |

说明：

1. 通道必须处于 ENABLED 状态，才可以在消息触达、流程画布等业务任务中被选择。
2. 已经被历史任务引用的通道，即使后续关闭或删除，历史任务详情中仍展示通道快照。
3. 删除通道后：
   * 不再出现在通道列表；
   * 不再出现在新建任务的通道下拉框；
   * 历史任务仍保留原通道名称、通道类型、发送目标 ID 类型等快照信息；
   * 删除为逻辑删除，不允许物理删除核心记录。

**5.5 开启通道交互**

点击关闭状态通道的开关：

1. 前端调用通道配置完整性校验接口。
2. 若缺少必填配置，开关回弹，弹出错误提示：
3. 当前通道配置不完整，请完成配置后再开启。
4. 若校验通过，弹出确认框：
5. 确认开启该通道？
6. 开启后，该通道可被新建触达任务选择。
7. 点击取消：
   * 弹窗关闭；
   * 开关保持关闭。
8. 点击确定：
   * 调用启用接口；
   * 成功后状态变为 ENABLED；
   * 列表局部刷新；
   * toast：通道已开启。

**5.6 关闭通道交互**

点击开启状态通道的开关：

1. 弹出确认框：
2. 确认关闭该通道？
3. 关闭后，新建任务将无法选择该通道；已创建任务不受影响。
4. 点击取消：
   * 开关保持开启。
5. 点击确定：
   * 调用关闭接口；
   * 成功后状态变为 DISABLED；
   * toast：通道已关闭。

**5.7 删除通道交互**

点击删除图标：

1. 若通道状态为 ENABLED：
   * 删除按钮置灰；
   * hover 提示：请先关闭通道后再删除。
2. 若通道状态为 DISABLED：
   * 弹出确认框：
   * 删除后，后续将无法创建使用该通道的任务。历史任务数据不受影响。
   * 确认删除？
3. 点击取消：
   * 不做任何变更。
4. 点击确定：
   * 调用删除接口；
   * 删除成功后从列表移除；
   * toast：通道已删除。

4. 保存后不影响已经完成发送的历史数据。
5. 正在执行中的任务下一批次发送时读取最新通道频控配置。

**6.6 触达时过滤顺序**

单个用户进入通道发送前，系统按以下顺序判断：

1. 校验通道状态是否开启

2. 校验用户是否有发送目标 ID

3. 校验通道触达范围白名单

4. 校验通道触达范围黑名单

5. 校验任务自身黑白名单

6. 校验跨任务频控

7. 校验通道频控

8. 校验通道勿扰

9. 校验任务勿扰

10. 校验流程画布 / 策略器勿扰

11. 进入实际发送

**7.4 新建 Webhook 流程**

点击「新建 Webhook」后打开右侧抽屉，采用四步流程：

步骤一：基础信息配置

步骤二：外接模板配置

步骤三：Webhook 请求响应配置

步骤四：回执配置

**7.4.1 步骤一：基础信息配置**

字段：

| **字段** | **必填** | **控件** | **校验** |
| --- | --- | --- | --- |
| Webhook 名称 | 是 | 输入框 | 1-50 字，不允许与同主体下未删除 Webhook 重名 |
| 所属主体 | 条件必填 | 下拉框 | 开启多主体时必填 |
| 消息接收地址 | 是 | URL 输入框 | 必须为 http 或 https URL |
| 请求方式 | 是 | 单选 | POST / GET，默认 POST |
| 发送目标 ID | 是 | 下拉框 | 从 ID 类型列表中选择 |
| QPS 上限 | 是 | 数字输入框 | 正整数 |
| 接口发送方式 | 是 | 单选 | 同步 / 异步，默认同步 |
| 鉴权方式 | 是 | 单选 | 不鉴权 / Header Token / AKSK / 自定义 |
| 鉴权参数 | 条件必填 | 动态表单 | 根据鉴权方式展示 |

交互：

1. 选择鉴权方式后，动态展示鉴权参数。
2. 若选择 Header Token：
   * 展示 Header Key、Header Value；
   * Header Value 密文保存。
3. 若选择 AKSK：
   * 展示 Access Key、Secret Key、签名有效期；
   * Secret Key 密文保存。
4. 点击「下一步」时校验当前步骤必填项。
5. 点击「取消」时若表单已修改，弹窗确认：
6. 当前配置尚未保存，确认离开？

**7.4.2 步骤二：外接模板配置**

用途：定义 GMP 消息内容如何映射到业务方接口请求体。

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| 模板名称 | 是 | 外接模板内部名称 |
| 请求 Header | 否 | 支持 key-value 多行配置 |
| 请求 Body 模板 | 是 | JSON 编辑器 |
| 变量映射 | 是 | 将 GMP 模板变量映射到外部接口字段 |

交互：

1. JSON 编辑器支持格式化、校验。
2. 变量映射支持添加、删除、编辑。
3. 点击「添加变量」新增一行映射。
4. 删除变量时不弹二次确认。
5. Body JSON 非法时不允许进入下一步。

**7.4.3 步骤三：Webhook 请求响应配置**

用途：配置业务方接口返回后，GMP 如何判断请求是否成功。

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| 成功 HTTP 状态码 | 是 | 默认 200，可配置多个 |
| 成功业务码路径 | 否 | jsonpath |
| 成功业务码值 | 否 | 支持多个值 |
| 失败业务码路径 | 否 | jsonpath |
| 失败业务码值 | 否 | 支持多个值 |
| 自定义返回码 | 否 | 配置业务方返回码与 GMP 状态映射 |

规则：

1. 先判断 HTTP 状态码。
2. HTTP 状态码不在成功范围内，直接判定请求失败。
3. HTTP 成功后，如配置业务码，则继续判断业务码。
4. 业务码命中成功值，判定发送请求成功。
5. 业务码命中失败值，判定发送请求失败。
6. 未配置业务码时，HTTP 成功即判定请求成功。

**7.4.4 步骤四：回执配置**

用途：配置发送后的异步回执解析。

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| 是否启用回执 | 是 | 默认否 |
| 回执地址 | 系统生成 | 只读展示 |
| 回执鉴权方式 | 否 | 不鉴权 / Token / AKSK |
| 送达量匹配规则 | 条件必填 | 启用回执时必填 |
| 点击量匹配规则 | 否 | 有点击回执时填写 |
| 自定义指标匹配规则 | 否 | 如外呼量、已读量等 |

回执匹配规则结构：

type WebhookReceiptRule = {

metricCode: string;

metricName: string;

jsonPath: string;

operator: "EQ" | "IN" | "NE";

values: string[];

**11.7 小程序订阅消息配置**

点击「订阅消息配置」打开配置页面或抽屉。

**11.7.1 Access Token 配置**

支持三种方式。

**方式一：小程序密钥托管在 GMP**

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| AppID | 系统带入 | 不可编辑 |
| Secret | 是 | 密文保存 |
| Token 刷新方式 | 系统默认 | GMP 使用 AppID + Secret 调微信接口 |

保存逻辑：

1. Secret 加密保存。
2. 保存后立即调用微信接口测试 Token 获取。
3. 获取成功才允许保存。
4. 获取失败展示微信错误码和错误信息。

**方式二：外部 Access Token URL**

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| Access Token URL | 是 | GET 请求地址 |
| 鉴权方式 | 是 | 不鉴权 / AKSK |
| 返回格式 | 固定 | JSON |

外部接口必须返回：

{

"errcode": 0,

"errmsg": "",

"access\_token": "",

"expires\_in": 7200

}

保存校验：

1. URL 必须可访问。
2. 返回 JSON 必须包含 errcode、access\_token、expires\_in。
3. errcode = 0 才认为成功。
4. expires\_in 必须大于 0。

**方式三：AKSK 鉴权请求 Access Token URL**

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| Access Token URL | 是 | GET 请求地址 |
| Access Key | 是 | 明文输入，后端加密 |
| Secret Key | 是 | 密文保存 |
| 签名有效期 | 是 | 毫秒或秒，根据后端统一约定 |
| Authorization Header | 系统生成 | 请求时自动放入 |

规则：

1. GMP 请求客户接口时按 AKSK 计算签名。
2. 签名放入 Authorization 请求头。
3. 保存前必须发起一次测试请求。
4. 测试失败不允许保存。

**11.7.2 事件回调地址配置**

支持两种模式：

| **模式** | **适用场景** |
| --- | --- |
| 开发者模式接入小程序 | 客户允许 GMP 直接作为微信回调服务 |
| 非开发者模式接入小程序 | 客户小程序已由第三方服务管理，需要第三方转发回执给 GMP |

**开发者模式**

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| URL 服务器地址 | 系统生成 | 需要复制到微信后台 |
| Token 令牌 | 是 | 与微信后台一致 |
| EncodingAESKey | 条件必填 | 加密模式时必填 |
| 消息加密方式 | 是 | 明文 / 兼容 / 安全 |
| 数据格式 | 是 | XML / JSON |

规则：

1. URL 必须带 wechat\_appid query 参数。
2. Token、EncodingAESKey 必须与微信后台一致。
3. 消息加密方式和数据格式必须与微信后台一致。

**非开发者模式**

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| GMP 回执接收地址 | 系统生成 | 提供给第三方平台 |
| 第三方 Token | 是 | 与第三方配置一致 |
| EncodingAESKey | 条件必填 | 根据第三方平台配置 |
| 消息加密方式 | 是 | 与第三方一致 |
| 数据格式 | 是 | 与第三方一致 |

规则：

1. 第三方收到微信事件后，必须转发到 GMP 回执地址。
2. 转发时 query 中必须包含：
   * wechat\_appid
   * encrypt\_type
   * timestamp
   * nonce
   * msg\_signature
3. Body 必须保持微信原始回调结构。
4. GMP 解析后写入订阅消息送达结果。

**11.8 发送小程序订阅消息时的校验**

在消息触达中选择「小程序订阅消息」并点击确定时，系统必须校验：

1. 选择的小程序通道状态为开启；
2. 小程序已完成订阅消息配置；
3. Access Token 获取成功；
4. 事件回调配置有效；
5. 所选模板属于当前小程序；
6. 模板字段已完整配置；
7. 跳转页面属于当前小程序路径。

校验失败时阻止进入下一步，并提示具体原因。

**14.4.1 企业消息平台通知**

页面布局：

左侧：审批流程画布

**14.5.1 节点字段**

| **字段** | **必填** | **说明** |

| 审批人 | 条件必填 | 根据审批人类型展示 |
| 默认审批人 | 条件必填 | 发起人自选时可配置 |
| 多人审批方式 | 条件必填 | 或签 / 会签 |
| 审批人等于创建人时禁止审批 | 否 | 默认开启 |

**14.5.2 审批人类型规则**

**指定成员**

1. 最多选择 10 人。
2. 支持按姓名、邮箱、账号搜索。
3. 已选成员可删除。
4. 若成员被禁用，流程保存时提示：
5. 审批人中存在已禁用成员，请调整后保存。

**指定角色**

1. 最多选择 20 个角色。
2. 审批时实时解析角色下的有效成员。
3. 若角色下无有效成员，发起审批时阻断并提示：
4. 当前审批节点无有效审批人，请联系管理员调整审批流程。

**发起人自选**

1. 管理员配置候选审批人。
2. 发起审批时，由申请人在候选人中选择。
3. 支持单选或多选。
4. 可配置默认审批人，避免发起人不知道如何选择。
5. 默认审批人只是默认选中，申请人可修改。

**14.5.3 多人审批方式**

| **方式** | **通过规则** | **拒绝规则** |
| --- | --- | --- |
| 或签 | 任一审批人同意即通过 | 任一审批人拒绝即拒绝 |
| 会签 | 所有审批人同意才通过 | 任一审批人拒绝即拒绝 |

**14.5.4 审批人等于创建人时禁止审批**

默认开启。

规则：

1. 开启时：
   * 若当前节点审批人包含任务创建人，创建人不能完成审批；
   * 如果该节点所有审批人都是创建人，则发起审批失败。
2. 关闭时：
   * 创建人可以审批自己创建的任务。

**14.5.5 添加节点**

1. 点击画布中的「+」添加下一个审批节点。
2. 每个流程至少 1 个审批节点。
3. 节点按顺序串行流转。
4. 前一个节点通过后进入下一个节点。
5. 任意节点拒绝后，审批整体拒绝，不再进入后续节点。

**14.5.6 保存流程**

点击保存时校验：

1. 流程名称必填且不重复。
2. 至少有 1 个节点。
3. 每个节点名称必填。
4. 每个节点审批人配置完整。
5. 发起人自选节点必须配置候选审批人。
6. 多人审批节点必须配置或签 / 会签。

保存成功后：

1. 新流程默认关闭。
2. 返回流程列表。
3. toast：审批流程保存成功。

**14.6 启用 / 禁用流程**

**14.6.1 启用流程**

点击开关开启：

1. 校验流程节点完整。
2. 校验审批人有效。
3. 通过后状态变为启用。
4. 启用后可被审批策略选择。

**14.6.2 禁用流程**

点击开关关闭时：

1. 若流程被策略使用，弹窗提示：

**18. 通道发送统一执行算法**

所有触达任务在真正调用通道前，统一执行以下算法。

async function beforeSend(context: SendContext): Promise<SendDecision> {

const channel = await getChannel(context.channelId);

if (!channel || channel.status !== "ENABLED") {

return reject("CHANNEL\_DISABLED");

}

const targetId = resolveTargetId(context.user, channel.sendTargetIdType);

if (!targetId) {

return reject("MISSING\_SEND\_TARGET\_ID");

}

if (await hitChannelScopeWhitelistButUserNotIn(channel, context.user)) {

return reject("NOT\_IN\_CHANNEL\_SCOPE\_WHITELIST");

}

if (await hitChannelScopeBlacklist(channel, context.user)) {

return reject("HIT\_CHANNEL\_SCOPE\_BLACKLIST");

}

if (await hitTaskBlacklist(context.taskId, context.user)) {

return reject("HIT\_TASK\_BLACKLIST");

}

if (await hitCrossChannelFrequency(context)) {

return reject("HIT\_CROSS\_CHANNEL\_FREQUENCY");

}

const isChannelFrequencyWhiteUser =

await hitChannelFrequencyWhitelist(channel, context.user);

if (!isChannelFrequencyWhiteUser) {

if (await hitChannelFrequency(channel, context.user)) {

return reject("HIT\_CHANNEL\_FREQUENCY");

}

}

if (await hitChannelDisturb(channel, context.user, context.sendTime)) {

return reject("HIT\_CHANNEL\_DISTURB");

}

if (await hitTaskDisturb(context.taskId, context.user, context.sendTime)) {

return reject("HIT\_TASK\_DISTURB");

}

if (await hitFlowDisturb(context.flowNodeId, context.user, context.sendTime)) {

return reject("HIT\_FLOW\_DISTURB");

}

return allow(targetId);

}

**21. 验收标准**

**21.1 通道配置验收**

1. 用户可按权限查看、创建、编辑、启停、删除通道。
2. 开启状态通道不可编辑核心配置。
3. 删除通道必须先关闭。
4. 新建任务只能选择开启状态通道。
5. 通道频控、勿扰、黑白名单保存后对后续发送生效。
6. 频控白名单只跳过通道频控，不跳过任务频控和跨通道频控。
7. Webhook 支持测试发送，测试数据不进入正式报表。
8. 短信通道可按不同供应商配置密钥和回执说明。
9. 微信公众号支持三方授权和开发者模式。
10. 微信小程序订阅消息必须完成订阅消息配置后才可创建任务。
11. Telegram QPS 必须限制在 10-30。
12. WhatsApp 支持 WABA ID 和手机号层级配置。

**21.2 审批管理验收**

1. 可创建多节点审批流程。
2. 节点支持指定成员、指定角色、发起人自选。
3. 支持或签、会签。
4. 默认禁止创建人审批自己的任务。
5. 流程关闭后不影响已提交审批。
6. 策略保存后为未执行，保存并执行后才参与匹配。
7. 多策略命中时按优先级和最近编辑时间匹配。
8. 审批通知发送失败不影响审批流转。

**21.3 指标管理验收**

1. 可创建指标策略组。
2. 可配置实时行为指标、明细数据指标、组合指标。
3. 可复用已有非组合指标。
4. 组合指标支持指标与常量运算。
5. 通道命中多个策略组时计算全部指标。
6. 关闭策略组不影响已创建任务。

**21.4 任务分组验收**

1. 可创建一级分组和最多 3 层子分组。
2. 一级分组可配置描述对象。
3. 子分组继承一级分组描述对象。
4. 每个描述对象最多 5 个一级分组。
5. 任务提交审批后分组不可修改。
6. 消息触达、流程画布、自定义分析可按分组筛选。

**21.5 防打扰验收**

1. 可配置跨通道频控。
2. 多主体开启时不支持跨主体频控。
3. 至少选择两个通道。
4. 支持天、周、月、近 X 天频控。
5. 跨通道频控与通道频控同时生效。
6. 保存后立即对后续触达生效。
