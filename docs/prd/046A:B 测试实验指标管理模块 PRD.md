**AB测试实验指标管理模块 PRD**

**1. 产品定位**

AB测试实验指标模块用于完成实验评估指标的创建、管理、复用、权限控制、报警监控和业务守护。该模块不是单纯维护一个“指标名称列表”，而是要让用户能够围绕实验目标建立可被计算、可被复用、可被授权、可被绑定实验、可被监控的指标体系。

本PRD覆盖以下功能范围：

1. 指标组列表与指标组生命周期管理
2. 事件指标创建与编辑
3. 留存指标创建与实验报告页临时留存分析
4. 漏斗指标创建与使用限制
5. 指标详情、关联实验查看、操作历史与权限管理
6. 指标灵活属性
7. 指标组模板管理与实验创建中的模板使用
8. 报警任务与接收组管理
9. 必看指标设置与必看指标看板
10. 与实验创建、实验报告、实验报警的联动逻辑

**2. 核心概念与对象关系**

**2.1 指标**

指标用于描述某个业务行为、用户行为或实验结果在一定时间与条件下的数值表现。系统内指标必须具备可执行计算口径，不能只保存一个名称。

指标分为三类：

| **指标类型** | **用途** | **是否可多个指标放在同一指标组** | **是否可作为核心指标** | **是否可作为关注指标** | **是否支持报警** |
| --- | --- | --- | --- | --- | --- |
| 事件指标 | 衡量事件发生、人数、金额、转化率、人均次数等 | 是，最多100个 | 是 | 是 | 是 |
| 留存指标 | 衡量起始行为后的第N日回访情况 | 否，每组只能1个 | 可作为关注指标；是否可作为核心指标由实验创建页配置策略决定 | 是 | 是，按具体实现指标判断 |
| 漏斗指标 | 衡量多步骤转化链路 | 否，每组只能1个 | 否 | 是，每个实验最多1个 | 否 |

**2.2 指标组**

指标组是同类型指标的集合。指标组是指标管理的主展示和主操作粒度。

规则如下：

1. 一个指标组只能包含一种指标类型。
2. 事件指标组最多包含100个事件指标。
3. 留存指标组只能包含1个留存指标。
4. 漏斗指标组只能包含1个漏斗指标。
5. 指标组可为公共指标组或私有指标组。
6. 指标组下线后不可再被新实验选择，但历史实验报告仍保留历史口径和历史计算结果。
7. 指标组被复制后生成一个新的指标组，新指标组与原指标组没有父子依赖关系，后续修改互不影响。

**2.3 核心指标**

核心指标是实验是否成功的主要判断指标。一个实验只能设置一个核心指标。

规则如下：

1. 每个实验最多一个核心指标。
2. 漏斗指标不可设置为核心指标。
3. 已下线指标不可设置为核心指标。
4. 用户必须拥有指标组查看权限，才能选择该指标作为核心指标。
5. 核心指标在实验报告中置顶展示，并参与实验结论判断。

常见核心指标类型包括：

1. 转化率类，例如 uv/au。
2. 人均次数类，例如 pv/au、pv/uv、sum/au、sum/uv。
3. 平均值类，例如 sum/pv。

**2.4 关注指标**

关注指标用于观察实验对其他业务指标的影响。关注指标不一定是实验直接优化目标，但不能出现明显负向影响。

规则如下：

1. 一个实验可以配置多个关注指标。
2. 关注指标可以来自事件指标、留存指标、漏斗指标。
3. 一个实验最多只能选择一个漏斗指标作为关注指标。
4. 已下线指标不可新增为关注指标。
5. 必看指标会自动加入实验关注指标。

**2.5 必看指标**

必看指标是必须守护的业务线指标。某个指标被设置为必看指标后，该应用下后续创建的每个实验都会默认带入该指标作为关注指标。

规则如下：

1. 只有集团管理员、应用管理员可以设置或取消必看指标。
2. 必看指标只能从可用指标中设置，已下线指标不可设置为必看指标。
3. 设置为必看指标后，后续新建实验自动带入关注指标。
4. 已经创建的实验不因取消必看状态而自动移除该指标。
5. 必看指标会进入必看指标看板，用于应用视角的指标趋势监控与实验反查。

**3. 权限模型**

**3.1 角色**

| **角色** | **说明** |
| --- | --- |
| 集团管理员 | 拥有应用内指标、模板、报警、必看指标的最高管理权限 |
| 应用管理员 | 拥有当前应用内指标、模板、报警、必看指标管理权限 |
| 指标组Owner | 指标组负责人，可编辑自己负责的指标组 |
| 模板Owner | 指标组模板负责人，可维护自己负责的模板 |
| 普通成员 | 根据角色权限和私有授权范围查看、使用指标 |
| 被授权用户 | 对某个私有指标组或个人模板拥有单独使用权限 |

**3.2 指标组权限**

| **权限项** | **公共指标组** | **私有指标组** |
| --- | --- | --- |
| 在指标组列表可见 | 有指标管理查看权限的用户可见 | 仅集团管理员、应用管理员、Owner、被授权用户可见 |
| 查看指标详情 | 有指标管理查看权限的用户可查看 | 仅有授权用户可查看 |
| 查看指标统计值 | 有指标统计值权限的用户可查看 | 同时需要指标组授权与指标统计值权限 |
| 编辑指标组 | 集团管理员、应用管理员、Owner | 集团管理员、应用管理员、Owner |
| 下线指标组 | 集团管理员、应用管理员、Owner | 集团管理员、应用管理员、Owner |
| 复制指标组 | 有查看权限的用户可复制；复制后自己成为新Owner | 有查看权限的用户可复制；复制后自己成为新Owner |
| 用户赋权 | 集团管理员、应用管理员、Owner | 集团管理员、应用管理员、Owner |

**3.3 模板权限**

| **模板类型** | **可见范围** | **可使用范围** | **可编辑范围** |
| --- | --- | --- | --- |
| 个人模板 | 模板Owner、指定可用用户、管理员 | 模板Owner、指定可用用户、管理员 | 模板Owner、管理员 |
| 通用模板 | 应用内所有有实验创建权限的用户 | 应用内所有有实验创建权限的用户 | 有模板编辑权限的用户、管理员 |

按钮文案：

创建指标组

位置：

页面右上角。

点击逻辑：

1. 打开指标组创建页。
2. 默认进入“基本信息”区域。

**5.4.3 合并指标组按钮**

按钮文案：

合并指标组

展示逻辑：

1. 表格左侧展示复选框。
2. 用户至少选择2个指标组后，合并按钮可点击。
3. 未选择或只选择1个指标组时，按钮置灰。

点击后校验：

1. 所选指标组必须全部为同一种指标类型。
2. 所选指标组必须全部为使用中状态。
3. 用户必须拥有所选指标组的查看权限。
4. 如果某个指标组是私有指标组但用户无权限，不应出现在列表中，也不能被选择。
5. 留存指标组和漏斗指标组允许合并，但合并后仍需满足每组只能1个指标，因此实际只允许合并事件指标组；留存和漏斗指标组合并时直接报错：留存指标组和漏斗指标组每组仅允许一个指标，不支持合并。

合并弹窗字段：

| **字段** | **类型** | **必填** | **逻辑** |
| --- | --- | --- | --- |
| 新指标组名称 | 输入框 | 是 | 默认空，最长50字符，同应用内不可与已有指标组重名 |
| 新指标组描述 | 多行输入框 | 否 | 最长1000字符 |
| Owner | 人员选择器 | 是 | 默认当前用户 |
| 权限类型 | 单选 | 是 | 公共指标组 / 私有指标组 |
| 授权用户 | 人员选择器 | 条件必填 | 仅私有指标组展示，可为空；Owner和管理员默认有权限 |
| 待合并指标列表 | 只读列表 | 是 | 展示来源指标组、指标名称、指标类型 |

重复指标名处理：

1. 如果不同指标组中存在同名指标，保存按钮置灰。
2. 重复项右侧展示红色提示：指标名称重复，请修改后再合并。
3. 用户可在弹窗内直接修改重复指标的新名称。
4. 修改后的名称必须在新指标组内唯一。

保存逻辑：

1. 创建一个新的指标组。
2. 原指标组不删除、不下线。
3. 新指标组复制所有指标口径。
4. 新指标组Owner为弹窗选择的Owner。
5. 新指标组状态为使用中。
6. 写入操作历史：合并创建指标组，记录来源指标组ID列表。

取消逻辑：

关闭弹窗，不保存任何数据。

**5.4.8 编辑按钮**

图标：

编辑icon。

点击逻辑：

1. 校验当前用户是否为集团管理员、应用管理员或指标组Owner。
2. 有权限则进入指标组编辑页。
3. 无权限则按钮不展示；如统一展示，则置灰，hover提示：仅指标组Owner或管理员可编辑。

编辑限制：

1. 指标组类型不可修改。
2. 已有关联运行中实验的指标，修改口径时必须二次确认。
3. 对已经运行过实验的指标，修改口径会影响后续计算口径展示，但历史实验应保留绑定时的口径快照。
4. 已下线指标组不可编辑。

**5.4.9 复制按钮**

图标：

复制icon。

点击逻辑：

1. 复制当前指标组的基本信息、指标配置、权限类型。
2. 新指标组名称默认：原指标组名称-复制。
3. 如果名称已存在，则自动递增：原指标组名称-复制2、原指标组名称-复制3。
4. 当前用户成为新指标组Owner。
5. 复制后的指标组状态为使用中。
6. 复制后进入新指标组编辑页，用户可修改后保存。
7. 未保存前不创建正式记录；点击保存后落库。
8. 点击取消时提示：复制内容尚未保存，确认离开？

**5.4.10 下线按钮**

图标：

下线或更多操作内的下线。

点击后校验：

1. 当前用户必须是集团管理员、应用管理员或指标组Owner。
2. 当前指标组下所有指标均未被运行中实验关联。
3. 如果有关联运行中实验，则不能下线，并展示阻断弹窗。

阻断弹窗内容：

标题：

无法下线指标组

正文：

当前指标组存在被运行中实验使用的指标，请先停止相关实验或移除指标后再下线。

表格字段：

1. 实验名称
2. 实验ID
3. 实验Owner
4. 实验状态
5. 关联指标名称

操作：

1. 查看实验：新页面打开实验详情页。
2. 知道了：关闭弹窗。

可下线时二次确认弹窗：

标题：

确认下线指标组？

正文：

下线后，该指标组不可再被新实验选择，历史实验报告仍保留原有数据和口径。

按钮：

1. 取消
2. 确认下线

确认后：

1. 指标组状态变为已下线。
2. 写入操作历史。
3. 列表按当前状态过滤刷新。
4. 如果当前过滤为“使用中”，该指标组从列表消失。

**6. 指标组创建与编辑页通用 PRD**

| --- | --- | --- |
| 新建 | mode=create | 创建新指标组 |

**6.3 顶部按钮**

1. 取消
2. 保存

1. 操作历史

**6.3.1 取消按钮**

点击逻辑：

1. 如果页面无改动，直接返回上一页。
2. 如果页面有改动，弹出确认框。

确认框：

标题：

确认离开？

正文：

当前修改尚未保存，离开后将丢失已编辑内容。

按钮：

1. 继续编辑
2. 确认离开

**6.3.2 保存按钮**

保存前统一校验：

1. 指标组类型必填。
2. 指标组名称必填。
3. 指标组名称同应用内唯一。
4. Owner必填。
5. 指标配置必须至少包含1个指标。
6. 指标名称在当前指标组内唯一。
7. 指标配置口径完整。
8. 留存指标组只能保存1个指标。
9. 漏斗指标组只能保存1个指标。
10. 事件指标组最多保存100个指标。
11. 私有指标组若配置了授权用户，授权用户必须是当前应用成员。
12. 必看指标开关只有管理员可操作。

保存成功后：

1. 展示toast：保存成功。
2. 返回指标组详情页。
3. 新建模式进入新指标组详情页。
4. 编辑模式刷新详情页。
5. 写入操作历史。

保存失败：

1. 接口返回字段级错误时，对应字段下方展示错误。
2. 接口返回全局错误时，页面顶部展示错误提示。
3. 保存按钮恢复可点击状态。

**6.4.1 指标组类型**

1. 事件指标
2. 留存指标
3. 漏斗指标

确认框：

标题：

**7.8.2 事件计算方式**

字段：

计算方式

事件指标支持以下算子：

| **算子** | **展示名称** | **计算含义** | **是否需要属性** | **是否支持新建** |
| --- | --- | --- | --- | --- |
| pv/au | 进组人均次数 | 事件总发生次数 / 实验进组用户数 | 否 | 是 |
| uv/au | 转化率 | 触发事件的进组用户数 / 实验进组用户数 | 否 | 是 |
| sum/au | 按属性求进组人均值 | 指定数值属性求和 / 实验进组用户数 | 是，数值属性 | 是 |
| sum/sum(dau) | 按属性求每日活跃均值 | 指定数值属性求和 / 用户活跃天数 | 是，数值属性 | 否，历史保留 |
| pv/sum(dau) | 每日活跃均次 | 事件发生次数 / 用户活跃天数 | 否 | 否，历史保留 |
| pv/uv | 人均次数 | 事件总发生次数 / 触发事件用户数 | 否 | 是 |
| sum/uv | 按属性求人均值 | 指定数值属性求和 / 触发事件用户数 | 是，数值属性 | 是 |
| sum/pv | 按属性求平均值 | 指定数值属性求和 / 事件发生次数 | 是，数值属性 | 是 |
| pv | 总次数 | 事件发生次数 | 否 | 是 |
| uv | 总人数 | 触发事件用户数 | 否 | 是 |
| sum | 按属性求和 | 指定数值属性求和 | 是，数值属性 | 是 |
| count\_distinct | 按属性求去重数 | 指定属性去重数量 | 是 | 是 |

计算公式口径：

$$
pv/au = \frac{\text{当前事件在实验进组用户中的总发生次数}}{\text{实验进组用户数}} , .
$$

$$
uv/au = \frac{\text{触发当前事件的实验进组用户数}}{\text{实验进组用户数}} , .
$$

$$
sum/au = \frac{\text{指定事件属性值求和}}{\text{实验进组用户数}} , .
$$

$$
pv/uv = \frac{\text{当前事件总发生次数}}{\text{触发当前事件的实验进组用户数}} , .
$$

$$
sum/uv = \frac{\text{指定事件属性值求和}}{\text{触发当前事件的实验进组用户数}} , .
$$

$$
sum/pv = \frac{\text{指定事件属性值求和}}{\text{当前事件总发生次数}} , .
$$

$$
pv = \text{当前事件总发生次数} , .
$$

$$
uv = \text{触发当前事件的实验进组用户数} , .
$$

$$
sum = \text{指定事件属性值求和} , .
$$

$$
count\_distinct = \text{指定事件属性的去重值数量} , .
$$

除数为0时：

1. 指标值返回null。
2. 前端展示为—。
3. 不计算置信度。
4. 报警任务不触发该指标的阈值判断。

4. 人均次数：pv/uv

6. 按属性求平均值：sum/pv

**7.13.2 不支持置信度的单一指标**

以下单一指标不支持计算置信度：

1. 总次数：pv
2. 总人数：uv
3. 按属性求和：sum
4. 按属性求去重数：count\_distinct

**7.13.3 支持置信度的组合指标**

1. uv / uv
2. pv / pv
3. pv / uv
4. pv / sum
5. sum / sum
6. sum / uv
7. sum / pv

不满足以上结构时：

1. 实验报告仍展示指标值。
2. 置信度区域展示：该指标暂不支持置信度计算。
3. 报警策略中的“变化显著时报警”不可勾选。

**8. 留存指标创建 PRD**

**8.1 使用限制**

5. 留存指标支持灵活属性。

2. 页面只展示一个留存指标配置卡片。
3. 不展示添加指标按钮。
4. 如果用户尝试通过接口提交多个留存指标，后端返回错误：留存指标组仅允许包含一个指标。

1. 指标名称
2. 指标描述

4. 回访事件

**8.5 指标名称与描述**

规则同事件指标。

**8.6 起始事件**

含义：

起始事件用于定义留存分析的目标用户群。

示例：

用户第一次使用拍摄功能，则起始事件为拍摄。

配置逻辑：

1. 必填。
2. 支持一般事件、虚拟事件、圈选事件。
3. 支持搜索。
4. 支持过滤条件。
5. 已下线事件不可新建选择。

**8.7 回访事件**

含义：

回访事件用于定义用户在起始事件发生后的第N天是否再次发生目标行为。

示例：

起始事件为播放短视频，回访事件为打开APP，表示观察播放短视频的用户之后是否再次打开APP。

配置逻辑：

1. 必填。
2. 支持一般事件、虚拟事件、圈选事件。
3. 支持搜索。
4. 支持过滤条件。
5. 起始事件和回访事件可以相同。
6. 起始事件和回访事件可以不同。

**8.8 留存计算逻辑**

第N日留存用户：

$$
R\_N = {u \mid u \in S\_0 \land u \text{ 在起始事件发生后的第 } N \text{ 天触发回访事件}} , .
$$

起始用户集合：

$$
S\_0 = {u \mid u \text{ 在实验观察期内触发起始事件}} , .
$$

第N日留存率：

$$
Retention\_N = \frac{|R\_N|}{|S\_0|} , .
$$

展示规则：

1. 默认展示第1日至第30日留存。
2. 如果起始用户数为0，对应留存率展示—。
3. 如果回访用户数为0，留存率展示0%。
4. 数字格式默认百分比，小数位默认4位。

**8.9 过滤条件**

起始事件和回访事件均可添加过滤条件。

规则同事件指标过滤条件。

注意：

1. 起始事件过滤条件用于圈定起始用户集合。
2. 回访事件过滤条件用于判断回访行为是否满足口径。
3. 两者互不替代。
4. 如果需要分析“新用户使用拍摄功能后的留存”，应在起始事件中增加新用户条件。
5. 如果需要分析“回访时再次使用某个功能且参数满足条件”，应在回访事件中增加过滤条件。

**9. 漏斗指标创建 PRD**

6. 漏斗指标开始收集、统计和分析数据后，不建议编辑；编辑会触发数据重新计算。

**9.2 创建入口**

**9.3 基本信息**

同指标组通用基本信息。

2. 不展示添加指标按钮。
3. 不展示必看指标开关。
4. 不展示灵活属性配置。

**9.4 漏斗指标配置项**

字段包括：

1. 指标名称
2. 指标描述
3. 转化窗口期
4. 漏斗事件步骤
5. 每步过滤条件
6. 全局过滤条件

**9.5 转化窗口期**

字段：

转化窗口期

选项：

1. 天
2. 小时
3. 分钟
4. 自定义时间

默认：

自定义时间 30 分钟

规则：

1. 必填。
2. 数值必须为正整数。
3. 单位为分钟、小时、天。
4. 用户必须在设定窗口期内按顺序完成全部步骤，才算转化成功。

示例：

用户在30分钟内依次完成步骤1、步骤2、步骤3，则计为完成完整漏斗转化。

**9.6 漏斗事件步骤**

字段：

漏斗事件

规则：

1. 最少2个事件。
2. 最多10个事件。
3. 每个步骤必须选择事件。
4. 支持一般事件、虚拟事件、圈选事件。
5. 每个步骤可单独添加过滤条件。
6. 步骤顺序严格影响计算结果。

**9.6.1 添加步骤**

按钮文案：

添加漏斗事件

点击逻辑：

1. 当前步骤数小于10时新增一步。
2. 新步骤追加到末尾。
3. 步骤编号自动递增。
4. 如果已有10步，按钮置灰，提示：漏斗事件最多支持10个步骤。

**9.6.2 删除步骤**

每个步骤右侧展示删除按钮。

规则：

1. 删除后后续步骤自动重新编号。
2. 如果删除后不足2步，不允许删除，提示：漏斗指标至少需要2个步骤。

**9.6.3 调整顺序**

每个步骤支持拖拽排序。

拖拽后：

1. 步骤编号重新计算。
2. 过滤条件跟随步骤移动。
3. 页面标记为已修改。

**9.7 步骤过滤条件**

每个步骤均可添加过滤条件。

逻辑同事件指标过滤条件。

**9.8 全局过滤条件**

字段：

全局过滤条件

作用：

对所有漏斗步骤统一生效。

支持属性：

1. 用户属性
2. 公共属性
3. 自定义属性

逻辑：

1. 全局过滤条件与每步过滤条件为且关系。
2. 用户必须同时满足全局条件和步骤条件，才计入该步骤。
3. 全局条件为空时，不进行全局过滤。

**9.9 漏斗计算逻辑**

完整转化用户集合：

$$
F = {u \mid u \text{ 在转化窗口内按照步骤顺序完成所有漏斗事件}} , .
$$

第i步用户集合：

$$
S\_i = {u \mid u \text{ 已按照顺序完成第 } 1 \text{ 步至第 } i \text{ 步}} , .
$$

第i步到第i+1步转化率：

$$
CVR\_i = \frac{|S\_{i+1}|}{|S\_i|} , .
$$

整体转化率：

$$
CVR\_{total} = \frac{|S\_n|}{|S\_1|} , .
$$

如果分母为0：

1. 转化率展示—。
2. 不参与报警。
3. 报告中提示样本不足。

**9.10 编辑风险提示**

按钮：

2. 确认保存

**10. 指标灵活属性 PRD**

**10.1 功能目标**

指标灵活属性用于解决大量相似指标重复创建的问题。

典型场景：

多个实验都评估同一个事件、同一个计算方式，但过滤属性值不同。如果为每个属性值都创建一个指标，会造成指标管理混乱。灵活属性允许在指标定义时预留属性，在实验选择指标时再指定属性值。

**10.2 支持范围**

支持：

1. 事件指标
2. 留存指标

不支持：

1. 漏斗指标

**10.3 创建指标时配置灵活属性**

位置：

指标卡片内的高级设置

默认状态：

关闭。

开关文案：

灵活属性

**10.3.1 打开灵活属性**

打开后展示灵活属性配置区。

事件指标配置结构：

| **范围** | **说明** |
| --- | --- |
| A | 对事件A生效 |
| B | 对事件B生效 |
| C... | 对对应事件生效 |
| 全 | 对当前指标中的所有事件生效 |

留存指标配置结构：

| **范围** | **说明** |
| --- | --- |
| 起始事件 | 对起始事件生效 |
| 回访事件 | 对回访事件生效 |
| 全 | 对起始事件和回访事件都生效 |

每行配置字段：

1. 生效范围
2. 属性选择器
3. 默认运算符，可为空
4. 默认属性值，可为空
5. 删除按钮

规则：

1. 同一生效范围下可添加多个灵活属性。
2. 同一生效范围下不能重复选择同一个属性。
3. 灵活属性只定义可变属性，不强制在指标创建时选择属性值。
4. 如果配置了默认值，实验选择指标时默认带出，用户可修改。
5. 如果未配置默认值，实验选择指标时该项为空。

**10.3.2 关闭灵活属性**

如果已经配置了灵活属性，关闭时弹出确认框。

**14.9.1 实验选择**

规则：

5. 已删除实验不可选择。

**14.9.2 指标名称**

规则：

1. 必填。

3. 漏斗指标不可选择。
4. 不支持置信度的指标可以选择，但变化显著时报警不可勾选。

**14.9.3 对比对照组**

实验报警固定以对照组为基准。

计算：

$$
ChangeRate = \frac{Metric\_{variant} - Metric\_{control}}{Metric\_{control}} , .
$$

如果对照组指标值为0：

1. ChangeRate返回null。
2. 不触发百分比变化报警。
3. 日志记录原因：control\_metric\_zero。

**14.9.4 变化显著时报警**

勾选后：

1. 系统必须同时判断指标变化方向、变化百分比和统计显著性。
2. 只有变化存在统计显著性时才触发报警。
3. 如果指标不支持置信度，则该勾选框置灰。

未勾选：

只根据变化百分比阈值判断。

**16.5.2 hover tooltip**

2. 指标值
3. 日环比

仅当时间粒度为天级时展示日环比和周环比。

日环比：

$$
DayOverDay = \frac{Value\_t - Value\_{t-1}}{Value\_{t-1}} , .
$$

周环比：

$$
WeekOverWeek = \frac{Value\_t - Value\_{t-7}}{Value\_{t-7}} , .
$$

如果前一周期值为0：

1. 环比展示—。
2. 不计算百分比。

**20. 验收标准**

**20.1 指标组列表**

1. 用户可以按名称、描述、创建人搜索指标组。
2. 默认只展示使用中的指标组。
3. 用户可以切换查看已下线和全部状态。
4. 有权限用户可以创建、编辑、复制、下线指标组。
5. 无权限用户不能编辑或下线他人指标组。
6. 下线前系统能正确识别运行中实验关联并阻断。
7. 复制指标组后，新旧指标组后续修改互不影响。
8. 合并指标组只允许同类型且符合数量限制的指标组合并。

**20.2 事件指标**

1. 事件指标组最多可创建100个指标。
2. 单一指标和组合指标均可保存。
3. 组合指标公式能正确校验非法字符、括号、未定义事件。
4. 所有算子按定义计算。
5. 已失效算子不可新建，但历史指标可查看。
6. 置信度支持状态能按规则正确展示。
7. 分母为0时展示—，不计算置信度。
8. 必看指标设置后，新实验自动带入关注指标。

**20.3 留存指标**

1. 留存指标组只能保存一个指标。
2. 起始事件和回访事件必填。
3. 起始事件和回访事件可以相同或不同。
4. 过滤条件分别作用于起始事件和回访事件。
5. 报告页可以选择已创建留存指标查询。
6. 报告页可以临时配置留存口径查询且不保存为指标。

**20.4 漏斗指标**

1. 漏斗指标组只能保存一个指标。
2. 漏斗步骤最少2个，最多10个。
3. 漏斗严格按步骤顺序计算。
4. 转化窗口期必填且必须为正整数。
5. 漏斗指标不可设为核心指标。
6. 一个实验最多只能添加一个漏斗指标。
7. 漏斗指标不支持报警。

**20.5 灵活属性**

1. 事件指标和留存指标可开启灵活属性。
2. 漏斗指标不展示灵活属性。
3. 实验选择指标时可为灵活属性配置属性值。
4. 灵活属性配置只影响当前实验绑定，不修改指标原始定义。
5. 实验报告中能展示实际生效的灵活属性口径。

**20.6 模板管理**

1. 有权限用户可创建、编辑、删除模板。
2. 个人模板只对Owner和指定人可用。
3. 通用模板对应用内用户可用。
4. 创建实验时可选择模板批量添加指标。
5. 已选指标可存为模板。
6. 模板删除不影响已创建实验。

**20.7 报警任务**

1. 支持创建大盘报警和实验报警。
2. 大盘报警支持绝对值、同比、环比。
3. 实验报警支持对比对照组变化百分比。
4. 支持勾选变化显著时报警，且仅支持置信度指标。
5. 支持飞书、钉钉、企业微信、邮件通知。
6. 未配置通知渠道时不能保存。
7. 任务关闭后不再计算和发送报警。
8. 接收组被报警任务使用时不能删除。

**20.8 必看指标看板**

1. 管理员可以设置和取消必看指标。
2. 必看指标会自动进入新实验关注指标。
3. 看板支持按时间、实验模式、实验版本、公共属性、用户分群筛选。
4. 趋势图hover展示指标值。
5. 天级粒度下展示日环比和周环比。
6. 点击查看当时新增实验可跳转实验列表并带入时间筛选。
7. 点击查看当时运行实验可跳转实验列表并带入运行时间筛选。
8. 指标事件或属性下线时，看板展示无数据说明。
