**A/B 测试实验创建与管理 PRD**

**1. 文档定位**

本 PRD 覆盖 A/B 测试平台中“实验创建、实验配置、实验调试、实验启动、实验运行管理、实验异常排查、实验权限管理、实验模板、实验固化、实验看板、广告实验及相关工具”的完整产品逻辑。

**2. 核心对象与状态模型**

**2.1 实验对象**

实验是 A/B 测试平台的核心资源。每个实验必须归属于一个应用，并具备实验类型、实验状态、实验版本、生效策略、实验指标、权限配置、操作日志等信息。

interface Experiment {

id: string;

appId: string;

name: string;

description?: string;

type: ExperimentType;

subtype?: ExperimentSubtype;

status: ExperimentStatus;

ownerId: string;

collaboratorIds: string[];

visibility: "PUBLIC" | "PRIVATE";

tags: string[];

durationDays: number;

startedAt?: string;

endedAt?: string;

createdAt: string;

updatedAt: string;

}

**2.2 实验类型**

type ExperimentType =

| "PROGRAMMING"

| "VISUAL"

| "SPLIT\_URL"

| "PUSH"

| "MVT"

| "MAB"

| "WEB\_PERSONALIZATION"

| "CODE\_PERSONALIZATION"

| "PARENT\_CHILD"

| "REVERSE"

| "AD";

编程实验继续细分为：

type ExperimentSubtype = "CLIENT" | "SERVER";

**2.3 实验状态**

type ExperimentStatus =

| "DRAFT"

| "DEBUGGING"

| "RUNNING"

| "PAUSED"

| "FROZEN"

| "STOPPED"

| "ENDED"

| "ARCHIVED";

**2.4 状态流转规则**

| **当前状态** | **可执行动作** | **目标状态** | **说明** |
| --- | --- | --- | --- |
| DRAFT | 保存草稿 | DRAFT | 允许反复编辑 |
| DRAFT | 提交调试 | DEBUGGING | 完整校验通过后进入调试 |
| DEBUGGING | 启动实验 | RUNNING | 白名单测试确认后启动 |
| DEBUGGING | 编辑 | DEBUGGING | 可继续编辑配置 |
| DEBUGGING | 删除 | ARCHIVED | 逻辑删除 |
| RUNNING | 暂停 | PAUSED | 已进组用户出组，新用户不进组 |
| RUNNING | 冻结 | FROZEN | 已进组用户保留，新用户不进组 |
| RUNNING | 停止 | ENDED | 实验结束，不再进组 |
| RUNNING | 编辑 | RUNNING | 仅允许安全字段或扩缩量 |
| PAUSED | 恢复 | RUNNING | 恢复后原进组用户仍在原版本 |
| FROZEN | 恢复 | RUNNING | 恢复后新用户重新参与分流 |
| ENDED | 重启 | RUNNING | 仅结束后 24 小时内允许 |
| ENDED | 固化至 Feature | ENDED | 将优胜版本转为 Feature |
| 任意非 ARCHIVED | 权限管理 | 原状态 | 仅修改权限，不改变实验状态 |

**3. 权限模型**

**3.1 用户角色**

| **角色** | **权限范围** |
| --- | --- |
| 集团管理员 | 查看和管理集团下所有应用、所有实验、所有模板、所有看板 |
| 应用管理员 | 管理当前应用下所有实验、模板、看板、流量层、互斥域 |
| 实验创建者 | 管理自己创建的实验 |
| 实验协作者 | 管理被授权协作的实验 |
| 普通用户 | 只能查看公共实验或被授权的私有实验 |
| 广告账户管理员 | 管理广告账户、广告资产、广告投放 |
| 看板 Owner | 管理自己创建的实验看板 |

**3.2 公共实验与私有实验**

实验创建时默认是公共实验。

公共实验：

1. 当前应用下有访问权限的用户均可查看。
2. 普通用户只能查看实验详情、实验报告、操作历史。
3. 普通用户不能修改、启动、停止、删除、诊断、复制实验。

私有实验：

1. 只有集团管理员、应用管理员、实验创建者、被授权用户可见。
2. 普通用户不可见。
3. 被授权用户默认只获得查看权限，除非额外授予协作权限。

**3.3 按钮级权限控制**

所有按钮在渲染前必须根据当前用户权限、实验状态、实验类型进行可用性判断。

按钮状态分为三类：

1. 可点击；
2. 置灰不可点击；
3. 不展示。

规则：

* 用户无查看权限：不展示实验。
* 用户有查看权限但无操作权限：展示详情，不展示高危操作按钮。
* 用户有操作权限但当前状态不允许：按钮置灰，并在 hover 时展示不可用原因。

**6. 通用实验创建向导**

普通实验创建向导统一为 4 步：

1. 输入基本信息；
2. 设置生效策略；
3. 配置实验版本；
4. 添加实验指标。

特殊实验可在此基础上增加或调整步骤，例如广告实验、MAB、Web 个性化。

顶部步骤条必须展示当前步骤。点击已完成步骤可返回修改，点击未完成步骤不可跳转。

底部固定按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 上一步 | 保存当前步骤草稿后返回上一页 |
| 下一步 | 校验当前步骤，通过后进入下一步 |
| 保存草稿 | 保存当前配置，不跳转 |
| 取消 | 有未保存内容时弹出确认 |
| 创建并进入调试 | 最后一步展示，完整校验后进入调试状态 |

**7. Step 1：输入基本信息**

**7.1 字段**

| **字段** | **是否必填** | **规则** |
| --- | --- | --- |
| 实验名称 | 是 | 1-100 字，同一应用下不可与未归档实验重名 |
| 实验描述 | 否 | 最多 1000 字 |
| 实验标签 | 否 | 可选择已有标签，也可输入新标签 |
| 实验类型 | 是 | 根据入口自动带入，部分类型不可修改 |
| 实验时长 | 是 | 默认 30 天，建议不少于 14 天 |
| 实验负责人 | 是 | 默认当前用户，可改为其他有权限成员 |
| 实验可见性 | 是 | 公共实验 / 私有实验 |
| 业务背景 | 否 | 用于说明实验目的、版本迭代背景 |

**7.2 字段交互**

实验名称：

1. 输入时实时统计字数。
2. 超过 100 字时禁止继续输入。
3. 失焦时校验重名。
4. 重名时输入框标红，提示“当前应用下已存在同名实验”。

实验标签：

1. 点击输入框展示已有标签。
2. 输入新标签后按回车创建临时标签。
3. 保存实验时若标签不存在，则同步创建标签。
4. 单个实验最多 20 个标签。

实验时长：

1. 默认为 30 天。
2. 小于 7 天时提示“实验周期过短，可能无法覆盖完整工作日与周末周期”。
3. 不阻塞创建。
4. 推送实验的“结束后持续观测时长”单独配置，最长 30 天。

**7.3 按钮逻辑**

| **按钮** | **点击结果** |
| --- | --- |
| 下一步 | 校验必填项，保存草稿，进入生效策略 |
| 取消 | 弹窗确认后返回实验列表 |
| 保存草稿 | 保存当前步骤，不校验后续步骤 |
| 展开帮助 | 展示字段说明 |

**8. Step 2：设置生效策略**

**8.1 页面目标**

该步骤用于决定：

1. 哪些用户有资格进入实验；
2. 实验使用多少流量；
3. 实验是否进入互斥层；
4. 实验流量如何生效；
5. 是否开启体验一致性；
6. 是否开启增强分流均匀性。

**8.2 流量设置字段**

| **字段** | **类型** | **规则** |
| --- | --- | --- |
| 是否互斥 | 单选 | 是 / 否 |
| 流量层 | 下拉 | 不互斥时选择流量层 |
| 互斥域 | 下拉 | 互斥时选择互斥域 |
| 实验流量 | 数字输入 | 0.01%-100% |
| 流量计算器 | 链接按钮 | 打开流量建议弹窗 |
| 流量生效方式 | 单选 | 立即生效 / 平滑生效 |
| 平滑生效时间 | 数字输入 | 1-1440 分钟 |
| 体验一致性 | 开关 | 默认开启 |
| 增强分流均匀性 | 开关 | 支持的实验类型展示 |

**8.3 是否互斥**

选择“否”：

1. 展示流量层下拉框。
2. 用户选择一个可用流量层。
3. 实验流量从该流量层扣减。

选择“是”：

1. 展示互斥域下拉框。
2. 只展示与实验类型一致的互斥域。
3. 客户端实验只能选客户端互斥域。
4. 服务端实验只能选服务端互斥域。
5. 互斥域中已有运行中实验时，运行中实验不可再次加入。

**8.4 实验流量**

规则：

1. 默认 100%。
2. 输入值必须大于 0 且不超过可用流量。
3. 支持两位小数。
4. 启用受众规则后，系统先筛选受众，再对受众用户应用实验流量。
5. 点击“流量计算器”后可根据样本量建议回填实验流量。
6. 流量不足时禁止进入下一步。

**8.5 流量生效方式**

立即生效：

1. 实验启动后立即按目标流量生效。
2. 不需要配置平滑时间。

平滑生效：

1. 展示平滑生效时间输入框。
2. 按分钟线性放量。
3. 例如实验流量 30%，平滑时间 30 分钟，则每分钟增加 1%。
4. 平滑期间不可修改实验流量和生效方式。

**8.6 用户受众规则**

页面展示条件组编辑器。

逻辑规则：

1. 可创建多个筛选组。
2. 筛选组之间为“或”关系。
3. 每个筛选组内多个条件为“且”关系。
4. 客户端实验支持用户属性、预置属性、自定义属性、用户分群。
5. 服务端实验支持服务端请求参数。
6. 未携带过滤参数的用户默认不满足条件。

条件字段：

| **字段** | **说明** |
| --- | --- |
| 属性名 | 从用户属性或服务端参数中选择 |
| 操作符 | 等于、不等于、包含、不包含、大于、小于、为空、不为空 |
| 属性值 | 根据属性类型展示输入控件 |
| 删除 | 删除当前条件 |
| 添加且条件 | 当前筛选组内增加条件 |
| 添加或条件 | 新增筛选组 |

**8.7 体验一致性**

开启后：

1. 用户一旦进入某实验版本，后续不因流量或受众条件调整而出组。
2. 除非实验暂停、关闭、停止，否则用户保持原版本。
3. 适合普通 A/B 实验。

关闭后：

1. 用户可进组、出组。
2. MAB 非体验一致性场景支持按配置参数调优。
3. 关闭体验一致性时，页面必须提示“用户可能在不同时间体验不同版本”。

**9. Step 3：配置实验版本**

**9.1 通用版本结构**

每个实验至少有一个对照版本和一个实验版本，特殊类型除外：

* MAB 不区分对照组和实验组，使用版本 1、版本 2；
* 个性化可配置单版本或多版本；
* MVT 由元素变体组合生成实验版本；
* 推送实验每个版本包含推送规则；
* 广告实验每个版本包含广告素材和广告配置。

**9.2 普通编程实验版本字段**

| **字段** | **是否必填** | **说明** |
| --- | --- | --- |
| 版本名称 | 是 | 版本内唯一 |
| 版本类型 | 是 | 对照组 / 实验组 |
| 版本描述 | 否 | 说明版本策略 |
| 测试用户 | 否 | 支持 SSID / UUID |
| 参数配置 | 是 | Number、String、Boolean、JSON |
| 流量分配 | 是 | 所有版本合计 100% |
| 是否关联 Feature | 否 | 可选择已有 Feature |

**9.3 版本操作按钮**

| **按钮** | **逻辑** |
| --- | --- |
| 添加实验版本 | 新增实验组，默认名称为“实验组 N” |
| 删除版本 | 删除当前实验组；对照组不可删除 |
| 复制版本 | 复制当前版本参数和测试用户 |
| 重命名版本 | 修改版本名称 |
| 设置为对照组 | 将当前版本设为对照组，原对照组转为实验组 |
| 添加测试用户 | 打开测试用户输入框 |
| 选择白名单组 | 打开白名单组选择弹窗 |
| 添加参数 | 新增实验参数 |
| 删除参数 | 删除当前参数 |
| 预览参数 | 展示最终下发 JSON |

**9.4 测试用户命中条件**

**17. MAB 智能调优实验**

**17.1 适用场景**

MAB 用于动态把流量倾斜给当前表现更好的版本，目标是整体收益最大化，而不是严格获得统计显著结论。

适用：

1. 活动周期短；
2. 高价值流量；
3. 小流量场景；
4. 标题、缩略图、Banner 等实时性强的优化；
5. 长期在线择优。

**17.2 基本信息字段**

| **字段** | **规则** |
| --- | --- |
| 调优名称 | 必填 |
| 调优描述 | 可选 |
| 调优场景 | 落地页优化 / APP 小程序优化 |
| 调优方式 | 可视化调优、多链接调优、客户端调优、服务端调优 |
| 调优方向与指标 | 只能选择一个核心指标 |
| 调优时长 | 默认 7 天，上限 60 天 |
| 负责人 | 默认当前用户 |

**17.3 指标限制**

MAB 指标要求：

1. 只能选择反馈较快的指标；
2. 推荐点击率、转化率类指标；
3. 不建议隔天或多个调优周期后才反馈的指标；
4. 指标不能带常数项；
5. 当前不建议使用浏览时长、人均点击次数等慢反馈指标。

**17.4 生效策略**

字段：

| **字段** | **规则** |
| --- | --- |
| 参与调优流量 | 默认 100% |
| 流量生效方式 | 立即 / 平滑 |
| 用户受众规则 | 与普通实验一致 |
| 体验一致性 | 默认开启 |
| 调优频率 | 0.5h-24h |

限制：

* 每个调优频率内，平均每组累计进组人数不能小于 500，否则系统等待样本累积后再调优。
* 指标值必须大于 0 才可正常调优。

**17.5 MAB 版本配置**

MAB 不区分对照组与实验组，使用版本 1、版本 2、版本 3。

流量分配逻辑：

默认模式：

1. 每个版本默认分配 3% 评估流量。
2. 评估流量用于算法调优和收益计算。
3. 剩余流量进入智能调优池。
4. 智能调优池根据算法动态分配。

自定义模式：

1. 打开“自定义流量分配”。
2. 用户手动设置评估流量和智能调优初始流量。
3. 保存前校验合计 100%。

**17.6 关闭体验一致性**

关闭体验一致性后：

1. MAB 不再按 VID 调优；
2. 改为按配置参数调优；
3. 必须上报事件公共属性 mab\_arm；
4. 后续行为事件必须携带 mab\_arm，否则统计不到进组和指标。

编辑运行中 MAB：

1. 可编辑下发版本；
2. 可打开预留版本；
3. 可关闭在线版本；
4. 可调整下发参数；
5. 参数变化版本进入冷启动；
6. 冷启动流量为在线版本平均流量；
7. 调优参数不支持 JSON 类型。

保存提醒：

* 编辑下发参数会影响实验报告中指标和提升比率可信度；
* 流量分配部分仍可信；
* 用户必须二次确认。

**25. 实验暂停、冻结、恢复**

**25.1 暂停**

点击“暂停”：

1. 弹出确认框。
2. 说明影响：
   * 已进组用户会出组；
   * 新用户不会进组；
   * 暂停期间事件不进入报告统计；
   * 用户不再上报曝光事件。
3. 用户点击确认。
4. 实验状态变为 PAUSED。

恢复后：

1. 原先进组用户仍回到原版本。
2. 实验数据继续产出。
3. 新用户按正常分流判断。

**25.2 冻结**

点击“冻结”：

1. 弹出确认框。
2. 说明影响：
   * 已进组用户保持不变；
   * 未进组用户不会进组；
   * 新用户不会进组；
   * 已进组用户继续上报曝光事件。
3. 用户确认后状态变为 FROZEN。

恢复后：

1. 已进组用户不受影响。
2. 新用户恢复正常分流判断。

**25.3 缓存提示**

暂停或冻结后：

1. 客户端可能因 SDK 缓存，在约 10 分钟内仍看到旧结果。
2. 下次请求分流服务后正式生效。
3. 页面必须展示缓存说明，避免用户误解。

**27. 关闭实验组**

**27.1 适用场景**

当多组实验中某一组出现工程问题或明显负向，需要及时止损，但其他组仍需继续实验时，可关闭单个实验组。

**27.2 入口**

实验报告页对应实验组区域：

关闭实验组

**27.3 关闭规则**

1. 用户不再命中该实验组。
2. 关闭当天之后该组不再产生数据。
3. 被关闭组流量不会释放。
4. 被关闭组流量不会分配给其他实验组。
5. 被关闭组流量不会回到同层其他实验。
6. 实验组关闭后不可重新开启。
7. 如果所有实验组均关闭，实验自动结束。
8. 后续扩量时，被关闭组仍占用对应比例，但不生效。

**27.4 点击逻辑**

1. 点击“关闭实验组”。
2. 弹出确认框。
3. 展示关闭影响。
4. 用户输入实验组名称或勾选确认。
5. 点击确认。
6. 状态更新为“已关闭”。
7. 写入操作日志。

**28. 实验固化至 Feature**

**28.1 入口**

1. 实验详情页；
2. 实验报告页；
3. 实验创建页版本配置中“关联 Feature”。

**28.2 前置条件**

1. 仅支持独立实验。
2. 独立实验指未关联过 Feature，且不是从 Feature 创建而来的实验。
3. 调试中实验不支持固化。
4. 支持运行中、冻结、已结束实验固化。
5. 当前仅支持包含 1 个参数变量的编程实验。
6. 支持参数类型：boolean、string、number、json。
7. 实验一旦固化到 Feature，不可再关联其他 Feature。
8. 需要实验协作者权限。

**28.3 命中优先级**

如果实验已固化到 Feature，且实验仍在运行：

1. 实验命中优先级高于 Feature。
2. 用户满足实验受众并进入实验流量，则命中实验。
3. 用户满足实验受众但未进入实验流量，且满足 Feature 受众和流量，则命中 Feature。
4. 用户不满足实验受众，但满足 Feature 条件，则命中 Feature。
5. 两者都不满足，则无行为。

**28.4 固化流程**

1. 点击“固化至 Feature”。
2. 系统校验是否满足固化条件。
3. 进入创建 / 编辑 Feature 页面。
4. 用户选择优胜版本。
5. 系统将该版本参数写入 Feature。
6. 用户选择全量发布或灰度发布。
7. 保存 Feature。
8. 实验详情展示已固化 Feature。

**36. 验收标准**

**36.1 实验创建**

1. 所有实验类型均可从统一入口进入。
2. 不满足前置条件的实验类型不可创建，并明确展示原因。
3. 普通实验可完成基本信息、生效策略、版本、指标配置。
4. 最后一步完整校验后进入调试状态。
5. 草稿可保存、恢复、继续编辑。

**36.2 实验管理**

1. 实验列表可按名称、状态、类型、标签、负责人筛选。
2. 不同状态展示不同操作按钮。
3. 无权限用户不可见或不可操作。
4. 暂停、冻结、恢复、停止、重启状态流转正确。
5. 高危操作必须二次确认。

**36.3 特殊实验**

1. 可视化实验可进入编辑器并保存页面修改。
2. 多链接实验只能通过对照 URL 触发分流。
3. 推送实验可配置通道、平台、内容、频控、推送时机。
4. MVT 可由元素变体自动生成组合版本。
5. MAB 可按调优频率动态调整流量。
6. 父子实验只能从运行中编程实验创建。
7. 反转实验只能从符合条件的已结束实验创建。
8. 广告实验可完成账户、资产、投放、版本配置。

**36.4 工具与看板**

1. 命中诊断能展示未命中原因。
2. 用户命中查询支持过滤、排序、下载。
3. 数据查重任务可创建并定时运行。
4. 实验看板可创建数据源、文本、排序、授权、复制链接。
5. 模板可固化字段、禁用字段，并用于创建实验。
