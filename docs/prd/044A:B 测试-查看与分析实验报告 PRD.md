**A/B 测试-查看与分析实验报告 PRD**

**1. 产品定位**

“查看与分析实验报告”模块用于在实验启动后，对实验进组用户、核心指标、关注指标、漏斗指标、留存指标、同期群、差异人群、热力图、MAB 调优收益和敏感人群洞察进行统一查看、解释和下钻分析。

该模块不是单纯展示统计结果，而是要帮助用户完成完整的实验决策链路：

1. 判断实验是否已经有可用数据。
2. 判断核心指标是否符合预期。
3. 判断指标变化是否统计显著。
4. 判断不显著时是“确实没效果”还是“样本不足、灵敏度不足”。
5. 下钻分析实验效果来自哪些人群、哪些行为路径、哪些页面点击变化。
6. 对 MAB 实验判断智能调优是否带来整体收益。
7. 输出可支持上线、下线、继续观察、扩大流量、细分人群投放的实验结论。

**2. 页面结构**

实验报告模块采用实验详情内页的多 Tab 结构。

页面路径：

A/B测试 > 实验列表 > 点击实验名称进入实验详情页> 点击“查看报告” > 实验报告页

或

A/B测试 > 实验列表 > 点击“查看报告” > 实验报告页

实验详情页顶部固定展示实验基础信息区，下面为一级 Tab。

一级 Tab 包括：

| **Tab** | **说明** |
| --- | --- |
| 实验结论 | 展示实验整体结论、核心指标汇总、进组人数、核心指标趋势、下载进组用户 |
| 数据指标 | 展示事件指标、留存指标、漏斗指标的明细分析 |
| 高级分析 | 展示同期群分析、差异分析与群体对比 |
| 热力图分析 | 仅可视化实验、多链接实验且开启热力图时展示 |

**3. 全局数据口径**

**3.1 实验进组用户口径**

实验指标计算必须基于“命中实验的用户”，即进组用户。

系统统一使用实验曝光事件作为用户进组依据。

客户端实验和服务端实验都按如下方式识别进组：

| **实验类型** | **进组判断逻辑** |
| --- | --- |
| 客户端实验 | 实验开始后上报过实验曝光事件的用户 |
| 服务端实验 | 实验开始后上报过实验曝光事件，并在统计周期内产生相关行为事件的用户 |
| 推送实验 | 以推送曝光字段或推送发送字段记录用户进入实验 |

曝光事件字段包括：

| **类型** | **曝光字段** |
| --- | --- |
| 普通实验 | abtest\_exposure |
| 推送实验 | rangers\_push\_send |

同一个用户在同一个实验、同一个实验版本内只计算一次进组。

如果用户多次曝光同一实验版本，进组人数仍按去重用户数计算。

如果实验开启了体验一致性，用户进组后始终归属于首次命中的实验版本。

如果实验关闭体验一致性，用户可能在不同调优轮次命中不同参数或版本，MAB 报告需按“参数维度”展示，而不是简单按固定实验版本展示。

**3.2 实验报告数据刷新口径**

| **实验状态** | **报告概览进组人数** | **指标数据** |
| --- | --- | --- |
| 实验开启当天 | 实时统计从实验开启到当前时刻的累计进组人数 | 支持实时查询，小时级和 5 分钟级用于排查实验配置和数据上报问题 |
| 实验运行第二天及之后 | 按 T-1 天级离线数据更新，展示截止昨日 0 点或完整天的累计进组人数 | 默认使用完整天累计数据 |
| 实验结束当天 | 仍支持小时级和 5 分钟级查看 | 天级、小时级、5 分钟级均可按限制查询 |
| 实验结束后非结束当天 | 展示实验开始至实验结束期间的完整累计数据 | 仅支持天级数据查询 |

页面右上角必须展示数据更新时间。

格式：

数据更新时间：YYYY-MM-DD HH:mm:ss

如果数据仍在计算中，展示：

数据计算中，当前展示上一次成功计算结果

并在刷新按钮旁显示黄色提示图标。

**3.3 多天累计数据口径**

实验报告默认采用多天累计数据。

多天累计不是对每日指标简单求平均，而是先按用户聚合多天行为，再基于聚合后的样本计算指标值、标准差、置信区间和 P-value。

示例逻辑：

用户 A 第 1 天 read/u = 13，第 2 天 read/u = 6，则多天累计 read/u = 19。

用户 B 第 1 天 read/u = 2，第 2 天 read/u = 0，则多天累计 read/u = 2。

多天累计的目的：

1. 保证各实验组样本同质可比。
2. 随着实验运行，样本量增加，检验灵敏度提高。
3. 可直接计算实验周期内累计指标变化的置信度。
4. 支持给出更稳定的实验结论。

**3.4 核心统计字段**

所有指标分析中统一使用以下字段。

| **字段** | **含义** |
| --- | --- |
| 进组人数 | 当前实验版本内累计进入实验的去重用户数 |
| 指标值 | 当前版本在当前统计口径下的指标实际值 |
| 差异绝对值 | 当前版本指标值减去基准版本指标值 |
| 差异相对值 | 差异绝对值除以基准版本指标值 |
| P-value | 在原假设成立时观察到当前差异或更极端差异的概率 |
| 置信区间 | 指标变化率的区间估计 |
| MDE | 当前样本条件下可有效检出的最小差异幅度 |
| 显著性状态 | 正向显著、负向显著、不显著 |

计算口径：

$$
\text{差异绝对值}=\text{实验版本指标值}-\text{基准版本指标值}\quad。
$$

$$
\text{差异相对值}=\frac{\text{实验版本指标值}-\text{基准版本指标值}}{\text{基准版本指标值}}\quad。
$$

默认置信水平为 95%。

显著性判断：

| **条件** | **状态** | **UI 展示** |
| --- | --- | --- |
| P-value < 0.05 且置信区间上下界均大于 0 | 正向显著 | 绿色底色、绿色文案 |
| P-value < 0.05 且置信区间上下界均小于 0 | 负向显著 | 红色底色、红色文案 |
| 置信区间跨 0 或 P-value ≥ 0.05 | 不显著 | 默认底色、黑色或灰色文案 |

置信区间优先用于展示方向和不确定性，P-value 用于辅助解释显著性强弱。

**4. 实验报告主页面：实验结论**

**4.1 页面目标**

实验结论页用于让用户快速回答：

1. 当前实验是否可以下结论。
2. 哪个实验版本表现最好。
3. 核心指标是否显著提升或显著下降。
4. 是否需要继续观察、扩大样本、停止实验或进入高级分析。

**4.2 页面布局**

页面从上到下分为 5 个区域：

实验基础信息区

实验结论横幅

核心指标汇总表

核心指标趋势分析区

进组用户下载区

实验结论横幅根据核心指标显著性自动生成。

状态包括：

| **状态** | **触发条件** | **文案规则** |
| --- | --- | --- |
| 正向显著 | 至少一个实验版本在核心指标上相对对照组正向显著，且无必看指标显著负向 | “当前实验核心指标存在正向显著提升，建议结合业务成本评估是否上线。” |
| 负向显著 | 任一实验版本核心指标显著低于对照组 | “当前实验核心指标存在显著负向影响，建议暂停或回滚相关策略。” |
| 不显著 | 核心指标均不显著 | “当前条件下尚未检测到显著差异，建议结合 MDE、样本量和实验周期判断是否继续观察。” |
| 数据不足 | 进组人数、指标事件量不足以计算统计结果 | “当前数据不足，暂无法输出实验结论。” |

| **字段** | **说明** |
| --- | --- |

| 核心指标变化 | 展示相对对照组变化率 |
| P-value | 展示核心指标对应 P-value |
| 置信区间 | 展示核心指标变化率置信区间 |
| MDE | 展示当前检验灵敏度 |

“建议动作”生成逻辑：

| **条件** | **建议** |
| --- | --- |
| 正向显著且核心指标达到预期提升 | 建议上线或进入分人群验证 |

| 不显著且 MDE 小于目标提升值 | 说明实验大概率未达到目标，建议综合业务价值判断 |
| 不显著且 MDE 大于目标提升值 | 说明灵敏度不足，建议扩大流量或延长实验 |

**8.7 漏斗计算规则**

漏斗指标按 UV 计算。

$$
\text{整体转化率}=\frac{\text{到达当前漏斗事件的人数}}{\text{第一步漏斗事件的人数}}\quad。
$$

$$
\text{上一步转化率}=\frac{\text{到达当前漏斗事件的人数}}{\text{上一步漏斗事件的人数}}\quad。
$$

实验曝光事件作为漏斗第一步之前的过滤事件。

即只有触发实验曝光事件且携带对应实验版本 VID 的用户，才参与漏斗计算。

限制：

1. 漏斗支持全局时间过滤。
2. 漏斗支持多维过滤。
3. 漏斗不受时间粒度影响。
4. 实时漏斗不支持置信度计算，只展示纯漏斗数据。
5. 漏斗无缓存，如果漏斗配置被修改，所有引用该漏斗的实验报告都展示最新漏斗配置和最新计算结果。

**13. 敏感人群洞察**

**13.2 入口**

实验报告 > 数据指标 Tab > 敏感人群洞察按钮

1. 当前实验已有进组数据。

**13.3 创建任务**

任务定义：

一个敏感人群洞察任务 = 一个实验 + 一个指标 + 一个实验组 + 一个对照组 + 一个挖掘方向 + 一组用户属性。

| **方向** | **说明** |

校验规则：

1. 任务名称不能为空。
2. 实验组不能等于对照组。
3. 必须选择分析指标。
4. 必须选择至少 4 个用户属性。
5. 建议进组人数大于 20000；低于该值可提交，但弹出确认提示。
6. 实验创建当天不允许创建任务。
7. 同一实验、同一指标、同一实验组、同一对照组、同一时间范围存在运行中任务时，不允许重复创建。

| 子人群下载 | 下载用户明细 |

**13.5.1 报告总览**

展示字段：

| **字段** | **说明** |
| --- | --- |
| 是否发现敏感人群 | 是、否 |

在重要特征交叉子人群中，与挖掘方向一致，且指标表现显著的子人群集合。

**14. 报告解读辅助逻辑**

**14.1 实验多久后可以看指标**

系统在实验运行不足 7 天时，在实验结论页展示提示：

当前实验运行未满一个自然周期，建议谨慎解读实验结论。

但如果实验属于短周期敏感策略，例如推荐策略、按钮点击策略，用户仍可查看实时和天级数据。

**14.2 指标是否符合预期**

如果实验创建时配置了目标提升值，则报告自动比较当前相对变化和目标提升值。

| **条件** | **提示** |
| --- | --- |
| 当前提升 ≥ 目标提升，且显著 | 达到预期 |
| 当前提升 < 目标提升，且显著 | 有提升但低于预期 |
| 当前不显著 | 暂无法判断是否达到预期 |
| 当前负向显著 | 明显不符合预期 |

**14.3 不显著时的判断**

当核心指标不显著时，页面展示 MDE 解读卡片。

判断逻辑：

| **条件** | **解读** |
| --- | --- |
| MDE < 目标提升值 | 当前实验已经有能力检出目标差异，但未检出，说明策略可能未达到预期 |
| MDE > 目标提升值 | 当前实验灵敏度不足，不能证明策略无效 |
| 样本量过小 | 建议扩大流量或延长实验 |
| 指标渗透率低 | 建议选择更敏感指标或延长观察 |
| 实验周期短 | 建议继续运行至少一个自然周期 |

**19. 验收标准**

**19.1 实验结论页**

1. 用户进入实验报告后，可以看到实验基础信息、数据更新时间、实验结论、核心指标汇总。
2. 正向显著、负向显著、不显著必须用不同颜色区分。
3. 点击指标单元格必须展示统计卡片。
4. 点击进组人数可以下载进组用户 ID。
5. 超过 500 万条下载限制时必须拦截。
6. 数据刷新失败时不能清空旧数据。

**19.2 数据指标页**

1. 用户可以切换核心指标、关注指标、事件指标、留存指标、漏斗指标。
2. 时间粒度必须按实验状态限制。
3. 属性过滤和用户分群过滤必须按 AND 逻辑生效。
4. 查询、重置、下载、模板保存、模板应用按钮逻辑必须完整。
5. 指标组视图必须支持差值类型切换。
6. PreAA 不支持时不展示入口，支持但数据不足时置灰。

**19.3 漏斗指标**

1. 漏斗必须支持列表视图和漏斗视图切换。
2. 对比版本必选，被对比版本可选。
3. 被对比版本选择“不对比版本”时，不计算置信区间。
4. 漏斗按 UV 计算。
5. 实验曝光事件必须作为漏斗计算前置过滤条件。

**19.4 高级分析**

1. 同期群分析必须支持指标切换、时间筛选、维度过滤、详细数据展开。
2. 差异分析必须支持添加多个群体，并校验群体配置。
3. 样本不足时必须提示，不允许直接给出强结论。
4. 差异分析结果必须展示实验版本、用户分群、客群对比数据。

**19.5 热力图**

1. 仅符合条件的实验展示热力图 Tab。
2. 点击热力图必须展示点击数、点击人数、点击占比、点击率。
3. 每个页面最多支持 5 个圈选区域。
4. 隐藏热力图后才允许操作页面。
5. 元素热力图必须展示 Top 20 元素点击排行。

**19.6 MAB 报告**

1. 仅 MAB 实验展示 MAB 报告。
2. 必须展示整体收益提升、核心指标明细表、核心指标趋势、流量分配。
3. 数据展示保留 4 位小数。
4. 非体验一致性场景必须按参数展示，并标记实验编辑节点。
5. 流量最高版本不得被直接标记为最终最优版本，只能作为概率性判断。

**19.7 敏感人群洞察**

1. 实验创建当天不允许创建任务。
2. 创建任务必须校验指标、实验组、对照组、时间范围、用户属性。
3. 任务状态必须展示数据准备、模型训练、模型预测、结果输出四个阶段。
4. 报告必须展示敏感人群、特征重要性、重要特征交叉子人群。
5. 子人群下载必须包含 treatment、uid、app\_id、属性、ite、bins 等字段。
