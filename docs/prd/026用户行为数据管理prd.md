# 用户行为数据管理 PRD

## 1. 文档定位

本文档面向前端、后端、数据工程、测试与 Codex 开发，实现一个完整的用户行为数据管理模块。该模块负责从埋点数据接入、元数据登记、事件与属性治理、实时验证、会话配置、虚拟事件/虚拟属性、圈选事件、关系事件、维度字典、埋点血缘、入库质量监控、校验规则、告警、成本治理等环节，形成闭环的数据管理能力。

本文档不是功能清单，而是可落地的产品功能逻辑级 PRD。每个模块均描述页面入口、数据结构、交互逻辑、状态流转、校验规则、接口设计、异常处理和验收标准。

## 2. 产品目标

用户行为数据管理模块要解决四类问题。

第一，数据能正确接入。系统要支持客户端、网页端、小程序端、服务端等多端行为数据接入，并通过统一 JSON 数据模型落库，保证事件、事件属性、用户属性、预置属性、Item 属性等数据能被统一识别。

第二，数据能被规范管理。系统要支持一般事件、事件属性、用户属性、虚拟事件、虚拟属性、圈选事件、被动事件、关系事件、会话等元数据管理能力，避免事件命名混乱、属性类型不一致、重复埋点、无效埋点泛滥。

第三，数据能被验证和治理。系统要支持埋点实时验证、验证报告、数据治理看板、数据入库明细、校验规则配置、告警管理，使研发、测试、数据管理员能在数据进入分析链路前发现问题。

第四，数据能降低使用成本。系统要支持事件分类、维度字典、埋点血缘和成本治理分析，帮助用户快速找到数据、理解数据、评估修改影响，并清理低 ROI、无效、重复、类似事件。

type PropertyDataType = 'int' | 'float' | 'string' | 'datetime' | 'list' | 'version';

系统需要内置以下规则。

| 类型 | 上报要求 | 落库与分析要求 |
| --- | --- | --- |
| int | JSON number，整数范围在 int64 内 | 支持求和、均值、人均值、分位数、区间筛选 |
| float | JSON number，最大精度 16 位 | 支持求和、均值、人均值、分位数、区间筛选 |
| string | UTF-8 字符串 | SaaS 云原生最大 2048 字符，非云原生最大 1024 字符；支持等于、不等于、包含、正则等 |
| datetime | 字符串格式，必须包含日期和时间 | 支持固定范围、相对当前时间、相对事件发生时间等筛选 |
| list | JSON array，元素为 string，同一数组元素类型一致 | 最多 500 个元素，落库时去重；支持包含类筛选 |
| version | string，通常 2-6 段英文句点分隔，每段最长 5 位 | 支持版本排序和版本大小比较 |

对象和布尔值允许上报，但统一转为 string 存储。嵌套 JSON 不直接作为结构化字段落库，如果业务需要使用其中字段，应转义为 string 后上报，再通过虚拟属性抽取。

## 6. 数据接入模块

### 6.1 接入概览页

#### 6.1.1 页面目标

接入概览页用于指导用户完成数据采集前的准备工作，包括确认应用、获取 app\_id、选择 SDK、确认上报地址、理解数据类型限制、进入实时验证。

#### 6.1.2 页面结构

页面包含以下区域。

1. 当前应用信息卡片：展示项目、应用、环境、地域、时区、app\_id、SDK 开关状态。
2. 接入步骤条：准备工作、SDK 集成、数据上报、实时验证、元数据管理、治理监控。
3. 端类型卡片：Android、iOS、HarmonyOS、Web JS、小程序、服务端、HTTP API。
4. 数据流说明：行为数据、用户数据、设备数据、Item 数据。
5. 快捷入口：数据上报地址、数据格式、实时验证、一般事件、事件属性、用户属性、数据治理看板。

#### 6.1.3 接入流程逻辑

用户进入页面时，系统按以下顺序初始化。

async function initAccessOverview(appId: string) {
 const app = await getAppContext(appId);
 const sdkVersions = await getSdkVersionMatrix(app.environmentType, app.region);
 const sdkSettings = await getSdkSettings(appId);
 const recentHealth = await getRecentIngestionHealth(appId, { range: 'last\_24h' });
 render({ app, sdkVersions, sdkSettings, recentHealth });
}

接入流程必须强调：自定义事件和属性在上报前应优先完成元数据登记。如果用户开启了入库校验模式，未登记或未验收的数据不允许入库；如果未开启入库校验，未知事件和属性会自动进入元数据，但仍可能因为类型、命名、数量、长度等原因被拦截或丢弃。

### 6.2 数据上报地址页

#### 6.2.1 页面目标

用户根据当前环境、地域和端类型获取正确的数据上报地址。错误的上报地址会导致数据无法查询。

#### 6.2.2 筛选区

字段：

| 字段 | 控件 | 默认值 | 逻辑 |

| 环境类型 | 单选 | 当前应用环境 | 不允许选择当前应用不支持的环境 |
| 地域 | 下拉 | 当前应用地域 | SaaS 云原生必须选择地域；私有化支持自定义域名 |
| 端类型 | 多选 | 全部 | 支持按客户端、服务端、HTTP API 分类 |

#### 6.2.3 地址展示逻辑

interface ReportEndpoint {

### 6.3 数据格式与事件属性分类页

#### 6.3.1 页面目标

帮助用户明确事件、事件属性、事件公共属性、用户属性、Item 属性的数据格式、限制和应用场景。

#### 6.3.2 数据分类

系统将数据分为：

1. 系统预置：预置事件公共属性、预置事件及事件属性、预置用户属性。
2. 自定义：自定义事件公共属性、自定义事件及事件属性、自定义用户属性。
3. 业务对象：Item 属性及事件与 Item 的关联关系。
4. 伪事件：any\_event、any\_active\_event，仅供查询分析使用，不真实上报。

#### 6.3.3 数据格式校验规则

前端在新建事件或属性时要进行前置校验，后端必须二次校验。

const EVENT\_NAME\_REGEX = /^[a-zA-Z0-9][a-zA-Z0-9\_ .-]{0,254}$/;
const PROPERTY\_NAME\_REGEX = /^[a-zA-Z0-9][a-zA-Z0-9\_ .-]{0,63}$/;
const VIRTUAL\_PROPERTY\_REGEX = /^[a-zA-Z\_][0-9a-zA-Z\_]{0,99}$/;
const VERSION\_REGEX = /^[0-9]{1,5}(\.[0-9]{1,5}){1,5}$/;

事件名不得与已存在的一般事件、虚拟事件、圈选事件重复。事件名不得以 $ 或 \_\_ 开头，系统白名单属性除外。

属性名不得为 user\_unique\_id、ssid、event\_id，不得与预置属性名称冲突。属性值建议不超过 255 字符；如果超过环境上限，系统按异常属性处理。

#### 6.3.4 数据类型选择指导

属性创建时增加“推荐类型说明”。

| 场景 | 推荐类型 | 说明 |
| --- | --- | --- |
| 年龄、次数、整数金额 | int | 需要数值计算且无小数 |
| 时长、折扣、金额小数 | float | 需要求和、均值、分位数 |
| 页面标题、按钮名称、商品 ID | string | 文本、ID、不参与数值计算 |
| 标签集合、多个分类 | list | 一个属性有多个值，按单个值筛选 |
| 注册时间、支付时间 | datetime | 需要时间范围筛选 |
| app 版本、系统版本 | version | 需要版本排序或版本比较 |

### 6.4 可视化数据集成页

#### 6.4.1 页面目标

支持通过 Kafka 消息订阅把第三方 UBA 行为数据或用户属性数据同步到系统中。用户可以通过可视化配置或自定义配置创建数据集成任务。

#### 6.4.2 任务模型

interface DataIntegrationTask {

 kafkaConfig?: KafkaConfig;
 fieldMappings: FieldMapping[];
 status: 'draft' | 'testing' | 'running' | 'paused' | 'failed' | 'completed';
 lastRunAt?: string;
 createdBy: string;
 createdAt: string;
}

interface KafkaConfig {
 consumerGroup: string;
 bootstrapServers: string[];
 topic: string;
 authType: 'none' | 'sasl\_plaintext' | 'sasl\_ssl';
 username?: string;
 password?: string;
}

interface FieldMapping {
 sourceField: string;
 targetField: string;
 targetType: 'header' | 'user' | 'event' | 'event\_param' | 'user\_profile';
 dataType: PropertyDataType;
 required: boolean;
 transformExpression?: string;
}

#### 6.4.3 创建任务流程

第一步，选择数据类型。用户选择“UBA 数据”或“用户属性”。选择后展示对应目标字段模板。

第二步，配置任务基本信息。任务名称必填，长度 1-64；描述选填，最多 500 字。

第三步，连接 Kafka。用户输入消费者组、Kafka Server、Topic、认证信息，点击“测试连接”。测试成功前不可进入下一步。失败时展示失败原因，例如网络不可达、认证失败、topic 不存在、无消费权限。

第四步，解析样例数据。系统从 Topic 拉取样例消息，解析出字段树。解析失败时提供原始消息预览和错误定位。

第五步，字段映射。用户把源字段映射到系统字段。必须映射事件名、事件发生时间、用户标识、事件属性或用户属性。系统自动校验目标字段类型和必填性。

第六步，预览转换结果。系统基于样例消息生成标准上报结构，展示 header、user、events 或 user profile payload。

第七步，保存并执行。任务进入 running 状态。运行过程中记录同步条数、失败条数、最近错误、延迟。

#### 6.4.4 自定义上传配置

自定义配置模式允许用户上传映射配置文件。上传后系统校验文件结构、字段名、目标类型、数据类型。校验通过后生成与可视化配置一致的任务。

#### 6.4.5 集成后数据使用

通过数据集成同步的用户行为数据应进入数据管理页面，可在一般事件、事件属性、用户属性中查看，并可在分析模块中使用。数据集成任务产生的数据仍然要进入入库校验、治理看板、错误日志和成本治理流程。

列表列包括事件名称、展示名、分类、描述、状态、来源、属性数、最近 30 天查询次数、昨日入库数、更新时间、操作。

### 7.1.3 筛选与搜索

支持事件名称、展示名模糊搜索；状态筛选；来源筛选；事件分类筛选；是否预置筛选；是否有截图筛选；最近 30 天是否被查询筛选。

搜索输入使用防抖，默认 300ms。筛选条件变化后重置页码为第一页。列表接口必须支持分页、排序和条件组合。

### 7.1.4 新建单个事件

入口：一般事件页右上角“新建事件” → “单个新建事件”。

表单字段：

| 字段 | 必填 | 校验 | 逻辑 |
| --- | --- | --- | --- |
| 事件名称 | 是 | 1-255；符合事件名正则；不重复；不与虚拟事件同名 | 保存后不可修改 |
| 展示名 | 否 | 1-100 | 建议填写业务含义 |
| 事件分类 | 否 | 已存在分类 | 公共分类需管理员维护，私人分类仅本人可见 |
| 事件描述 | 否 | 0-1000 | 建议填写上报时机和业务场景 |
| 属性设置 | 否 | 可多选事件属性 | 只能选择一般事件属性，即 params 上报属性 |

提交逻辑：

async function createEvent(form: CreateEventForm) {
 validateEventName(form.eventName);
 await assertEventNameNotExists(form.eventName);
 await assertVirtualEventNameNotExists(form.eventName);
 const event = await api.createEvent(form);
 await auditLog('metadata.event.create', event.id, form);
 return event;
}

成功后关闭弹窗，刷新列表，toast：“事件创建成功”。失败时保持表单内容，错误定位到具体字段。

### 7.1.5 批量新建事件

入口：一般事件页右上角“新建事件” → “批量新建事件”。

流程：下载埋点设计模板 → 本地填写 → 上传 → 预校验 → 错误修正 → 确认导入。

一次最多提交 200 个事件。预校验结果以表格展示，包括行号、事件名称、错误类型、错误说明。存在错误时“确认导入”按钮禁用。重复事件可选择“跳过已存在项”或“覆盖展示信息”，但事件名称不可被修改。

### 7.1.6 事件详情侧边栏

点击事件名称打开右侧详情。详情包含：基本信息、事件属性、事件公共属性、预置属性说明、埋点截图、图表血缘、分群血缘、入库质量、操作日志。

事件属性区支持“添加事件属性”。只能添加自定义事件属性，不能添加事件公共属性。删除事件已添加的自定义属性时，如果该属性仍在入库或分析中被使用，需要展示影响提示；如果启用了埋点血缘，展示被影响图表和分群。

### 7.1.7 编辑事件展示信息

可编辑字段：展示名、描述、分类。事件名称不可编辑。支持单个编辑和批量编辑。

批量编辑逻辑：用户可导出当前筛选结果为 CSV，在 CSV 中补充展示名和描述，再上传导入。批量导入仅允许修改展示名和描述，不允许修改事件名称、状态、数据类型。

### 7.1.8 事件状态管理

状态操作：启用、禁用、隐藏。

| 状态 | 是否占用配额 | 是否构建存储 | 是否产品内可用 | 是否计费 | 是否支持导出 |
| --- | --- | --- | --- | --- | --- |
| 禁用 | 否 | 否 | 否 | 否 | 否 |
| 启用 | 是 | 是 | 是 | 是 | 是 |
| 隐藏 | 是 | 是 | 否 | 是 | 是 |

禁用前必须弹出确认弹窗。弹窗展示事件最近 30 天查询次数、昨日入库数、关联图表、关联分群、相关虚拟事件、相关虚拟属性。若用户确认禁用，则事件不可在分析模块选择，后续上报该事件不构建入库。

隐藏用于系统后台消费或不希望业务用户在分析工具中看到的事件。隐藏后继续构建存储和计费，但分析工具事件选择器不展示。

### 7.1.9 事件验收

开启入库校验后，未知事件进入待验收列表。一般事件列表只展示已验收或已登记事件。点击“验收事件”进入数据验收页。

待验收事件列表最多展示 1000 个，超过部分不可查。用户可验收、加入黑名单、批量验收。验收时必须确认事件名称、展示名、数据类型、属性归属。验收通过后状态为启用或隐藏。

黑名单事件永远不入库。从黑名单移除后，如再次上报，则重新进入待验收列表。

### 7.1.10 验证埋点入口

一般事件页右上角提供“验证埋点”按钮，点击后跳转到埋点实时验证页，并携带当前应用和事件上下文。若从事件详情进入，验证页默认过滤该事件。

## 7.2 事件属性管理

### 7.2.1 页面目标

事件属性用于描述事件发生时的维度信息，包括设备信息、位置、页面、业务参数等。系统区分事件属性和事件公共属性。

事件属性又称 params，不同事件可以有不同属性。事件公共属性又称 header，每个事件都可使用。

### 7.2.2 数据模型

interface EventPropertyMetadata {
 id: string;
 appId: string;
 propertyName: string;
 displayName?: string;
 description?: string;
 dataType: PropertyDataType;
 propertyScope: 'event\_param' | 'event\_common\_header';
 associatedEventIds: string[];
 isPreset: boolean;
 status: MetadataStatus;
 dictionaryStatus: 'none' | 'uploaded' | 'processing' | 'effective' | 'failed';
 createdAt: string;
 updatedAt: string;
}

### 7.2.3 新增事件属性

入口：事件属性页右上角“新增事件属性”。

表单字段：属性名称、展示名、是否事件公共属性、数据类型、关联事件、属性描述。

逻辑：

1. 如果登记一般事件属性，不勾选“事件公共属性”，必须选择至少一个关联事件。否则该属性在查询事件时无法被使用。
2. 如果登记事件公共属性，必须勾选“事件公共属性”，不需要关联特定事件。
3. 常见设备、时间等通用参数优先使用预置属性，不建议重复创建。
4. 属性名称必须具体，系统在输入泛化名称如 time、name 时给出弱提示：“建议使用更明确名称，如 order\_time、product\_name”。

### 7.2.4 属性状态

事件属性状态包括启用、禁用、不显示。

* 启用：数据正常更新，分析模块可用。
* 禁用：数据被丢弃，系统内不可查。
* 不显示：数据正常更新，但系统内不可查，适用于后台消费属性。

### 7.2.5 验收属性

开启入库校验时，未登记事件属性进入待验收列表。验收属性与新增属性最终效果一致，都会注册到事件属性列表。区别是：验收属性必须先有上报数据被系统识别；新增属性可以在埋点上线前完成登记。

### 7.2.6 修改数据类型

允许修改自定义属性的数据类型。系统必须在弹窗中提示历史数据影响。

转换规则：

* string 数值型 → int/float：可转换，历史数据不丢失。
* float → int：可转换，但小数部分丢失。
* int → float：新数据可入库，但历史查询可能受影响。
* int/float → string：历史数据可能丢失。
* string 非数值 → int/float：历史数据有损。
* string → datetime 等其他转换不可逆，必须强确认。

用户确认后，后端记录类型变更日志。前端展示“修改前请同步修改 SDK 上报代码，否则可能导致入库失败或数据丢失”。

### 7.2.7 批量编辑展示名和描述

支持筛选展示名为空或描述为空的属性，批量导出 CSV。用户在本地补齐后上传。导入只允许修改展示名和属性描述，其他字段忽略并提示。

## 7.3 用户属性管理

### 7.3.1 页面目标

用户属性描述用户自身状态或相对稳定的信息，例如年龄、性别、注册时间、VIP 等级、最近一次支付时间。用户属性与行为无关或变化频率较低，不随单个事件触发而变化。

### 7.3.2 用户属性模型

interface UserPropertyMetadata {
 id: string;
 appId: string;
 propertyName: string;
 displayName?: string;
 description?: string;
 dataType: PropertyDataType;
 calculationLogic: 'all\_values' | 'latest\_value';
 isPreset: boolean;
 status: MetadataStatus;
 dictionaryStatus: 'none' | 'uploaded' | 'processing' | 'effective' | 'failed';
 createdAt: string;
 updatedAt: string;
}

### 7.3.3 新增用户属性

字段：属性名、展示名、数据类型、计算逻辑、描述。

数据类型支持 int、string、float、datetime、list、version。选择的数据类型必须与后续上报一致，否则可能无法正常落库。

计算逻辑：

* 计算全部值：用户属性变化前后的事件按当时属性值归属。例如用户从普通会员升级为 VIP，升级前事件归普通会员，升级后事件归 VIP。
* 计算最终值：所有历史事件都按用户最新属性值归属。例如用户最终为 VIP，则历史所有事件均归 VIP。

### 7.3.4 修改与验收

用户属性支持验收、加入黑名单、修改数据类型、批量编辑展示名和描述。数据类型修改遵循事件属性同类规则，但用户属性的历史归属计算会额外受计算逻辑影响，因此修改前必须展示二次确认。

## 7.4 虚拟事件管理

### 7.4.1 页面目标

虚拟事件用于把多个一般事件按 OR 逻辑组合成一个复合事件，便于在分析中统一使用。例如“浏览页面 A 或浏览页面 B”的去重用户数。

### 7.4.2 数据模型

interface VirtualEvent {
 id: string;
 appId: string;
 eventName: string;
 displayName: string;
 description?: string;
 combinedEvents: VirtualEventComponent[];
 status: 'enabled' | 'disabled';
 createdAt: string;
 updatedAt: string;
}

interface VirtualEventComponent {
 eventId: string;
 eventName: string;
 filters: FilterCondition[];
}

### 7.4.3 列表逻辑

进入虚拟事件页默认展示所有已创建虚拟事件。支持按事件名称、展示名筛选。列表字段包括虚拟事件名称、展示名、组合事件数、描述、状态、创建人、更新时间、操作。

### 7.4.4 创建虚拟事件

表单字段：虚拟事件名称、展示名、描述、组合一般事件。

组合事件逻辑：

1. 至少选择一个一般事件。
2. 每个一般事件可配置过滤条件。
3. 多个一般事件之间为 OR 关系，任意一个组件事件命中即视为虚拟事件命中。
4. 虚拟事件名称不得与一般事件、已有虚拟事件重复。
5. 虚拟事件用于查询分析，不是真实 SDK 上报事件，不参与客户端上报。

### 7.4.5 使用限制

虚拟事件可在分析工具选择事件时作为“虚拟事件”类型展示。虚拟事件不进入一般事件列表，但公共事件分类可同步展示。虚拟事件可以使用用户虚拟属性和部分事件虚拟属性，具体依赖虚拟属性适用范围。

## 7.5 虚拟属性管理

### 7.5.1 页面目标

虚拟属性用于对现有属性做二次加工，支持通过 SQL 表达式片段完成四则运算、字符串处理、URL 解析、JSON 字段抽取、属性合并、精度处理、分层标签、类型转换等。

### 7.5.2 创建限制

SaaS 云原生、SaaS 非云原生每个应用最多 200 个虚拟属性。私有化每个应用最多 5000 个。达到上限后“创建虚拟属性”按钮不可点击，并提示上限原因。

### 7.5.3 数据模型

interface VirtualProperty {
 id: string;
 appId: string;
 propertyType: 'event\_virtual\_property' | 'user\_virtual\_property';
 propertyName: string;
 displayName?: string;
 description?: string;
 dataType: Exclude<PropertyDataType, 'version'>;
 sqlExpression: string;
 associationMode?: 'any\_referenced\_property\_has\_value' | 'all\_referenced\_properties\_have\_value';
 referencedProperties: ReferencedProperty[];
 status: 'valid' | 'invalid' | 'deleted';
 invalidReason?: string;
 dictionaryStatus?: string;
 createdAt: string;
 updatedAt: string;
}

### 7.5.4 创建表单逻辑

字段：属性类型、属性名称、展示名、数据类型、SQL 表达式、关联方式、描述。

属性名称规则：仅英文、数字、下划线，以字母或下划线开头，长度 100 以内，大小写敏感。系统自动增加默认前缀 $vp。

数据类型支持 string、int、float、datetime、list。

SQL 表达式只允许 SQL 片段，不允许多语句。只执行第一段 SQL。表达式可以引用事件属性 event\_params.xxx 和用户属性 user\_profiles.xxx。引用数字、中文等特殊字符开头属性时使用反引号包裹。

事件虚拟属性需要选择关联方式：

* 任一：SQL 中用到的任一属性有值时，事件关联虚拟属性。
* 全部：SQL 中全部属性都有值时，事件才关联虚拟属性。

### 7.5.5 SQL 校验逻辑

提交前后端执行 dry-run 校验。

interface SqlValidationResult {
 valid: boolean;
 outputType?: PropertyDataType;
 referencedProperties: ReferencedProperty[];
 errors: Array<{ code: string; message: string; start?: number; end?: number }>;
}

校验项包括：语法正确、引用属性存在、引用属性未禁用、表达式输出类型与选择类型兼容、未基于虚拟属性创建虚拟属性、用户虚拟属性表达式中不包含事件属性。

### 7.5.6 示例能力

虚拟属性应支持以下表达式场景。

* 利润计算：event\_params.sale\_price - event\_params.cost\_price
* 本息计算：event\_params.principal + event\_params.principal \* pow(event\_params.interest\_rate, event\_params.duration)
* 域名抽取：domain(event\_params.full\_url)
* JSON 字段抽取：JSONExtractString(event\_params.body\_json, 'product')
* 拼写错误字段合并：if(event\_params.product\_name IS NOT NULL, event\_params.product\_name, event\_params.produc\_name)
* 金额展示格式化：concat('￥', toString(event\_params.price))
* 精度处理：round(event\_params.price, 0)
* 用户等级：multiIf(user\_profiles.total\_cost < 100, '青铜', user\_profiles.total\_cost >= 100 and user\_profiles.total\_cost < 200, '黄金', user\_profiles.total\_cost >= 200 and user\_profiles.total\_cost < 500, '白金', user\_profiles.total\_cost >= 500 and user\_profiles.total\_cost < 1000, '钻石', '黑金')
* 类型转换：cast(event\_params.media\_duration\_info / 1000 / 60 as Nullable(int))

类型转换时，槽位化后 Map 列中事件属性为 nullable，强制转换必须使用 Nullable 类型，避免转换失败。

### 7.5.7 编辑与删除

可编辑展示名、描述、字典、数据类型、SQL 表达式。任何字段修改都要重新验证 SQL。SQL 表达式修改后，已有字典自动删除，并提示用户确认。

如果虚拟属性失效，例如引用属性被禁用、引用属性类型被修改、引用属性被删除，则状态为 invalid。失效虚拟属性不支持字段编辑，只能查看失效原因或删除。

### 7.5.8 适用范围

虚拟属性在分析主体、属性关联、用户路径、虚拟事件中适用；自定义查询不适用；事件虚拟属性不适用于圈选事件，用户虚拟属性适用于圈选事件；不适用于 any\_event、any\_active\_event；不允许基于虚拟属性再次创建虚拟属性。

## 7.6 圈选事件管理

### 7.6.1 页面目标

圈选事件支持在已开启全埋点的 Web 或 App 中，通过可视化方式选择页面元素并定义事件。用户无需写代码即可将页面元素点击、页面访问等行为定义为可分析事件。

### 7.6.2 前提条件

必须启用全埋点。Web 端或 App 端 SDK 中需打开全埋点开关。如果未开启，创建圈选时应提示：“未检测到全埋点能力，请确认 SDK 配置”。

### 7.6.3 列表页

支持网页端圈选事件和移动端圈选事件页签。支持按事件名称/事件描述搜索。支持按最近关注、创建日期、包含事件数排序。

圈选事件卡片展示：事件名称、描述、端类型、页面/页面组、元素缩略图、最近 48 小时触发次数、触发人数、创建时间、状态。

### 7.6.4 Web 圈选流程

第一步，点击“新建圈选事件-网页端”。

第二步，输入圈选网址并提交。系统生成圈选会话并在新标签页打开目标页面。若未出现圈选工具条，提示用户检查是否已接入圈选埋点 SDK 或开启全埋点。

第三步，使用浮动工具条。

工具条包含浏览、圈选、热力图三种视角。默认选中“圈选”。浏览模式下禁用圈选功能。热力图模式需选择页面或页面组。

工具条支持：定义页面、高亮已定义事件、本页已标记元素列表、关闭。

高亮已定义事件默认关闭，开启后页面展示所有已圈选前端控件元素，并使用不同颜色区分已定义和当前新建元素。

第四步，圈选元素。鼠标移动时展示绿色浮层。点击元素后打开定义弹窗。用户填写事件名称、选择所属页面、勾选限定条件。底部展示当前元素最近 48 小时按小时粒度的触发次数和触发人数。

第五步，定义页面或页面组。页面定义字段包括页面名称、域名协议、路径、查询参数、更多设置。页面组支持通配路径，例如 /product/\*；支持限定参数，例如 keyword=SUV&\*。

第六步，保存。保存后圈选事件可在事件分析、留存分析、转化分析、用户路径、用户分群等模块的事件选择器中出现，使用方式与一般事件基本相同。

### 7.6.5 移动端圈选流程

第一步，点击“新建圈选事件-移动端”。

第二步，展示二维码。用户用手机扫码，在手机浏览器中打开，并选择圈选方式。

第三步，启动成功后，PC 页面进入可圈选状态。点击元素后，选中元素展示绿色粗边框和透明底色。

第四步，填写事件名称、选择所属页面、保存。

若启动失败，页面展示错误原因和重试入口。常见错误包括 App 未安装、Scheme 配置错误、SDK 版本不支持、全埋点未开启、网络连接失败。

### 7.6.6 圈选事件详情

详情包含圈选元素、缩略图、数据预览、事件详情、所属页面、限定条件、最近 48 小时数据、操作日志。支持查看和编辑事件描述、页面配置和截图；事件名称修改需谨慎，修改前展示血缘影响。

## 7.7 被动事件与关系事件

### 7.7.1 页面目标

被动事件和关系事件用于描述用户既可能是行为发起者，也可能是行为影响者的场景。主动触发行为称为主动事件，被影响用户接收的行为称为被动事件。主动事件和被动事件成对出现时称为关系事件。

典型场景：关注与被关注、发送消息与接收消息、发红包与收红包、评论与被评论、投诉与被投诉。

### 7.7.2 事件生成逻辑

当主动事件中上报 $inline = "true" 且包含 $target\_uuid\_list 时，系统自动为每个目标用户生成一个被动事件。被动事件名称自动添加 $inactive\_ 前缀。

interface RelationEventParams {
 $inline?: 'true' | 'false' | string;
 $target\_uuid\_list?: string[];
 $inactive?: 'true' | 'false' | string;
 $source\_uuid?: string;
}

系统生成被动事件时：

1. 被动事件 $inactive = "true"。
2. 被动事件 $inline = "true"。
3. 被动事件 $source\_uuid 等于主动事件触发用户 uuid。
4. 如果 $target\_uuid\_list 包含多个 uuid，则为每个目标用户生成一条被动事件。

### 7.7.3 手动上报被动事件

用户也可以手动上报被动事件。只要事件属性中 $inactive = "true"，系统即可识别为被动事件。注意 $inactive 数据类型为 string，不是 boolean。

### 7.7.4 分析逻辑

关系事件可用于转化分析。例如互关漏斗：第一步选择 $inactive\_subscribe，关联发起对象 ID；第二步选择 subscribe，关联目标对象 ID；按用户 ID 分组。

被动事件默认计入事件量消耗，但不计入 MAU 和 DAU。被禁用的被动事件不产生消耗。

## 7.8 会话管理

### 7.8.1 页面目标

会话管理用于设置 Web/JS SDK 应用的会话切割间隔。App 和小程序默认从 app\_launch 到 app\_terminate 作为一次会话，两个事件时间间隔作为会话时长。

### 7.8.2 会话定义

会话是用户在网站上连续活跃的一系列行为。默认情况下，两个浏览页面事件或任意页面交互事件之间间隔超过 30 分钟，则后者归入新的会话；如果关闭浏览器或停止操作但 30 分钟内继续访问，则仍纳入同一会话。

### 7.8.3 切割规则

1. 从用户行为起点开始，若访问页面或行为事件间隔 ≤ 会话间隔，则当前会话不中断。
2. 若间隔 > 会话间隔，则开启新会话。
3. 用户由站外访问到网站时，立即开启新会话。
4. 系统所在时区午夜 0 点开始产生新会话；若上一个会话未结束，则按 0 点切分为两个会话。

### 7.8.4 设置逻辑

页面路径：数据管理 → 元数据管理 → 会话管理。

字段：会话间隔，单位分钟，默认 30。一般不推荐修改默认时长。修改后仅影响修改后的会话相关指标，不回算历史数据，除非系统提供重算任务。

interface WebSessionConfig {
 appId: string;
 intervalMinutes: number;
 updatedBy: string;
 updatedAt: string;
}

保存时提示：“修改会话间隔后，后续会话指标将按新规则计算。历史指标是否变化取决于离线重算配置。”

## 7.9 自定义 Session

### 7.9.1 页面目标

自定义 Session 用于分析访问次数、平均交互深度、使用时长、停留时长、跳出率、退出率等场景。用户可以按指定事件集合、开始结束事件、切割时长创建业务会话。

### 7.9.2 数据模型

interface CustomSession {
 id: string;
 appId: string;
 sessionName: string;
 displayName: string;
 description?: string;
 platformScope: Platform[];
 eventScope: SessionEventScope;
 cutRule: SessionCutRule;
 startEventId?: string;
 endEventId?: string;
 status: 'enabled' | 'disabled';
 createdAt: string;
 updatedAt: string;
}

interface SessionEventScope {
 mode: 'all\_events' | 'selected\_events';
 eventIds: string[];
 filters?: FilterCondition[];
}

interface SessionCutRule {
 type: 'time\_gap' | 'start\_end\_event';
 gapMinutes?: number;
}

### 7.9.3 创建流程

用户点击“创建 Session”，填写名称、选择事件范围、配置切割时长或开始结束事件。

常规建议：Web 端切割时长 30 分钟；App 和小程序建议 1-2 分钟；视频播放、直播、在线教育课程等长交互场景可适当延长。

当用户只想分析某类功能并发人数或功能使用时长时，应选择事件切割，仅选择该功能相关事件，排除其他事件。

### 7.9.4 使用逻辑

创建后的 Session 可在事件分析中选择，支持查看 session 整体时长总和、人均值、平均值，也支持选择单个事件查看该事件时长。Session 计算是近似值，结果与切割时间和选择事件强相关。

## 8. 分类管理功能模块

## 8.1 事件分类

### 8.1.1 页面目标

事件分类用于将具有相同业务特征的事件归类展示，提升事件查找和使用效率。

### 8.1.2 分类类型

系统提供公共分类和私人分类。

* 公共分类：所有人可见，仅集团管理员或管理员可编辑和维护。
* 私人分类：仅本人可见，仅本人可编辑和使用。

用户可以设置默认分类页。设置后，每次进入分析页面和事件分类页面默认展示该分类页。

### 8.1.3 数据模型

interface EventCategory {
 id: string;
 appId: string;
 scope: 'public' | 'private';
 ownerUserId?: string;
 name: string;
 sortOrder: number;
 eventIds: string[];
 createdAt: string;
 updatedAt: string;
}

### 8.1.4 分类规则

系统提供默认“未分类”。所有事件默认归入未分类。当事件被加入其他分类后，自动从未分类移除。不考虑未分类，每个分类页最多 20 个分类标签。每个事件在一个分类页中只能属于一个分类。

### 8.1.5 操作逻辑

用户可以创建、编辑、删除、排序事件分类。编辑分类时，可将事件加入目标分类。若事件已经属于该分类页下其他分类，则系统自动从原分类移除，并加入新分类。

公共分类标签同步展示到一般事件、虚拟事件、圈选事件模块，并支持按分类筛选。分析工具事件选择器也支持按分类快速查找事件。

## 8.2 维度字典

### 8.2.1 页面目标

维度字典用于把可读性差、不统一的属性值翻译为可读文字，并在查询时生效。例如 xiaomi、Xiaomi 均翻译为“小米”。

### 8.2.2 入口

在事件属性和用户属性列表中增加“字典”列。可上传时显示“上传”；已上传时显示“已上传”，并提供下载和删除。系统预置属性不支持上传字典时，按钮置灰。

### 8.2.3 文件要求

上传文件必须满足：

1. UTF-8 编码。
2. 后缀为 csv 或 txt。
3. 每行一个映射关系，以英文逗号分割，例如 原始值,翻译值。
4. 文件内容小于 10 万行。
5. 文件整体小于 10MB。
6. 原始值和翻译值长度均不超过 1024 字符。

### 8.2.4 上传流程

用户点击上传 → 选择文件 → 前端校验后缀和大小 → 后端解析前 100 行预览 → 用户确认 → 后端异步处理 → 状态为 processing → 20-30 分钟后状态变为 effective。

上传成功后提示：“字典文件上传成功，系统需要约 20-30 分钟更新，请稍后查询。”

### 8.2.5 生效逻辑

字典在筛选和分组时作为翻译值展示。对于最大值、最小值、平均值、SUM、PCT、去重数，以及大于等于、小于等于等数值计算，仍使用原始值计算。

### 8.2.6 支持类型

| 数据类型 | 是否支持字典 | 说明 |
| --- | --- | --- |
| string | 支持 | 常用 |
| int | 支持 | 展示翻译，计算仍用原始值 |
| float | 支持 | 展示翻译，计算仍用原始值 |
| version | 支持 | 展示翻译，版本比较仍用版本规则 |
| list | SaaS 不支持，私有化支持 | 需逐元素翻译 |
| datetime | 不支持 | 无需字典 |

### 8.2.7 删除字典

删除字典前，如果开通埋点血缘，则展示该字典 value 的图表和分群影响范围。删除后查询结果恢复原始值展示。

## 8.3 埋点血缘

### 8.3.1 页面目标

埋点血缘用于展示事件或属性被哪些图表、看板、分析工具、用户分群使用，以便用户在禁用、编辑、删除、上传字典前评估影响范围。

### 8.3.2 支持范围

血缘支持一般事件、事件属性、用户属性。覆盖预置和自定义数据。当前统计图表和分群场景。

### 8.3.3 引用类型

直接引用：事件或属性直接作为图表分析指标、过滤条件、分组条件。

间接引用：事件或属性通过虚拟事件、虚拟属性、属性自定义分组、用户分群、指标被使用，用户可能无法在查询条件中直接看到元数据。

### 8.3.4 字典值血缘

属性字典值血缘需要精确到字典 value。若图表只使用 is\_login=true，则只有编辑或删除该 value 时才展示该图表影响范围。

### 8.3.5 页面展示

在事件详情、属性详情中展示“图表血缘”和“分群血缘”。

图表血缘字段：图表名称、所属看板、分析工具类型、引用方式、引用路径、最近查询时间、创建人。

分群血缘字段：分群名称、分群人数、近 30 天查询次数、引用方式、创建人、更新时间。

在禁用事件、修改属性类型、删除字典、编辑虚拟属性等高风险操作前，弹窗必须调用血缘接口并展示影响范围。

## 9. 埋点实时验证与验证报告

## 9.1 埋点实时验证

### 9.1.1 页面目标

埋点实时验证用于研发或测试人员 debug。建立连接后，每一次事件触发都会实时显示在页面内，验证埋点是否正确及数据上传情况。

### 9.1.2 支持端类型

支持 Android、iOS、Web JS、微信小程序、服务端 Java。Web JS 需 SDK 版本 5.1.2 及以上。服务端当前仅支持 Java。通过实时验证产生的事件不构建到项目数据库，不占用事件用量。暂不支持验证 app\_launch、app\_terminate。

新版能力支持快速验证、按元数据验证、按需求验证。其中快速验证为标准功能；按元数据和按需求验证支持自动校验和报告能力，可能需要付费开通。

### 9.1.3 连接模型

interface RealtimeVerifySession {
 id: string;
 appId: string;
 platform: 'android' | 'ios' | 'web\_js' | 'wechat\_mp' | 'server\_java';
 verifyMode: 'quick' | 'metadata' | 'requirement';
 status: 'created' | 'connected' | 'verifying' | 'paused' | 'ended' | 'expired';
 targetUrl?: string;
 userUniqueId?: string;
 qrCodeUrl?: string;
 testUrl?: string;
 startedAt?: string;
 endedAt?: string;
}

### 9.1.4 Web 验证流程

用户进入 Web 页签，输入待验证网址，点击生成二维码。系统生成测试 URL 和二维码。用户可以手机扫码打开，也可以在电脑浏览器打开 URL。连接建立后进入验证结果页。

如果网页未集成 SDK 或 SDK 版本过低，系统提示“未检测到支持实时验证的 Web SDK，请确认 SDK 版本不低于 5.1.2”。

### 9.1.5 移动端 App 验证流程

用户进入移动端页签，页面展示二维码。手机必须安装正确版本 App，应用名称、App\_name、App\_id、唤起 Scheme 正确。扫码后跳转测试页面，用户点击“开始检测埋点”。连接成功后页面进入验证结果页。

### 9.1.6 微信小程序验证流程

用户进入小程序页签。若未上传小程序码，则先上传。上传时系统提供生成参数，用户在小程序后台配置合法 request 域名。上传成功后生成带检测参数的小程序码。扫码进入小程序后，SDK 根据参数建立实时检测连接。

若多个用户扫码但未开始检测，页面按扫码时间倒序列出用户设备，用户选择自己的设备继续。

### 9.1.7 服务端验证流程

用户输入测试 user\_unique\_id，点击获取 URL。系统生成测试 URL。用户复制 URL 并按提示配置到 SDK 初始化指定位置。服务端触发测试事件后，页面展示实时日志。

### 9.1.8 验证规则

验证规则支持：

* 按元数据验证：只展示已在元数据管理录入的事件和属性。未录入的测试数据不展示。
* 按需求验证：只验证某个埋点需求中的事件和属性。不在需求中的事件不展示。
* 快速验证：不依赖规则，快速查看实时上报。

开始验证后，页面右上角展示总览：成功事件数、失败事件数、待校验数、总触发数。左侧展示行为流，右侧展示事件日志详情、属性列表、校验结果、原始 payload。

### 9.1.9 操作控制

验证过程中支持暂停、结束、清空埋点。暂停后停止接收新事件但保留当前记录；结束后断开连接；清空只清空当前页面展示，不影响已保存报告。

### 9.1.10 埋点截图

付费开通后，Android 端支持采集埋点触发前后约 1 秒内最多 5 张 App 界面截图。事件列表中有截图的事件显示图片 icon。用户点击事件，在右侧“自动截图模式”查看截图。

部分截图自动用红色框圈选埋点位置。若位置不准确，用户可点击手动圈选，撤销原标注后重新框选并保存。

每个事件最多保存 10 张截图。保存截图前要求事件元信息已存在，否则提示“事件元信息不存在，请先在元数据管理中创建该事件”。保存后，事件详情和分析工具事件选择器可查看截图和描述。

## 9.2 验证报告

### 9.2.1 页面目标

验证报告用于将一次埋点实时验证过程固化保存，便于后续回看验证过程和上报情况。

### 9.2.2 保存报告

报告功能需开通，且仅部分环境支持。埋点验证进行中不能保存报告，需要先暂停。快速验证不支持保存报告。

保存流程：暂停验证 → 点击保存报告 → 填写报告名称 → 浏览验证结果 → 对不正确的结果进行人为校准 → 补充备注 → 点击生成报告。

### 9.2.3 报告模型

interface VerifyReport {

 totalEvents: number;
 successEvents: number;
 failedEvents: number;
 manualCorrectedEvents: number;
 };
 eventLogs: VerifyEventLog[];
 createdBy: string;

}

interface VerifyEventLog {

}

### 9.2.4 报告列表与删除

验证报告页展示所有已保存报告。支持按报告名称、端类型、验证方式、创建人、时间范围筛选。用户可查看详情或删除。删除前二次确认，删除后不可恢复。

## 10. 数据治理模块

## 10.1 数据治理看板

### 10.1.1 页面目标

数据治理看板自动检测项目埋点数据质量和埋点使用情况，帮助数据管理员判断数据是否健康，并采取修复异常、清理无用埋点等动作。

### 10.1.2 核心指标

interface GovernanceDashboardMetrics {
 eventInterceptRate: number;
 dataErrorRate: number;
 delayRate: number;
 receivedEventCount: number;
 interceptedEventCount: number;
 abnormalPropertyCount: number;
 metadataUsage: MetadataUsageSummary;
}

事件拦截率 = 事件错误拦截条数 / 接收总条数。拦截条数仅计算启用、启用不显示状态的元数据。禁用、待验收、黑名单属于预期拦截，不计入异常拦截率。

数据错误率 = 被检测到事件异常的条数 / 服务端接收总条数。

延迟率 = 入库事件发生时间超出有效窗口期的事件条数 / 服务端接收总条数。客户端 SDK 默认只接收发生时间在接收时间向前 7 天内、向后 24 小时内的数据。超过窗口期的数据被丢弃。

### 10.1.3 入库校验监控逻辑

系统接收 SDK 数据后校验：

1. 如果事件名称异常，整条事件丢弃，不入库。
2. 如果事件名称通过，但部分属性异常，则异常属性丢弃，事件和其他正常属性仍可入库。

页面中所有蓝色数字均可点击进入数据入库明细，查看日志与错误详情。

### 10.1.4 埋点管理模式

项目支持开启或关闭入库校验模式。

开启：首次出现的事件及属性必须人工验收后才允许入库，未提前登记或验收的数据不接收入库。开启后约 10 分钟生效。

关闭：事件和属性自动入库，不需要提前登记或人工验收。只有事件或属性被标记为禁用时才阻止入库。

页面提供“去修改”按钮，跳转项目管理通用设置。切换模式前二次确认，并说明对待验收数据的影响。开启后又关闭，已进入待验收列表的数据不会自动验收，仍需人工处理。

### 10.1.5 元数据使用情况

展示当前项目元数据创建数量和使用统计。指标包括最近 30 天查询次数、最近 30 天查询人数、关联图表数、昨日入库数。事件支持关联图表数和昨日入库数；属性按可用指标展示。

系统建议数据管理员停用无人查询或长期无数据上报的事件/属性。

### 10.1.6 导出埋点方案

页面右上角提供“导出埋点方案”。导出 Excel 包含自定义事件/属性、预置事件/属性、用户属性、状态、数据类型、描述、关联事件、分类、更新时间等。

## 10.2 数据入库明细

### 10.2.1 页面目标

数据入库明细用于查看项目内数据上报后的入库情况，包括入库事件数量、抛弃事件数量、错误类型命中数量和详细错误日志。

### 10.2.2 列表字段

| 字段 | 说明 |
| --- | --- |
| 事件名称 | 上报事件名称 |
| SDK 类型 | web、mp、app；为空表示 HTTP API 等非 SDK 上报 |
| SDK 版本 | SDK 版本号 |
| 错误类型 | 事件错误或属性错误 |
| 接收条数 | 服务端接收条数，尚未合法性校验 |
| 抛弃条数 | 因错误、超限等原因未进入系统条数 |
| 入库条数 | 进入系统可查询的数据条数 |
| 异常属性条数 | 包含异常属性的次数；属性异常通常不影响事件本身入库 |

入库条数 = 接收条数 - 抛弃条数。异常属性条数不直接与抛弃条数挂钩。

### 10.2.3 错误详情

点击事件名称查看错误详情，默认展示最新 10 条错误日志。支持按错误类型、错误码筛选。详情仅支持最近 7 天记录。超过 7 天只保留统计结果，不展示日志。

被禁用的事件/属性、上报类型与元数据登记不一致的事件属性会被直接抛弃。若希望在详情查看这类数据，需要上报事件公共属性 $data\_validation\_test = true。

### 10.2.4 下载错误明细

每条事件右侧提供下载按钮，导出该事件错误数据。列表右上角提供“下载错误明细”，导出全部错误数据。

### 10.2.5 入库异常监控告警

用户可在数据入库明细页创建监控告警。支持监控对象：事件、事件属性、用户属性。监控任务创建后约 10 分钟生效。

监控配置字段：监控名称、监控对象、具体事件/属性、错误类型、监控规则、监控范围。

监控规则支持任意条件满足和累计条件满足。多条监控规则之间为 OR。监控范围支持使用事件属性过滤，多条过滤条件统一设置为 AND 或 OR。用户属性不支持监控范围过滤。

告警设置字段：监控时段、告警渠道、收件人、企业群 Webhook。告警渠道支持邮箱和企业群。

## 10.3 校验规则配置

### 10.3.1 页面目标

系统预置常见入库校验规则，同时支持用户根据业务需要创建自定义校验规则。规则可用于告警和数据拦截。

### 10.3.2 规则类型

type ValidationRuleType = 'event\_volume' | 'event\_property' | 'user\_property';

* 事件量：校验一段时间内事件上报数量。
* 事件属性校验：校验指定事件下指定属性是否满足规则。
* 用户属性校验：校验用户属性是否满足规则。

### 10.3.3 创建流程

第一步，配置基本信息：规则名称、规则类型、校验对象。

第二步，配置校验规则。事件属性规则需先选择事件，再选择属性。多条校验规则之间为 OR。每条规则可配置过滤条件，过滤条件之间为 AND。

第三步，配置告警设置。用户可选择是否开启告警。开启后，当异常数据达到阈值，系统发送告警。渠道支持邮箱和企业群。

第四步，配置数据拦截设置。事件属性/用户属性规则可选择是否拦截异常数据；事件量规则无需配置拦截。

### 10.3.4 属性规则种类

| 规则 | 异常定义 |
| --- | --- |
| 必传校验 | 属性未上传或 value 为 null |
| 枚举校验 | 属性已上传且不在枚举值内；未上传或 null 不算异常 |
| 正则匹配 | 属性已上传但不匹配正则；未上传或 null 不算异常 |
| 区间校验 | 数值属性已上传但不在区间内；未上传或 null 不算异常 |
| 包含校验 | 属性值不包含指定值；未上传或 null 不算异常 |

事件量校验的最小时间间隔为 10 分钟。示例：订单支付事件 5 分钟内超过 10000 条时告警；如果实现时限制最小 10 分钟，则前端不允许选择 5 分钟，并提示最小粒度为 10 分钟。

### 10.3.5 规则状态与编辑

创建完成后，规则列表支持开启、关闭、编辑、删除。关闭规则后，数据不再按该规则拦截，可正常入库。但如果告警配置仍开启，告警可能继续发送。因此关闭拦截和关闭告警是两项独立设置。

已创建规则的校验对象和校验条件不支持修改，只能修改告警和拦截设置。如果要修改校验条件，需要删除后重建。已关闭规则支持删除。

## 10.4 告警管理

### 10.4.1 页面目标

告警管理汇总展示数据治理模块中所有监控告警规则、告警记录和异常数据详情。

### 10.4.2 告警来源

告警来源包括：

1. 校验规则配置中的自定义校验规则告警。
2. 数据入库明细页面创建的监控告警。

校验规则配置页面的告警用于自定义校验规则触发。数据入库明细页面的告警用于所有建议规则的监控，既包括预置入库校验规则，也包括自定义校验规则。

### 10.4.3 列表字段

interface AlertRecord {

用户点击监控名称查看监控任务详情；点击告警条数查看告警历史；点击异常数据条数查看异常数据明细。

### 10.4.4 操作规则

## 10.5 成本治理分析

### 10.5.1 页面目标

成本治理分析帮助用户了解当前埋点成本现状，并治理低 ROI、无效、类似、冗余事件。

### 10.5.2 页面内容

页面展示当前项目已消耗事件量、月均事件使用量、事件 ROI 排序。低 ROI 事件列表支持按事件名称、入库量、查询次数、查询人数、关联图表数、成本估算排序。

用户可点击事件名称查看事件详情。支持单个禁用和批量禁用。

### 10.5.3 AI 智能诊断

若开启 AI 成本治理开关，右上角展示智能诊断结果。系统按治理优先级展示 P0、P1、P2 待治理项。

P0：关闭全埋点。若全埋点导致大量冗余事件上报，用户可在详情页一键关闭全埋点开关。关闭前必须提示影响：关闭后自动全埋点事件不再上报，需在 SDK 中配置业务分析所需事件。

P1：禁用无效事件。系统识别可能无效事件，展示入库量、查询次数、最近查询时间、关联图表、昨日入库数。用户评估后可一键禁用。

P2：禁用类似事件。系统识别类似事件，并结合上报与查询情况生成保留建议。用户评估后保留一个事件，禁用其他类似事件。

### 10.5.4 禁用保护

禁用前必须展示血缘影响、最近查询、昨日入库、是否在虚拟事件中被引用、是否为关系事件、是否为圈选事件。用户需勾选“我已确认禁用影响”才能提交。

## 14. 关键交互流程

### 14.1 新事件从设计到可分析

数据管理员新建一般事件
→ 选择或新增事件属性
→ 研发按约定 SDK 上报
→ 测试人员进入埋点实时验证
→ 触发事件并查看校验结果
→ 保存验证报告
→ 数据进入入库校验
→ 治理看板显示入库健康
→ 分析工具事件选择器可使用

若开启入库校验且事件未提前登记：

SDK 上报未知事件
→ 系统识别为待验收
→ 数据不入库
→ 数据管理员在验收列表确认
→ 验收通过后后续数据入库

### 14.2 属性类型错误处理

研发上报属性 price='abc'
→ 元数据中 price 为 float
→ 系统尝试强转失败
→ 事件本身可入库，price 属性被拦截
→ 数据入库明细记录 1020004
→ 治理看板异常属性数增加
→ 若配置告警且达到阈值，发送告警
→ 管理员查看日志并通知研发修复上报格式

### 14.3 禁用低 ROI 事件

数据管理员进入成本治理分析
→ 查看低 ROI 事件排序
→ 选择某事件
→ 系统加载血缘、查询次数、入库量、关联图表
→ 用户确认该事件无用
→ 点击禁用
→ 系统二次确认影响范围
→ 禁用成功
→ 后续数据不构建、不计费、分析工具不可选

### 14.4 修改字典

数据管理员在属性列表点击字典上传
→ 上传 UTF-8 csv/txt
→ 系统解析并展示预览
→ 校验文件大小、行数、字段长度
→ 保存并进入 processing
→ 20-30 分钟后生效
→ 查询分组展示翻译值
→ 数值计算仍使用原始值

## 15. 验收标准

### 15.1 元数据管理验收

1. 可新建一般事件，事件名称校验准确，重复事件不可创建。
2. 可批量新建最多 200 个事件，并展示行级错误。
3. 可编辑展示名、描述、分类，但不可编辑事件名称。
4. 可启用、禁用、隐藏事件，并按状态规则影响分析可用性、构建、计费。
5. 可新增事件属性、事件公共属性、用户属性，并正确校验数据类型。
6. 可验收待验收事件和属性，黑名单数据不入库。
7. 可创建虚拟事件，多个一般事件按 OR 关系生效。
8. 可创建虚拟属性，SQL 校验失败时不能保存。
9. 虚拟属性引用字段失效后状态变为 invalid，不允许继续编辑。
10. 圈选事件创建后可在分析事件选择器中出现。

### 15.2 数据接入验收

1. 上报地址页能根据环境、地域、端类型展示正确地址和配置提示。
2. 数据格式页能展示类型限制和选择建议。
3. 可视化数据集成支持 Kafka 连接测试、字段解析、映射、预览和执行。
4. 集成数据进入统一入库校验和元数据管理流程。

### 15.3 实时验证验收

1. Web、App、小程序、服务端验证流程可建立连接。
2. 连接后事件触发实时展示在行为流。
3. 按元数据验证只展示已登记事件和属性。
4. 按需求验证只展示需求内事件和属性。
5. 支持暂停、结束、清空。
6. 支持保存验证报告，验证中不能保存，快速验证不能保存。
7. Android 截图保存不超过每事件 10 张。

### 15.4 治理验收

1. 治理看板正确计算事件拦截率、数据错误率、延迟率。
2. 事件异常整条拦截，属性异常只拦截属性。
3. 数据入库明细展示接收、抛弃、入库、异常属性条数。
4. 错误日志仅展示最近 7 天明细。
5. 自定义校验规则支持事件量、事件属性、用户属性。
6. 告警管理能区分数据入库明细告警和校验规则告警。
7. 成本治理支持低 ROI 事件禁用、P0/P1/P2 治理建议。
8. 禁用、删除、类型修改前可展示血缘影响范围。

## 16. 非功能要求

### 16.1 性能

列表接口默认分页 20 条，最大 100 条。搜索接口 300ms 防抖。治理看板指标按近实时或离线聚合输出，页面初次加载不超过 3 秒。实时验证日志使用 WebSocket 或 SSE 推送，单会话至少支持每秒 100 条事件展示，前端对日志列表虚拟滚动。

### 16.2 安全

所有写操作必须校验权限。下载导出文件需鉴权。Kafka 认证信息、Webhook 密钥等敏感信息后端加密存储，前端不回显明文。

### 16.3 审计

以下操作必须记录审计日志：新建/编辑/禁用事件，修改属性类型，上传/删除字典，创建/删除虚拟属性，创建/修改校验规则，创建/关闭告警，禁用低 ROI 事件，切换入库校验模式。

interface AuditLog {
 id: string;
 appId: string;
 resourceType: string;
 resourceId: string;
 action: string;
 before?: unknown;
 after?: unknown;
 operator: string;
 operatedAt: string;
 ip?: string;
}

### 16.4 可扩展性

端类型、环境类型、地域、预置属性、错误码、校验规则均需后端配置化，前端不得硬编码。私有化部署需要支持自定义上报域名、自定义元数据上限、自定义功能开关。
