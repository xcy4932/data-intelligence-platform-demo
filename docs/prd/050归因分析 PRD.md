**归因分析 PRD**

**1. 功能定位**

归因分析用于衡量多个触点、事件、渠道、活动、广告属性对最终业务目标事件的贡献。

它要解决的问题是：

用户最终完成了支付、注册、留资、下单、激活等目标行为；

在目标行为之前，用户可能经历了搜索、浏览、点击 banner、进入活动页、咨询客服、加入购物车、广告点击、渠道访问等多个触点；

系统需要按照指定归因模型，把目标事件的贡献分配给这些触点；

最终帮助业务判断：哪些事件、渠道、活动、页面、坑位、搜索词、广告属性真正促进了转化。

典型业务问题：

用户完成支付前，搜索、商品详情页、加购、客服咨询分别贡献了多少转化？

不同广告渠道、推广活动、优化师、创意对注册/支付的贡献是多少？

用户在多个页面和运营位之间跳转后，最后转化应该归功于哪个触点？

同一个目标事件，在首次归因、末次归因、线性归因、位置归因、时间衰减归因下结果有何差异？

某些待归因事件虽然触发次数多，但是否真正带来了有效转化？

**3. 核心概念**

**3.1 目标事件**

目标事件是需要被解释、被分配贡献的最终转化事件。

例如：

支付成功

注册成功

提交订单

留资完成

报名成功

App 激活

会员开通

完成首充

广告观看完成

目标事件代表业务最终结果。

目标事件配置结构：

type TargetEventConfig = {

eventName: string;

eventDisplayName: string;

filters?: FilterGroup;

metric: TargetMetricConfig;

};

目标指标配置结构：

type TargetMetricConfig = {

aggregator:

| "COUNT"

| "USER\_COUNT"

| "SUM"

| "AVG"

| "MAX"

| "MIN";

propertyName?: string;

propertyType?: "number" | "string" | "datetime" | "boolean";

};

默认目标指标：

目标事件次数 COUNT

如果用户希望归因支付金额，则配置为：

{

"aggregator": "SUM",

"propertyName": "pay\_amount",

"propertyType": "number"

}

目标事件支持过滤条件：

支付成功 且 商品类型 = 会员

支付成功 且 金额 > 0

注册成功 且 注册方式 = 手机号

留资完成 且 线索来源 = 表单

**3.2 待归因节点**

待归因节点是可能对目标事件产生贡献的触点。

归因节点分两类：

事件归因

属性归因

**3.3 事件归因**

事件归因用于分析多个事件对目标事件的贡献。

适用场景：

站内运营位归因

功能路径归因

商品购买前行为归因

活动路径归因

搜索词、浏览、加购、咨询对支付的贡献

事件归因的节点是一个或多个事件。

例如：

商品搜索

商品详情页浏览

加入购物车

客服咨询

领取优惠券

活动页点击

首页 banner 点击

金刚位点击

结构：

type AttributionEventNode = {

id: string;

nodeType: "event";

eventName: string;

eventDisplayName: string;

alias?: string;

filters?: FilterGroup;

groupBy?: AttributionNodeGroupBy;

};

限制规则：

1. 至少配置 1 个待归因事件。

2. 默认最多配置 10 个待归因事件。

3. 同一事件可以重复配置，但必须通过过滤条件或别名区分。

4. 每个待归因事件可配置事件过滤条件。

5. 每个待归因事件可配置属性分组，用于比较不同属性值的贡献。

**3.4 属性归因**

属性归因用于分析某个属性值对目标事件的贡献。

适用场景：

渠道归因

广告活动归因

推广媒介归因

广告创意归因

优化师归因

搜索词归因

页面来源归因

utm 参数归因

属性归因不是看多个事件，而是看某个归因属性的不同取值。

例如：

utm\_source = google / facebook / tiktok

utm\_campaign = campaign\_A / campaign\_B

creative\_id = c001 / c002 / c003

tr\_admaster = optimizer\_A / optimizer\_B

search\_keyword = 手机 / 电脑 / 会员

结构：

type AttributionPropertyNode = {

id: string;

nodeType: "property";

sourceEventName?: string;

propertyScope:

| "event\_property"

| "event\_public\_property"

| "user\_property"

| "subject\_property";

propertyName: string;

propertyDisplayName: string;

valueLimit: number;

includeUnknown: boolean;

includeOthers: boolean;

filters?: FilterGroup;

};

属性归因限制：

1. 属性归因模式下，只能选择一个归因属性。

2. 不支持“也计算其他转化”。

3. 支持对属性值做 Top N 展示。

4. 超出 Top N 的属性值合并为“其他”。

5. 空值进入“未知”，可由用户选择是否展示。

6. 不支持 item 属性和虚拟属性。

**3.5 过程事件**

过程事件是目标事件之前必须发生的事件，用来收紧目标转化范围，提高归因结果可信度。

例如目标事件是：

支付成功

过程事件可以配置为：

商品详情页浏览

加入购物车

提交订单

这样系统只分析满足以下条件的目标转化：

用户在目标事件之前发生过指定过程事件

结构：

type ProcessEventConfig = {

enabled: boolean;

events: ProcessEvent[];

relation: "ALL\_REQUIRED" | "ANY\_REQUIRED";

};

type ProcessEvent = {

id: string;

eventName: string;

eventDisplayName: string;

relationProperties?: RelationProperty[];

};

过程事件支持两种逻辑：

| **逻辑** | **含义** |
| --- | --- |
| ALL\_REQUIRED | 所有过程事件都必须发生 |
| ANY\_REQUIRED | 任意一个过程事件发生即可 |

默认：

ALL\_REQUIRED

**3.6 关联属性**

关联属性用于保证过程事件、待归因事件、目标事件之间确实属于同一业务对象。

例如：

商品详情页浏览.product\_id = 支付成功.product\_id

加入购物车.product\_id = 支付成功.product\_id

商品搜索.keyword = 搜索结果点击.keyword

结构：

type RelationProperty = {

id: string;

leftEventId: string;

leftPropertyName: string;

rightEventId: string;

rightPropertyName: string;

propertyType: "string" | "number" | "datetime" | "boolean";

};

校验规则：

1. 左右属性类型必须一致。

2. 关联属性值为空时，不满足关联。

3. 多个关联属性之间为 AND。

4. 关联属性只影响路径匹配，不改变事件本身的触发次数。

**3.7 查询周期**

查询周期指目标事件发生的时间范围。

例如：

查询周期 = 2026-05-01 至 2026-05-07

系统先找出这个时间范围内发生的目标事件，再向前回溯寻找待归因节点。

结构：

type QueryTimeConfig = {

startTime: string;

endTime: string;

granularity: "hour" | "day" | "week" | "month";

timezone: string;

};

V1 默认支持：

day

**3.8 回溯期**

回溯期是从目标事件发生时间向前寻找待归因节点的时间窗口。

例如：

目标事件：2026-05-07 20:00 支付成功

回溯期：7 天

则系统只在以下时间范围内寻找待归因节点：

2026-04-30 20:00 至 2026-05-07 20:00

结构：

type LookbackWindow = {

value: number;

unit: "minute" | "hour" | "day";

};

默认：

{

"value": 7,

"unit": "day"

}

校验规则：

| **校验项** | **规则** |
| --- | --- |
| 最小回溯期 | 1 分钟 |
| 最大回溯期 | 默认 90 天，可由系统配置 |
| 回溯方向 | 只能向目标事件之前回溯 |
| 边界 | 归因事件时间必须早于或等于目标事件时间 |
| 同时间戳 | 默认按事件发生时间和事件 ID 稳定排序 |

**4. 归因类型设计**

**4.1 事件归因模式**

**4.1.1 使用场景**

1. 商品搜索

2. 商品详情页浏览

3. 加入购物车

4. 客服咨询

5. 领取优惠券

系统在每次支付成功前的回溯期内，查找这些待归因事件，形成路径：

商品搜索 → 商品详情页浏览 → 加入购物车 → 支付成功

然后根据归因模型分配贡献。

**5. 归因模型**

**5.1 支持模型**

系统支持 5 类基础归因模型：

首次归因

末次归因

线性归因

位置归因

时间衰减归因

前端字段：

type AttributionModelType =

| "FIRST\_TOUCH"

| "LAST\_TOUCH"

| "LINEAR"

| "POSITION\_BASED"

| "TIME\_DECAY";

页面允许多选模型做对比：

selectedModels: AttributionModelType[];

默认：

LAST\_TOUCH

**5.2 首次归因**

**逻辑**

目标事件前的所有待归因节点中，时间最早的节点获得 100% 贡献。

示例：

路径：A → B → C → 支付

首次归因：

A = 100%

B = 0%

C = 0%

计算函数：

function firstTouchWeights(touches: TouchPoint[]): Record<string, number> {

const first = touches[0];

return Object.fromEntries(touches.map(t => [t.id, t.id === first.id ? 1 : 0]));

}

**5.3 末次归因**

**逻辑**

目标事件前的所有待归因节点中，时间最晚的节点获得 100% 贡献。

示例：

路径：A → B → C → 支付

末次归因：

A = 0%

B = 0%

C = 100%

计算函数：

function lastTouchWeights(touches: TouchPoint[]): Record<string, number> {

const last = touches[touches.length - 1];

return Object.fromEntries(touches.map(t => [t.id, t.id === last.id ? 1 : 0]));

}

**5.4 线性归因**

**逻辑**

目标事件前所有待归因节点平分贡献。

示例：

路径：A → B → C → 支付

线性归因：

A = 33.33%

B = 33.33%

C = 33.33%

计算函数：

function linearWeights(touches: TouchPoint[]): Record<string, number> {

const w = 1 / touches.length;

return Object.fromEntries(touches.map(t => [t.id, w]));

}

**5.5 位置归因**

**逻辑**

首末节点各获得 40% 贡献，中间节点平分剩余 20%。

示例：

路径：A → B → C → D → 支付

位置归因：

A = 40%

D = 40%

B = 10%

C = 10%

特殊情况：

| **触点数量** | **分配规则** |
| --- | --- |
| 1 | 唯一触点获得 100% |
| 2 | 首触点 50%，末触点 50% |
| >= 3 | 首 40%，末 40%，中间平分 20% |

计算函数：

function positionBasedWeights(touches: TouchPoint[]): Record<string, number> {

const n = touches.length;

if (n === 1) {

return { [touches[0].id]: 1 };

}

if (n === 2) {

return {

[touches[0].id]: 0.5,

[touches[1].id]: 0.5,

};

}

const middleWeight = 0.2 / (n - 2);

const result: Record<string, number> = {};

touches.forEach((t, index) => {

if (index === 0) result[t.id] = 0.4;

else if (index === n - 1) result[t.id] = 0.4;

else result[t.id] = middleWeight;

});

return result;

}

**5.6 时间衰减归因**

**逻辑**

越接近目标事件的触点获得越高贡献，权重按半衰期衰减。

原始权重：

rawWeight = 0.5 ^ (timeDistance / halfLife)

其中：

timeDistance = 目标事件时间 - 触点事件时间

halfLife = 半衰期

归一化：

finalWeight = rawWeight / sum(rawWeight)

结构：

type TimeDecayConfig = {

halfLifeValue: number;

halfLifeUnit: "hour" | "day";

};

默认半衰期：

{

"halfLifeValue": 7,

"halfLifeUnit": "day"

}

计算函数：

function timeDecayWeights(

touches: TouchPoint[],

targetTime: string,

halfLifeMs: number

): Record<string, number> {

const targetTimestamp = new Date(targetTime).getTime();

const raw = touches.map(t => {

const distanceMs = Math.max(0, targetTimestamp - new Date(t.eventTime).getTime());

return {

id: t.id,

weight: Math.pow(0.5, distanceMs / halfLifeMs),

};

});

const total = raw.reduce((sum, item) => sum + item.weight, 0);

return Object.fromEntries(

raw.map(item => [item.id, total === 0 ? 0 : item.weight / total])

);

}

**6. 归因路径生成逻辑**

**6.1 输入事件**

系统需要三类事件：

目标事件

待归因事件或待归因属性所在事件

过程事件

统一事件结构：

type RawEvent = {

eventId: string;

subjectId: string;

eventName: string;

eventTime: string;

properties: Record<string, any>;

userProperties?: Record<string, any>;

};

**6.2 路径生成步骤**

对于每一个目标事件实例：

1. 判断目标事件是否在查询周期内。

2. 判断目标事件是否满足目标事件过滤条件。

3. 如果配置过程事件，检查目标事件之前是否满足过程事件要求。

4. 根据回溯期计算回溯开始时间。

5. 在回溯窗口内查找同一主体的待归因节点。

6. 对待归因节点应用事件过滤、属性过滤、关联属性。

7. 按事件时间升序排序。

8. 生成归因路径。

9. 按归因模型计算每个节点贡献。

10. 聚合到结果表。

**6.3 路径结构**

**6.4 目标指标值**

如果目标指标是 COUNT：

如果目标指标是 SUM(pay\_amount)：

targetMetricValue = 当前目标事件的 pay\_amount

如果属性为空或无法转为数值：

该目标事件不参与 SUM 类指标计算

**7. 也计算其他转化**

**7.1 功能说明**

“也计算其他转化”用于发现未配置进待归因节点列表的转化来源。

当用户无法完整列出所有待归因事件时，可以开启该功能。

开启后，系统会额外统计：

在回溯期内，目标事件之前没有发生任何已配置待归因节点的转化

这些转化归入：

其他事件

**7.2 计算规则**

假设配置：

待归因事件：A、B

目标事件：C

用户路径：

A → B → D → C

系统仍按：

A → B → C

进行归因，不会把 D 纳入模型分配。

用户路径：

D → C

如果 D 不在待归因事件列表内，且回溯期内没有 A、B，则该目标事件计入“其他事件”。

**7.3 限制规则**

1. 仅事件归因支持“也计算其他转化”。

2. 属性归因不支持。

**12. 指标体系**

**12.1 触发次数**

定义：

查询周期及回溯期涉及的路径中，待归因节点实际触发的总次数。

对于事件归因：

待归因事件触发次数

对于属性归因：

某属性值在归因路径中出现的次数

**12.2 有效转化触发次数**

定义：

按照当前归因模型，真正获得目标事件贡献的触点次数。

例如末次归因：

某待归因事件触发 100 次，但只有 50 次出现在末次触点位置，则有效转化触发次数 = 50。

有效转化触发率：

有效转化触发率 = 有效转化触发次数 / 触发次数

**12.3 转化目标指标**

定义：

目标事件指标按照归因模型分配后，归属于某个待归因节点的数值。

例如目标指标是支付次数：

一次支付目标事件 metricValue = 1

如果路径是：

A → B → A → 支付

位置归因下：

A 获得 0.4 + 0.4 = 0.8

B 获得 0.2

如果目标指标是支付金额：

支付金额 = 100

A 获得 80

B 获得 20

**12.4 贡献度**

定义：

贡献度 = 当前节点获得的目标指标 / 所有节点获得的目标指标总和

计算：

contributionRate = row.targetMetricValue / total.targetMetricValue

**12.5 相关性**

相关性用于衡量待归因事件与目标事件之间的线性相关程度。

实现建议：

按时间粒度生成两个序列：

X = 每个周期内待归因节点触发次数

Y = 每个周期内目标事件发生次数

然后计算 Pearson 相关系数。

公式：

corr(X,Y)=cov(X,Y)/(std(X)\*std(Y))

返回范围：

-1 到 1

空值规则：

1. 如果序列长度 < 2，相关性为空。

2. 如果 X 或 Y 标准差为 0，相关性为空。

3. 前端展示为 “-”。

**18. 权限设计**

权限点：

| **权限** | **说明** |
| --- | --- |
| attribution:view | 查看归因分析页面 |
| attribution:query | 执行归因查询 |
| attribution:save | 保存分析 |
| attribution:dashboard | 保存到看板 |
| attribution:export | 导出结果 |
| attribution:user\_detail | 查看用户列表 |
| attribution:user\_export | 导出用户 ID |
| attribution:path\_detail | 查看归因路径 |
| cohort:create | 保存为用户分群 |

权限拦截：

1. 没有 attribution:view：不可进入页面。

2. 没有事件权限：事件选择器不展示该事件。

3. 没有属性权限：属性选择器不展示该属性。

4. 打开保存分析时，如果部分字段无权限，则置灰并提示。

5. 没有 user\_detail：隐藏查看用户列表。

6. 没有 path\_detail：隐藏查看归因路径。

7. 没有 export：隐藏导出按钮。

**19. 异常状态**

**19.1 无目标事件**

请选择目标事件后开始归因分析

**19.2 无待归因节点**

请至少配置一个待归因节点

**19.3 无归因结果**

当前条件下暂无归因结果

可能原因：

1. 查询周期内没有目标事件。

2. 回溯期内没有待归因节点。

3. 目标事件过滤条件过窄。

4. 待归因事件过滤条件过窄。

5. 过程事件要求过严格。

6. 关联属性未匹配成功。

7. 细分筛选后用户范围为空。

**19.4 未归因转化**

部分目标事件在回溯期内没有匹配到待归因节点，已计入未归因转化。

如果开启“也计算其他转化”：

未命中已配置待归因节点的目标事件已计入其他事件。

**19.5 查询超时**

当前查询范围较大，建议缩短查询周期、减少待归因事件、缩短回溯期或减少归因模型数量。
