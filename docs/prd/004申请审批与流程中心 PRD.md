**申请审批与流程中心 PRD**

**1. 模块定位**

**1.1 模块目标**

申请审批与流程中心是数据平台中承接“高风险操作、权限申请、资源访问、配置变更、数据导出、发布上下线”等场景的统一流程引擎。

该中心不只提供一个待办列表，而是要完成以下闭环：

1. 用户在业务页面或申请中心发起申请。
2. 系统根据申请类型、资源类型、项目空间、敏感级别、申请人身份、操作风险等级匹配审批流程。
3. 审批节点按规则依次流转。
4. 审批通过后自动执行生效动作，例如授予权限、开放资源、创建策略、允许导出、发布资源。
5. 全流程可追踪、可撤回、可催办、可转交、可驳回、可重提。
6. 管理员可以配置不同申请类型对应的审批流程、审批节点、审批人规则、通知策略和超时策略。
7. 所有申请、审批、授权、生效、异常动作都进入审计日志。

**1.2 适用场景**

申请审批与流程中心至少支持以下申请类型：

| **申请类型** | **典型入口** | **审批通过后的生效动作** |
| --- | --- | --- |
| 项目加入申请 | 项目空间详情页、申请中心 | 将申请人加入项目成员 |
| 项目角色变更申请 | 项目成员管理页、申请中心 | 修改申请人在项目内的角色 |
| 资源访问申请 | 数据源、数据表、指标、标签、仪表盘、API、文件详情页 | 创建资源授权记录 |
| 敏感数据访问申请 | 敏感字段、脱敏字段、受限数据集详情页 | 开放敏感字段访问权限或脱敏例外 |
| 数据下载/导出申请 | SQL 查询、数据集、分析结果、仪表盘导出页 | 生成导出任务或解锁下载按钮 |
| 资源发布申请 | 指标、标签、数据集、仪表盘、API、流程模板编辑页 | 将资源状态变更为已发布 |
| 资源下线/删除申请 | 资源详情页、资源管理页 | 将资源下线、软删除或进入回收站 |
| 权限策略变更申请 | 权限与策略中心 | 新增、修改、停用权限策略 |
| 安全配置变更申请 | 数据安全与合规中心 | 修改脱敏规则、访问白名单、安全策略 |
| 流程模板发布申请 | 流程模板编辑页 | 发布新版审批流程 |
| 自定义通用申请 | 申请中心 | 不自动生效，只记录审批结论 |

**1.3 使用角色**

| **角色** | **权限说明** |
| --- | --- |
| 普通用户 | 发起申请、查看自己的申请、撤回未完成申请、催办当前审批人、复制申请 |
| 项目成员 | 可在项目范围内发起资源、权限、发布、导出类申请 |
| 资源负责人 | 审批自己负责资源的访问、发布、下线、删除申请 |
| 项目管理员 | 审批项目成员、项目角色、项目内资源权限申请 |
| 数据管理员 | 审批数据资源访问、数据集、指标、标签、API 等数据资产申请 |
| 安全管理员 | 审批敏感数据、脱敏例外、下载导出、安全配置申请 |
| 平台管理员 | 配置流程模板、审批规则、通知策略、处理异常流程、查看全量流程实例 |
| 审计员 | 只读查看全部申请、审批记录、生效记录和操作日志 |

**2. 全局功能规则**

**2.1 全局状态定义**

**2.1.1 申请单状态**

| **状态编码** | **状态名称** | **说明** | **前端展示** |
| --- | --- | --- | --- |
| DRAFT | 草稿 | 用户保存但未提交 | 草稿 |
| SUBMITTED | 已提交 | 用户已提交，系统正在匹配流程 | 已提交 |
| IN\_APPROVAL | 审批中 | 已进入审批节点 | 审批中 |
| APPROVED\_WAIT\_EFFECT | 审批通过待生效 | 审批已通过，但生效任务尚未完成 | 待生效 |
| APPROVED\_EFFECTIVE | 已通过并生效 | 审批通过且权限、资源或配置已完成生效 | 已通过 |
| PARTIAL\_EFFECTIVE | 部分生效 | 多资源申请中部分资源生效失败 | 部分生效 |
| REJECTED | 已驳回 | 任一驳回节点导致流程结束 | 已驳回 |
| WITHDRAWN | 已撤回 | 申请人主动撤回 | 已撤回 |
| TERMINATED | 已终止 | 管理员终止异常流程 | 已终止 |
| EXPIRED | 已过期 | 超过流程有效期且规则要求自动过期 | 已过期 |
| EFFECT\_FAILED | 生效失败 | 审批通过但自动生效动作失败 | 生效失败 |

**2.1.2 审批节点状态**

| **状态编码** | **状态名称** | **说明** |
| --- | --- | --- |
| NOT\_STARTED | 未开始 | 前置节点未完成 |
| PENDING | 待处理 | 当前节点正在等待审批 |
| APPROVED | 已同意 | 当前节点审批通过 |
| REJECTED | 已驳回 | 当前节点审批驳回 |
| SKIPPED | 已跳过 | 条件不满足或系统自动跳过 |
| AUTO\_APPROVED | 自动通过 | 命中自动审批规则 |
| TRANSFERRED | 已转交 | 原审批人转交给其他审批人 |
| ADDED\_SIGN | 已加签 | 当前节点增加额外审批人 |
| TIMEOUT | 已超时 | 超过节点 SLA |
| TERMINATED | 已终止 | 流程被管理员终止 |

**2.2 申请单编号规则**

申请单编号由系统自动生成，不允许用户编辑。

编号格式：

APP-{yyyyMMdd}-{6位递增序号}

示例：

APP-20260528-000128

生成规则：

1. 每个自然日从 000001 开始递增。
2. 编号生成时机为用户点击“提交申请”并通过前端校验、后端校验之后。
3. 草稿不生成正式申请单编号，只生成草稿 ID。
4. 同一用户连续提交多笔申请时，编号必须唯一。
5. 编号生成失败时，提交接口返回失败，前端提示“申请编号生成失败，请稍后重试”。

**2.3 申请单权限规则**

用户能看到的申请单范围如下：

| **用户身份** | **可见范围** |
| --- | --- |
| 申请人 | 自己发起的所有申请 |
| 当前审批人 | 自己当前待审批的申请 |
| 历史审批人 | 自己已审批过的申请 |
| 抄送人 | 抄送给自己的申请 |
| 项目管理员 | 自己管理项目下的申请 |
| 平台管理员 | 全部申请 |
| 审计员 | 全部申请，只读 |
| 资源负责人 | 涉及自己负责资源的申请 |

前端所有申请列表接口必须根据登录用户身份做服务端过滤，不能只依赖前端隐藏。

**2.4 流程匹配规则**

用户提交申请后，系统按以下优先级匹配流程模板：

1. 精确匹配项目空间 + 申请类型 + 资源类型 + 操作类型。
2. 匹配项目空间 + 申请类型 + 操作类型。
3. 匹配租户级申请类型 + 资源类型 + 操作类型。
4. 匹配租户级申请类型 + 操作类型。
5. 匹配系统默认流程。
6. 若无可用流程模板，则禁止提交。

匹配成功后，系统必须将流程模板版本快照写入申请单实例。后续流程模板被修改，不影响已经提交的申请单。

**2.5 流程生效规则**

审批通过不等于业务权限立即可用。系统必须区分审批结论和生效结果。

审批通过后，系统根据申请类型执行对应生效动作：

| **申请类型** | **生效动作** |
| --- | --- |
| 项目加入申请 | 创建 project\_member 记录 |
| 项目角色变更申请 | 更新 project\_member.role\_id |
| 资源访问申请 | 创建 resource\_permission\_grant 记录 |
| 敏感数据访问申请 | 创建 sensitive\_access\_grant 或 masking\_exception 记录 |
| 数据下载申请 | 创建 export\_permission\_token 或 export\_task |
| 资源发布申请 | 更新 resource.status = PUBLISHED |
| 资源下线申请 | 更新 resource.status = OFFLINE |
| 资源删除申请 | 更新 resource.status = DELETED 或 RECYCLED |
| 权限策略变更申请 | 写入 permission\_policy 新版本并启用 |
| 安全配置变更申请 | 写入 security\_policy 新版本并启用 |
| 流程模板发布申请 | 将 workflow\_template.status 改为 PUBLISHED |

生效动作必须具备幂等性。若同一申请因网络或任务重试重复调用生效接口，不能重复创建权限或重复执行删除。

**4.3 顶部统计卡片区**

| **卡片** | **统计口径** | **点击行为** |

**4.5.1 “同意”按钮逻辑**

点击“同意”：

1. 弹出审批确认弹窗。
2. 弹窗展示：
   * 申请标题
   * 申请类型
   * 当前节点
   * 审批意见输入框
3. 审批意见非必填。
4. 点击弹窗“确认同意”后调用审批接口。
5. 成功后该申请从待审批区移除。
6. 如果该节点是最后一个节点，则申请进入“审批通过待生效”。
7. 如果还有后续节点，则流转到下一节点。
8. 操作成功后提示“已同意，流程已流转”。

**4.5.2 “驳回”按钮逻辑**

点击“驳回”：

1. 弹出驳回确认弹窗。
2. 驳回原因必填，长度 5 到 500 字。
3. 支持选择驳回方式：
   * 驳回至申请人，流程结束。
   * 驳回至上一节点，前提是流程模板允许回退。
   * 驳回至指定节点，前提是当前节点配置了可驳回节点范围。
4. 若流程模板不允许回退，只展示“驳回至申请人”。
5. 点击“确认驳回”后，申请状态变为 REJECTED 或回退到指定节点。
6. 操作成功后提示“已驳回”。

**4.5.3 “查看更多”按钮逻辑**

点击“查看更多”跳转到“我的审批”页面，并默认筛选：

审批状态 = 待审批

排序 = 提交时间倒序

**5. 发起申请页面**

**5.1 页面目标**

发起申请页面用于创建新的申请单。用户可以从申请中心进入，也可以从业务资源页面带参进入。

**5.2 页面入口**

支持以下入口：

1. 左侧菜单“发起申请”。
2. 申请工作台快捷卡片。
3. 数据源详情页“申请访问”按钮。
4. 数据表详情页“申请权限”按钮。
5. 指标详情页“申请使用”按钮。
6. 标签详情页“申请使用”按钮。

**5.4 步骤一：选择申请类型**

**5.4.1 页面元素**

| **元素** | **说明** |
| --- | --- |
| 申请类型搜索框 | 支持按申请类型名称搜索 |

**5.4.2 申请类型卡片选择逻辑**

1. 用户点击某个申请类型卡片后，该卡片高亮。
2. 页面右侧展示该申请类型说明，包括：

点击“下一步”时：

1. 校验是否已选择申请类型。
2. 若未选择，提示“请选择申请类型”。
3. 若选择的申请类型需要项目上下文但当前未选择项目，进入第二步时项目字段必填。
4. 若入口已带入申请类型，则步骤一自动完成，用户仍可以点击步骤条返回修改。

**5.5.3 项目加入申请表单**

校验规则：

1. 当前角色与申请角色相同，禁止提交。
2. 若申请角色为项目管理员，必须填写有效期或由租户配置决定是否允许长期。
3. 若已有审批中的角色变更申请，禁止重复提交。

**5.5.5 资源访问申请表单**

字段：

| **字段** | **类型** | **是否必填** | **规则** |
| --- | --- | --- | --- |
| 资源类型 | 下拉选择 | 是 | 数据源、数据表、字段、指标、标签、数据集、仪表盘、API、文件 |
| 资源选择 | 资源选择器 | 是 | 支持多选 |
| 申请权限 | 多选 | 是 | 查看、使用、编辑、管理、调用、下载 |
| 权限范围 | 单选 | 是 | 个人、项目、用户组 |
| 权限有效期 | 日期范围 | 是 | 结束日期必须晚于开始日期 |
| 使用场景 | 多行文本 | 是 | 10-1000 字 |
| 是否包含敏感数据 | 系统展示 | 否 | 自动识别 |
| 风险提示 | 系统展示 | 否 | 命中敏感资源时展示 |

资源选择器逻辑：

1. 用户点击“选择资源”按钮打开资源选择弹窗。
2. 弹窗左侧为资源类型树，右侧为资源列表。
3. 支持按资源名称、负责人、项目、标签搜索。
4. 每个资源展示敏感等级、负责人、所属项目、当前权限状态。
5. 已拥有所选权限的资源不可勾选，展示“已拥有权限”。
6. 已下线或已删除资源不可勾选。
7. 选择完成后回填到申请表单。

批量资源规则：

1. 同一申请最多选择 50 个资源。
2. 若资源敏感等级不同，流程按最高敏感等级匹配。
3. 若资源负责人不同，审批流程中资源负责人节点需要自动拆分为多人并行审批。
4. 多资源申请通过后，系统逐条创建授权记录。
5. 部分资源授权失败时，申请状态变为 PARTIAL\_EFFECTIVE，并在详情页展示失败资源和失败原因。

**5.5.6 敏感数据访问申请表单**

字段：

| **字段** | **类型** | **是否必填** | **规则** |
| --- | --- | --- | --- |
| 敏感资源 | 资源选择器 | 是 | 只能选择敏感等级大于等于 S2 的资源 |
| 申请字段 | 字段选择器 | 是 | 支持选择字段级权限 |
| 访问方式 | 多选 | 是 | 查询、下载、API 调用、报表展示 |
| 是否申请脱敏例外 | 开关 | 是 | 默认关闭 |
| 申请原因 | 多行文本 | 是 | 20-1500 字 |
| 使用场景 | 下拉选择 | 是 | 业务分析、监管报送、客户服务、风控审核、其他 |
| 数据最小化说明 | 多行文本 | 是 | 说明为什么必须访问这些字段 |
| 权限有效期 | 日期范围 | 是 | 最大不能超过租户配置 |
| 附件 | 上传 | 视规则而定 | 命中高敏字段时必填 |

特殊规则：

1. 选择身份证、手机号、银行卡、地址等高敏字段时，必须填写“数据最小化说明”。
2. 开启“脱敏例外”后，流程必须包含安全管理员审批节点。
3. 高敏字段权限有效期默认不超过 30 天，除非租户配置允许延长。
4. 若用户申请下载包含高敏字段的数据，必须同时触发数据下载审批规则。
5. 若字段已配置禁止申请原文访问，则“脱敏例外”开关不可开启。

若扩大权限范围，审批流程必须包含安全管理员节点。

**5.6 步骤三：确认审批流程**

**5.6.1 页面内容**

展示以下内容：

1. 申请内容摘要。
2. 审批流程图。
3. 每个审批节点的审批人。
4. 预计审批耗时。
5. 审批通过后的生效动作。
6. 风险提示。
7. 提交按钮。

**5.6.2 流程图展示规则**

流程图按节点顺序展示：

发起人 -> 项目管理员审批 -> 资源负责人审批 -> 安全管理员审批 -> 自动生效 -> 完成

节点卡片展示：

| **信息** | **说明** |
| --- | --- |
| 节点名称 | 例如“资源负责人审批” |
| 节点类型 | 人工审批、自动审批、条件分支、自动生效 |
| 审批方式 | 或签、会签、顺序审批 |
| 审批人 | 展示具体人名或审批组 |
| 超时时间 | 例如 24 小时 |
| 超时动作 | 提醒、升级、自动通过、自动驳回 |

**5.6.3 审批人为空处理**

若某节点解析不到审批人：

1. 如果该节点配置了兜底审批人，则展示兜底审批人。
2. 如果未配置兜底审批人，则禁止提交。
3. 页面提示：“流程节点【节点名称】未解析到审批人，请联系管理员配置审批规则。”
4. “提交申请”按钮置灰。

**5.6.4 重复申请检测**

进入步骤三时，系统执行重复申请检测。

检测条件：

1. 同一申请人。
2. 同一申请类型。
3. 同一资源或项目。
4. 同一权限动作。
5. 已存在状态为 IN\_APPROVAL、SUBMITTED、APPROVED\_WAIT\_EFFECT 的申请。

若命中重复申请：

1. 页面顶部展示警告。
2. 展示重复申请编号和状态。
3. 提供“查看已有申请”按钮。
4. 不允许提交重复申请。

**5.6.5 “提交申请”按钮逻辑**

点击“提交申请”：

1. 前端再次校验表单必填项。
2. 后端校验用户是否有发起权限。
3. 后端校验申请内容是否合法。
4. 后端执行流程模板匹配。
5. 后端生成申请单编号。
6. 后端创建流程实例。
7. 后端创建首个审批节点任务。
8. 后端发送通知给首个审批人。
9. 状态变为 IN\_APPROVAL。
10. 页面进入步骤四。

若流程首节点为自动审批：

1. 系统自动执行该节点。
2. 继续推进到下一个节点。
3. 直到遇到人工审批节点或流程结束。
4. 若全部自动通过，则进入生效阶段。

**6.5.2 审批中状态**

撤回逻辑：

1. 申请人点击“撤回”。
2. 弹出撤回确认框。
3. 撤回原因非必填，最多 500 字。
4. 确认后申请状态变为 WITHDRAWN。
5. 当前审批任务全部关闭。
6. 已完成审批记录保留。
7. 已撤回申请不执行生效动作。
8. 通知当前审批人申请已撤回。

限制：

1. 已通过待生效、已生效的申请不可撤回。
2. 审批节点正在执行自动生效时不可撤回。

**同意**

点击“同意”：

1. 审批意见输入框可选。
2. 若当前节点配置“同意意见必填”，则必填。
3. 若申请风险等级为高或极高，审批意见必填。
4. 点击确认后调用审批接口。
5. 审批成功后按钮区变为只读。
6. 流程进入下一节点或生效阶段。

**驳回**

点击“驳回”：

1. 驳回原因必填。
2. 根据流程模板展示可驳回目标：
   * 驳回至申请人
   * 驳回至上一节点
   * 驳回至指定节点
3. 默认选中“驳回至申请人”。
4. 若选择“驳回至上一节点”，系统关闭当前节点任务，重新激活上一节点。
5. 若驳回至申请人，申请状态变为 REJECTED。
6. 驳回后通知申请人。

**转交**

点击“转交”：

1. 打开转交弹窗。
2. 选择新审批人，单选。
3. 转交原因必填，5-500 字。
4. 新审批人不能为申请人本人，除非流程模板允许。
5. 新审批人必须具备该节点审批权限。
6. 转交后当前审批任务归属变更。
7. 原审批人保留“转交记录”，不再能审批。
8. 新审批人收到待办通知。

**加签**

点击“加签”：

1. 打开加签弹窗。
2. 选择加签人，可多选。
3. 选择加签方式：
   * 前加签：加签人先审批，当前审批人后审批。
   * 后加签：当前审批人先审批，加签人后审批。
   * 并行加签：当前审批人与加签人都审批，全部通过后进入下一节点。
4. 加签原因必填。
5. 加签人不能重复。
6. 加签后流程时间轴增加加签节点。
7. 加签节点完成后按配置继续流转。

**暂存意见**

点击“暂存意见”：

1. 保存当前审批意见草稿。
2. 不改变流程状态。
3. 再次进入审批详情时自动恢复。
4. 仅当前审批人可见自己的暂存意见。

**11.4.1 审批方式规则**

**或签**

1. 多个审批人任意一人同意，则节点通过。
2. 任意一人驳回，则节点驳回。
3. 节点通过后，其他审批人的待办自动关闭。
4. 关闭原因记录为“或签已由其他审批人处理”。

**会签**

1. 所有审批人都同意，节点才通过。
2. 任意一人驳回，节点立即驳回。
3. 已同意的审批记录保留。
4. 被驳回后未处理审批人的待办关闭。

**顺序审批**

1. 审批人按配置顺序依次处理。
2. 前一人同意后，才创建下一人的待办。
3. 任意一人驳回，节点驳回。
4. 顺序不可为空。

**11.4.2 审批人来源规则**

| **来源** | **解析规则** |
| --- | --- |
| 指定成员 | 使用配置的成员列表 |
| 指定角色 | 查找当前项目或租户下拥有该角色的用户 |
| 资源负责人 | 根据申请资源 owner\_id 解析 |
| 项目管理员 | 根据申请项目 project\_admin 解析 |
| 部门负责人 | 根据申请人部门 manager\_id 解析 |
| 安全管理员 | 查找租户安全管理员角色 |
| 申请人上级 | 根据组织架构查找 direct\_manager\_id |
| 用户组 | 查找用户组成员 |
| 动态规则 | 执行审批规则表达式 |

审批人解析为空时：

1. 优先使用节点兜底审批人。
2. 兜底审批人为空则流程发布失败。
3. 已发布流程运行时解析为空，则申请提交失败，不允许进入异常待办。

**11.4.3 申请人自审规则**

默认不允许申请人审批自己的申请。

若节点解析出的审批人包含申请人：

1. 若“允许申请人自审”为关闭，则自动剔除申请人。
2. 剔除后仍有其他审批人，则继续流程。
3. 剔除后审批人为空，则使用兜底审批人。
4. 若允许申请人自审，则保留申请人，并在节点上展示“允许自审”标签。

**11.9 顶部按钮逻辑**

**保存草稿**

1. 保存当前模板配置。
2. 不要求流程完全合法。
3. 模板状态为 DRAFT。
4. 保存成功提示“流程模板草稿已保存”。

**校验流程**

校验内容：

1. 是否存在开始节点和结束节点。
2. 所有节点是否连通。
3. 是否存在环路。
4. 人工审批节点是否配置审批人规则。
5. 条件分支是否有默认分支。
6. 自动生效节点是否配置生效动作。
7. 是否至少存在一个审批节点。
8. 是否存在适用条件冲突。
9. 是否有不可达节点。

校验失败时：

1. 在画布中高亮异常节点。
2. 右侧展示错误列表。
3. 点击错误项定位到节点。

**预览流程**

1. 打开预览弹窗。
2. 用户选择模拟申请类型、资源、申请人、项目。
3. 系统按当前模板配置模拟审批人解析。
4. 展示实际流转路径。
5. 若某节点无法解析审批人，标红提示。
6. 预览不创建真实申请单。

**发布**

1. 先执行流程校验。
2. 校验通过后弹出发布确认框。
3. 展示发布影响：
   * 申请类型
   * 适用范围
   * 是否替换旧模板
   * 新版本号
4. 用户确认后发布。
5. 若需要审批发布，则自动创建“流程模板发布申请”。
6. 若不需要审批发布，则立即发布。

**取消**

1. 若存在未保存修改，弹窗确认。
2. 确认放弃后返回流程模板列表。
3. 若无修改，直接返回。

**17. 异常处理规则**

**17.1 审批人离职**

若审批人账号被停用：

1. 未处理任务进入异常状态。
2. 系统根据节点配置寻找兜底审批人。
3. 若存在兜底审批人，自动转派。
4. 若不存在，通知平台管理员处理。
5. 申请状态仍为 IN\_APPROVAL。

**17.2 资源被删除**

申请审批中资源被删除：

1. 系统在详情页展示“资源已删除”。
2. 若申请尚未通过，当前审批人仍可驳回。
3. 若审批通过进入生效阶段，生效失败。
4. 状态变为 EFFECT\_FAILED。
5. 失败原因记录为“目标资源不存在”。

**17.3 权限已被其他方式授予**

申请审批中，申请人已通过其他方式获得同等权限：

1. 审批流程继续。
2. 生效阶段检测到权限已存在。
3. 生效记录标记为 SUCCESS。
4. 生效说明为“权限已存在，无需重复授予”。

**17.4 流程模板被停用**

申请提交后模板被停用：

1. 已提交申请继续使用提交时的模板版本快照。
2. 不影响当前流程。
3. 新申请不再匹配停用模板。

**17.5 通知发送失败**

通知发送失败：

1. 不影响流程流转。
2. 写入通知失败日志。
3. 支持后台重试。
4. 前端不向普通用户暴露通知技术错误。

**18. 验收标准**

**18.1 发起申请验收**

1. 用户可以从申请中心选择申请类型并发起申请。
2. 用户可以从资源详情页带入资源信息发起申请。
3. 必填字段缺失时不能提交。
4. 重复申请会被拦截。
5. 流程审批人无法解析时不能提交。
6. 提交成功后生成申请编号和流程实例。
7. 首个审批人能收到待办。

**18.2 我的申请验收**

1. 用户只能看到自己发起的申请。
2. 草稿可编辑、删除、复制。
3. 审批中申请可撤回、催办。
4. 已驳回申请可重新提交。
5. 已通过申请可查看生效结果。
6. 生效失败申请能展示失败原因。

**18.3 我的审批验收**

1. 审批人只能看到分配给自己的待办。
2. 审批人可以同意、驳回、转交、加签。
3. 或签、会签、顺序审批流转结果正确。
4. 批量审批遵守风险和节点限制。
5. 审批意见、驳回原因、转交原因均按规则校验。
6. 所有审批动作都写入流程日志。

**18.4 流程模板验收**

1. 管理员可以新建、编辑、复制、发布、停用模板。
2. 发布前必须通过完整性校验。
3. 条件分支必须有默认分支。
4. 人工审批节点必须能解析审批人或配置兜底审批人。
5. 新版本发布不影响历史申请。
6. 流程预览能正确模拟审批路径和审批人。

**18.5 生效验收**

1. 审批通过后自动执行对应生效动作。
2. 授权、发布、导出、策略启用等动作具备幂等性。
3. 生效成功后申请状态为 APPROVED\_EFFECTIVE。
4. 生效失败后申请状态为 EFFECT\_FAILED。
5. 管理员可以重试失败的生效动作。
6. 部分资源失败时状态为 PARTIAL\_EFFECTIVE，并展示失败明细。

**18.6 审计验收**

1. 申请提交、审批、撤回、催办、转交、加签、终止、生效都写入日志。
2. 日志包含操作人、操作时间、操作前状态、操作后状态、IP。
3. 审计员可以查询和导出日志。
4. 普通用户不能查看无关申请日志。
5. 导出日志行为本身也必须写入审计日志。

**19. 前端开发注意事项**

1. 所有按钮显示必须由后端权限接口返回，不允许只靠前端角色判断。
2. 申请详情页必须支持动态表单渲染，不同申请类型展示不同 payload。
3. 流程图组件必须支持节点状态、审批人、时间线和异常状态展示。
4. 审批操作必须防重复提交，按钮点击后进入 loading 状态。
5. 同意、驳回、转交、加签成功后必须刷新详情和列表。
6. 生效状态应独立展示，不要只用审批状态替代。
7. 附件上传、下载、预览必须接入权限校验。
8. 批量审批必须在前端先做基础校验，后端再做最终校验。
9. 流程模板编辑器必须支持保存草稿，不能要求一次性配置完成。
10. 流程模板发布前必须提供校验错误定位能力。

**20. 本模块与其他中心的关系**

**20.1 与组织与身份中心**

使用组织架构、用户、角色、部门负责人、用户组解析审批人。

**20.2 与项目与空间中心**

项目加入、项目角色变更、项目内资源权限申请都依赖项目成员和项目角色体系。

**20.3 与权限与策略中心**

审批通过后创建或修改权限授权、权限策略、角色绑定。

**20.4 与资源与资产中心**

资源访问、资源发布、资源下线、资源删除申请依赖资源元数据、负责人、敏感等级、血缘关系。

**20.5 与数据安全与合规中心**

敏感数据访问、脱敏例外、数据导出、出域申请必须接入安全规则和审计策略。

**20.6 与通知中心**

流程流转、待办、催办、超时、生效结果需要通过站内信、邮件、企业通信工具通知相关用户。
