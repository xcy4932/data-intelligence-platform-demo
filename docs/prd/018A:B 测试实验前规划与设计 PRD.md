**A/B 测试实验前规划与设计 PRD**

**1. 产品定位**

**1.1 功能目标**

本模块用于支持用户在正式启动 A/B 实验前，完成实验设计、分流设计、流量预估、用户圈选、版本参数配置、实验流量生效方式配置等工作，确保实验上线前具备以下条件：

1. 实验类型选择正确，避免客户端、服务端、可视化、多链接、推送、MAB、父子实验、反转实验等场景混用。
2. 实验版本参数设计清晰，开发侧能够通过实验参数直接控制功能行为。
3. 实验用户受众与分流 ID 设计明确，分流结果稳定、可复现、可排查。
4. 实验流量大小经过预估，避免流量不足导致实验不显著，也避免过度占用线上流量。
5. 实验加入正确的流量层或互斥域，避免相关实验互相污染。
6. 实验开始前可通过增强分流均匀性降低各版本初始样本差异。
7. 实验流量可选择立即生效或平滑生效，降低策略上线、扩量、暂停、停止时对线上系统的冲击。

**1.2 功能边界**

本 PRD 只覆盖“实验前规划与设计”，包括：

* 选择实验类型；
* 配置实验基础信息；
* 配置实验版本与实验参数；
* 配置分流模型与用户受众；
* 预估实验所需流量；
* 配置流量层、互斥域与互斥关系；
* 配置增强分流均匀性；
* 配置实验流量立即生效或平滑生效；
* 实验提交前校验与预览。

不覆盖：

* 实验运行后的报告分析；
* 实验显著性结果解读；
* 实验结论发布；
* 实验复盘；
* 广告平台实际投放创建细节；
* 推送内容发送系统细节；
* SDK 接入文档本身。

**2. 用户角色与权限**

**2.1 角色定义**

| **角色** | **可执行操作** |
| --- | --- |
| 超级管理员 | 创建、编辑、删除所有实验前配置；管理所有流量层、互斥域；修改系统级默认置信水平；查看所有实验配置 |
| 应用管理员 | 管理当前应用下实验、流量层、互斥域、受众、指标；创建和编辑实验 |
| 实验创建者 | 创建实验草稿；编辑自己创建的实验；配置版本、参数、流量、受众；提交调试 |
| 实验协作者 | 查看被授权实验；编辑指定实验配置；不可删除实验 |
| 普通查看者 | 只读查看实验配置、流量规划、参数配置，不可编辑 |

**2.2 权限规则**

1. 流量层、互斥域属于“应用级公共资源”。
2. 同一应用下，有权限创建实验的用户均可查看流量层和互斥域。
3. 创建、修改、删除流量层和互斥域需要 experiment\_traffic\_manage 权限。
4. 创建实验需要 experiment\_create 权限。
5. 修改草稿实验需要满足以下任一条件：
   * 当前用户是实验创建者；
   * 当前用户是实验协作者；
   * 当前用户拥有应用管理员权限。
6. 运行中实验不允许修改会影响分流一致性的配置，包括：
   * 实验类型；
   * 分流 ID；
   * 流量层；
   * 互斥域；
   * 版本数量；
   * 版本流量比例；
   * 用户受众过滤条件；
   * 增强分流均匀性配置。
7. 运行中实验可以扩量，但必须走“实验扩量”流程，不允许直接修改原始实验流量字段。
8. 平滑生效过程中，不允许修改生效方式和实验流量。

**3. 实验前规划总流程**

**3.1 页面流程**

用户从“实验列表”点击“新建实验”后，进入实验创建向导。

实验创建向导分为 6 步：

1. 选择实验类型
2. 填写基础信息
3. 配置实验版本与参数
4. 配置用户受众与分流模型
5. 配置流量层、互斥域、实验流量与生效方式
6. 提交前检查与预览

页面顶部展示步骤条，步骤条固定在页面顶部，不随页面滚动消失。

**3.2 草稿保存规则**

1. 用户每完成一个步骤并点击“下一步”，系统自动保存当前步骤配置为草稿。
2. 用户点击“保存草稿”时，立即保存当前所有已填写内容。
3. 草稿不要求所有必填项完整，但保存时要保留当前输入内容。
4. 进入下一步时，只校验当前步骤必填项和当前步骤内逻辑。
5. 点击“提交调试”时，执行全量校验。
6. 草稿状态实验可以随时编辑、删除。
7. 调试中实验可以编辑除实验类型外的大部分配置。
8. 运行中实验不允许回到创建向导修改核心配置，只能通过实验详情页执行扩量、暂停、停止等操作。

**4.4 实验类型选择规则**

**4.4.1 编程实验-客户端实验**

适用条件：

* 实验策略需要在 App 启动、页面打开或客户端本地交互时立即生效；
* 实验内容主要由客户端控制；
* 客户端已接入 A/B 测试 SDK；
* 客户端能够根据实验参数控制页面元素、按钮样式、本地功能逻辑。

典型场景：

* 按钮颜色；
* 按钮位置；
* 页面布局；
* 本地弹窗；
* 客户端功能开关；
* 本地推荐样式展示。

选择限制：

1. 若当前应用未接入客户端 SDK，卡片置灰，不允许选择。
2. 鼠标悬停置灰卡片时，显示原因：“当前应用未检测到客户端 SDK 接入，无法创建客户端实验。”
3. 点击不可用卡片时，不选中卡片，只弹出提示。

**4.4.2 编程实验-服务端实验**

适用条件：

* 实验策略由服务端决定；
* 用户访问服务端后，服务端根据分流结果下发不同策略；
* 不要求 App 启动瞬间实验配置立即生效；
* 服务端已接入 SDK 或部署分流 Agent。

典型场景：

* 推荐算法；
* 内容分发策略；
* 搜索排序；
* 推送策略；
* 服务端功能开关；
* 后端配置策略。

选择限制：

1. 若当前应用未接入服务端 SDK 或分流 Agent，卡片置灰。
2. 若用户无服务端实验创建权限，卡片置灰。
3. 服务端实验后续只能选择服务端流量层和服务端互斥域。

**4.4.3 MAB 智能调优实验**

适用条件：

* 实验目标不是单纯判断哪个版本显著更优，而是在实验过程中尽快把更多流量分配给当前表现更好的版本；
* 活动周期短；
* 流量价值高；
* 机会成本高；
* 需要持续动态调优。

选择限制：

1. MAB 实验必须配置唯一优化指标。
2. MAB 实验不支持将实验版本流量固定为长期不变。
3. 如果用户选择 MAB，后续“版本流量比例”页面展示为初始探索流量配置，而不是固定比例配置。
4. 如果业务方需要严格统计检验结论，系统提示：“MAB 更适合收益最大化，不适合作为标准显著性检验实验。”

**4.4.4 可视化实验**

适用条件：

* 用户希望无需开发，通过可视化编辑器修改页面元素；
* 适合 Web、H5 或支持可视化编辑的页面；
* 页面元素可被编辑器识别。

选择限制：

1. 当前应用未开启可视化能力时不可选择。
2. 可视化实验后续必须进入可视化编辑器配置版本。
3. 可视化实验不展示代码参数配置区，展示页面元素变更配置区。

**4.4.5 多链接实验**

适用条件：

* 不同版本是不同 URL；
* 用户命中不同版本后跳转到不同页面；
* 适合落地页对比。

配置要求：

1. 每个版本必须配置 URL。
2. URL 必须以 http:// 或 https:// 开头。
3. 不允许多个版本 URL 完全相同。
4. 对照组 URL 必填。
5. 实验组 URL 必填。

**4.4.6 推送实验**

适用条件：

* 对推送标题、推送内容、跳转动作、按钮文案进行测试；
* 可用于多文案推送、小流量文案验证、智能文案调优。

配置要求：

1. 必须选择推送通道。
2. 每个版本必须配置推送标题和推送内容。
3. 推送实验必须配置触达用户范围。
4. 推送实验必须配置发送时间或触发条件。

**4.4.7 多变体可视化实验 MVT**

适用条件：

* 同时测试页面多个元素的组合效果；
* 页面访问量足够高；
* 需要验证多个元素组合。

配置要求：

1. 至少配置 2 个实验元素。
2. 每个元素至少配置 2 个变体。
3. 系统自动生成组合版本。
4. 组合版本数量过多时，系统提示样本量风险。

**4.4.8 个性化实验**

适用条件：

* 根据用户特征、行为、地域、兴趣等条件展示不同内容；
* 不同用户群体体验不同策略。

配置要求：

1. 必须配置人群规则。
2. 每个人群至少绑定一个策略版本。
3. 同一用户同时命中多个人群时，需要配置优先级。
4. 优先级数值越小，优先级越高。

**4.4.9 父子实验**

适用条件：

* 子实验只在父实验某个实验组流量下开展；
* 适合在已有实验组策略基础上继续细分验证。

配置要求：

1. 必须选择一个运行中的父实验。
2. 必须选择父实验中的一个版本作为子实验流量来源。
3. 子实验流量不能超过父实验目标版本的可用流量。
4. 父子实验会打破普通流量层正交关系，页面必须展示风险提示。
5. 父实验停止时，子实验必须自动暂停或停止，具体策略由创建时选择。

**4.4.10 反转实验**

适用条件：

* 某实验组已经胜出并上线；
* 需要在未体验新策略的对照人群中再次小流量验证长期收益；
* 适合重要功能全量发布后的长期风险观测。

配置要求：

1. 必须关联一个已完成或已发布实验。
2. 必须选择原对照组作为反转实验候选流量。
3. 默认建议小流量。
4. 系统自动带入原实验核心指标作为候选指标，用户可修改。

**4.4.11 广告实验**

适用条件：

* 需要验证广告策略；
* 已完成广告账户和外部广告平台授权；
* 需要在相同广告设置下比较不同广告策略效果。

配置要求：

1. 必须绑定广告账户。
2. 必须选择广告项目或应用。
3. 必须完成外部平台授权校验。
4. 未授权时卡片置灰，并展示“去授权”按钮。

1. 未选择实验类型时，“下一步”禁用。
2. 选择不可用实验类型时，不允许进入下一步。
3. 用户切换实验类型时：
   * 如果后续步骤尚未填写，直接切换；
   * 如果后续步骤已有数据，弹出确认框：“切换实验类型将清空后续配置，是否继续？”
4. 确认切换后，清空实验版本、参数、受众、流量、互斥域、生效方式等后续配置。

**6. 页面三：实验版本与实验参数配置**

**6.1 页面目标**

该页面用于配置实验有几个版本、每个版本叫什么、每个版本使用什么实验参数。

实验参数不是按照“实验组编号”硬编码，而是按照“功能控制项”设计。这样同一个参数可以在多个实验中复用，实验调整时无需重新开发。

**6.2 页面布局**

页面分为三块：

1. 实验版本区；
2. 参数模板区；
3. 各版本参数值配置区。

底部固定按钮：

* 上一步；
* 保存草稿；
* 下一步；
* 取消。

**6.3 实验版本区**

默认创建两个版本：

| **版本类型** | **默认名称** | **是否可删除** |
| --- | --- | --- |
| 对照组 | 对照组 | 不可删除 |
| 实验组 | 实验组 1 | 可删除，前提是至少保留一个实验组 |

字段：

| **字段** | **类型** | **规则** |
| --- | --- | --- |
| 版本名称 | 输入框 | 1-50 字，同一实验内唯一 |
| 版本描述 | 多行输入框 | 0-200 字 |
| 是否对照组 | 单选 | 只能有一个对照组 |
| 参数值 | 根据参数模板生成 | 必须符合参数类型 |

版本数量规则：

1. 普通 A/B 实验至少 2 个版本。
2. 普通多组实验最多 20 个版本。
3. MVT 版本由元素组合自动生成，不允许手工新增普通版本。
4. MAB 版本至少 2 个，最多 20 个。
5. 多链接实验每个版本必须有 URL。
6. 推送实验每个版本必须有推送内容。

**6.4 实验版本按钮**

| **按钮** | **位置** | **点击逻辑** |
| --- | --- | --- |
| 新增实验组 | 版本区右上角 | 新增一个实验组，名称自动为“实验组 N” |
| 删除 | 每个实验组行 | 删除该实验组；若只剩一个实验组则禁用 |
| 复制版本 | 每个版本行 | 复制当前版本名称、描述、参数值，新版本名称追加“副本” |
| 设为对照组 | 实验组行 | 将当前版本设为对照组，原对照组变为实验组 |

**7. 页面四：分流模型与用户受众配置**

**7.1 页面目标**

该页面用于定义：

1. 用什么 ID 进行分流；
2. 哪些用户可以进入实验；
3. 分流请求需要携带哪些属性；
4. 客户端或服务端如何获得实验分组；
5. 曝光事件如何上报。

**7.2 分流模型字段**

| **字段** | **类型** | **是否必填** | **说明** |
| --- | --- | --- | --- |
| 分流 ID 类型 | 下拉框 | 是 | 如 uuid、did、uid、device\_id、自定义 |
| 分流 ID 字段名 | 输入框 | 是 | SDK 请求中的 decisionID 字段来源 |
| 应用标识 appkey | 只读 | 是 | 当前应用唯一标识 |
| 分流稳定性说明 | 文本 | 否 | 说明该 ID 是否跨端稳定 |
| 曝光事件上报方式 | 单选 | 是 | 自动上报、手动上报 |
| 过滤属性来源 | 多选 | 否 | 用户属性、设备属性、事件属性、服务端属性 |

**7.3 分流 ID 选择规则**

1. 分流 ID 必须能唯一标识用户或设备。
2. 同一个用户在实验周期内，分流 ID 必须保持稳定。
3. 如果选择 device\_id，页面提示：
   “使用设备 ID 分流时，同一用户更换设备可能进入不同版本。”
4. 如果选择 uid，页面提示：
   “使用用户 ID 分流时，未登录用户可能无法进入实验，需配置兜底策略。”
5. 如果选择自定义 ID，必须填写字段名和示例值。
6. 分流 ID 一旦实验进入运行状态，不允许修改。

**7.4 客户端实验分流逻辑**

客户端实验流程：

1. 用户打开 App。
2. 客户端 SDK 初始化。
3. SDK 向分流服务发送请求。
4. 请求中包含 appkey、decisionID、过滤属性。
5. 分流服务返回用户是否命中实验、命中的版本 VID、实验参数。
6. SDK 将分流结果缓存到本地。
7. 客户端代码调用获取实验参数 API。
8. 客户端根据参数生效功能。
9. 用户进入曝光区域时，SDK 自动或手动上报曝光事件。
10. 用户行为事件进入数仓后，用于实验指标分析。

缓存规则：

1. 客户端 SDK 每 10 分钟重新请求分流服务。
2. 如果服务端返回新分流结果，覆盖本地缓存。
3. 如果本地无缓存，首次请求结果写入本地。
4. 实验停止后，下次刷新分流结果时不再命中该实验。

**7.5 服务端实验分流逻辑**

服务端实验流程：

1. 服务端 SDK 初始化。
2. SDK 定时拉取实验元信息，包括实验名称、版本比例、目标受众、白名单、参数配置。
3. 用户访问客户端应用。
4. 客户端向业务服务端发起请求。
5. 业务服务端调用服务端 SDK 或分流 Agent。
6. SDK 根据实验元信息和 decisionID 计算分流结果。
7. 服务端返回策略或配置给客户端。
8. 服务端上报曝光事件。
9. 服务端将版本配置传递给下游服务。
10. 指标事件可通过客户端 SDK、HTTP API 或数据集成进入分析链路。

限制：

1. 服务端 SDK 只负责分流和曝光上报。
2. 如果实验指标事件不在服务端产生，仍需客户端或数据集成补充指标事件。
3. 服务端实验只能选择服务端流量层和服务端互斥域。

**8.4 测试精度配置**

字段：

| **字段** | **类型** | **默认值** | **规则** |
| --- | --- | --- | --- |
| MDE 类型 | 单选 | 相对值 | 相对值、绝对值 |
| MDE 数值 | 数字输入 | 无 | 必填，大于 0 |
| 实验版本个数 | 数字输入 | 当前实验版本数 | 2-20 |
| 修正多重比较 | 开关 | 关闭 | 版本数大于 2 时建议开启 |
| 统计功效 Power | 下拉框 | 80% | 50%、80%、90%、99%、99.99% |
| 显著性水平 α | 下拉框 | 5% | 1%、5%、10%、20% |
| 流量过滤比例 | 数字输入 | 100% | 0-100% |

MDE 规则：

1. MDE 表示实验希望检测出的最小指标变化。
2. MDE 越小，所需样本量越大。
3. 如果用户输入的 MDE 极小，系统提示：
   “当前 MDE 设置较小，可能需要大量流量，请确认该提升幅度是否具备业务 ROI。”
4. 如果用户输入的 MDE 大于预期提升，系统提示：
   “当前灵敏度可能无法检测出预期收益，建议降低 MDE 或增加样本量。”

多重比较规则：

1. 实验版本数大于 2 时，展示“修正多重比较”开关。
2. 默认提示用户开启。
3. 开启后，后端计算样本量时使用修正后的显著性水平。
4. 若关闭，提交前检查页展示风险：“多版本实验未修正多重比较，择优判断出错风险较高。”

**8.5 计算结果**

输出字段：

| **字段** | **说明** |
| --- | --- |
| 单组所需样本量 | 每个版本至少需要的样本量 |
| 建议实验总样本量 | 单组样本量 × 实验版本个数 |
| 建议实验总流量 | 建议实验总样本量 / 预计实验周期内可触达用户数 |
| 是否超过 100% | 若建议流量超过 100%，说明当前实验周期内流量不足 |
| 推荐处理建议 | 延长实验天数、提高 MDE、减少版本数、扩大受众 |

计算规则：

recommendedTotalSampleSize = sampleSizePerGroup \* versionCount;

effectiveReachableUsers = estimatedTotalUsers \* trafficFilterRatio;

recommendedTrafficRatio = recommendedTotalSampleSize / effectiveReachableUsers;

其中：

* trafficFilterRatio 为 0-1；
* 如果用户不设置过滤条件，则为 1；
* 结果大于 1 时，展示为超过 100%。

**10.4 互斥域流量比例规则**

1. 同一互斥域组下，各互斥域流量占比之和必须等于 100%。
2. 输入比例时支持小数，最多两位。
3. 若总和小于 100%，页面提示剩余比例。
4. 若总和大于 100%，禁止保存。
5. 删除互斥域后，系统不自动调整其他互斥域比例，由用户手动调整。
6. 点击“平均分配”可将当前组下所有互斥域比例平均设置。

**10.5 子互斥域规则**

1. 开启“启用子互斥域”后，当前互斥域可以绑定子互斥域。
2. 可选择已有互斥域作为子互斥域。
3. 可直接新建互斥域作为子互斥域。
4. 已经关联过父级互斥域的互斥域，不允许再次绑定为子互斥域。
5. 不允许形成循环引用。
6. 父互斥域实验类型必须与子互斥域一致。
7. 子互斥域的可用流量来自父互斥域分配流量。

**10.6 绑定流量层规则**

1. 一个流量层只能绑定到一个互斥域。
2. 已有关联实验的流量层不允许绑定到互斥域，避免影响已有实验。
3. 客户端互斥域只能绑定客户端流量层。
4. 服务端互斥域只能绑定服务端流量层。
5. 绑定后，该流量层在实验创建时将以互斥域形式被选择。

4. 如果互斥域中已有运行中实验，则其他运行中实验不能再加入该互斥域。
5. 草稿和调试中实验可以加入已有运行中实验所在互斥域，但提交运行时必须再次校验。
6. 运行中实验不允许移除互斥域。

3. 不得超过当前流量层或互斥域剩余可用流量。
4. 若使用流量计算器应用结果，自动填充。
5. 若用户手动修改，清除“由计算器推荐”标记。
6. 若实验流量过小，系统提示：

6. 对照组比例可以不等于实验组，但系统提示样本量风险。

**12. 增强分流均匀性配置**

**12.1 功能目标**

增强分流均匀性用于在实验正式开始前，通过重随机方式寻找更均匀的分流结果，使指定指标或指定人群在各实验版本之间差异不显著，从而降低实验启动前的样本偏差。

**12.2 入口**

实验创建向导第 5 步“流量设置”中展示“增强分流均匀性”开关。

展示条件：

1. 当前部署环境支持该能力；
2. 当前实验类型支持该能力；
3. 当前实验尚未运行。

不支持时：

* 开关置灰；
* 鼠标悬停展示不可用原因。

**12.3 配置字段**

| **字段** | **类型** | **说明** |
| --- | --- | --- |
| 是否开启增强分流均匀性 | 开关 | 默认关闭 |
| 均匀分流方式 | 单选 | 按指标值、按分群 |
| 需调平指标 | 多选 | 最多 3 个 |
| 指标时间范围 | 日期范围 | 用于计算调平指标 |
| 选择分群 | 多选 | 按分群时展示 |
| 最大运行次数 | 数字输入 | 防止重随机无限循环 |
| p-value 阈值 | 数字输入 | 判断实验前差异不显著的阈值 |

**12.4 按指标值均匀分流**

规则：

1. 用户最多选择 3 个指标。
2. 被选择的指标自动加入实验关注指标。
3. 系统在实验开始前多次模拟分流。
4. 每次模拟后计算各版本在所选指标上的差异。
5. 当所有指标均满足 p-value 阈值时，认为调平成功。
6. 达到最大运行次数仍不满足时，标记为调平失败。
7. 调平失败时，不允许直接开始实验，用户需要：
   * 调整指标；
   * 调整 p-value；
   * 增加最大运行次数；
   * 关闭增强分流均匀性。

**12.5 按分群均匀分流**

规则：

1. 用户选择一个或多个分群。
2. 系统在实验开始前确保这些分群在各版本中平均分布。
3. 分群可以来自用户分群系统或受众模板。
4. 若分群人数过少，系统提示：
   “当前分群人数较少，可能无法保证各版本均匀分布。”
5. 按分群模式下，也需要配置最大运行次数和 p-value 阈值。

**12.6 重随机状态**

实验创建后，在调试阶段展示重随机状态。

状态枚举：

type RerandomizationStatus =

| "NOT\_STARTED"

| "RUNNING"

| "SUCCESS"

| "FAILED"

| "CANCELED";

状态说明：

| **状态** | **页面展示** | **允许操作** |
| --- | --- | --- |
| NOT\_STARTED | 待调平 | 开始调平、编辑配置 |
| RUNNING | 调平中 | 查看进度、取消 |
| SUCCESS | 已满足条件 | 可开始实验 |
| FAILED | 未满足条件 | 修改配置、重新调平、关闭功能 |
| CANCELED | 已取消 | 重新调平 |

**13. 实验流量平滑生效**

**13.1 功能目标**

平滑生效用于控制实验流量在指定时间内线性增长或降低，避免新实验、扩量、暂停、停止时流量瞬间变化导致服务压力或策略风险。

**13.2 生效方式**

字段：流量生效方式。

选项：

1. 立即生效；
2. 平滑生效。

当选择平滑生效时，展示“平滑生效时间”。

字段规则：

| **字段** | **规则** |
| --- | --- |
| 平滑生效时间 | 1-1440 分钟 |
| 时间单位 | 分钟 |
| 是否必填 | 选择平滑生效时必填 |
| 默认值 | 30 分钟 |
| 最大值 | 1440 分钟 |

**13.3 新建实验平滑生效**

当实验流量设置为 30%，平滑生效时间设置为 30 分钟时：

1. 实验启动时实际生效流量为 0%。
2. 每分钟增加 1%。
3. 第 30 分钟达到 30%。
4. 达到目标流量后，状态变为“平滑生效完成”。

计算规则：

currentTraffic =

targetTraffic \* elapsedMinutes / smoothDurationMinutes;

如果计算结果超过目标流量，则取目标流量。

**13.4 实验扩量平滑生效**

场景：

当前实验流量为 20%，用户扩量到 50%，平滑时间为 30 分钟。

规则：

1. 起始流量为 20%。
2. 目标流量为 50%。
3. 需要增加 30%。
4. 每分钟增加 1%。
5. 第 30 分钟达到 50%。

计算规则：

currentTraffic =

startTraffic +

(targetTraffic - startTraffic) \* elapsedMinutes / smoothDurationMinutes;

**13.5 实验暂停平滑生效**

场景：

用户暂停实验时选择平滑生效。

规则：

1. 起始流量为当前实验流量。
2. 目标流量为 0%。
3. 在指定时间内线性降至 0%。
4. 降至 0% 后，实验状态变为“已暂停”。

**13.6 实验停止平滑生效**

场景：

用户停止实验时选择平滑生效。

规则：

1. 起始流量为当前实验流量。
2. 目标流量为 0%。
3. 在指定时间内线性降至 0%。
4. 降至 0% 后，实验状态变为“已停止”。
5. 停止后不可恢复。

**13.7 平滑生效进度展示**

实验详情页展示进度卡片。

字段：

| **字段** | **说明** |
| --- | --- |
| 生效类型 | 新建实验、扩量、暂停、停止 |
| 起始流量 | 平滑开始时流量 |
| 目标流量 | 平滑目标流量 |
| 当前流量 | 当前已生效流量 |
| 平滑时长 | 用户设置的分钟数 |
| 预计完成时间 | 根据开始时间和时长计算 |
| 当前进度 | 当前流量 / 目标流量 |
| 状态 | 进行中、已暂停、已完成、已回滚 |

**13.8 平滑生效按钮**

| **按钮** | **点击逻辑** |
| --- | --- |
| 暂停 | 暂停平滑放量过程，实验流量保持暂停时刻值 |
| 回滚 | 实验流量立刻回滚到 0% |
| 跳过 | 实验流量立刻变为目标值 |
| 刷新 | 重新获取最新进度 |
| 查看日志 | 打开流量变化日志 |

**13.9 平滑生效限制**

1. 平滑生效期间，不可修改生效方式。
2. 平滑生效期间，不可修改实验流量。
3. 平滑生效完成后，允许再次扩量。
4. 扩量时可再次选择平滑生效。
5. 平滑生效期间暂停实验后再恢复，重新开始平滑生效。
6. 平滑生效完成后暂停实验再恢复，立即生效。
7. 实验详情页的进度需要主动刷新或定时刷新。
8. 若用户关闭页面，平滑任务仍由后端继续执行。
9. 后端必须以任务状态为准，不能依赖前端计时。

**14. 提交前检查与预览页**

**14.1 页面目标**

**18. 验收标准**

**18.1 选择实验类型**

1. 用户可以看到所有实验类型。
2. 不可用实验类型置灰，并展示不可用原因。
3. 选择实验类型后可以进入下一步。
4. 切换实验类型时，后续配置会按确认结果清空。
5. 实验类型保存后，在草稿中可恢复。

**18.2 实验参数配置**

1. 用户可以新增、删除、复制实验版本。
2. 用户可以配置 Number、String、Boolean、Json 参数。
3. 参数 Key 唯一性校验正确。
4. Json 参数非法时无法提交。
5. 参数预览展示每个版本最终下发 JSON。
6. 按实验组硬编码式参数设计会出现提示。

**18.3 用户受众与分流模型**

1. 用户可以配置分流 ID。
2. 用户可以配置 AND/OR 受众规则。
3. 受众条件字段类型与输入组件匹配。
4. 点击预估受众可以返回预计用户数。
5. 未配置分流 ID 不允许提交调试。

**18.4 流量计算器**

1. 支持预计算指标和手动填写。
2. 支持人均值、留存、uv\_ctr、pv\_ctr。
3. 支持配置 MDE、版本数、power、alpha、过滤比例。
4. 可计算单组样本量和建议实验总流量。
5. 建议流量超过 100% 时不允许应用。
6. 应用成功后写入实验流量字段。

**18.5 流量层与互斥域**

1. 用户可以创建、编辑、删除流量层。
2. 已被实验使用的流量层不能删除。
3. 用户可以创建互斥域组。
4. 互斥域组下各互斥域比例合计必须为 100%。
5. 已绑定实验或流量层的互斥域不能删除。
6. 客户端实验只能选择客户端互斥域。
7. 服务端实验只能选择服务端互斥域。
8. 运行中实验不能移除互斥域。

**18.6 增强分流均匀性**

1. 开启后可选择按指标值或按分群。
2. 按指标值最多选择 3 个指标。
3. 支持配置最大运行次数和 p-value 阈值。
4. 调平成功前不能开始实验。
5. 调平失败后可以修改配置并重新调平。

**18.7 平滑生效**

1. 新建实验可以选择立即生效或平滑生效。
2. 平滑时间必须在 1-1440 分钟之间。
3. 平滑进度按线性规则变化。
4. 平滑过程中不能修改实验流量。
5. 支持暂停、回滚、跳过。
6. 扩量、暂停、停止实验时均可选择立即生效或平滑生效。

**20. 关键异常场景**

**20.1 流量不足**

触发条件：

* 用户设置实验流量大于可用流量。

处理：

1. 实验流量输入框标红。
2. 展示错误：“当前可用流量不足，请降低实验流量或选择其他流量层。”
3. 禁止进入下一步。
4. 禁止提交调试。

**20.2 互斥域冲突**

触发条件：

* 运行中实验尝试加入已有运行中实验的互斥域。

处理：

1. 下拉列表中该互斥域标记为不可选。
2. 展示原因：“该互斥域已有运行中实验。”
3. 用户可查看占用实验。
4. 不允许强制加入。

**20.3 版本流量比例不等于 100%**

处理：

1. 比例合计区域标红。
2. 展示当前合计值。
3. “下一步”禁用。
4. 点击“平均分配”可自动修复。

**20.4 JSON 参数非法**

处理：

1. JSON 输入框标红。
2. 展示解析错误行列。
3. 禁止进入下一步。
4. 支持点击“格式化”尝试修复格式。

**20.5 平滑生效任务失败**

触发条件：

* 后端任务执行异常；
* 流量更新失败；
* 实验状态变化冲突。

处理：

1. 进度卡片状态变为“失败”。
2. 展示失败原因。
3. 支持“重试”“回滚”“联系管理员”。
4. 写入操作日志。

**22. 非功能要求**

**22.1 性能要求**

1. 实验创建页面首屏加载时间不超过 2 秒。
2. 流量层列表查询响应不超过 1 秒。
3. 互斥域树加载不超过 2 秒。
4. 流量计算器计算响应不超过 3 秒。
5. 受众预估允许异步执行，超过 5 秒展示 loading 和取消按钮。
6. 重随机任务必须异步执行，前端轮询状态。

**22.2 安全要求**

1. 所有创建、修改、删除操作必须校验权限。
2. 参数 JSON 不允许注入脚本执行。
3. 前端展示参数时必须转义。
4. 操作日志不可被普通用户删除。
5. 实验配置变更必须保留历史版本。

**22.3 可用性要求**

1. 所有复杂字段旁边提供说明 tooltip。
2. 所有不可用按钮必须展示不可用原因。
3. 所有删除操作必须二次确认。
4. 页面离开时若有未保存内容，必须提醒。
5. 所有异步任务必须展示状态和失败原因。
