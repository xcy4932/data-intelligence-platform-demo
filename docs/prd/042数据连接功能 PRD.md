**2. 产品定位**

**2.1 功能定位**

数据连接是 CDP 数据接入层的统一入口。它不直接等同于“数据集”，而是负责建立 CDP 与外部数据源之间的连接关系，并根据不同连接类型完成以下动作：

1. 校验连接参数是否完整；
2. 测试外部数据源连通性；
3. 获取数据表、字段、Schema 或接口返回结构；
4. 生成数据预览；
5. 保存连接配置；
6. 根据连接类型决定是否自动生成数据集；
7. 对支持一键接入的连接器，自动创建可视化建模任务；
8. 将原始数据和结构化数据存储到指定引擎；
9. 向元数据、标签、分群、ID-Mapping、画像、广告分析等下游模块开放使用。

**2.2 核心原则**

| **原则** | **说明** |
| --- | --- |
| 统一入口 | 所有数据源统一通过「数据连接」创建、管理、测试、保存 |
| 分类配置 | 不同数据源有不同字段，但必须复用统一的创建流程、状态机和权限体系 |
| 先测试后保存 | 需要外部连通性的连接器，必须通过测试连接才能保存 |
| 保存不等于接入完成 | 普通数据库连接保存后只是建立连接；一键接入类连接保存后还需触发接入任务 |
| 数据连接不直接替代数据集 | 数据连接是源头，数据集是接入后可被分析和建模消费的数据资产 |
| 原始数据与结构化数据分层 | 三方平台、公共数据、一键接入类连接需要同时生成原始数据和结构化数据 |
| 权限优先 | 无项目编辑或新建连接权限，不允许创建数据连接 |
| 可追溯 | 每个连接、测试、保存、接入、自动建模、数据集生成都必须有操作记录和任务记录 |

**3. 适用范围与连接器分类**

**3.1 连接器总分类**

数据连接按技术形态分为以下大类：

| **一级分类** | **二级类型** | **示例** |
| --- | --- | --- |
| 关系型数据库 | JDBC 数据源 | MySQL、Oracle、SQL Server、PostgreSQL、IBM DB2、Access、达梦、OceanBase、OpenGauss |
| 大数据 / 数仓 | Hive / SQL 查询引擎 / MPP | Hive、Impala、Presto、StarRocks、Doris、Greenplum、Teradata、Vertica、Hologres、LAS、MaxCompute、Databricks、FusionInsight、星环 Inceptor |
| OLAP / 云数仓 | 高性能分析引擎 | ClickHouse、ByteHouse CE、ByteHouse CDW、AnalyticDB for MySQL 2.0、AnalyticDB for MySQL 3.0、Amazon Athena、Amazon Redshift |
| NoSQL / 列式数据库 | 非关系型数据源 | MongoDB、HBase、HBase Phoenix |
| 文件类 | 本地文件 / 文件服务器 | Excel、CSV、FTP |
| 对象存储 | 云存储文件 | 火山云 TOS、阿里云 OSS、腾讯云 COS |
| API | HTTP 接口 | REST API |
| 流式数据 | 消息队列 / CDC | Kafka、Pulsar、CDC MySQL |
| 行为数据 | 行为分析产品 | DataFinder、神策 |
| 营销广告平台 | 广告账户 / 监测日志 / 电商订单 | 巨量引擎 2.0、巨量千川、抖店、抖音来客订单、广告监测 |
| 私域触点 | 微信生态 | 微信公众号、企业微信、企业微信自建应用 |
| 内容与公共数据 | 内容、日历、星座等 | 内容平台、日历数据、星座数据 |

数据库类连接通常要求提前收集服务器 IP、端口、数据库名称、用户名和密码；用户需具备项目编辑或“按内容管理-模块-数据连接-新建连接”权限后，才可新建连接。

**3.2 是否支持一键接入**

| **连接器类型** | **是否支持一键接入** | **接入后动作** |
| --- | --- | --- |
| 普通数据库连接 | 否 | 保存连接后，供数据集、建模任务选择 |
| 文件上传 Excel / CSV | 部分支持 | 上传文件后生成结构化表 |
| FTP / 对象存储 | 部分支持 | 根据目录、格式、分区规则结构化文件 |
| REST API | 部分支持 | 根据接口返回结构生成数据表 |
| Kafka / Pulsar / CDC | 否，偏实时接入配置 | 保存实时源配置，供实时任务消费 |
| 巨量引擎 2.0 | 是 | 自动建模，生成原始 Hive 数据和结构化 ClickHouse 数据 |
| 巨量千川 | 是 | 自动建模，生成原始 Hive 数据和结构化 ClickHouse 数据 |
| 抖音来客订单 | 是 | 自动接入并生成原始数据集和结构化数据集 |
| 日历数据 | 是 | 自动创建可视化建模任务，输出日历数据集 |
| 星座数据 | 是 | 自动创建可视化建模任务，输出星座数据集 |
| 广告监测数据 | 自动生成数据集 | 测试并保存后自动生成数据集 |
| 内容平台 | 否，需授权和测试 | 保存连接后用于内容数据与行为数据关联 |
| DataFinder | 否，直连数据集 | 只支持数据集直连，默认在 CDP 单品部署关闭 |

保存后支持“一键接入”，系统会自动创建可视化建模并生成数据集，原始数据存为 Hive，结构化数据集存为 ClickHouse。点击“一键接入”后，系统会自动创建对应可视化建模任务，并输出公共数据集。

**22. 保存连接功能 PRD**

**22.1 保存前置校验**

点击保存时，系统按以下顺序校验：

1. 用户有保存权限；

7. 连接名称当前项目内唯一；

**30. 开发实现关键点**

数据连接模块不能按“每个连接器单独写页面”的方式开发，而应采用“连接器元数据驱动表单”的方式实现。

推荐架构：

Connector Registry

↓

Connector Schema

↓

Dynamic Form Renderer

↓

Test Connection Service

↓

Secret Manager

↓

Ingestion Job Engine

↓

Dataset Service

↓

Modeling Task Service

↓

Lineage Service

核心设计：

1. 连接器通过 Schema 描述字段；
2. 前端根据 Schema 动态渲染表单；
3. 后端根据 connectorType 路由到对应测试器；
4. 密钥统一进入 Secret Manager；
5. 一键接入统一进入 Ingestion Job Engine；
6. 数据集生成统一调用 Dataset Service；
7. 可视化建模任务统一调用 Modeling Task Service；
8. 所有生成资产写入血缘服务。

这样才能支持 30+ 连接器持续扩展，不会出现每新增一个连接器就重复开发一套页面的问题。
