**用户路径分析 PRD**

**1. 功能定位**

用户路径分析用于分析一组用户在产品中的行为序列分布，帮助业务理解：

用户从某个行为开始后，下一步去了哪里？

用户到达某个关键行为之前，通常经历了哪些行为？

用户在哪一步大量流失？

哪些未配置事件吸走了用户流量？

不同用户群、渠道、版本、属性分组下的路径结构是否不同？

某个页面或功能是否成为用户路径中的主要中转节点？

它不是漏斗分析。漏斗分析要求用户按配置步骤转化，重点是“是否完成指定流程”；用户路径分析重点是“真实行为流向是什么”。因此用户路径需要允许：

1. 只固定起点，向后展开真实路径。

2. 只固定终点，向前倒推真实路径。

3. 配置一组参与分析事件，但不要求用户必须按某个固定顺序完成。

4. 将未展示、未配置、流失等结果合并成特殊节点。

5. 用桑基图表达不同步骤之间的流量流转。

**3. 核心概念**

**3.1 用户路径**

用户路径是一组用户在产品中产生的行为序列的统计分布。

例如用户 A 的真实行为：

App 启动 → 浏览首页 → 搜索商品 → 浏览商品详情 → 加入购物车 → 支付成功

用户 B 的真实行为：

App 启动 → 浏览首页 → 点击活动页 → 浏览商品详情 → 退出

如果配置：

开始于：App 启动

路径步数：5

系统会统计从 App 启动开始的后续 5 步流向，并聚合成路径图。

**3.2 路径步骤**

路径步骤是路径图中的第 N 层。

例如：

第 0 步：起始事件

第 1 步：起始事件后的第一个行为

第 2 步：起始事件后的第二个行为

...

第 N 步：第 N 个行为

如果是“结束于”模式，则方向相反：

第 0 步：终止事件

第 -1 步：终止事件前一个行为

第 -2 步：终止事件前两个行为

...

前端展示时仍从左到右展示，但在“结束于”模式下，左侧是更早步骤，右侧是终止事件。

**3.3 参与分析事件**

参与分析事件是用户希望在路径图中识别和展示的事件集合。

分为三类：

1. 核心事件：开始于或结束于的事件。

2. 中间事件：用户手动添加的参与分析事件。

3. 特殊合并事件：流失、更多分组、未选中事件。

使用限制：

1. 除开始事件、终止事件外，中间参与分析事件最多 13 个。

2. 当前最多分析 10 步用户路径。

3. 每个路径步骤最多展示 10 个参与分析事件，超出后合并为“更多分组”。

4. SaaS 云原生默认最多支持历史 20 天路径数据。

5. SaaS 非云原生默认最多支持历史 30 天路径数据。

这些限制来自用户路径文档中的使用限制：中间事件最多 13 个、路径最多 10 步、每步最多展示 10 个节点，并且云原生与非云原生环境的历史查询范围不同。

**3.4 会话**

会话是用户连续活跃的一段行为序列。用户路径分析需要基于会话判断“一个路径是否还在继续”。

会话切割依赖会话间隔：

如果两个相邻事件之间的时间间隔 <= 会话间隔，则它们属于同一会话；

如果两个相邻事件之间的时间间隔 > 会话间隔，则后一个事件开启新会话；

用户路径文档中默认路径会话间隔为 10 分钟；会话管理文档中 Web 默认 30 分钟，App 和小程序默认从 app\_launch 到 app\_terminate 作为一次会话；自定义 Session 文档中也说明，Session 切割时间是两个事件之间可以接受的最长间隔，而不是 Session 的最大持续时长。

**4. 功能总流程**

用户完整使用流程：

1. 用户进入用户路径分析页面。

2. 选择路径方向：开始于 / 结束于。

3. 选择核心事件。

4. 可选：为核心事件配置过滤条件。

5. 添加参与分析的中间事件。

6. 可选：为每个参与分析事件配置过滤条件。

7. 配置是否同时计算未选中事件。

8. 配置会话间隔。

9. 配置是否合并连续重复路径。

10. 配置细分筛选。

11. 可选：配置属性分组。

12. 选择查询时间范围。

13. 选择路径步数。

14. 配置单级最大节点数和流量占比阈值。

15. 点击查询。

16. 系统生成路径图。

17. 用户点击节点或连线查看详情。

18. 用户可保存为用户分群、导出用户 ID、导出图片。

19. 用户可保存分析或保存到看板。

**5. 路径配置**

**5.1 路径方向：开始于 / 结束于**

**5.1.1 功能逻辑**

路径方向决定路径计算方式。

字段结构：

type PathDirection = "START\_FROM" | "END\_AT";

**5.1.2 开始于**

“开始于”用于分析某个事件之后用户去了哪里。

示例：

开始于：App 启动

分析：用户启动 App 后的后续路径

计算方向：

从核心事件发生时间向后找后续事件

路径序列：

核心事件 → 第 1 步 → 第 2 步 → 第 3 步

**5.1.3 结束于**

“结束于”用于分析某个事件之前用户经历了什么。

示例：

结束于：注册失败

分析：用户注册失败之前都做了什么

计算方向：

从核心事件发生时间向前找历史事件

路径序列：

第 -3 步 → 第 -2 步 → 第 -1 步 → 核心事件

**5.1.4 交互逻辑**

页面左上角提供切换控件：

开始于 / 结束于

切换规则：

1. 用户从“开始于”切换到“结束于”时，保留已选择的核心事件。

2. 清空当前图表结果。

3. 保留参与分析事件、筛选条件、会话间隔、合并重复路径配置。

4. 展示提示：“路径方向已切换，请重新查询。”

5. 如果当前配置未保存，页面进入未保存状态。

**5.2 核心事件配置**

**5.2.1 功能逻辑**

核心事件是路径分析的锚点。

字段结构：

type CoreEventConfig = {

eventName: string;

eventDisplayName: string;

filters?: FilterGroup;

};

核心事件在不同方向下含义不同：

| **路径方向** | **核心事件含义** |
| --- | --- |
| START\_FROM | 起始事件 |
| END\_AT | 终止事件 |

**5.2.2 事件选择交互**

点击事件选择框后打开事件选择器。

事件选择器支持：

1. 搜索事件中文名。

2. 搜索事件英文名。

3. 搜索事件描述。

4. 按事件分类筛选。

5. 展示最近使用事件。

6. 展示收藏事件。

7. 展示事件是否有权限。

选择事件后：

1. 事件名称回填到核心事件选择框。

2. 如果参与分析事件中没有该事件，系统自动将核心事件加入参与分析事件集合。

3. 如果参与分析事件中已有该事件，不重复添加。

4. 清空图表结果。

5. 页面进入未保存状态。

**5.2.3 核心事件过滤条件**

核心事件支持过滤条件。

示例：

App 启动 且 操作系统 = iOS

注册失败 且 失败原因 = 验证码错误

商品曝光 且 商品二级分类 = 手机

字段结构：

type FilterGroup = {

relation: "AND" | "OR";

conditions: Array<FilterCondition | FilterGroup>;

};

type FilterCondition = {

fieldType:

| "event\_property"

| "user\_property"

| "user\_tag"

| "cohort"

| "subject\_property";

fieldName: string;

operator:

| "eq"

| "neq"

| "in"

| "not\_in"

| "contains"

| "not\_contains"

| "gt"

| "gte"

| "lt"

| "lte"

| "between"

| "is\_null"

| "not\_null";

value: any;

};

过滤交互：

1. 点击核心事件右侧“过滤”图标。

2. 打开过滤条件浮层。

3. 默认新增一条空条件。

4. 用户选择字段、操作符、值。

5. 支持 AND / OR 切换。

6. 支持最多两层嵌套。

7. 点击确定后关闭浮层。

8. 未完整配置的过滤条件不允许保存，不允许查询。

**5.3 参与分析事件配置**

**5.3.1 功能逻辑**

参与分析事件决定路径图中哪些真实事件可以作为节点展示。

字段结构：

type PathEventConfig = {

id: string;

eventName: string;

eventDisplayName: string;

alias?: string;

filters?: FilterGroup;

isCoreEvent: boolean;

};

配置结构：

type PathEventListConfig = {

coreEvent: CoreEventConfig;

intermediateEvents: PathEventConfig[];

};

**5.3.2 添加事件**

点击：

+ 添加事件

交互逻辑：

1. 点击后打开事件选择器。

2. 用户选择一个事件。

3. 如果事件已经存在，则提示“该事件已添加”，不重复添加。

4. 如果中间事件数量已达到 13 个，则添加按钮置灰，并展示 tooltip：“最多支持添加 13 个中间事件。”

5. 添加成功后，事件出现在配置列表末尾。

6. 清空当前图表结果。

**5.3.3 删除事件**

每个中间事件右侧提供删除按钮。

删除逻辑：

1. 用户点击删除。

2. 如果删除的是核心事件，不允许删除，只能通过更换核心事件修改。

3. 如果删除的是中间事件，直接从 intermediateEvents 移除。

4. 同时删除该事件上的过滤条件和属性分组引用。

5. 清空当前图表结果。

**5.3.4 事件别名**

每个参与分析事件允许设置别名。

字段：

alias?: string;

规则：

1. 别名为空时，图表展示事件显示名。

2. 别名不为空时，图表、Tooltip、明细表、导出图片、看板组件均展示别名。

3. 别名最大 30 个字符。

4. 别名只影响展示，不影响计算。

**6. 分析范围配置**

**6.1 同时计算未选中事件**

**6.1.1 功能逻辑**

用户真实路径中可能包含大量未配置事件。如果不处理这些事件，用户可能被误判为流失。实际“流失”应该表示用户在会话窗口内没有任何后续行为，而不是仅仅没有发生已选择事件。用户路径文档也说明，“同时计算未选中事件”用于展示那些没有归到流失、但命中了未配置事件的用户比例。

字段：

includeUnselectedEvents: boolean;

默认：

false

**6.1.2 关闭时的计算**

如果关闭：

系统只把参与分析事件作为路径节点；

未选中事件不展示为节点；

如果在会话间隔内没有下一个参与分析事件，则该路径进入“流失”。

示例：

配置事件：A、B、C

真实路径：A → X → Y

includeUnselectedEvents = false

结果：

A → 流失

**6.1.3 开启时的计算**

如果开启：

系统仍优先展示已配置参与分析事件；

如果下一步真实事件不是参与分析事件，但在会话内发生，则进入“未选中事件”节点；

“未选中事件”节点只表示该步发生了非配置事件，不展示具体事件名；

如果后续又发生已配置事件，路径可以继续流转。

示例：

配置事件：A、B、C

真实路径：A → X → B

includeUnselectedEvents = true

结果：

A → 未选中事件 → B

**6.1.4 交互逻辑**

页面展示复选框：

同时计算未选中事件

Tooltip：

开启后，路径中发生了未配置事件但没有真正流失的用户，会被归入“未选中事件”，避免误判为流失。

切换规则：

1. 用户勾选或取消勾选后，清空当前图表结果。

2. 页面进入未保存状态。

3. 如果已查询过结果，展示提示：“配置已变更，请重新查询。”

**6.2 会话间隔**

**6.2.1 功能逻辑**

会话间隔用于判断路径是否还属于同一次访问。

字段结构：

type PathSessionConfig = {

intervalValue: number;

intervalUnit: "second" | "minute" | "hour";

};

默认：

{

"intervalValue": 10,

"intervalUnit": "minute"

}

**6.2.2 校验规则**

| **单位** | **最小值** | **最大值** |
| --- | --- | --- |
| second | 1 | 3600 |
| minute | 1 | 1440 |
| hour | 1 | 24 |

这些范围与自定义 Session 文档中的时间切割粒度约束保持一致：秒最大 3600、分钟最大 1440、小时最大 24。

**6.2.3 计算规则**

对同一主体的事件按时间升序排序。

如果路径方向为 START\_FROM：

从核心事件开始，向后寻找事件；

若当前事件与下一候选事件的时间差 <= 会话间隔，则下一事件属于同一路径；

若时间差 > 会话间隔，则当前路径结束，下一候选事件不再进入该路径；

如果路径方向为 END\_AT：

从核心事件开始，向前寻找事件；

若当前事件与上一候选事件的时间差 <= 会话间隔，则上一事件属于同一路径；

若时间差 > 会话间隔，则当前路径向前结束；

注意：

会话间隔不是会话最大时长。

只要相邻事件间隔持续小于等于会话间隔，会话可以持续很久。

**6.2.4 交互逻辑**

页面展示：

会话间隔： [数值输入框] [单位下拉框]

输入逻辑：

1. 用户输入非数字，输入框标红。

2. 用户输入小于最小值，提示“会话间隔不能小于 1”。

3. 用户输入超过当前单位最大值，提示“当前单位下最大值为 X”。

4. 修改后不自动查询。

5. 修改后清空结果，并提示重新查询。

**6.3 合并连续重复路径**

**6.3.1 功能逻辑**

合并连续重复路径用于简化路径，避免连续重复事件导致路径过长。

字段：

mergeConsecutiveDuplicateEvents: boolean;

默认：

false

**6.3.2 关闭时**

真实路径：

A → B → B → B → C

结果路径：

A → B → B → B → C

**6.3.3 开启时**

真实路径：

A → B → B → B → C

结果路径：

A → B → C

只合并连续重复事件，不合并非连续重复事件：

A → B → A → B

结果仍为：

A → B → A → B

**6.3.4 合并维度**

如果配置了属性分组，重复判断使用：

eventName + groupValue

示例：

商品曝光[手机] → 商品曝光[电脑]

不合并，因为分组值不同。

**6.3.5 交互逻辑**

页面展示复选框：

合并连续重复事件

Tooltip：

开启后，一个 Session 中连续重复出现的相同事件会被合并为一个节点，适合社交、内容浏览等高频重复行为场景。

切换后：

1. 清空当前图表结果。

2. 页面进入未保存状态。

3. 提示重新查询。

**7. 细分筛选**

**7.1 功能逻辑**

细分筛选用于圈定参与路径分析的目标用户或目标行为。

支持：

用户属性

用户标签

用户分群

事件属性

行为圈选

动态圈选

用户路径文档中举例，细分筛选可用于筛选核心用户、操作系统为 iOS/Android、软件版本 2.0 以上的用户。

字段结构：

type SegmentFilterConfig = {

relation: "AND" | "OR";

conditions: Array<FilterCondition | FilterGroup>;

};

**7.2 筛选应用范围**

细分筛选默认作用于“参与分析主体”，即先筛出用户，再对这些用户的事件序列做路径分析。

执行顺序：

1. 根据用户属性、标签、分群、行为圈选筛选主体集合。

2. 仅保留这些主体的事件日志。

3. 在事件日志中应用核心事件和参与分析事件过滤条件。

4. 生成路径。

如果筛选条件包含事件属性：

事件属性筛选只用于筛选满足行为条件的用户，不会自动过滤所有路径事件。

如需过滤某个路径节点事件，必须在该参与分析事件上配置事件过滤条件。

**7.3 交互逻辑**

点击：

+ 添加筛选条件

弹出筛选类型菜单：

属性过滤

用户分群

用户标签

行为圈选

动态圈选

每条筛选规则逻辑：

1. 用户选择字段来源。

2. 选择字段。

3. 选择操作符。

4. 输入或选择值。

5. 多条件默认 AND。

6. 支持切换 AND / OR。

7. 支持最多两层嵌套。

8. 未完成条件不允许查询。

**8. 属性分组**

**8.1 功能逻辑**

属性分组用于将某个事件按照属性值拆成多个路径节点。

示例：

起始事件：商品曝光

属性分组：商品二级分类

则路径图中的起始节点不再是单一的“商品曝光”，而是：

商品曝光\_手机

商品曝光\_电脑

商品曝光\_服饰

商品曝光\_美妆

用户路径文档中说明，属性分组会将事件按照某事件属性分组，每一个属性值都会作为一个参与分析事件进行计算。

**8.2 数据结构**

type PathGroupByConfig = {

enabled: boolean;

targetEventId: string;

fieldType: "event\_property" | "user\_property" | "user\_tag" | "subject\_property";

fieldName: string;

fieldDisplayName: string;

valueLimit: number;

includeOthers: boolean;

includeUnknown: boolean;

};

默认：

{

"enabled": false,

"valueLimit": 20,

"includeOthers": true,

"includeUnknown": true

}

**8.3 分组值控制**

由于属性值可能过多，系统必须提供控制逻辑。

规则：

1. 默认最多展示 Top 20 属性值。

2. Top 依据该属性值命中的路径人数降序计算。

3. 超出 Top N 的属性值合并为“其他属性值”。

4. 属性为空、null、空字符串时合并为“未知属性值”。

5. 用户可通过事件过滤条件减少属性值范围。

**8.4 交互逻辑**

点击：

+ 属性分组

交互步骤：

1. 用户先选择应用分组的事件。

2. 系统加载该事件可用属性。

3. 用户选择分组属性。

4. 用户设置最大属性值数量，默认 20。

5. 用户选择是否展示“其他属性值”。

6. 用户选择是否展示“未知属性值”。

7. 点击确定后，图表结果清空。

校验：

1. 必须先选择事件，才能选择属性。

2. 如果目标事件已被删除，则同步清空属性分组。

3. 如果属性无权限，则打开保存分析时置灰并提示。

**9. 时间范围与路径步数**

**9.1 查询时间范围**

**9.1.1 功能逻辑**

查询时间范围用于限定核心事件发生时间。

如果是 START\_FROM：

只选取在查询时间范围内发生的起始事件作为路径起点。

如果是 END\_AT：

只选取在查询时间范围内发生的终止事件作为路径终点。

后续路径事件或前序路径事件可以在会话间隔约束下超出查询结束时间或开始时间，但必须在系统允许的事件查询扩展范围内。

**9.1.2 默认范围**

最近 7 天

最大范围：

SaaS 云原生：最近 20 天

SaaS 非云原生：最近 30 天

私有化：由部署配置决定，默认 30 天

**9.2 路径步数**

**9.2.1 功能逻辑**

路径步数控制从核心事件向前或向后最多展开多少层。

字段：

pathStepCount: number;

默认：

5

最大：

10

**9.2.2 交互逻辑**

图表区域右上角提供：

路径步数：[-] [5] [+]

按钮逻辑：

1. 点击 +，pathStepCount + 1。

2. 如果当前值 = 10，+ 按钮置灰。

3. 点击 -，pathStepCount - 1。

4. 如果当前值 = 1，- 按钮置灰。

5. 修改步数后，如果已有 queryId，可直接基于同一查询条件重新请求图表数据。

6. 修改步数后页面进入未保存状态。

**10. 图表展示控制**

**10.1 单级最大节点数**

**10.1.1 功能逻辑**

单级最大节点数控制每个路径步骤最多展示多少个节点。

字段：

maxNodesPerStep: number;

默认：

10

范围：

1 到 20

文档限制为每步最多展示 10 个参与分析事件；产品实现可以 V1 固定 10，V2 再开放至 20。为了兼容文档，V1 最大值按 10 处理。

**10.1.2 节点裁剪规则**

对每一层 step：

1. 计算该层每个节点的 nodeUserCount。

2. 按 nodeUserCount 降序排序。

3. 保留前 maxNodesPerStep 个节点。

4. 超出的节点合并为“更多分组”。

5. “更多分组”的人数 = 被合并节点去重人数之和。

6. “更多分组”的出边 = 被合并节点出边按目标节点再次聚合。

注意：

如果同一用户在同一步只会落入一个节点，则人数可直接相加；

如果开启属性分组导致同一用户可能命中多个属性值，则合并时必须按 subjectId 去重。

**10.2 流量占比阈值**

**10.2.1 功能逻辑**

流量占比阈值用于隐藏占比过低的节点。

字段：

minTrafficRatio: number;

默认：

0

单位：

百分比

范围：

0 到 100

**10.2.2 计算规则**

对于每一层 step：

stepTotalUsers = 当前层所有节点去重用户数

nodeRatio = nodeUserCount / stepTotalUsers

如果：

nodeRatio < minTrafficRatio

则节点不单独展示，合并到：

更多分组

**10.2.3 优先级**

节点合并顺序：

1. 先应用流量占比阈值。

2. 再应用单级最大节点数。

3. 两类被合并节点统一进入“更多分组”。

**11. 路径计算逻辑**

**11.1 原始事件结构**

type RawEvent = {

eventId: string;

subjectId: string;

eventName: string;

eventDisplayName: string;

eventTime: string;

serverTime: string;

properties: Record<string, any>;

userProperties?: Record<string, any>;

};

排序字段：

serverTime ASC, eventTime ASC, eventId ASC

说明：

如果服务端接收时间和客户端事件时间都存在，默认以 serverTime 做稳定排序；

如果项目配置为客户端时间优先，则以 eventTime 做主排序；

同一时间戳下使用 eventId 保证排序稳定。

用户路径文档中提醒，当前划分时间是按照服务端接收日志时间划分 Session，SDK 批量上报会导致秒级间隔有误差，因此建议使用分钟级间隔。

**11.2 查询事件集合**

系统需要查询：

1. 核心事件。

2. 参与分析事件。

3. 如果 includeUnselectedEvents = true，还需要查询同一主体在窗口内的所有事件。

4. 如果 includeUnselectedEvents = false，仍需要查询用于判断真实流失的事件，但不展示未选中事件。

为了避免误判流失，后端必须知道会话间隔内是否存在任何事件。否则：

A 后面发生了 X，但 X 未被选择；

系统如果没有查询 X，就会把 A → X 误判为 A → 流失。

因此计算引擎内部事件集合分为两层：

type EventQueryScope = {

displayEvents: string[]; // 核心事件 + 参与分析事件

allEventsForSession: boolean; // 用于判断会话是否仍有行为

};

规则：

allEventsForSession 必须为 true。

includeUnselectedEvents 只决定未选中事件是否展示为节点，不决定是否查询未选中事件。

**11.3 START\_FROM 路径生成**

**11.3.1 输入**

type BuildForwardPathInput = {

subjectId: string;

sortedEvents: RawEvent[];

coreEvent: CoreEventConfig;

displayEventSet: Set<string>;

includeUnselectedEvents: boolean;

sessionIntervalMs: number;

pathStepCount: number;

mergeConsecutiveDuplicateEvents: boolean;

};

**11.3.2 算法**

对每个用户的事件按时间升序排序；

遍历事件列表；

当事件匹配核心事件时，尝试生成一条路径；

路径第 0 个节点为核心事件；

继续向后扫描事件；

如果下一事件与当前路径最后一个真实事件时间差 > 会话间隔，则路径结束；

如果下一事件命中 displayEventSet，则加入路径；

如果下一事件未命中 displayEventSet：

如果 includeUnselectedEvents = true，则加入“未选中事件”节点；

如果 includeUnselectedEvents = false，则不加入展示路径，但更新当前真实事件时间，用于继续判断会话；

如果达到 pathStepCount，则路径结束；

如果会话内没有任何后续事件，则补充“流失”节点；

如果一个会话内再次出现核心事件，不再生成新的路径起点。

**11.3.3 关键规则：同一会话内核心事件不重复作为起点**

示例：

真实路径：A1 → B → C → A2 → D

核心事件：A

如果 A1 已经作为当前会话的起点，则 A2 不再作为新的起点。用户路径文档中的计算逻辑也说明，一个会话内出现两次 A 事件时，第二次 A 不会再作为起始事件。

实现方式：

const usedCoreEventIdsInSession = new Set<string>();

更准确的方式是：

一旦某个核心事件生成路径，直到该路径会话结束前，后续核心事件不再生成新路径。

**11.4 END\_AT 路径生成**

**11.4.1 输入**

type BuildBackwardPathInput = {

subjectId: string;

sortedEvents: RawEvent[];

coreEvent: CoreEventConfig;

displayEventSet: Set<string>;

includeUnselectedEvents: boolean;

sessionIntervalMs: number;

pathStepCount: number;

mergeConsecutiveDuplicateEvents: boolean;

};

**11.4.2 算法**

对每个用户的事件按时间升序排序；

遍历事件列表；

当事件匹配核心事件时，尝试生成一条反向路径；

路径最后一个节点为核心事件；

继续向前扫描事件；

如果当前路径最早真实事件与上一事件时间差 > 会话间隔，则路径向前结束；

如果上一事件命中 displayEventSet，则加入路径头部；

如果上一事件未命中 displayEventSet：

如果 includeUnselectedEvents = true，则在路径头部加入“未选中事件”节点；

如果 includeUnselectedEvents = false，则不加入展示路径，但更新当前真实事件时间；

如果达到 pathStepCount，则路径结束；

如果会话内没有任何前序事件，则补充“起点未知”或“不再展示前序”节点。

**11.4.3 END\_AT 特殊节点**

END\_AT 不使用“流失”表示前序缺失，因为流失是向后路径中的概念。

END\_AT 的前序缺失节点命名为：

无前序事件

规则：

如果终止事件之前，在会话间隔内没有任何事件，则前一层展示“无前序事件”。

**11.5 未选中事件处理**

内部节点结构：

type PathNodeType =

| "EVENT"

| "UNSELECTED\_EVENT"

| "DROP\_OFF"

| "MORE\_GROUP"

| "NO\_PREVIOUS\_EVENT"

| "UNKNOWN\_GROUP\_VALUE";

未选中事件节点：

const UNSELECTED\_EVENT\_NODE = {

nodeType: "UNSELECTED\_EVENT",

nodeKey: "\_\_UNSELECTED\_\_",

nodeLabel: "未选中事件"

};

合并规则：

1. 同一步中所有未选中事件统一合并为一个“未选中事件”节点。

2. “未选中事件”不展示具体事件名。

3. 点击“未选中事件”节点时，可以在详情中查看 Top 未选中事件列表。

4. 如果用户没有事件明细权限，只展示人数和占比，不展示具体未选中事件名称。

**11.6 流失节点处理**

流失节点只用于 START\_FROM。

定义：

从当前节点之后，在会话间隔内没有任何后续事件，则进入流失。

注意：

如果后续有未选中事件，即使 includeUnselectedEvents = false，也不应算流失；

只有会话间隔内没有任何事件，才算流失。

流失节点结构：

const DROP\_OFF\_NODE = {

nodeType: "DROP\_OFF",

nodeKey: "\_\_DROP\_OFF\_\_",

nodeLabel: "流失"

};

**11.7 更多分组节点处理**

更多分组来自两类合并：

1. 超出单级最大节点数。

2. 低于流量占比阈值。

结构：

const MORE\_GROUP\_NODE = {

nodeType: "MORE\_GROUP",

nodeKey: "\_\_MORE\_GROUP\_\_",

nodeLabel: "更多分组"

};

点击“更多分组”节点时：

1. 打开节点详情抽屉。

2. 展示被合并的原始节点列表。

3. 列表字段：事件名、人数、占比、进入人数、流出人数。

4. 支持在抽屉中选择某个节点“提升展示”。

提升展示逻辑：

1. 用户点击“提升展示”。

2. 系统将该节点加入 pinnedNodes。

3. 重新计算图表。

4. 即使该节点低于阈值或超出 Top N，也强制展示。

数据结构：

pinnedNodes: Array<{

stepIndex: number;

nodeKey: string;

}>;

**21. 权限设计**

权限点：

| **权限** | **说明** |
| --- | --- |
| user\_path:view | 查看用户路径页面 |
| user\_path:query | 执行路径查询 |
| user\_path:save | 保存分析 |
| user\_path:dashboard | 保存到看板 |
| user\_path:export\_image | 导出图片 |
| user\_path:user\_detail | 查看用户列表 |
| user\_path:user\_export | 导出用户 ID |
| user\_path:path\_sample | 查看路径样本 |
| cohort:create | 保存为用户分群 |

权限拦截：

1. 没有 user\_path:view：不可进入页面。

2. 没有事件权限：事件选择器不展示该事件。

3. 没有属性权限：属性选择器不展示该属性。

4. 没有 user\_detail：隐藏查看用户列表。

5. 没有 user\_export：隐藏导出用户 ID。

6. 没有 cohort:create：隐藏保存为用户分群。

7. 打开保存分析时，如果部分事件或属性无权限，对应字段置灰并提示。

**22. 异常状态**

**22.1 未选择核心事件**

请选择起始事件或终止事件

**22.2 中间事件超过上限**

最多支持添加 13 个中间事件

**22.3 路径步数超过上限**

最多支持分析 10 步用户路径

**22.4 时间范围超过上限**

当前环境最多支持分析最近 20 天的用户路径数据

如果是非云原生：

当前环境最多支持分析最近 30 天的用户路径数据

**22.5 无数据**

当前条件下暂无用户路径数据

可能原因：

1. 核心事件在当前时间范围内无人触发。

2. 核心事件过滤条件过窄。

3. 细分筛选后用户范围为空。

4. 会话间隔过短，路径被切断。

5. 参与分析事件过少，且未开启同时计算未选中事件。

**22.6 秒级会话间隔风险提示**

当用户选择秒级间隔时，提示：

当前系统可能按服务端接收时间划分路径，SDK 批量上报可能导致秒级间隔存在误差，建议使用分钟级间隔。

**23. 验收标准**

**23.1 配置验收**

| **编号** | **验收项** | **通过标准** |
| --- | --- | --- |
| P-001 | 路径方向 | 支持开始于和结束于切换 |
| P-002 | 核心事件 | 可选择事件、配置过滤条件 |
| P-003 | 中间事件 | 可添加、删除、配置过滤，最多 13 个 |
| P-004 | 未选中事件 | 可开启/关闭，并影响结果节点 |
| P-005 | 会话间隔 | 支持秒、分、小时，校验上下限 |
| P-006 | 合并重复事件 | 开启后连续重复事件合并 |
| P-007 | 细分筛选 | 支持属性、分群、标签、行为圈选 |

| P-011 | 流量占比 | 支持隐藏低占比节点并合并更多分组 |

**23.2 计算验收**

| **编号** | **验收项** | **通过标准** |
| --- | --- | --- |
| C-001 | START\_FROM | 从起始事件向后生成路径 |
| C-002 | END\_AT | 从终止事件向前生成路径 |
| C-003 | 会话切割 | 相邻事件间隔超过会话间隔则切断 |
| C-004 | 非最大时长 | 连续小于会话间隔时，会话可持续超过间隔值 |
| C-005 | 同会话核心事件 | 同一会话内第二个核心事件不再作为新起点 |
| C-006 | 未选中事件 | 开启后非配置事件进入未选中事件节点 |
| C-007 | 流失 | 只有会话间隔内无任何后续事件才算流失 |
| C-008 | 更多分组 | 超出节点数或低于阈值的节点合并 |
| C-009 | 合并重复 | 只合并连续重复，不合并非连续重复 |
| C-010 | 属性分组 | 按属性值拆节点，空值进入未知 |
| C-011 | 节点人数 | 按 stepIndex + nodeKey 去重统计主体数 |
| C-012 | 连线人数 | 按 source + target 去重统计主体数 |
