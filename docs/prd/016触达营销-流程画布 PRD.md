**营销触达-流程画布 PRD**

**1. 产品定位与功能边界**

**1.1 产品目标**

流程画布用于让运营人员通过“触发器 + 原子节点”的方式，配置多步骤、分支化、可持续流转的营销触达流程。它解决单一消息触达任务只能完成一次性或单链路触达的问题，使用户可以根据分群、行为、延时、A/B 实验、赛马实验、多通道触达、触达结果等条件，自动进入不同运营路径。

流程画布需要支持以下核心能力：

1. 创建定时型或触发型流程；
2. 配置用户进入流程的条件；
3. 在画布中拖拽或添加判断、流程、触达类原子节点；
4. 支持用户在不同节点之间按规则流转；
5. 支持节点级触达、频控、勿扰、黑白名单、非交易日、主体转换；
6. 支持流程级基础信息、互斥、任务优先级、外部系统同步；
7. 支持流程级和节点级关注指标；
8. 支持提交审批、审批通过后执行；
9. 支持运行后查看整体表现和分步表现；
10. 支持对每一个节点查看进入量、预备发送量、发送量、送达量和关注指标数据。

**1.2 功能范围**

本 PRD 覆盖以下页面与功能：

| **模块** | **功能范围** |
| --- | --- |
| 流程画布列表 | 查询、筛选、新增、查看、编辑、复制、删除、提交审批、暂停、重启、取消、数据分析 |
| 新建流程画布 | 空白画布创建、模板创建、触发器配置、画布设计、基础信息、关注指标、提交审批 |
| 触发器 | 定时型-单次、定时型-重复、触发型-完成 A、触发型-完成 A 未完成 B |
| 原子节点 | 分群判断、事件判断、延时、A/B 分流、A/B 赛马、分群分流、事件分流、各类触达节点 |
| 触达节点 | 短信、Webhook、服务号模板消息、公众号活跃消息、公众号群发消息、小程序订阅消息、Telegram、WhatsApp 等 |
| 审批 | 提交审批、选择审批人、我的申请、我的审批、审批通过、审批驳回 |
| 效果评估 | 整体表现、分步表现、节点配置详情、节点指标数据 |

**1.3 不在本 PRD 中展开的功能**

以下能力作为流程画布依赖能力使用，但不展开后台配置细节：

1. CDP / DataFinder 分群创建器；
2. 通道管理，例如短信通道、Webhook 通道、微信公众号通道、Telegram 通道、WhatsApp 通道配置；
3. 内容中心模板管理；
4. 审批流管理后台；
5. 开放平台业务集成配置；
6. 频控、配额、企业日历的后台配置页。

**2. 角色、权限与访问控制**

**2.1 用户角色**

| **角色** | **能力** |
| --- | --- |
| 普通运营人员 | 查看有权限的流程画布、创建流程画布、保存草稿、提交审批、查看数据分析 |
| 流程创建人 | 编辑本人草稿、查看审批状态、查看驳回原因、复制任务、查看任务效果 |
| 审批人 | 查看待审批任务、审批通过、审批驳回 |
| 项目管理员 | 管理项目内流程画布、分组、权限、部分配置 |
| 集团管理员 | 具备跨项目或集团级管理能力 |

**2.2 GMP 权限**

用户进入流程画布页面前，系统需要校验：

permission.flow\_canvas.view === true

新增流程画布时校验：

permission.flow\_canvas.create === true

编辑流程画布时校验：

permission.flow\_canvas.edit === true

删除流程画布时校验：

permission.flow\_canvas.delete === true

查看数据分析时校验：

permission.flow\_canvas.analysis === true

提交审批时校验：

permission.flow\_canvas.submit\_approval === true

审批时校验：

permission.flow\_canvas.approve === true

**2.3 分群权限**

流程画布中涉及分群能力时，系统按项目购买情况判断。

**2.3.1 已购买 VeCDP**

可使用：

1. 标签与行为圈选；
2. 已有分群；
3. 分群预估；
4. 分群同步到 CDP 列表；
5. 分群授权。

需要校验：

permission.vecdp.segment.view === true

permission.vecdp.segment.create\_or\_edit === true

**2.3.2 未购买 VeCDP，但购买 DataFinder**

可使用：

1. 已有分群；
2. 在已有分群入口新建 DataFinder 分群；
3. 分群预估。

需要校验：

permission.datafinder.segment.view === true

**2.3.3 未购买 VeCDP 和 DataFinder**

1. 不展示标签与行为圈选能力；
2. 不展示已有分群能力；
3. 如项目完成了技术接口对接，可按对接能力展示外部分群或自定义受众入口；
4. 未完成接口对接时，流程画布创建入口不可用，提示：当前项目未完成流程画布受众接口对接，请联系管理员或实施人员。

**2.4 通道权限**

在流程画布触达节点中，用户只能选择自己有权限的通道。

| **通道** | **权限标识** |
| --- | --- |
| 短信 | permission.channel.sms.view |
| Webhook | permission.channel.webhook.view |
| 微信公众号 | permission.channel.wechat\_official\_account.view |
| 微信小程序 | permission.channel.wechat\_mini\_program.view |
| Telegram | permission.channel.telegram.view |
| WhatsApp | permission.channel.whatsapp.view |

无权限时：

1. 节点选择面板中不展示该触达节点；
2. 如果历史任务中已使用该节点，查看时可展示但不可编辑；
3. 编辑历史任务时，该节点展示无权限标识，保存或提交审批前必须替换为有权限节点，否则禁止提交。

**4. 流程画布列表页**

**4.1 页面入口**

路径：

左侧导航-智能运营-营销触达-流程画布

页面打开时：

1. 校验流程画布查看权限；
2. 加载当前项目下流程画布列表；
3. 默认按创建时间倒序展示；
4. 默认展示全部状态。

**4.2 页面结构**

页面由以下区域组成：

1. 顶部操作区；
2. 筛选区；
3. 状态统计区；
4. 流程画布列表；
5. 分页区。

**4.3 顶部操作区**

**4.3.1 「新增流程画布」按钮**

展示条件：

permission.flow\_canvas.create === true

点击后：

1. 打开创建方式选择弹窗；
2. 用户可选择“空白画布”或“使用模板”；
3. 选择后进入流程画布编辑页。

按钮状态：

| **状态** | **逻辑** |
| --- | --- |
| 可点击 | 有创建权限，且项目已完成必要配置 |
| 置灰 | 无创建权限或项目未完成流程画布接口对接 |
| 隐藏 | 菜单级权限不可见 |

**4.3.2 「我的申请」入口**

点击后：

1. 打开当前用户提交的全部审批申请；
2. 支持查看申请状态；
3. 点击任务名称进入流程画布详情；
4. 若审批被驳回，可查看驳回原因。

**4.3.3 「我的审批」入口**

点击后：

1. 打开待当前用户审批的流程画布任务；
2. 待审批数量每 5 分钟刷新一次；
3. 点击「审批」查看审批详情；
4. 支持审批通过或驳回。

**4.4 筛选区**

筛选字段：

| **字段** | **控件** | **逻辑** |
| --- | --- | --- |
| 流程名称 | Input | 支持模糊搜索 |
| 任务类型 | Select | 普通活动、紧急活动、通知活动 |
| 触发类型 | Select | 定时单次、定时重复、完成 A、完成 A 未完成 B |
| 关联活动 | Select | 按活动筛选 |
| 创建人 | Select / Input | 按创建人筛选 |
| 审批状态 | Select | 未提交、审批中、审批通过、审批驳回 |
| 任务状态 | Select | 草稿、等待执行、运行中、已暂停、已取消、已结束、异常 |
| 创建时间 | DateRangePicker | 按创建时间筛选 |

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 查询 | 按当前筛选条件刷新列表 |
| 重置 | 清空所有筛选条件，恢复默认查询 |
| 展开 / 收起 | 展开高级筛选条件 |
| 刷新 | 保留筛选条件重新加载列表 |

查询规则：

1. 多条件之间为 AND；
2. 空值字段不参与查询；
3. 流程名称前后空格 trim 后再查询；
4. 点击查询后分页回到第一页。

**4.5 状态统计区**

展示当前筛选条件下各状态数量：

| **状态** | **含义** |
| --- | --- |
| 全部 | 当前筛选条件下全部流程画布 |
| 草稿 | 未提交审批的流程 |
| 审批中 | 已提交但未审批完成 |
| 审批驳回 | 审批被驳回 |
| 等待执行 | 审批通过但未到执行时间 |
| 运行中 | 正在执行或监听事件 |
| 已暂停 | 人工暂停 |
| 已取消 | 人工取消或审批超时取消 |
| 已结束 | 到达结束时间或流程完成 |
| 异常 | 执行异常 |

点击状态卡片后：

1. 自动带入任务状态筛选；
2. 再次点击同一状态取消筛选；
3. 任务列表和统计区同步刷新。

**4.6 列表字段**

| **字段** | **说明** |
| --- | --- |
| 流程 ID | 系统生成唯一 ID |
| 流程名称 | 点击进入查看页 |
| 触发类型 | 定时单次 / 定时重复 / 完成 A / 完成 A 未完成 B |
| 任务类型 | 普通活动 / 紧急活动 / 通知活动 |
| 关联活动 | 展示活动名称 |
| 进入量 | 成功进入流程的用户数或人次 |
| 发送量 | 流程中所有触达节点发送量合计 |
| 送达量 | 流程中所有触达节点送达量合计 |
| 创建人 | 创建人姓名 |
| 创建时间 | 创建时间 |
| 审批状态 | 当前审批状态 |
| 任务状态 | 当前运行状态 |
| 操作 | 按状态展示可用操作 |

**4.7 列表操作**

**4.7.1 查看**

所有状态均可查看。

点击后：

1. 进入流程画布只读页；
2. 展示触发器、节点、连线、基础信息、关注指标；
3. 所有表单禁用；
4. 可点击节点查看配置详情；
5. 可点击「返回」回到列表。

**4.7.2 编辑**

仅以下状态允许编辑：

1. 草稿；
2. 审批驳回。

点击后：

1. 进入流程画布编辑页；
2. 回填所有配置；
3. 用户可修改触发器、节点、基础信息、关注指标；
4. 修改后可保存草稿或重新提交审批。

运行中、已暂停、已取消、已结束、异常流程不允许直接编辑。

**4.7.3 复制**

点击后：

1. 创建一个新的草稿流程；
2. 新流程名称默认为：原流程名称-副本；
3. 复制触发器配置、节点配置、连线配置、基础信息、关注指标；
4. 不复制审批记录；
5. 不复制执行数据；
6. 不复制运行状态；
7. 若原流程中的通道、模板、分群、指标已失效，则进入编辑页时标红提示用户重新配置。

**4.7.4 删除**

仅草稿状态可删除。

点击后弹出确认框：

确认删除该流程画布吗？删除后不可恢复。

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 取消 | 关闭弹窗 |
| 确认删除 | 删除草稿并刷新列表 |

**4.7.5 提交审批**

草稿和审批驳回状态可提交审批。

点击后：

1. 执行全量校验；
2. 校验通过后打开审批确认弹窗；
3. 用户确认审批人后提交；
4. 状态变为审批中。

**4.7.6 催审**

审批中且当前用户为提交人时展示。

点击后：

1. 向当前审批节点审批人发送催审通知；
2. 同一流程同一审批节点 5 分钟内只能催审一次；
3. 成功后提示：催审已发送。

**4.7.7 审批**

审批中且当前用户为审批人时展示。

点击后：

1. 打开审批详情；
2. 展示流程基本信息、触发器摘要、节点摘要、审批流；
3. 支持通过或驳回。

**4.7.8 暂停**

仅运行中流程可暂停。

点击后：

1. 弹出确认框；
2. 用户确认后状态变为已暂停；
3. 定时型流程停止后续周期调度；
4. 触发型流程停止监听新事件；
5. 已进入流程实例但停留在延时节点的用户暂停继续流转；
6. 已进入通道发送队列的消息不保证撤回。

**4.7.9 重启**

仅已暂停流程可重启。

点击后：

1. 状态变为运行中；
2. 定时重复流程从下一个有效周期继续执行；
3. 触发型流程重新监听新事件；
4. 暂停期间错过的事件默认不补偿；
5. 已在延时节点等待的用户继续按剩余时间流转。

**4.7.10 取消**

运行中、已暂停、等待执行状态可取消。

点击后：

1. 弹出确认框；
2. 用户确认后状态变为已取消；
3. 后续不再触发新流程实例；
4. 已在流程中的实例停止继续流转；
5. 已产生的数据保留；
6. 已进入通道发送队列的消息不保证撤回。

**4.7.11 数据分析**

以下状态可查看数据分析：

1. 运行中；
2. 已暂停；
3. 已取消；
4. 已结束；
5. 异常。

点击后进入流程画布效果评估页。

**5. 新建流程画布入口**

**5.1 创建方式选择弹窗**

点击「新增流程画布」后展示弹窗。

弹窗标题：

新建流程画布

创建方式：

| **方式** | **说明** |
| --- | --- |
| 空白画布 | 创建一个无节点的流程画布，需要用户从触发器开始配置 |
| 使用模板 | 从模板创建，系统带入模板中的触发器、节点和连线配置 |

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 取消 | 关闭弹窗 |
| 下一步 | 根据选择进入编辑页 |

**5.2 空白画布创建**

用户选择空白画布后：

1. 系统创建本地临时草稿；
2. 进入流程画布编辑页；
3. 默认展示触发器选择面板；
4. 画布区域为空；
5. 未保存前不生成正式任务 ID；
6. 点击保存草稿后生成正式任务 ID。

**5.3 模板创建**

用户选择模板后：

1. 展示模板列表；
2. 模板列表支持搜索模板名称；
3. 用户选择模板后点击「使用模板」；
4. 系统复制模板配置到新流程；
5. 新流程状态为未保存草稿；
6. 需要用户检查并重新保存或提交审批。

模板复制规则：

1. 复制节点和连线；
2. 复制触发器类型和配置；
3. 复制基础信息中的任务类型和勿扰配置；
4. 不复制原任务名称；
5. 不复制审批记录；
6. 不复制运行数据；
7. 若模板引用的通道、分群、指标已失效，进入编辑页后对应字段标红提示。

**6. 流程画布编辑页整体结构**

**6.1 页面布局**

编辑页由以下区域组成：

1. 顶部工具栏；
2. 左侧步骤区；
3. 中间画布区；

**7. Step 1：触发器配置**

触发器决定什么时间、哪些用户可以进入流程。系统支持四种触发方式：

1. 定时型-单次；
2. 定时型-重复；
3. 触发型-完成 A；
4. 触发型-完成 A 未完成 B。

**7.1 触发器选择**

用户进入空白画布后，首先展示触发器选择卡片。

每张卡片包含：

| **元素** | **内容** |
| --- | --- |
| 类型名称 | 定时型-单次等 |
| 类型说明 | 简要说明使用场景 |
| 示例 | 例如每日 10 点进入流程 |
| 选择按钮 | 点击后进入配置 |

用户选择一种触发器后：

1. 打开触发器配置抽屉；
2. 保存后在画布起点生成触发器节点；
3. 后续所有节点从触发器节点向下流转。

切换触发器类型时：

1. 若画布已有节点，弹出确认；
2. 文案：切换触发器类型可能导致部分节点配置失效，是否继续？
3. 确认后保留画布节点，但清空与触发器强相关的配置；
4. 取消则保持原触发器。

**7.2 定时型-单次**

**7.2.1 使用场景**

用于创建一次性执行流程。到达指定时间后，满足受众条件的用户进入流程。

**7.2.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 任务开始时间 | DateTimePicker | 是 | 固定时间点，用户在该时间进入流程 |
| 任务结束时间 | DateTimePicker | 是 | 到达后流程状态变为已结束，所有流转逻辑不再执行 |
| 审批超时策略 | Radio | 是 | 到达触发时间时仍未审批通过的处理方式 |
| 受众用户 | SegmentSelector | 是 | 选择进入流程的用户范围 |
| 执行前刷新分群 | Checkbox | 条件展示 | 执行前是否刷新按需分群 |
| 刷新分群失败策略 | Radio | 条件展示 | 刷新失败后是否继续执行 |

**7.2.3 任务开始时间**

校验规则：

1. 必须晚于当前时间；
2. 必须早于任务结束时间；
3. 保存草稿时允许不填；
4. 提交审批时必填；
5. 审批通过时若开始时间已过，按审批超时策略处理。

**7.2.4 任务结束时间**

规则：

1. 必须晚于任务开始时间；
2. 到达结束时间后，流程状态变为已结束；
3. 已进入流程但尚未完成流转的实例停止继续流转；
4. 后续延时节点、事件判断、触达节点均不再执行。

**7.2.5 审批超时策略**

可选项：

| **选项** | **逻辑** |
| --- | --- |
| 取消该任务 | 到达开始时间仍未审批通过时，任务自动取消 |
| 审批通过后立即执行 | 若开始时间已过但仍在 72 小时内，审批通过后立即执行 |

补充规则：

1. 即使选择审批通过后立即执行，若 72 小时内未审批完成，任务仍自动取消；
2. 自动取消后状态变为已取消；
3. 执行记录中记录原因：审批超时取消。

**7.3 定时型-重复**

**7.3.1 使用场景**

用于创建周期性执行流程。例如 3 月内每日 10 点，或 4 月内每周五 16 点。

**7.3.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 任务循环周期 | RepeatPicker | 是 | 定义每次进入流程的周期 |
| 任务结束时间 | DateTimePicker | 是 | 到达后流程结束 |
| 受众用户 | SegmentSelector | 是 | 每个周期进入流程的用户范围 |
| 进入频率限制 | FrequencyRule | 否 | 限制单个用户进入流程频次 |
| 审批超时策略 | Radio | 是 | 同定时型-单次 |
| 执行前刷新分群 | Checkbox | 条件展示 | 周期执行前刷新分群 |
| 刷新分群失败策略 | Radio | 条件展示 | 刷新失败处理 |

**7.3.3 任务循环周期**

支持配置：

1. 每日固定时间；
2. 每周指定星期几和时间；
3. 每月指定日期和时间；
4. 指定起止日期内重复执行。

校验规则：

1. 循环周期必须至少生成一个未来执行时间点；
2. 循环周期生成的执行时间不得晚于任务结束时间；
3. 如果循环周期无有效执行点，禁止提交。

**7.3.4 进入频率限制**

用于避免用户多次进入同一个流程。

配置项：

| **字段** | **说明** |
| --- | --- |
| 是否开启 | 开启后限制用户进入流程频次 |
| 时间窗口 | 例如每天、每 7 天、整个任务周期 |
| 次数限制 | 一个用户在窗口内最多进入 N 次 |

计数规则：

1. 只要用户成功进入流程，就扣减进入频控额度；
2. 是否后续触达成功不影响进入频控计数；
3. 仅对当前流程画布生效；
4. 不影响其他流程画布或消息触达任务。

执行逻辑：

当用户满足定时周期受众条件时：

判断该用户是否达到当前流程进入频率限制

若达到限制：不进入流程，记录过滤原因

若未达到限制：进入流程，进入次数 +1

**7.4 触发型-完成 A**

**7.4.1 使用场景**

用户完成某个行为后进入流程。例如用户收藏、点赞、转发后进入积分提醒流程。

**7.4.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 事件描述 | Input | 是 | 仅用于预览和查看，不影响触达 |
| 事件 A 起止时间 | DateTimeRangePicker | 是 | 该时间段内发生的 A 事件可触发流程 |
| 触发事件 | EventSelector | 是 | 用户完成该事件后触发 |
| 完成次数规则 | Radio + Number | 是 | 累计完成 A / 每完成 A / 分别做过 |
| 受众用户 | SegmentSelector | 是 | 完成事件后还需满足受众过滤 |
| 任务结束时间 | DateTimePicker | 是 | 到达后流程结束 |
| 进入频率限制 | FrequencyRule | 否 | 限制单个用户进入频次 |

**7.4.3 事件描述**

规则：

1. 必填；
2. 仅用于画布预览、查看视图、审批摘要；
3. 不参与事件判断；
4. 修改事件描述不会影响流程执行逻辑。

**7.4.4 事件 A 起止时间**

规则：

1. 起始时间必须早于结束时间；
2. 只有在该时间段内发生的 A 事件才会触发流程；
3. 超出时间范围的事件不进入流程；
4. 到达任务结束时间后，即使仍在事件 A 起止时间内，也不再执行。

**7.4.5 触发事件**

配置方式：

1. 选择数据源；
2. 选择事件；
3. 可添加事件属性筛选条件；
4. 用户完成事件后，还需满足受众用户条件；
5. 同时满足“触发事件 + 受众用户”才进入流程。

**7.4.6 完成次数规则**

| **规则** | **含义** |
| --- | --- |
| 累计完成 A | 例如累计完成 A 3 次，用户达到 3 次后只进入流程一次 |
| 每完成 A | 例如每完成 A 3 次，用户每累计 3 次都会进入流程 |
| 分别做过 | 多个事件可配置且 / 或关系，每个事件可单独配置次数 |

**7.4.7 GMP 回传事件选择**

若用户希望基于 GMP 自身触达行为触发流程：

1. 在事件选择框搜索 GMP；
2. 选择 GMP 回传事件；
3. 系统自动加载 3 个属性：
   1. 活动类型 / 任务类型；
   2. 活动 ID / 任务 ID；
   3. 指标名称。
4. 用户需手动填写属性值；
5. 例如基于某个消息触达任务发送成功触发，可选择任务类型为消息触达、任务 ID 为对应任务、指标名称为发送量或成功触达量。

**7.5 触发型-完成 A 未完成 B**

**7.5.1 使用场景**

用于断点营销。例如用户启动应用后 20 分钟内未访问页面，则进入提醒流程。

**7.5.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 事件描述 | Input | 是 | 仅用于预览和查看 |
| 事件 A 起止时间 | DateTimeRangePicker | 是 | A 事件发生时间范围 |
| 完成事件 A | EventSelector | 是 | 用户完成 A 后进入等待判断 |
| 未完成事件 B | EventSelector | 是 | 判断时间内未完成 B 才触发 |
| 完成次数规则 | Radio + Number | 是 | 累计完成 A / 每完成 A / 分别做过 |
| 完成 A 后判断是否未完成 B | JudgeWindow | 是 | 配置判断 B 的时间窗口 |
| 受众用户 | SegmentSelector | 是 | 完成 A 后仍需经过受众过滤 |
| 任务结束时间 | DateTimePicker | 是 | 到达后流程结束 |
| 进入频率限制 | FrequencyRule | 否 | 限制用户进入流程频次 |

**7.5.3 判断 B 的时间窗口**

支持两种方式：

| **方式** | **说明** |
| --- | --- |
| 完成 A 后的一段时间内判断 B | 例如完成 A 后 20 分钟内未完成 B |
| 完成 A 当天的一段时间内判断 B | 例如完成 A 当天 23:59 前未完成 B |

执行逻辑：

用户完成事件 A

-> 判断是否满足受众条件

-> 若不满足，流程不触发

-> 若满足，进入 B 判断等待期

-> 等待期内用户完成 B：不进入流程

-> 等待期结束仍未完成 B：进入流程

补充规则：

1. 若任务在等待 B 的过程中结束，则不再触发流程；
2. 若用户多次完成 A，按完成次数规则判断是否生成新的等待实例；
3. 若进入频率限制已达上限，则不进入流程。

**8. Step 2：画布设计与原子节点**

**8.1 原子节点分类**

流程画布节点分为三类：

| **类型** | **节点** |
| --- | --- |
| 判断 | 分群判断、事件判断 |
| 流程 | 延时、A/B 分流、A/B 赛马、分群分流、事件分流 |
| 触达 | 短信、Webhook、服务号模板消息、公众号活跃消息、公众号群发消息、小程序订阅消息、Telegram、WhatsApp |

**8.2 节点添加规则**

用户可在以下位置添加节点：

1. 触发器下方；
2. 任意已有节点的下方；
3. 分支节点的某个分支下方；
4. 空白画布区域拖拽后连接。

添加节点后：

1. 生成临时节点 ID；
2. 节点默认名称为节点类型名称；
3. 自动打开配置抽屉；
4. 节点未配置完成前状态为未配置；
5. 节点保存后，根据节点类型生成分支。

**8.3 节点删除规则**

删除节点时：

1. 删除该节点；
2. 删除该节点相关连线；
3. 若删除的是中间节点，下游节点不自动删除；
4. 若下游节点因此无上游，则标记为孤立节点；
5. 提交审批时不允许存在孤立节点。

**8.4 节点复制规则**

复制节点时：

1. 复制节点配置；
2. 生成新的节点 ID；
3. 节点名称默认为原节点名称-副本；
4. 不复制上下游连线；
5. 用户需手动连接或在指定分支下添加。

**9. 分群判断节点**

**9.1 功能说明**

分群判断用于判断进入该节点的用户是否满足某个分群条件。判断完成后，系统自动生成两条分支：

1. 满足；
2. 不满足。

**9.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 节点名称 | Input | 是 | 用于区分不同节点 |
| 分群配置方式 | Radio | 是 | 标签与行为圈选 / 已有分群 |
| 分群圈选 | SegmentBuilder | 条件必填 | 使用标签、属性、分群包、明细数据、行为数据圈选 |
| 已有分群 | SegmentSelect | 条件必填 | 选择已有分群 |
| 分群预估 | Button | 否 | 预估本层和联合受众数量 |
| 同步到 CDP 分群列表 | Switch | 否 | 是否将新增分群同步到 CDP |
| 分群授权 | RoleSelect | 否 | 授权角色查看分群 |

**9.3 节点名称**

规则：

1. 必填；
2. 默认值为“分群判断”；
3. 同一流程内允许重名，但建议提示用户保持可读；
4. 节点名称展示在画布卡片和效果评估中。

**9.4 标签与行为圈选**

展示条件：

hasVeCDP === true

圈选能力：

1. 标签；
2. 属性；
3. 分群包；
4. 明细数据；
5. 行为数据。

保存逻辑：

1. 保存节点时保存圈选规则；
2. 保存草稿或提交审批时可创建该节点对应的临时分群；
3. 若开启同步到 CDP，则分群在 CDP 分群列表可见；
4. 若未开启同步，则仅供当前流程节点使用。

**9.5 已有分群**

用户可直接选择一个已创建分群。

规则：

1. 若开通多主体，仅展示当前主体对应分群；
2. 分群失效时不可选择；
3. 分群无权限时不可选择；
4. 已选分群失效后，节点标记为错误。

**9.6 分群预估**

点击「分群预估」后展示两类数量：

| **指标** | **含义** |
| --- | --- |
| 本层受众预估 | 仅根据当前分群圈选条件计算数量 |
| 联合受众预估 | 当前分群圈选条件与所有上层原子节点结果取交集后的数量 |

执行逻辑：

1. 先校验分群条件；
2. 调用预估接口；
3. 展示人数或 ID 数量；
4. 若联合受众为 0，提示：当前节点与上层条件交集为空，请检查配置。

**9.7 分支生成**

保存节点后：

1. 自动生成“满足”分支；
2. 自动生成“不满足”分支；
3. 两条分支均可继续添加下游节点；
4. 提交审批前，每条有业务意义的分支至少需要有下游节点或设置为结束。

**10. 事件判断节点**

**10.1 功能说明**

事件判断用于判断用户进入该节点后，在一段时间内是否满足事件条件。系统根据判断结果生成两条分支：

1. 满足；
2. 不满足。

**10.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 节点名称 | Input | 是 | 区分节点 |
| 判断时间范围 | TimeWindowPicker | 是 | 用户进入节点后，在多长时间内判断事件 |
| 事件规则类型 | Radio | 是 | 累计做过 / 分别做过 / 未做过 |
| 事件配置 | EventRuleBuilder | 是 | 配置一个或多个事件及次数 |
| 筛选条件 | FilterBuilder | 否 | 事件属性限制 |
| 保存 | Button | 是 | 保存节点配置 |

**10.3 累计做过**

规则：

1. 支持多个事件；
2. 多个事件之间仅支持“或”逻辑；
3. 用户在判断时间范围内，只要完成任意一个事件对应次数，即满足条件。

示例：

累计做过：

浏览商品详情页 >= 3 次

或

加入购物车 >= 1 次

只要用户满足其中一个事件，即进入“满足”分支。

**10.4 分别做过**

规则：

1. 支持多个事件；
2. 事件之间支持“且 / 或”；
3. 每个事件可单独配置次数。

逻辑：

| **关系** | **含义** |
| --- | --- |
| 或 | 任意一个事件完成对应次数即满足 |
| 且 | 每个事件都完成对应次数才满足 |

**10.5 未做过**

规则：

1. 支持多个事件；
2. 事件之间支持“且 / 或”；
3. 判断用户在指定时间范围内完成次数是否为 0。

逻辑：

| **关系** | **含义** |
| --- | --- |
| 或 | 多个事件中任意一个事件完成次数为 0，即满足 |
| 且 | 多个事件完成次数都为 0，才满足 |

**10.6 分支生成**

保存后：

1. 自动生成“满足”分支；
2. 自动生成“不满足”分支；
3. 两个分支均可继续添加节点；
4. 运行时用户只能进入其中一个分支。

**11. 延时节点**

**11.1 功能说明**

延时节点用于让用户在流程中等待一段时间或等待到指定时间后再继续流转。

**11.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 节点名称 | Input | 是 | 默认“延时” |
| 延时规则 | Radio | 是 | 选择延时方式 |
| 延时时长 / 时间点 | 动态控件 | 是 | 根据延时规则展示 |
| 保存 | Button | 是 | 保存延时配置 |

**11.3 延时规则**

**11.3.1 延时相对时间**

支持单位：

1. 秒；
2. 分钟；
3. 小时；
4. 天。

规则：

1. 延迟 1 天等于延迟 24 小时；
2. 用户进入节点后开始计时；
3. 到达延时时长后流出节点。

**11.3.2 延时至指定时间**

规则：

1. 用户进入节点后等待到指定时间；
2. 如果用户进入节点时指定时间已过，则该用户不会继续流出；
3. 系统记录过滤原因：错过指定延时时间。

**11.3.3 延时至第几天几点**

规则：

1. “第几天”指最近第几个目标时间点；
2. 例如设置延时到第 1 天 08:00：
   1. 08:00 前进入节点，当天 08:00 流出；
   2. 08:00 后进入节点，次日 08:00 流出。

**11.3.4 延时至周几**

规则：

1. 等待到最近一个指定星期几；
2. 例如设置周二：
   1. 周一进入节点，本周二流出；
   2. 周三进入节点，下周二流出。

**11.3.5 延时到交易日**

展示条件：

feature.trading\_day\_delay === true

规则：

1. 支持延时到进入节点当周或当月的交易日；
2. 交易日来自企业日历；
3. 若未开通该增值功能，不展示该选项；
4. 若日历缺失，节点校验失败。

**11.3.6 延时到本月自然日**

规则：

1. 每月第 N 天指定时间；
2. 例如每月第 15 天 08:00：
   1. 本月 15 日 08:00 前进入节点，本月 15 日 08:00 流出；
   2. 本月 15 日 08:00 后进入节点，下个月 15 日 08:00 流出。

**11.4 流转逻辑**

用户进入延时节点后：

1. 系统生成等待任务；
2. 到达延时目标时间后继续流转；
3. 若流程被暂停，等待任务暂停；
4. 若流程被取消或结束，等待任务取消；
5. 若用户错过指定时间，实例结束或进入过滤状态。

**12. A/B 分流节点**

**12.1 功能说明**

A/B 分流节点用于将进入节点的用户按流量比例随机分配到不同实验分支。

**12.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 节点名称 | Input | 是 | 默认“A/B 分流” |
| 实验组配置 | GroupEditor | 是 | 配置对照组和实验组 |
| 分支流量比例 | PercentInput | 是 | 所有分支比例之和必须等于 100% |
| 分组名称 | Input | 是 | 每个分支名称 |
| 保存 | Button | 是 | 保存节点 |

**12.3 实验组规则**

1. 至少 2 个分支；
2. 默认第一个为对照组；
3. 可新增实验组；
4. 可删除实验组，但至少保留 2 个；
5. 所有分支比例之和必须等于 100%；
6. 比例支持整数或系统允许的小数精度。

校验失败提示：

A/B 分流各分支流量比例之和必须为 100%

**12.4 分流逻辑**

执行时：

1. 系统根据用户 ID 或流程实例 ID 进行 hash；
2. 根据分支比例确定用户进入哪个分支；
3. 同一用户在同一次流程实例中只能进入一个分支；
4. 分流结果记录到执行明细中；
5. 后续分支可配置不同触达节点或流程节点。

**12.5 分支生成**

保存后：

1. 系统按实验组数量生成多个分支；
2. 每个分支名称等于实验组名称；
3. 用户可在每个分支下继续添加节点。

**13. A/B 赛马节点**

**13.1 功能说明**

A/B 赛马用于先用小流量测试多个分支效果，再由运营人员选择优胜分支承接剩余流量。

限制：

一个流程画布仅支持一个 A/B 赛马节点

**13.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 节点名称 | Input | 是 | 默认“A/B 赛马” |
| 赛马流量 | PercentInput | 是 | 进入赛马阶段的流量占比 |
| 实验版本 | GroupEditor | 是 | 赛马期间对比的版本 |
| 实验提醒 | Switch + Contact | 否 | 赛马完成后短信或邮件提醒创建人 |
| 实验指标 | MetricSelector | 否 | 用于判断哪个版本更优 |
| 保存 | Button | 是 | 保存赛马节点 |

**13.3 赛马流量**

示例：

赛马流量 = 30%

含义：

1. 进入该节点的用户中，30% 进入赛马实验；
2. 剩余 70% 暂不进入下游触达；
3. 等创建人选择优胜组后，剩余 70% 进入优胜组分支。

**13.4 实验版本**

规则：

1. 至少 2 个版本；
2. 每个版本生成一个分支；
3. 赛马流量在版本间均分或按配置比例分配；
4. 每个版本分支可配置不同后续节点。

**13.5 实验提醒**

开启后：

1. 用户选择提醒方式：短信 / 邮件；
2. 填写提醒接收人；
3. 赛马阶段完成后，系统通知接收人；
4. 通知内容包含流程名称、赛马节点名称、实验结果入口。

**13.6 剩余流量全量逻辑**

赛马阶段完成后：

1. 数据分析页展示各实验版本指标；
2. 创建人点击「选择优胜组」；
3. 选择一个实验版本；
4. 系统将剩余流量送入该版本对应分支；
5. 后续进入该节点的新用户也按优胜组逻辑处理。

若未选择优胜组：

1. 剩余流量保持等待；
2. 若流程到达结束时间，剩余流量不再执行；
3. 数据分析中记录未全量原因。

**14. 分群分流节点**

**14.1 功能说明**

分群分流用于针对多个分群条件生成多个分支。它与分群判断的区别是：

1. 分群判断只判断一个分群，生成满足 / 不满足两条分支；
2. 分群分流可判断多个分群，生成多个业务分支。

**14.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 节点名称 | Input | 是 | 默认“分群分流” |
| 分流方式 | Radio | 是 | 按优先级进入分支 / 满足条件即可进入分支 |
| 分支配置 | BranchEditor | 是 | 配置多个分群分支 |
| 分群配置方式 | Radio | 是 | 标签与行为圈选 / 已有分群 |
| 分群预估 | Button | 否 | 预估本层和联合受众 |
| 保存 | Button | 是 | 保存节点 |

**14.3 分流方式**

**14.3.1 按优先级进入分支**

逻辑：

1. 系统按配置顺序从左到右判断；
2. 用户满足第一个分支条件后进入该分支；
3. 不再判断后续分支；
4. 一个用户最多进入一个分支。

适用场景：

1. 用户分层；
2. 等级优先级；
3. 会员分层；
4. 风险等级分流。

**14.3.2 满足条件即可进入分支**

逻辑：

1. 系统判断所有分支条件；
2. 用户满足哪个分支，就进入哪个分支；
3. 若用户同时满足多个分支，会同时进入多个分支；
4. 每个分支生成独立流程实例或子实例。

适用场景：

1. 用户可同时命中多个标签；
2. 多策略并行运营；
3. 多兴趣偏好路径。

**14.4 分支配置**

每个分支字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| 分支名称 | 是 | 展示在画布分支上 |
| 分群条件 | 是 | 标签圈选或已有分群 |
| 优先级 | 条件必填 | 按优先级进入分支时必填 |
| 备注 | 否 | 内部说明 |

**14.5 分支生成**

保存后：

1. 系统按分支数量生成多条分支；
2. 分支名称来自用户配置；
3. 分支顺序可拖拽调整；
4. 按优先级模式下，顺序即判断顺序；
5. 满足条件即可进入分支模式下，顺序仅影响展示。

**15. 事件分流节点**

**15.1 功能说明**

事件分流用于针对多组事件条件生成多个分支。它与事件判断的区别是：

1. 事件判断只判断一组事件条件，生成满足 / 不满足；
2. 事件分流可配置多组事件条件，生成多条分支。

**15.2 字段**

| 分流方式 | Radio | 是 | 按优先级进入分支 / 满足条件即可进入分支 |
| 分支事件规则 | EventBranchEditor | 是 | 配置多个事件分支 |
| 保存 | Button | 是 | 保存节点 |

**15.3 分支事件规则**

每个分支支持：

1. 累计做过；
2. 分别做过；
3. 未做过；
4. 事件属性筛选；
5. 次数条件。

**15.4 执行逻辑**

**15.4.1 按优先级进入分支**

1. 用户进入节点；
2. 系统按分支顺序逐个判断事件条件；
3. 满足第一个条件后进入该分支；
4. 不再判断其他分支。

**15.4.2 满足条件即可进入分支**

1. 用户进入节点；
2. 系统判断全部事件分支；

4. 每条分支独立继续流转。

**16.4 主体转换**

**16.4.1 展示条件**

hasCDPMultiSubject === true

AND hasGMPMultiSubjectTouch === true

未开通时，不展示主体转换。

**16.4.2 使用场景**

流程以一个主体流转，但触达前需要转换为另一个关联主体。

示例：

1. 流程以“车”为主体；
2. 车险到期事件触发流程；
3. 触达对象需要是“购车人”；
4. 在触达节点前将主体从“车”转换为“用户”。

**16.4.3 字段**

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| 目标主体 | 是 | 转换后的触达主体 |
| 主体关系 | 是 | 原主体与目标主体之间的关系 |
| 多目标处理规则 | 是 | 任选其一触达 / 都触达 |

**16.4.4 多目标处理规则**

| **场景** | **可选规则** |
| --- | --- |
| 一个原主体对应多个目标主体 | 任选其一触达 / 都触达 |
| 多个原主体对应一个目标主体 | 只能都触达 |

规则说明：

1. 任选其一触达：系统从多个目标主体中选择一个进行触达；
2. 都触达：所有目标主体均触达；
3. 多个原主体对应同一目标主体时，目标主体会被触达多次，因为每个原主体对应一次业务语义。

**16.5 触达内容**

不同通道展示不同表单：

**16.5.1 短信触达节点**

字段：

1. 短信通道；
2. 地区；
3. 签名；
4. 短信模板；
5. 模板参数；
6. 默认值；
7. 短链；
8. 插入用户属性 / 标签 / ID；
9. 测试发送。

校验：

1. 国内短信必须选择签名；
2. 模板必填；
3. 模板变量必须配置取值或默认值；

**16.6 非交易日触达**

**16.6.1 展示条件**

industry === "SECURITIES"

AND feature.nonTradingDay === true

AND channelType 不属于弹窗类通道

**16.6.2 选项**

| **选项** | **逻辑** |
| --- | --- |
| 顺延到下个交易日发送 | 若发送日为非交易日，顺延至下个交易日 |
| 不发送 | 若发送日为非交易日，本次触达过滤 |
| 正常发送 | 忽略非交易日，按原计划发送 |

**16.6.3 顺延逻辑**

1. 查询企业日历；
2. 若发送时间为非交易日，定位下一个交易日；
3. 以原计划时间点在下一个交易日发送；
4. 顺延后若与其他周期重复，由频控限制控制是否重复触达；
5. 若流程已结束，则不再顺延。

**16.7 通道黑白名单**

**16.7.1 黑名单**

开启后：

1. 发送前判断用户 ID 是否在通道黑名单；
2. 若在黑名单，不发送；
3. 过滤原因记录为通道黑名单。

**16.7.2 频控白名单**

开启后：

1. 白名单用户不受通道频控限制；
2. 仍受任务状态、流程结束时间等基础限制；
3. 若用户同时在黑名单和白名单，黑名单优先。

**16.8 勿扰配置**

字段：

| **字段** | **说明** |
| --- | --- |
| 是否开启勿扰 | 开启后配置勿扰时间 |
| 勿扰开始时间 | 每日时间点 |
| 勿扰结束时间 | 每日时间点 |
| 命中勿扰处理方式 | 放弃本次触达 / 勿扰结束后继续触达 |

执行逻辑：

1. 节点计划发送时判断是否命中勿扰；
2. 若选择放弃本次触达，用户在该节点被过滤；
3. 若选择勿扰结束后继续触达，则延迟到勿扰结束后重新判断；
4. 延迟后仍需校验流程状态、频控、黑白名单、非交易日；
5. 若流程取消或结束，不再发送。

**16.9 节点级关注指标**

触达节点可配置节点级关注指标。

规则：

1. 指标只统计经过该节点触达后的用户；
2. 指标在流程画布效果评估的该节点下展示；
3. 支持实时行为、离线行为、明细数据、组合指标；
4. 指标窗口期从该节点成功触达时间开始计算。

**16.10 是否持续触达**

用于配置用户完成本触达节点后是否继续向下流转。

选项：

| **选项** | **逻辑** |
| --- | --- |
| 不持续触达 | 用户到达该触达节点后，完成触达处理即结束当前路径 |
| 持续触达 | 用户完成本节点触达处理后继续进入下游节点 |
| 按触达结果分支 | 根据触达成功 / 触达失败生成不同分支 |

当选择“按触达结果分支”时，系统生成：

1. 触达成功分支；
2. 触达失败分支。

触达成功判定：

1. 对有回执通道，以通道回执成功为准；
2. 对无回执通道，以 GMP 成功调用通道发送接口为准；
3. 若超过回执等待时间未收到回执，按项目配置标记为未知或失败。

**17. Step 3：基础信息**

**17.1 页面字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 画布名称 | Input | 是 | 用于区分不同流程，不可与其他任务重名 |
| 任务类型 | Radio | 是 | 普通活动 / 紧急活动 / 通知活动 |
| 关联活动 | Select | 否 | 归属到营销活动 |
| 勿扰设置 | Switch + TimeRange | 否 | 限制用户进入流程 |
| 任务同步到外部系统 | Switch | 否 | 同步任务变更通知 |
| 流程互斥 | TaskSelector | 否 | 与其他任务互斥 |

**17.2 画布名称**

规则：

1. 必填；
2. 前后空格 trim；
3. 同一项目下不可与其他流程画布任务重名；
4. 建议最大长度 50 个字符；
5. 支持中文、英文、数字、下划线、中划线、空格。

校验：

1. 失焦时校验重名；
2. 提交审批前再次校验；
3. 重名提示：画布名称已存在，请修改。

**17.3 任务类型**

选项：

1. 普通活动；
2. 紧急活动；
3. 通知活动。

优先级：

通知活动 > 紧急活动 > 普通活动

执行规则：

1. 当多个任务同时触发且发送队列积压时，优先执行优先级更高的任务；
2. 每个任务完成一次触发，对应通道频控次数消耗一次；
3. 通知活动在某些频控场景下可优先保障发送，具体是否绕过频控以项目配置为准；
4. 普通活动和紧急活动需严格遵守频控限制。

**17.4 关联活动**

规则：

1. 选填；
2. 可将流程画布归属到某个营销活动；
3. 消息触达、流程画布、资源位任务可关联到同一个活动；
4. 后续可基于活动进行分析。

**17.5 流程级勿扰设置**

流程级勿扰控制的是用户能否进入流程画布，而不是节点发送消息时的勿扰。

字段：

| **字段** | **说明** |
| --- | --- |
| 是否开启 | 开启后生效 |
| 勿扰开始时间 | 每日时间点 |
| 勿扰结束时间 | 每日时间点 |
| 命中勿扰处理方式 | 不进入流程 / 勿扰结束后进入流程 |

执行逻辑：

1. 系统计划让用户进入流程时，先判断是否命中流程级勿扰；
2. 若选择不进入流程，则该用户本次不进入；
3. 若选择勿扰结束后进入流程，则延迟至勿扰结束后再次判断；
4. 若延迟期间流程结束或取消，则不再进入；
5. 流程级勿扰不替代节点级勿扰，二者可同时生效。

**17.6 任务同步到外部系统**

展示条件：

project.externalTaskSyncConfigured === true

开启后：

1. 流程创建、编辑、提交审批、审批通过、审批驳回、启动、暂停、重启、取消、结束、异常时，向外部系统发送任务变更通知；
2. 外部系统来自项目中心开放平台业务集成；
3. 同步失败不阻断主流程；
4. 同步失败记录日志；
5. 数据分析或任务详情中可查看同步失败提示。

若不需要该能力，可通过项目配置隐藏该入口。

**17.7 流程互斥**

**17.7.1 功能说明**

流程互斥用于避免同一用户被多个互斥任务重复触达。

规则：

1. 用户选择一个或多个互斥任务；
2. 若用户已被互斥任务成功触达，则当前流程不再触达该用户；
3. 当前流程成功触达用户后，互斥任务也不再触达该用户；
4. 互斥基于用户 ID 判断。

**17.7.2 选择任务**

字段：

| **字段** | **说明** |
| --- | --- |
| 任务名称 / ID 搜索 | 支持搜索任务 |
| 任务列表 | 默认展示前 50 条 |
| 已选任务 | 展示已选互斥任务 |

规则：

1. 默认仅展示前 50 条任务；
2. 更多任务需要搜索；
3. 不允许选择当前任务自己；
4. 已取消或已删除任务不可选择；
5. 已选互斥任务失效后提交审批失败。

**18. Step 4：关注指标**

**18.1 功能说明**

流程画布关注指标用于追踪所有成功进入流程画布用户的后续行为表现。

它与节点级关注指标的区别：

| **指标类型** | **统计对象** |
| --- | --- |
| 流程级关注指标 | 所有成功进入流程的用户 |
| 节点级关注指标 | 成功经过某个触达节点的用户 |

**18.2 字段**

| **字段** | **控件** | **必填** | **说明** |
| --- | --- | --- | --- |
| 设置方式 | Radio | 是 | 新建指标 / 使用已有指标 |
| 指标名称 | Input | 是 | 在数据分析页面展示 |
| 管理指标 | Button | 否 | 查看系统所有指标 |
| 计算条件 | DynamicForm | 是 | 根据指标类型配置 |
| 窗口期 | DurationPicker | 是 | 用户进入流程后多长时间内统计 |

**18.3 设置方式**

**18.3.1 新建指标**

用户在当前流程中创建指标。

保存后：

1. 指标可用于当前流程；
2. 若保存到指标库，则后续可作为已有指标选择；
3. 指标名称展示在数据分析页。

**18.3.2 使用已有指标**

用户选择系统中已有指标。

规则：

1. 只展示当前用户有权限的指标；
2. 指标被删除后，已配置任务的数据不受影响；
3. 删除指标只影响后续新建任务时无法选择。

**18.4 管理指标按钮**

点击后：

1. 打开指标管理弹窗；
2. 展示系统已有指标；
3. 支持查看指标配置；
4. 支持删除指标；
5. 删除指标不影响已配置任务的数据展示；
6. 删除后当前页面“选择已有指标”列表刷新。

**18.5 通过实时行为数据计算**

适用条件：

数据源具备实时行为消息。

字段：

1. 数据源；
2. 事件；
3. 筛选条件；
4. 统计口径：人数 / 次数；
5. 窗口期。

统计逻辑：

1. 用户成功进入流程后开始计算窗口期；
2. 在窗口期内完成事件即计入指标；
3. 指标实时更新；
4. 若配置了事件筛选条件，必须同时满足事件和筛选条件。

**18.6 通过离线行为数据计算**

适用条件：

数据源是按天更新的增量表。

统计逻辑：

1. 用户进入流程后开始计算窗口期；
2. 系统每天 5、11、17、23 点统计指标；
3. 指标存在延迟；
4. 如果数据源同时支持实时行为，建议优先使用实时行为指标。

**18.7 通过明细数据计算**

适用场景：

1. 订单数；
2. GMV；
3. 支付金额；
4. 购买商品件数。

字段：

1. 数据源；
2. 字段；
3. 筛选条件；
4. 统计方式：人数 / 次数 / 求和；
5. 窗口期。

规则：

1. 若统计字段出现次数，选择人数 / 次数；
2. 若统计金额类指标，选择求和；
3. 离线统计按固定时间批量更新。

**18.8 组合指标**

示例：

1. 加购率；
2. 客单价；
3. 短信发送成本；
4. 转化成本。

配置逻辑：

1. 选择已有指标；
2. 或直接输入固定数值；
3. 支持指标之间组合运算；
4. 可选择发送量、送达量以及当前页面已选择指标；
5. 保存时校验公式合法性；
6. 除数为 0 时，展示为 “-”，不报错。

**18.9 窗口期**

窗口期含义：

用户被触达或进入流程后，统计多长时间内的数据。

流程级指标：

窗口期开始时间 = 用户成功进入流程时间

节点级指标：

窗口期开始时间 = 用户在该节点成功触达时间

**21. 流程运行逻辑**

**21.1 审批通过后执行**

审批通过后：

1. 定时单次：等待任务开始时间；
2. 定时重复：生成周期调度；
3. 触发型完成 A：开始监听事件 A；
4. 触发型完成 A 未完成 B：开始监听事件 A，并在 A 后判断 B。

**21.2 用户进入流程**

用户进入流程前需经过：

1. 触发条件判断；
2. 受众用户判断；
3. 流程级勿扰判断；
4. 进入频率限制判断；
5. 流程状态判断；
6. 任务结束时间判断。

满足全部条件后：

1. 创建流程执行实例；
2. 进入触发器下游第一个节点；
3. 记录进入量。

**21.3 节点执行顺序**

每个节点执行时：

1. 判断流程状态是否仍为运行中；
2. 判断任务是否已结束；
3. 读取节点配置；
4. 执行节点逻辑；
5. 根据节点结果选择下游分支；
6. 记录节点进入量和执行结果。

**21.4 流程暂停**

暂停后：

1. 不再触发新用户进入；
2. 已在流程中的用户暂停流转；
3. 延时节点倒计时暂停；
4. 事件判断等待暂停；
5. 已进入通道发送队列的消息不撤回。

**21.5 流程重启**

重启后：

1. 新用户可继续进入；
2. 暂停中的流程实例继续流转；
3. 延时节点按剩余等待时间继续；
4. 定时重复任务从后续周期继续，不补发暂停期间周期；
5. 触发型任务从重启后监听新事件。

**21.6 流程取消**

取消后：

1. 不再触发新用户进入；
2. 已在流程中的实例终止；
3. 未执行节点不再执行；
4. 已产生数据保留；
5. 数据分析仍可查看。

**21.7 流程结束**

结束条件：

1. 到达任务结束时间；
2. 用户流转到无下游节点；
3. 用户被过滤；
4. 用户在某节点执行失败且无失败分支；
5. 人工取消；
6. 异常终止。

**22. 流程画布效果评估**

**22.1 入口**

流程运行后，在流程画布列表点击「数据分析」。

可查看数据分析的状态：

1. 运行中；
2. 已暂停；
3. 已取消；
4. 已结束；
5. 异常。

**22.2 页面结构**

数据分析包含两部分：

1. 整体表现；
2. 分步表现。

Tab：

| **Tab** | **说明** |
| --- | --- |
| 整体表现 | 查看流程画布整体数据 |
| 分步表现 | 查看每个节点的数据 |

**22.3 整体表现**

整体表现展示：

1. 流程进入量；
2. 总发送量；
3. 总送达量；
4. 总点击量；
5. 流程级关注指标；
6. 转化数据；
7. 运行状态；
8. 异常原因。

指标口径：

| **指标** | **含义** |
| --- | --- |
| 进入量 | 成功进入流程画布的人数或次数 |
| 发送量 | 所有触达节点发送量合计 |
| 送达量 | 所有触达节点送达量合计 |
| 关注指标 | 流程级关注指标数据 |

**22.4 分步表现**

分步表现以画布形式展示每个节点的数据卡片。

每个节点展示：

| **字段** | **含义** |
| --- | --- |
| 节点名称 | 展示配置的节点名称 |
| 节点 ID | 节点名称右侧展示节点 ID |
| 进入量 | 进入本节点的次数或人数 |
| 预备发送量 | 满足本节点条件且满足勿扰、频控等过滤后的 ID 次数或人数 |
| 发送量 | GMP 发送消息数量 |
| 送达量 | 下游通道实际送达数量，依赖回执 |
| 关注指标数据 | 若节点设置了关注指标，则展示指标数据 |

**22.5 节点配置详情**

点击节点卡片中的「配置详情」：

1. 展开该节点配置页面；
2. 展示该节点的完整配置；
3. 只读展示；
4. 支持关闭详情。

展示内容按节点类型变化：

| **节点类型** | **展示内容** |
| --- | --- |
| 分群判断 | 分群条件、预估结果、分支 |
| 事件判断 | 事件规则、判断时间范围、满足 / 不满足 |
| 延时 | 延时规则和流出时间逻辑 |
| A/B 分流 | 分组、比例、分支 |
| A/B 赛马 | 赛马流量、实验版本、优胜组状态 |
| 分群分流 | 分支分群条件、分流方式 |
| 事件分流 | 分支事件条件、分流方式 |
| 触达节点 | 通道、内容、勿扰、黑白名单、指标 |

**22.6 人数 / 人次切换**

分步表现支持人数 / 人次切换。

| **口径** | **说明** |
| --- | --- |
| 人数 | 去重用户数 |
| 人次 | 用户每进入一次节点计一次 |

默认展示人次。

切换后：

1. 所有节点指标同步刷新；
2. 整体表现同步刷新；
3. 图表和表格口径保持一致。

**22.7 异常节点展示**

若节点执行异常：

1. 节点卡片红色标识；
2. 展示异常原因；
3. 支持点击查看执行记录；
4. 异常不影响其他已完成节点数据展示。

**23. 校验规则汇总**

**23.1 流程级校验**

| **校验项** | **规则** |
| --- | --- |
| 画布名称 | 必填，不可重名 |
| 任务类型 | 必选 |
| 触发器 | 必须配置 |
| 节点 | 不可存在未配置节点 |
| 连线 | 不可存在孤立节点 |
| 分支 | 必要分支必须配置下游或设置结束 |
| 结束时间 | 必须晚于开始时间 |
| 审批状态 | 审批通过前不可执行 |

**23.2 节点级校验**

| **节点** | **校验** |
| --- | --- |
| 分群判断 | 必须选择分群条件或已有分群 |
| 事件判断 | 必须配置事件规则和判断时间 |
| 延时 | 必须配置合法延时规则 |
| A/B 分流 | 比例之和必须等于 100% |
| A/B 赛马 | 全流程只能存在一个，赛马流量必须大于 0 小于 100 |
| 分群分流 | 至少两个分支，每个分支必须配置条件 |
| 事件分流 | 至少两个分支，每个分支必须配置事件规则 |
| 触达节点 | 通道、触达内容、必填变量必须完整 |

**23.3 权限校验**

| **场景** | **校验** |
| --- | --- |
| 创建流程 | 流程画布创建权限 |
| 编辑流程 | 流程画布编辑权限 |
| 使用分群 | CDP / DataFinder 分群权限 |
| 使用通道 | 对应通道权限 |
| 审批 | 当前用户必须是审批人 |
| 查看数据 | 数据分析权限 |

**24. 空状态与异常状态**

**24.1 列表空状态**

无流程时展示：

暂无流程画布

若有创建权限，展示按钮：

新增流程画布

**24.2 画布空状态**

空白画布未配置触发器时展示：

请先选择流程触发方式

并展示四种触发方式卡片。

**24.3 节点未配置状态**

节点未配置时：

1. 节点卡片展示灰色；
2. 显示“未配置”标签；
3. 提交审批时阻断；
4. 点击节点可继续配置。

**24.4 节点配置错误**

节点错误时：

1. 节点红色描边；
2. 节点卡片展示错误图标；
3. hover 展示错误摘要；
4. 校验结果面板展示完整错误。

**24.5 接口异常**

接口异常时：

1. 页面展示错误提示；
2. 保留用户已填写内容；
3. 支持重试；
4. 保存失败时不清空本地编辑状态。

**25. 验收标准**

**25.1 流程画布列表验收**

1. 用户有查看权限时可进入流程画布列表；
2. 用户无权限时不可见菜单或展示无权限页；
3. 列表支持按名称、任务类型、触发类型、审批状态、任务状态、创建人、创建时间筛选；
4. 点击新增流程画布可选择空白画布或模板；
5. 草稿可编辑、复制、删除；
6. 审批中可查看、复制、催审、审批；
7. 运行中可查看、复制、暂停、取消、数据分析；
8. 已暂停可重启、取消、数据分析；
9. 已结束、已取消、异常可查看数据分析。

**25.2 创建流程验收**

1. 空白画布进入后必须先配置触发器；
2. 支持四类触发器；
3. 支持判断、流程、触达三类原子节点；
4. 节点可添加、编辑、删除、复制；
5. 画布支持拖拽、连线、缩放、预览；
6. 保存草稿不强制完整校验；
7. 提交审批必须完整校验；
8. 校验错误可定位到节点或字段。

**25.3 触发器验收**

1. 定时单次按指定时间进入流程；
2. 定时重复按周期多次进入流程；
3. 触发型完成 A 在用户完成事件后进入流程；
4. 触发型完成 A 未完成 B 在等待期内未完成 B 时进入流程；
5. 进入频率限制按用户进入流程次数扣减；
6. 到达任务结束时间后不再执行任何流转逻辑。

**25.4 节点验收**

1. 分群判断生成满足 / 不满足分支；
2. 事件判断生成满足 / 不满足分支；
3. 延时节点按配置时间流出；
4. A/B 分流按比例生成多分支；
5. A/B 赛马全流程只能配置一个；
6. 分群分流支持按优先级和满足即可两种方式；
7. 事件分流支持多事件条件分支；
8. 触达节点支持主体转换、通道内容、黑白名单、勿扰、非交易日、关注指标、持续触达。

**25.5 审批验收**

1. 提交审批前必须全量校验；
2. 审批确认弹窗展示审批流程和审批人；
3. 发起人自选审批人时可选择候选人；
4. 指定成员审批人不可修改；
5. 审批通过后流程进入等待执行或运行中；
6. 审批驳回必须填写驳回原因；
7. 我的审批待办数量每 5 分钟刷新。

**25.6 效果评估验收**

1. 运行后可点击数据分析；
2. 数据分析包含整体表现和分步表现；
3. 整体表现展示流程级数据；
4. 分步表现展示每个节点数据；
5. 每个节点展示节点名称、节点 ID、进入量、预备发送量、发送量、送达量、关注指标；
6. 点击配置详情可展开节点配置；
7. 支持人数 / 人次口径切换；
8. 异常节点展示异常原因，不影响其他节点数据查看。
