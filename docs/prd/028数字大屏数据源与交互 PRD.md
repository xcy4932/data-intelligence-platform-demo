**数字大屏数据源与交互 PRD**

**1. 产品定位**

数字大屏数据源与交互模块用于解决两个核心问题：

第一，用户如何为大屏组件接入数据，包括静态数据、数据集、API、JavaScript、MySQL、飞书表格、飞书多维表格等来源，并将返回数据转为统一的二维表结构，供图表字段配置、筛选、排序、TopN、参考线和渲染使用。

第二，用户如何让大屏从“静态展示”变成“可交互应用”，包括图表点击联动、图元点击、设置筛选项、切换页面、修改变量、刷新数据、GIS 钻取、动态面板切换、UE 动作触发等。

本模块不是单独页面，而是数字大屏编辑器的底部数据配置区、右侧交互配置区、字段胶囊配置区、筛选配置区、分析配置区共同组成的一套能力。

**2. 总体功能架构**

**2.1 编辑器中的入口位置**

数字大屏编辑器内需要支持以下入口：

| **区域** | **入口** | **功能** |
| --- | --- | --- |
| 画布 | 选中图表组件 | 激活底部数据查询栏 |
| 底部查询栏 | 数据来源下拉框 | 选择 Static、Dataset、API、JavaScript、MySQL、飞书表格、飞书多维表格 |
| 底部查询栏 | 查询 / 获取数据 | 执行当前数据源查询 |
| 底部查询栏 | 查看数据 | 查看解析后的二维表 |
| 底部查询栏 | 数据更新方式 | 设置只请求一次、自动更新、不自动请求 |
| 数据配置区 | 数据可视化 | 配置轴、分拆、值、额外字段、排序、筛选、TopN |
| 数据配置区 | 分析 | 配置参考线 |
| 数据配置区 | 筛选 | 配置图表筛选、作为筛选器、图表联动 |
| 右侧面板 | 交互 Tab | 配置事件、条件、响应 |

**2.2 用户主流程**

拖入图表组件

→ 默认生成 Static 示例数据

→ 用户选择数据来源

→ 配置数据源参数

→ 点击获取数据

→ 系统将返回结果解析为二维表

→ 系统生成字段胶囊

→ 用户拖拽字段到轴、分拆、值等字段槽位

→ 配置排序、筛选、TopN、参考线

→ 图表渲染

→ 配置交互事件

→ 预览验证

→ 保存大屏

→ 发布后按同样逻辑执行数据请求与交互响应

**3. 核心数据模型**

**3.1 组件数据配置模型**

每个支持数据绑定的组件都必须保存一份 DataConfig。

type DataSourceType =

| 'static'

| 'dataset'

| 'api'

| 'javascript'

| 'mysql'

| 'feishuSheet'

| 'feishuBitable';

type RefreshMode =

| 'once'

| 'auto'

| 'manual';

interface ComponentDataConfig {

componentId: string;

sourceType: DataSourceType;

sourceConfig:

| StaticSourceConfig

| DatasetSourceConfig

| ApiSourceConfig

| JavaScriptSourceConfig

| MysqlSourceConfig

| FeishuSheetSourceConfig

| FeishuBitableSourceConfig;

refreshConfig: RefreshConfig;

lastQueryState?: QueryState;

}

**3.2 数据刷新配置模型**

interface RefreshConfig {

mode: RefreshMode;

intervalSeconds?: number;

}

规则：

| **mode** | **含义** | **执行逻辑** |
| --- | --- | --- |
| once | 只请求一次 | 组件首次加载时请求一次，后续只在用户手动刷新、交互刷新、配置变化时重新请求 |
| auto | 自动更新 | 组件首次加载时请求一次，之后按 intervalSeconds 周期重复请求 |
| manual | 不自动请求 | 组件加载时不主动请求，只在用户点击查询、交互刷新、刷新可视化内容时请求 |

自动更新规则：

1. intervalSeconds 允许范围为 5-10000。
2. 小于 5 时输入框报错：“自动更新时间不能小于 5 秒”。
3. 大于 10000 时输入框报错：“自动更新时间不能大于 10000 秒”。
4. 组件被删除、页面切换、编辑器卸载时必须清除定时器。
5. 如果上一次请求尚未完成，下一次定时触发时默认跳过，不并发发起同一组件的重复请求。
6. 用户手动刷新时可以中断当前请求并重新请求。
7. 发布态页面不可见时可以暂停自动刷新，页面重新可见后立即触发一次刷新，再恢复周期刷新。

**3.3 统一二维表模型**

所有数据源最终必须转换成统一表结构。

interface TableSchema {

columns: TableColumn[];

rows: TableRow[];

}

interface TableColumn {

id: string;

name: string;

displayName: string;

dataType: 'string' | 'number' | 'date' | 'datetime' | 'boolean' | 'object';

role: 'dimension' | 'measure' | 'unknown';

sourceFieldPath?: string;

}

interface TableRow {

id: string;

values: Record<string, any>;

}

字段识别规则：

1. number 类型默认识别为指标。
2. string、date、datetime、boolean 默认识别为维度。
3. object 类型默认不允许直接拖入图表字段槽位。
4. API 与 JavaScript 返回复杂对象时，必须通过 Transformer 或脚本处理成扁平对象。
5. 字段名为空时自动生成 field\_1、field\_2，但 UI 提示“字段名为空，建议修改表头”。
6. 字段名重复时自动追加序号，例如 销售额、销售额\_2，避免字段引用冲突。

**4. 数据查询执行生命周期**

**4.1 查询状态**

interface QueryState {

status: 'idle' | 'loading' | 'success' | 'error';

startedAt?: string;

finishedAt?: string;

errorMessage?: string;

rawDataPreview?: any;

parsedTable?: TableSchema;

}

**4.2 通用查询流程**

用户触发查询

→ 校验数据源配置

→ 将组件状态置为 loading

→ 调用对应数据源执行器

→ 获取原始结果

→ 执行 Transformer 或脚本转换

→ 将结果解析成二维表

→ 推断字段类型与字段角色

→ 写入 tableSchema

→ 更新字段胶囊区

→ 执行字段配置计算

→ 渲染图表

→ 触发“数据更新完成”事件

**4.3 查询失败流程**

请求失败 / 解析失败 / 脚本失败

→ 组件 queryState.status = error

→ 底部查询栏展示错误信息

→ 图表区域展示空态或保留上一次成功结果

→ 交互事件“数据更新完成”不触发

→ 控制台记录完整错误

失败展示规则：

| **失败类型** | **UI 提示** |
| --- | --- |
| URL 为空 | 请填写 API URL |
| 请求体不是 JSON | 请求体必须是合法 JSON |
| API 跨域失败 | 当前接口存在跨域限制，请使用代理请求或允许 CORS |
| Transformer 执行失败 | Transformer 执行失败，请检查代码 |
| 返回数据无法解析 | 返回结果无法转换为二维表 |
| JS 脚本超时 | JavaScript 数据源执行超时 |
| 数据集不存在 | 当前数据集不存在或无访问权限 |
| 字段被删除 | 当前字段已不存在，请重新配置字段 |

**5. Static 静态数据 PRD**

**5.1 功能定位**

Static 静态数据用于 demo、样式预览、学习和少量固定数据展示。新建图表时默认使用 Static 示例数据，用户可直接编辑表格内容。

**5.2 默认行为**

当用户拖入一个支持数据绑定的图表组件时：

创建组件

→ 自动生成默认 Static 数据

→ 自动生成字段胶囊

→ 自动绑定默认字段槽位

→ 图表完成默认渲染

示例数据需要根据图表类型生成。柱状图默认可生成：

[

{ "时间": "2:00", "销售额": 1000 },

{ "时间": "3:00", "销售额": 1290 },

{ "时间": "4:00", "销售额": 2022 }

]

**5.3 静态表格编辑**

**5.3.1 单元格编辑**

用户双击单元格进入编辑状态。

规则：

1. 输入框默认填充当前单元格值。
2. 按 Enter 保存并退出编辑。
3. 按 Esc 放弃修改。
4. 失焦时保存修改。
5. 修改后立即更新 sourceConfig.rows。
6. 修改后重新解析字段类型。
7. 修改后重新渲染图表。

**5.3.2 表头编辑**

用户双击表头可修改字段名。

规则：

1. 表头不能为空。
2. 表头不能与其他字段重名。
3. 重名时提示：“字段名已存在，请修改”。
4. 表头修改后，需要同步更新字段胶囊 displayName。
5. 如果该字段已被绑定到轴、值、筛选、排序、TopN、参考线中，需要保持字段 id 不变，只更新展示名称。
6. 不允许因为表头改名导致已有字段配置丢失。

**5.3.3 粘贴数据**

用户从 Excel 复制数据后，在静态表格中选中单元格并粘贴。

规则：

1. 粘贴方向为从当前单元格向右下覆盖。
2. 不支持将第一行作为表头自动粘贴。
3. 超出现有行列时自动扩展表格。
4. 粘贴空值时写入空字符串。
5. 粘贴后重新推断字段类型。
6. 如果粘贴内容导致已有字段类型从 number 变成 string，字段角色需要重新计算，但已绑定的字段槽位不自动删除，只在图表渲染时提示字段类型不匹配。

**5.3.4 行列操作**

右键单元格显示菜单：

| **操作** | **逻辑** |
| --- | --- |
| 在上方插入行 | 在当前行 index 前插入空行 |
| 在下方插入行 | 在当前行 index 后插入空行 |
| 删除行 | 删除当前行 |
| 在左侧插入列 | 在当前列 index 前插入空字段 |
| 在右侧插入列 | 在当前列 index 后插入空字段 |
| 删除列 | 删除当前列，并清理相关字段配置 |

删除列时：

1. 如果该列字段已被图表使用，弹出确认：“该字段已用于图表配置，删除后相关配置将失效。”
2. 用户确认后删除字段。
3. 同步移除轴、分拆、值、排序、筛选、TopN、参考线、额外字段中的字段引用。
4. 图表重新渲染。

**6. Dataset 数据集来源 PRD**

**6.1 功能定位**

Dataset 来源用于接入平台内已经创建的数据集，适合正式大屏、动态数据、实时数据展示。Dataset 支持 StarRocks、Doris、LAS 等数据集类型，具体底层查询能力复用数据集模块。

**6.2 选择数据集流程**

选中图表组件

→ 底部查询栏选择 Dataset

→ 打开数据集选择器

→ 用户选择数据集

→ 系统读取数据集字段

→ 生成字段胶囊

→ 用户配置字段槽位

→ 点击查询

→ 图表渲染

**6.3 数据集选择器**

数据集选择器字段：

| **字段** | **说明** |
| --- | --- |
| 搜索框 | 按数据集名称搜索 |
| 数据集列表 | 展示用户有权限访问的数据集 |
| 数据集类型 | 展示 StarRocks、Doris、LAS 等来源类型 |
| 最近更新时间 | 用于辅助用户判断数据新旧 |
| 确认按钮 | 选中数据集后生效 |

选择规则：

1. 无权限数据集不展示。
2. 数据集被删除后，已绑定组件展示“数据集不存在或无权限”。
3. 更换数据集时，原字段配置默认失效。
4. 若新旧数据集中存在同名同类型字段，可提示用户是否自动映射。
5. 自动映射只根据字段名和字段类型匹配，不根据展示名称匹配。

**6.4 Dataset 配置模型**

interface DatasetSourceConfig {

datasetId: string;

datasetName?: string;

}

**6.5 Dataset 字段配置**

Dataset 字段会进入数据可视化配置区，支持：

| **配置区** | **功能** |
| --- | --- |
| 轴 | 指定分类轴、时间轴或地理轴字段 |
| 分拆 | 指定系列分组字段 |
| 值 | 指定指标字段及聚合方式 |
| 排序 | 指定排序字段和排序方向 |
| 筛选 | 指定字段过滤条件 |
| TopN | 指定展示头部或尾部 N 条 |
| 全局筛选 | 将字段拖入全局筛选区，影响多个组件 |

**6.6 Dataset 查询执行逻辑**

读取 datasetId

→ 读取字段槽位配置

→ 合并组件筛选、全局筛选、交互筛选

→ 构造查询请求

→ 后端执行数据集查询

→ 返回二维表或聚合结果

→ 前端更新图表

过滤合并顺序：

数据集权限过滤

→ 全局筛选

→ 组件静态筛选

→ 交互设置筛选项

→ 下钻筛选

→ TopN

如果同一字段存在多个筛选：

1. 默认使用 AND 关系。
2. “包含列表新增一项”会追加到该字段 include list。
3. “包含列表减去一项”会从 include list 移除。
4. “不包含列表新增一项”会追加到 exclude list。
5. “不包含列表减去一项”会从 exclude list 移除。
6. replace 类型操作会清空该字段旧筛选，再写入新筛选。

**7. API 数据来源 PRD**

**7.1 功能定位**

API 来源用于通过 HTTP 接口获取外部数据，适合实时指标、监控、告警、销售破峰、风险看板等场景。

API 数据源本质上是浏览器端或代理端 HTTP 请求，只支持 HTTP / HTTPS 协议，不支持 TCP、WebSocket、数据库直连等非 HTTP 协议。

**7.2 API 配置项**

interface ApiSourceConfig {

method: 'GET' | 'POST';

url: string;

headers: ApiHeader[];

body?: string;

transformerCode?: string;

useProxy?: boolean;

}

interface ApiHeader {

key: string;

value: string;

enabled: boolean;

}

**7.3 请求方式**

| **请求方式** | **配置项** | **逻辑** |
| --- | --- | --- |
| GET | URL、Headers | 从服务器获取数据，不读取 body |
| POST | URL、Headers、Body | 向服务器提交数据，body 必须是合法 JSON |

GET 规则：

1. GET 请求不展示请求体编辑区，或展示但置灰。
2. 如果用户需要 query 参数，必须拼接在 URL 中。
3. GET 发起时忽略 body 字段。
4. URL 必须以 http:// 或 https:// 开头。

POST 规则：

1. POST 请求体必须是合法 JSON。
2. 请求体为空时默认 {}。
3. 请求体 JSON 校验失败时阻止请求。
4. 请求头默认包含 Content-Type: application/json。
5. 用户可以新增、删除、启用、停用请求头。

**7.4 URL 校验**

校验规则：

1. URL 不能为空。
2. URL 必须为合法 URL。
3. URL 不允许包含前后多余引号。
4. URL 不允许直接输入对象格式。
5. 私有化环境可以允许相对路径，但必须以 / 开头。
6. 发布态请求必须使用与当前环境可访问的地址。

错误提示：

| **场景** | **提示** |
| --- | --- |
| URL 为空 | 请填写接口 URL |
| URL 非法 | URL 格式不正确 |
| 非 HTTP 协议 | API 数据来源仅支持 HTTP/HTTPS 请求 |
| GET 填写 body | GET 请求不会发送请求体，请将参数拼接到 URL 中 |

**7.5 请求头配置**

默认请求头：

{

"Content-Type": "application/json"

}

请求头规则：

1. key 不能为空。
2. value 可以为空。
3. 禁止重复 key，重复时提示“请求头名称重复”。
4. 禁止用户配置浏览器不允许修改的 header，例如 Host、Content-Length。
5. disabled 的 header 不参与请求。
6. 新增 header 时默认 enabled=true。

**7.6 请求体配置**

请求体编辑器要求：

1. 仅 POST 生效。
2. 内容必须是 JSON 字符串。
3. 支持格式化 JSON。
4. 支持压缩 JSON。
5. JSON 校验失败时展示行列位置。
6. body 保存为字符串，执行前再 parse。

**7.7 Transformer**

Transformer 是 API 返回后的二次处理方法，输入为接口返回数据，输出为用于表格解析的新数据。

配置模型：

interface TransformerConfig {

enabled: boolean;

code: string;

}

执行包装：

async function transform(data: any) {

// 用户代码块

}

用户实际输入只写函数体，例如：

return data.data;

执行规则：

1. Transformer 在 API 请求成功后执行。
2. Transformer 的入参名固定为 data。
3. Transformer 可返回对象或数组。
4. Transformer 执行失败时，查询失败。
5. Transformer 返回 undefined 时，查询失败。
6. Transformer 不允许修改全局 window 对象。
7. Transformer 执行超时时间默认 5 秒。
8. 执行结果进入统一表格解析流程。

**7.8 API 返回结果解析**

**7.8.1 非数组 JSON**

如果目标数据为非数组对象：

{ "name": "John", "age": 12 }

解析为一行表格：

| **name** | **age** |
| --- | --- |
| John | 12 |

规则：

1. 只读取第一层字段作为表头。
2. 第一层字段值为对象时，字段类型识别为 object。
3. object 字段默认不能直接用于图表值字段。
4. 如果需要使用深层字段，必须通过 Transformer 扁平化。

**7.8.2 数组 JSON**

如果目标数据为数组对象：

[

{ "name": "John", "age": 12 },

{ "name": "Nancy", "age": 14 }

]

解析为多行表格。

规则：

1. 数组中每一项必须是对象。
2. 数组中所有对象字段集合必须一致。
3. 如果某一项缺少字段，解析失败并提示“数组对象字段不一致”。
4. 如果某一项多出字段，解析失败并提示“数组对象字段不一致”。
5. 若字段存在但值为空，应显式返回 null 或空字符串，不允许省略字段。
6. 空数组可以解析成功，但 table rows 为空，字段需要由用户手动或根据历史 schema 保留。

**7.9 跨域与代理**

当浏览器直接请求 API 出现 CORS 问题时，用户可以启用代理查询。

代理查询逻辑：

用户开启代理

→ 前端将真实请求封装为 proxyQuery 请求

→ 后端代理服务请求真实 API

→ 后端返回结果给前端

→ 前端继续执行 Transformer 与表格解析

代理请求参数：

interface ProxyQueryPayload {

appId: string;

proxyType: 'HttpApi';

queryParams: {

method: 'GET' | 'POST';

url: string;

params: Record<string, any>;

headers: Record<string, string>;

body: Record<string, any>;

};

}

发布态规则：

1. 编辑态可以使用普通代理接口。
2. 发布态必须使用发布态代理接口。
3. 私有化部署时代理接口域名必须使用当前私有化环境域名。
4. 代理失败时需要展示真实错误摘要，但不能暴露敏感 header。

**8. JavaScript 数据来源 PRD**

**8.1 功能定位**

JavaScript 数据源用于通过自定义 JS 生成或获取数据，适合以下场景：

1. 生成动态时间戳、随机数、模拟数据。
2. 对 API 返回数据进行复杂加工。
3. 多接口组合请求。
4. 在前端根据变量构造数据。
5. 对返回数据进行二次映射、过滤、聚合。

**8.2 JS 配置模型**

interface JavaScriptSourceConfig {

code: string;

timeoutMs: number;

}

默认：

timeoutMs = 5000;

**8.3 执行包装**

用户只编写方法块内代码：

return new Date().getTime();

系统实际执行：

async function getData() {

// 用户代码

}

执行流程：

用户点击查询

→ 校验 JS 代码非空

→ 创建异步执行上下文

→ 执行 getData

→ 等待 Promise resolve

→ 将返回值进入统一表格解析

→ 生成字段胶囊

→ 渲染图表

**8.4 返回值规则**

JavaScript 返回值与 API 解析规则一致。

允许返回：

return { name: 'John', age: 12 };

或：

return [

{ name: 'John', age: 12 },

{ name: 'Nancy', age: 14 }

];

也允许返回异步请求结果：

const res = await fetch('/api/demo');

const data = await res.json();

return data.list;

规则：

1. 返回对象时解析为一行。
2. 返回数组对象时解析为多行。
3. 返回 number、string、boolean 时，解析为单行单列，列名默认为 value。
4. 返回 null 或 undefined 时，查询失败。
5. 返回数组中字段不一致时，查询失败。
6. 异步 Promise reject 时，查询失败。
7. 执行超过 timeoutMs 时，查询失败。

**8.5 安全限制**

JavaScript 数据源必须放在隔离执行环境中执行。

建议实现：

1. 编辑态使用 Web Worker 或 sandbox iframe 执行。
2. 发布态同样使用隔离执行环境。
3. 禁止访问父页面 DOM。
4. 禁止直接读取 cookie、localStorage 中的敏感信息。
5. 禁止修改全局对象。
6. 允许 fetch，但受浏览器 CORS 限制。
7. 执行日志输出到数据源调试面板，不污染浏览器控制台。

**11.4 列表类操作**

**11.4.1 包含列表新增一项**

当前筛选：

姓名 包含 A,B

执行：

包含列表新增一项 C

结果：

姓名 包含 A,B,C

规则：

1. 如果原字段无 include list，则创建 include list。
2. 如果新增值已存在，不重复添加。
3. 多个新增值用英文逗号分隔。
4. 新增后立即刷新目标组件数据。

**11.4.2 包含列表减去一项**

当前筛选：

姓名 包含 A,B

执行：

包含列表减去一项 A

结果：

姓名 包含 B

规则：

1. 如果要删除的值不存在，不报错。
2. 如果删除后列表为空，则移除该字段 include 筛选。
3. 移除后刷新目标组件数据。

**11.4.3 不包含列表新增一项**

含义是将某个值加入排除列表。

当前无排除：

分类 不包含 []

执行：

不包含列表新增一项 家具

结果：

分类 不包含 家具

**11.4.4 不包含列表减去一项**

含义是从排除列表中移除某个值，让该值重新可见。

**11.5 维度字段输入规则**

维度字段规则：

1. 所有比较操作符只支持单个值。
2. 包含列表新增/减去支持单个值或英文逗号分隔的多个值。
3. 不包含列表新增/减去支持单个值或英文逗号分隔的多个值。
4. contains、notContains、startsWith、endsWith、like、notLike、in 支持字符串数组。
5. FX 点亮时支持数组表达式，例如 ['AAA','BBB']。
6. FX 不点亮时，支持字符串形式 AAA,BBB。
7. 英文逗号是分隔符，中文逗号按普通字符处理。

**11.6 指标字段输入规则**

指标字段支持维度字段的子集。

规则：

1. 大于、大于等于、小于、小于等于只接受数值。
2. 输入值无法转为 number 时提示“请输入数值”。
3. between 类型要求两个数值。
4. 指标字段不支持 startsWith、endsWith。
5. 指标字段不支持日期类操作符。

**11.7 日期字段输入规则**

**11.7.1 位于日期区间**

格式：

YYYY-MM-DD;YYYY-MM-DD

规则：

1. 起止日期用英文分号分隔。
2. 月份和日期必须两位，不足两位前面补 0。
3. 起始日期不能晚于结束日期。
4. 使用变量时必须点亮 FX，例如：

`${变量A};${变量B}`

**11.7.2 位于时间区间**

格式：

YYYY-MM-DD HH:mm:ss;YYYY-MM-DD HH:mm:ss

规则：

1. 时、分、秒必须两位。
2. 起止时间用英文分号分隔。
3. 起始时间不能晚于结束时间。

**11.7.3 最近**

格式：

n,(day|week|month|quarter|year)(,(today-included|today-excluded))?

示例：

5,day

5,day,today-included

5,day,today-excluded

规则：

1. n 必须为正整数。
2. today-included 表示截止到今天。
3. today-excluded 表示截止到昨天。
4. 不写第三段时默认 today-included。

**11.7.4 最近有数**

格式：

n,(day|week|month|quarter|year)

规则：

1. 仅支持分区字段。
2. 表示最近 N 个周期内有数据。
3. 不支持 today-included 参数。

**11.7.5 符合时间表达式**

支持两类：

static@YYYY-MM-DD;YYYY-MM-DD

static@YYYY-MM-DD HH:mm:ss;YYYY-MM-DD HH:mm:ss

recent@n,(day|week|month|quarter|year)(,(today-included|today-excluded))?

规则：

1. static@ 等价于固定时间区间。
2. recent@ 等价于最近时间表达式。
3. 使用变量时必须点亮 FX，例如：

static@${变量A};${变量B}

**12. 图表联动 PRD**

**14. 下钻 PRD**

**14.1 功能定位**

下钻用于在多层级字段之间进行向下或向上分析，例如：

地区

→ 省份

→ 城市

→ 区县

用户点击图表数据项后，可进入下一层级；用户点击返回后，可回到上一层级。

**14.2 配置入口**

选中图表

→ 数据配置

→ 数据可视化

→ 鼠标悬浮在轴或分拆字段上

→ 点击字段右侧下钻图标

→ 拖入下钻字段

**14.3 下钻字段模型**

interface DrillConfig {

**14.4 字段层级规则**

1. 支持多个字段形成多层级下钻。
2. L1、L2、L3 表示字段所在层级。
3. L1 是初始展示层级。
4. 用户点击 L1 中某个图元后，进入 L2。
5. 用户点击 L2 中某个图元后，进入 L3。
6. 如果当前已经是最后一层，再点击不继续下钻。

**14.5 下钻字段配置**

| **配置** | **说明** |
| --- | --- |

| 展示字段 | 控制该字段是否在图表上展示 |

展示字段规则：

1. 默认勾选。
2. 取消勾选后，该字段不在图表中显示。
3. 字段不展示不代表不参与下钻逻辑。
4. 如果某层字段被隐藏，用户从上一层下钻时，系统自动跳过隐藏层，进入下一可见层。
5. 如果所有后续层级均隐藏，则不继续下钻。

**14.6 下钻执行逻辑**

→ 将当前字段值写入 drill filter

→ currentLevelIndex + 1

→ 使用下一层字段重新构造查询

→ 图表刷新

示例：

当前配置：

L1: 省

L2: 市

L3: 区县

用户点击：

系统生成筛选：

省 = 山东

图表展示字段切换为：

用户继续点击：

市 = 青岛

筛选变为：

省 = 山东 AND 市 = 青岛

图表展示字段切换为：

区县

**16. VFormula 表达式 PRD**

**16.1 功能定位**

VFormula 是数字大屏中的轻量表达式语言，用于在文本、链接、属性、条件、变量、交互参数中嵌入动态内容。

形式：

普通文本 {{ expression }} 普通文本

示例：

共加载{{ $table.count }}项

{{ FORMAT($row.measure.sales,"3,2") }}

{{ CEIL($row.measure.sales/10000) }}万

**16.2 解析规则**

interface VFormulaResult {

value: any;

type: 'string' | 'number' | 'boolean' | 'object' | 'null';

}

规则：

1. VFormula 大小写敏感。
2. 表达式必须写在 {{ }} 中。
3. 一个文本中可以包含多个表达式。
4. 如果整个输入只有一个表达式，则返回表达式原始类型。
5. 如果输入中混合了普通文本和表达式，则最终返回 string。
6. 表达式解析失败时，返回空字符串，并在调试面板展示错误。
7. 不允许执行任意 JavaScript。
8. 只允许变量、运算符、对象访问、内置方法。

**16.3 数据类型**

| **类型** | **写法** | **说明** |
| --- | --- | --- |
| Text | "hello" | 双引号文本 |
| Number | 12、12.2 | 数字，小数计算最多保留 4 位 |
| Bool | true、false | 真值 |
| Object | $row.measure.sales | 通过对象索引访问 |

**16.4 运算符**

支持：

+ - \* / % > >= < <= == !=

优先级：

/ = % = \* > + = - > >= = == = != = > = < = <=

规则：

1. 同优先级从左到右。
2. 小括号提升优先级。
3. + 同时支持数字相加和文本拼接。
4. 对象不能作为最终展示结果，除非被 TEXT 转换。

**16.5 内置变量**

系统需要提供以下变量，同时为了兼容历史配置，可提供大小写别名。

| **变量** | **说明** |
| --- | --- |
| $Table / $table | 当前表格数据上下文 |
| $RowData / $row | 当前行数据上下文 |
| $Min / $min | 当前字段最小值 |
| $Max / $max | 当前字段最大值 |
| $Event / $event | 当前事件上下文 |

$RowData 示例：

$RowData.dimension.name

$RowData.measure.age

$Event 示例：

$Event.region

$Event.index

$Event.data

**17. 交互配置 PRD**

**17.1 功能定位**

交互配置采用：

事件 + 条件 + 响应

或：

事件 + 响应

当事件发生时，系统判断条件是否满足，满足后按顺序执行响应动作。

**17.2 交互模型**

interface InteractionConfig {

id: string;

actions: InteractionAction[];

enabled: boolean;

}

interface InteractionConditionGroup {

logic: 'and' | 'or';

rules: InteractionConditionRule[];

}

interface InteractionConditionRule {

left: string;

leftIsFormula: boolean;

operator:

| 'eq'

| 'neq'

| 'gt'

| 'gte'

| 'lt'

| 'lte'

| 'contains'

| 'notContains'

| 'isBlank'

| 'isNotBlank';

right?: string;

rightIsFormula: boolean;

}

**17.3 交互配置 UI**

右侧交互 Tab 中：

新建交互

→ 默认事件为“单击”

→ 用户切换事件类型

→ Hover 事件行显示“新增条件”

→ 用户添加任意数量规则

→ 用户点击“新增响应”

→ 选择响应类型

→ 配置响应参数

→ 保存

规则：

1. 不同组件展示不同事件列表。
2. 不支持的事件不展示。
3. 条件可为空。
4. 响应至少一个。
5. 多响应按配置顺序执行。
6. wait 响应会阻塞后续响应。
7. 某个响应失败时，默认继续执行后续响应，但调试面板记录错误。
8. 用户可禁用单条交互。

**19. 条件 PRD**

**19.1 条件组逻辑**

条件组支持：

| **逻辑** | **含义** |
| --- | --- |
| and | 所有规则满足 |
| or | 任意规则满足 |

执行：

事件触发

→ 构建事件上下文

→ 逐条计算条件规则

→ 根据 and/or 得出结果

→ true 执行响应

→ false 跳过响应

**19.2 条件表达式**

左右值均支持两种模式：

| **模式** | **说明** |
| --- | --- |
| 普通值 | 按字符串或数字常量处理 |
| FX 表达式 | 使用 VFormula 计算 |

示例：

Event.index > 3

RowData.measure.sales >= 10000

$Event.region == "山东"

**19.3 条件失败处理**

1. 表达式解析失败时，该条件规则返回 false。
2. 条件组为 and 时，任一 false 则整体 false。
3. 条件组为 or 时，至少一个 true 则整体 true。
4. 错误记录在调试面板，不弹窗打断用户。

→ 全局筛选

→ 组件静态筛选

→ 交互筛选

→ 联动筛选

→ 下钻筛选

→ 聚合计算

→ 排序

→ TopN

→ 参考线计算

→ 图表渲染

→ 触发数据更新完成事件

这样可以保证：

1. 图表联动结果影响参考线。
2. 下钻结果影响 TopN。
3. TopN 结果影响参考线。
4. 交互筛选不会破坏原始数据源。
5. 全局筛选优先于组件局部筛选。

**25. 异常处理**

**25.1 数据源异常**

| **异常** | **处理** |
| --- | --- |
| 数据源配置为空 | 阻止查询，提示配置缺失 |
| 数据集无权限 | 图表展示错误态 |
| API 请求失败 | 底部展示错误，图表保留旧数据 |
| API 跨域 | 提示使用代理或开启 CORS |
| JS 执行失败 | 展示脚本错误 |
| 表格解析失败 | 展示解析失败原因 |
| 字段缺失 | 对应字段配置标红 |
| 自动刷新失败 | 不停止后续刷新，但展示最近一次错误 |

**25.2 交互异常**

| **异常** | **处理** |
| --- | --- |
| 目标组件不存在 | 跳过响应 |
| 目标页面不存在 | 跳过响应 |
| VFormula 解析失败 | 当前响应不执行 |
| 筛选字段不存在 | 设置筛选项失败 |
| 事件循环过深 | 停止事件链 |
| wait 中组件销毁 | 取消后续响应 |
| UE 容器不存在 | 跳过响应 |

**26. 权限与发布态规则**

**26.1 编辑态**

1. 用户可查看完整数据源配置。
2. 用户可修改数据源参数。
3. 用户可点击查询调试。
4. 用户可查看返回数据。
5. 用户可查看错误详情。

**26.2 预览态**

1. 按保存后的数据源配置请求。
2. 按保存后的刷新策略运行。
3. 交互完整生效。
4. 不允许修改配置。
5. 错误只展示用户友好的摘要。

**26.3 发布态**

1. 不暴露敏感配置。
2. API 代理使用发布态代理接口。
3. 自动刷新正常生效。
4. 用户交互正常生效。
5. 无权限数据源展示错误态。
6. 不展示编辑器调试按钮。

**27. 验收标准**

**27.1 数据源验收**

1. 新建图表默认生成 Static 数据。
2. Static 表格支持粘贴、编辑、插入行列、删除行列。
3. Static 表头修改后字段配置不丢失。
4. Dataset 可选择已有数据集。
5. Dataset 支持字段拖拽到轴、分拆、值、筛选、排序、TopN。
6. API 支持 GET、POST。
7. POST 请求体必须校验 JSON。
8. API 支持请求头新增、删除、启用、停用。
9. API 支持 Transformer。
10. API 返回对象可解析为一行表格。
11. API 返回数组可解析为多行表格。
12. 数组字段不一致时必须报错。
13. JavaScript 支持同步返回数据。
14. JavaScript 支持异步返回数据。
15. JavaScript 超时必须报错。
16. 所有数据源支持只请求一次、自动更新、不自动请求。
17. 自动更新时间限制为 5-10000 秒。
18. 查询成功后可查看解析后的二维表。
19. 查询失败时底部展示错误信息。

**27.2 字段配置验收**

1. 字段自动识别维度和指标。
2. 字段可拖入轴、分拆、值、筛选、排序、TopN。
3. 值字段支持 count、sum、avg、max、min。
4. 筛选支持维度、指标、日期字段。
5. TopN 支持全部、头部、尾部。
6. 排序支持升序、降序、自定义排序。
7. 全局筛选可影响绑定组件。
8. 字段删除后相关配置自动清理。

**27.3 交互验收**

1. 右侧交互 Tab 可新建交互。
2. 不同组件展示不同事件。
3. 支持事件 + 响应。
4. 支持事件 + 条件 + 响应。
5. 条件支持 and/or。
6. 响应按顺序执行。
7. wait 响应可延迟后续响应。
8. 打开链接支持固定 URL 和表达式 URL。
9. 切换页面可切到指定大屏页面。
10. 设置元素属性可修改目标组件样式。
11. 切换面板状态可控制标签页、轮播器、重复器。
12. 变更轮播状态可播放、暂停、切换。
13. 设置筛选项可刷新目标图表。
14. 修改变量可触发依赖组件更新。
15. 刷新数据只刷新目标组件。
16. 刷新可视化内容刷新当前页面所有数据组件。
17. 引发事件可触发其他组件事件。
18. 事件链循环需要被限制。

**27.4 图元交互验收**

1. 表格支持行单击、行双击。
2. 柱状图、条形图支持柱形单击、双击。
3. 折线图、面积图支持节点单击、双击。
4. 饼图、环形图、玫瑰图、3D 环形图支持扇区单击、双击。
5. 词云支持文字单击、双击。
6. 散点图、圆视图支持气泡单击、双击。
7. 图元事件 payload 可访问字段区域和额外字段。
8. 图元交互可用于打开链接、设置筛选、联动、下钻。

**27.5 图表联动验收**

1. 图表可设置为筛选器。
2. 只能勾选同一数据集的目标图表。
3. 点击源图表数据项后，目标图表按对应字段筛选。
4. 删除联动后，目标图表恢复原状态。
5. 联动筛选不覆盖组件静态筛选，而是与其共同生效。

**27.6 下钻验收**

1. 支持在轴或分拆字段上配置下钻。
2. 支持多个字段形成 L1、L2、L3 层级。
3. 点击图元可进入下一层。
4. 返回可回到上一层。
5. 隐藏字段不展示，但可参与下钻路径。
6. 不支持下钻的图表不展示下钻入口。
7. 地图字段下钻只接收地理角色字段。
8. 3D 地球不支持字段下钻。

**27.7 参考线验收**

1. 支持新增多条参考线。
2. 支持修改参考线名称。
3. 支持计算值：平均值、最大值、最小值、求和。
4. 支持固定值。
5. 支持数据格式配置。
6. 支持线条颜色、粗细、线形。
7. 支持标签字体、颜色、位置、偏移。
8. 筛选、联动、下钻、TopN 后参考线重新计算。
