**A/B 测试-配置管理 PRD**

**1. 文档定位**

本文档定义 A/B 测试平台中的“配置管理”模块，核心对象为 Feature Flag。该模块用于将功能开关、动态配置、灰度发布、人群定向发布、实验固化、版本回滚、白名单测试、权限管理、发布历史与生命周期治理统一管理。

本 PRD 的目标不是描述功能清单，而是把每个页面、每个按钮、每个状态、每个交互逻辑、每个数据规则写到可以直接进入前端、后端、接口、状态机开发的程度。

**2. 产品目标**

配置管理模块解决以下问题：

1. 新功能已经开发完成，但不希望随代码部署立即对全量用户生效。
2. 产品或运营希望按人群、城市、系统、版本、用户分群等条件动态下发不同策略。
3. A/B 实验得出结论后，需要将优胜组快速固化为线上 Feature 并全量发布。
4. 发布过程中需要灰度、定时发布、定时下线、秒级回滚，降低线上风险。
5. 线上异常时，需要通过全局发布历史快速定位最近有哪些 Feature 发生变更。
6. Feature 长期使用后，需要通过生命周期管理识别冗余配置和潜在技术债。
7. 不同角色对 Feature 的查看、编辑、发布、权限管理范围需要隔离。

**3. 核心概念**

**3.1 Feature**

Feature 是一个可被业务代码读取的动态配置项，也可以理解为一个功能开关、业务参数、策略参数或功能配置。

每个 Feature 由唯一 key 标识。研发在代码中通过该 key 获取平台下发的配置值。

示例：

| **字段** | **示例** |
| --- | --- |
| Feature 名称 | APP 登录方式 |
| Feature Key | app\_login\_type |
| 业务含义 | 控制不同用户看到的登录方式 |
| 变体 1 | wechat，微信登录 |
| 变体 2 | qq，QQ 登录 |
| 变体 3 | douyin，抖音登录 |

**3.2 变体**

变体是 Feature 的具体取值。

一个 Feature 可以配置多个变体。运行时系统根据受众规则、灰度发布比例、白名单、实验优先级等逻辑，向用户下发某个变体值。

支持的变体类型：

| **类型** | **说明** |
| --- | --- |
| boolean | 仅支持 true、false 两个变体 |
| string | 字符串类型 |
| number | 数值类型，整数位最多 10 位，小数位最多 5 位 |
| json | JSON 类型，支持多层嵌套，必须符合 JSON 规范 |

**3.3 发布受众**

发布受众是 Feature 生效规则。

系统按照 if / else 逻辑判断用户应该命中哪个规则、下发哪个变体。

基本规则：

1. 自定义受众规则为 if 规则。
2. 最终默认规则为 else 规则。
3. 多个 if 规则自上而下判断。
4. 用户命中第一条 if 规则后，不再继续判断后续规则。
5. 未命中任何 if 规则时，进入 else 默认规则。
6. 每条规则内部可以包含多个过滤条件，多个条件之间为“且”关系。
7. 多条受众规则之间为“或”关系，但不是同时生效，而是按顺序取第一条命中规则。

**3.4 Feature 与 A/B 实验关系**

A/B 实验和 Feature Flag 共用参数接入能力，但用途不同。

| **对象** | **用途** |
| --- | --- |
| A/B 实验 | 用于验证不同版本或策略的效果 |
| Feature Flag | 用于动态配置、灰度发布、人群定向发布、实验结果全量 |

同一个参数既存在运行中的实验，又存在已发布的 Feature 时，线上生效优先级为：

白名单测试 > A/B 实验 > Feature Flag > 本地默认值

说明：

1. 白名单测试用于 QA 或指定用户验证，允许在未发布 Feature 的情况下强制命中测试配置。
2. A/B 实验优先于 Feature，用于保证实验期间样本和策略不被 Feature 全量配置干扰。
3. Feature 仅对未命中实验、未命中白名单的用户生效。
4. 如果 Feature 关闭或未发布，则客户端或服务端使用本地默认值。

Feature 列表页用于集中管理当前应用下所有 Feature，支持创建、搜索、筛选、查看状态、进入详情、创建关联实验、权限管理、查看发布历史。

**5.3 页面布局**

顶部操作区

**5.4 顶部操作区**

**5.4.1 “+ 创建 Feature”按钮**

位置：页面右上角。

显示条件：

| **条件** | **说明** |
| --- | --- |
| 用户具备 Feature 协作者权限 | 显示并可点击 |
| 用户仅具备查看权限 | 按钮隐藏或置灰 |
| 当前未选择应用 | 按钮置灰 |

点击逻辑：

1. 点击后进入“创建 Feature 页面”。
2. 页面默认进入手动创建流程。
3. 如果当前只选择了一个 App，则创建页自动带入该 App。
4. 如果用户有多个 App 权限，创建页要求选择适用 App。
5. 如果用户无创建权限，点击时提示：

你暂无新建 Feature 权限，请联系管理员开通协作者权限。

**5.4.2 “创建关联实验”按钮**

位置：Feature 列表表格操作列，或 Feature 行内操作菜单。

显示条件：

1. 用户具备 Feature 协作者权限。
2. 当前 Feature 未被删除。
3. 当前 Feature 至少存在一个可用版本。
4. 当前用户具备实验创建权限。

点击逻辑：

1. 打开“创建关联实验”流程。
2. 系统将当前 Feature 的 key、变体类型、变体值带入实验参数配置。
3. 后续流程复用实验创建流程。
4. 创建完成后，实验与 Feature 建立关联关系。
5. 如果当前 Feature 已存在运行中的关联实验，则弹窗提示：

当前 Feature 已有关联实验正在运行，继续创建可能造成策略冲突。是否继续？

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 继续创建 | 进入创建实验流程 |
| 取消 | 关闭弹窗 |

**5.4.3 “发布历史”入口**

位置：左侧导航二级菜单，或 Feature 列表顶部快捷入口。

点击逻辑：

1. 跳转至“发布历史页”。
2. 默认筛选当前 App 下全部 Feature 发布操作。
3. 如果从某个 Feature 行点击进入，则自动带入该 Feature 的 key 作为筛选条件。

筛选项包括：

| 终端类型 | 多选 | 客户端、服务端 |
| 标签 | 多选 | 按 Feature 标签筛选 |
| Owner | 人员选择器 | 按负责人筛选 |
| 名称 / Key 搜索 | 输入框 | 支持 Feature 名称、key、标签模糊搜索 |
| 重置 | 按钮 | 清空筛选 |
| 查询 | 按钮 | 按当前条件刷新列表 |

搜索规则：

2. 标签搜索支持精确匹配。

4. 多个状态值之间为 OR。
5. 点击“查询”后刷新表格。

**5.7 表格操作列**

**5.7.1 “查看”**

点击后进入 Feature 详情页。

如果用户无查看权限，不展示该 Feature。

**5.7.2 “编辑”**

显示条件：

1. 用户具备协作者权限。
2. Feature 未被删除。
3. 当前 Feature 未被禁用。
4. 如果 Feature 正在发布确认中，编辑按钮置灰。

1. 跳转到 Feature 编辑页面。
2. key 不可编辑。
3. 修改变体、发布受众、生效规则等核心信息后，保存会生成新版本。
4. 新版本默认未发布，需要发布后才会线上生效。

**5.7.3 “创建实验”**

逻辑同“创建关联实验”。

**5.7.4 “白名单”**

**5.7.5 “发布 / 回滚”**

按钮名称根据当前状态变化。

| **当前发布状态** | **按钮** |
| --- | --- |
| 未发布 | 发布 |
| 灰度中 | 发布 / 回滚 |
| 发布确认 | 发布确认 / 回滚 |

显示条件：

2. Feature 未被删除。

点击后打开权限管理弹窗，可设置公共 Feature 或私有 Feature。

**5.7.7 “删除”**

显示条件：

1. 用户具备协作者权限。
2. Feature 开关状态为关闭。
3. 当前 Feature 不存在运行中的实验关联。
4. 当前 Feature 不存在灰度中或待发布的版本。

点击后弹出二次确认：

确认删除 Feature「{Feature名称}」吗？删除后不可恢复，代码中继续读取该 key 时将使用本地默认值。

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 确认删除 | 执行删除 |
| 取消 | 关闭弹窗 |

删除后：

1. Feature 从列表中移除。
2. 已产生的发布历史和操作日志保留。
3. Runtime 不再下发该 Feature。
4. SDK 获取该 key 时返回本地默认值或空值。

**6. 创建 Feature 页面 PRD**

**6.1 页面入口**

配置管理 > Feature 列表 > + 创建 Feature

**6.2 页面目标**

支持用户手动创建一个 Feature，并完成基本信息、适用 App、变量、变体、发布受众、示例代码配置。

**6.3 页面结构**

创建页面采用分区表单。

1. 基本信息

2. 适用 App

3. 自定义变量

4. 设置变体

5. 发布受众

6. 示例代码

底部操作按钮

页面右侧固定展示“字段说明”帮助区域，点击某字段时右侧自动滚动至对应说明。

**6.4 基本信息区**

字段如下：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| Key 名称 | 是 | Feature 的唯一 key，创建后不可修改 |
| Feature 名称 | 是 | 用于业务识别 |
| Feature 描述 | 否 | 说明该 Feature 的用途 |
| 上传配图 | 否 | 上传功能截图、页面截图或配置说明图 |
| 标签 | 否 | 用于分类和搜索 |
| Owners | 是 | Feature 负责人 |
| 终端类型 | 是 | 客户端 / 服务端 |

**6.4.1 Key 名称**

输入规则：

| **规则** | **说明** |
| --- | --- |
| 唯一性 | 全局唯一 |
| 支持字符 | 英文字符、数字、下划线 |
| 长度 | 最长 200 字符 |
| 创建后 | 不允许修改 |

校验触发：

1. 输入框失焦时校验格式。
2. 点击保存时再次校验唯一性。
3. 后端最终校验唯一性，避免并发创建重复 key。

错误提示：

| **场景** | **提示** |
| --- | --- |
| 为空 | 请输入 Key 名称 |
| 包含非法字符 | Key 仅支持英文字符、数字、下划线 |
| 超长 | Key 最长不超过 200 个字符 |
| 重复 | 当前 Key 已存在，请更换后重试 |

**6.4.2 Feature 名称**

输入规则：

| **规则** | **说明** |
| --- | --- |
| 唯一性 | 全局唯一 |
| 支持字符 | 中英文、数字、下划线 |
| 长度 | 最长 100 字符 |
| 特殊符号 | 不允许特殊符号 |

错误提示：

| **场景** | **提示** |
| --- | --- |
| 为空 | 请输入 Feature 名称 |
| 重复 | Feature 名称已存在 |
| 超长 | Feature 名称最长不超过 100 个字符 |
| 特殊符号 | Feature 名称不支持特殊符号 |

**6.4.3 Feature 描述**

输入规则：

| **规则** | **说明** |

**6.4.5 标签**

交互规则：

1. 支持选择已有标签。
2. 支持输入新标签。
3. 最多添加 10 个标签。
4. 每个标签最长 20 字符。
5. 标签去重，大小写不敏感。
6. 输入后按 Enter 创建标签。
7. 点击标签右侧 x 删除。

错误提示：

| **场景** | **提示** |
| --- | --- |
| 超过 10 个 | 最多添加 10 个标签 |
| 标签超长 | 单个标签最长 20 个字符 |
| 标签重复 | 标签已存在 |

**6.4.6 Owners**

默认值：

当前创建人自动成为 Owner

交互：

1. 点击人员选择框打开人员选择器。
2. 支持搜索用户名、邮箱、工号。
3. 支持多选。
4. 至少保留 1 个 Owner。
5. 当前创建人可以被移除，但必须保证仍有其他 Owner。

Owner 权限：

1. 默认拥有该 Feature 协作者权限。
2. 可编辑 Feature。
3. 可发布、回滚、关闭 Feature。
4. 可管理 Feature 权限。

**6.4.7 终端类型**

选项：

| **类型** | **使用场景** |
| --- | --- |
| 客户端 | 客户端交互、UI 样式、按钮展示、页面逻辑 |
| 服务端 | 服务端算法、推荐策略、内容分发、后端业务逻辑 |

创建后是否可修改：

不可修改。

原因：

1. 客户端和服务端 SDK 获取链路不同。
2. 修改终端类型会导致代码接入方式变化。
3. 为避免线上风险，终端类型创建后锁定。

| 描述 | 否 | 变量业务含义 |
| 是否必传 | 是 | SDK 请求时是否必须传入 |
| 默认值 | 否 | 未传入时使用的默认值 |

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 添加变量 | 新增变量行 |
| 删除变量 | 删除当前变量 |
| 编辑变量 | 修改当前变量 |
| 上移 / 下移 | 调整变量展示顺序 |

校验规则：

1. 变量 Key 在当前 Feature 内唯一。
2. 变量 Key 支持英文、数字、下划线。
3. 必传变量未传入时，运行时不能命中依赖该变量的规则。
4. 变量删除前，如果发布受众规则正在引用该变量，需要弹窗提示：

该变量已被发布受众规则引用，删除后相关条件将失效。是否继续删除？

点击“继续删除”后：

1. 删除变量。
2. 自动删除引用该变量的条件。
3. 规则如果无剩余条件，则标记为无效，需要用户重新配置。

**6.7 设置变体区**

**6.7.1 变体类型**

显示条件：

| **状态** | **说明** |

| **类型** | **校验项** |

**6.7.3 变体列表**

每个变体包含：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| 变体名称 | 是 | 便于业务识别 |
| 变体值 | 是 | 实际下发值 |
| 变体描述 | 否 | 说明该变体含义 |
| 上传配图 | 否 | 展示该变体对应 UI 或策略效果 |

**boolean 类型**

默认生成两个变体：

| **变体名称** | **变体值** |
| --- | --- |
| True | true |
| False | false |

规则：

1. 不允许新增第三个 boolean 变体。
2. 允许修改变体名称和描述。
3. 不允许修改 true / false 实际值。

**string 类型**

规则：

1. 变体值不能为空。
2. 变体值可重复性：不允许重复。
3. 支持中英文、数字、符号，最终以字符串原样下发。
4. 如果开启枚举校验，则变体值必须在枚举范围内。

**number 类型**

规则：

1. 变体值必须为合法数字。
2. 整数位最多 10 位。
3. 小数位最多 5 位。
4. 如果开启最小值、最大值校验，必须在范围内。
5. 如果关闭负数，不能输入小于 0 的数字。

**json 类型**

规则：

1. 变体值必须是合法 JSON。
2. 支持多层嵌套。
3. 如果配置 JSON Schema，必须通过 schema 校验。
4. 页面提供 JSON 格式化按钮。
5. 格式化失败时，定位到错误行并提示：

JSON 格式错误，请检查第 {line} 行附近内容。

按钮名称：

+ 添加变体

显示规则：

| **类型** | **显示逻辑** |
| --- | --- |
| boolean | 隐藏或置灰 |
| string / number / json | 显示 |

点击逻辑：

1. 在变体列表末尾新增一个空变体卡片。
2. 自动聚焦变体名称输入框。
3. 新增后必须填写名称和值才能保存。

**6.7.5 删除变体按钮**

显示位置：每个变体卡片右侧。

删除限制：

1. 至少保留 1 个变体。
2. 如果该变体已被发布受众规则引用，需要二次确认。
3. 如果该变体是当前线上生效版本中的唯一变体，不允许删除。
4. boolean 类型变体不允许删除。

二次确认文案：

该变体已被发布受众规则引用，删除后相关规则将变为无效。确认删除吗？

删除后：

1. 变体从列表移除。
2. 引用该变体的发布受众规则标记为“未配置发布范围”。
3. 保存前必须重新配置这些规则。

**6.8 发布受众区**

**6.8.1 区域结构**

发布受众区分为：

if 自定义受众规则

else 最终默认规则

每条 if 规则由两部分组成：

过滤条件

发布范围

**6.8.2 添加受众规则**

按钮：

+ 添加受众规则

点击后：

1. 在当前规则列表末尾新增一条规则。
2. 新规则默认无过滤条件。
3. 发布范围默认为“不下发参数值”。
4. 规则标题自动命名为“规则 N”。

规则顺序：

1. 规则按页面顺序自上而下判断。
2. 支持拖拽排序。
3. 支持上移、下移按钮。
4. 排序改变后，需要保存新版本才生效。

**6.8.3 过滤条件**

每条规则可以添加多个过滤条件。

字段：

| **字段** | **说明** |
| --- | --- |
| 属性来源 | 用户属性、设备属性、事件属性、自定义变量、用户分群 |
| 属性名称 | 选择具体字段 |
| 操作符 | 等于、不等于、包含、不包含、大于、小于、为空、不为空、属于分群、不属于分群 |
| 属性值 | 根据属性类型展示输入框、数值框、日期框、多选框 |

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 添加过滤条件 | 在当前规则下新增条件 |
| 删除条件 | 删除当前条件 |
| 清空条件 | 清空当前规则所有条件 |

逻辑：

1. 同一规则内多个条件之间为 AND。
2. 条件未配置完整时，规则状态显示“未完成”。
3. 未完成规则不允许保存并发布。
4. 可保存草稿，但草稿版本不可发布。

**6.8.4 发布范围**

每条规则的发布范围支持三种类型：

| **发布范围** | **说明** |
| --- | --- |
| 某个变体 | 命中该规则的用户全部下发一个变体 |
| 多变体 | 命中该规则的用户按比例随机下发多个变体 |
| 不下发参数值 | 命中该规则的用户不下发 Feature 值，使用本地默认值 |

**某个变体**

字段：

| **字段** | **说明** |
| --- | --- |
| 变体选择 | 从已配置变体中选择一个 |

运行逻辑：

用户命中该规则后，100% 下发该变体值。

**多变体**

字段：

| **字段** | **说明** |
| --- | --- |
| 变体 | 选择多个变体 |
| 流量比例 | 每个变体对应比例 |
| 总比例 | 必须等于 100% |

校验：

| **场景** | **提示** |
| --- | --- |
| 总比例小于 100% | 多变体流量比例总和必须等于 100% |
| 总比例大于 100% | 多变体流量比例总和不能超过 100% |
| 某变体比例为 0 | 该变体比例不能为 0 |
| 未选择变体 | 请至少选择两个变体 |

分流规则：

1. 系统使用稳定哈希分流。
2. 哈希因子包含 appId + featureKey + versionId + ruleId + userId。
3. 同一用户在同一版本同一规则下多次请求，应稳定命中同一变体。
4. 发布版本变化后，因 versionId 改变，用户可能重新分桶。

**不下发参数值**

运行逻辑：

1. 用户命中该规则。
2. Runtime 不返回 Feature 值。
3. 客户端或服务端使用本地默认值。
4. 返回结果中标记 decisionReason = no\_value\_by\_rule，便于调试。

**6.8.5 else 最终默认规则**

else 规则必须存在，不允许删除。

发布范围支持：

1. 某个变体。
2. 不下发参数值。

默认值：

不下发参数值

如果用户未配置任何 if 规则，所有用户进入 else 规则。

**7. 实验固化至 Feature PRD**

**7.1 功能目标**

实验固化至 Feature 用于把实验参数转化为可长期管理和发布的 Feature。

常见场景：

1. 实验已有结论，需要将优胜组全量上线。
2. 实验尚未得出明确结论，但该功能后续仍需以 Feature 形式继续管理。
3. 实验中的多个参数需要沉淀为长期配置项。
4. 实验结束后，希望复用实验参数创建后续灰度发布能力。

**7.2 入口**

入口 1：

实验详情页 > 右侧操作区 > 固化至 Feature

入口 2：

配置管理 > Feature 列表 > 创建关联实验

**7.3 固化流程**

页面采用三步：

1. 选择全量组

2. 确认 Feature 信息

3. 发布 Feature

**7.4 第一步：选择全量组**

字段：

| **字段** | **说明** |
| --- | --- |
| 实验名称 | 只读 |
| 实验参数 | 展示当前实验涉及的参数 |
| 实验分组 | 展示对照组、实验组 |
| 选择全量分组 | 选择要固化的实验分组 |
| 固化方式 | 单组固化 / 多组按流量比例固化 |

**7.4.1 单组固化**

用户选择一个实验分组后：

1. 左侧展示该组的 A/B 参数信息，只读。
2. 右侧生成 Feature 信息，可编辑。
3. Feature 默认发布范围为该分组对应变体 100%。
4. else 默认规则根据用户配置，可为同一变体或不下发参数值。

**7.4.2 多组按流量比例固化**

显示条件：

实验中至少有两个分组。

用户选择多个分组后：

1. 系统读取实验原始流量比例。
2. 生成 Feature 多变体发布规则。
3. 每个实验分组对应一个 Feature 变体。
4. 默认比例等于实验流量比例。
5. 用户可手动调整比例，但总和必须等于 100%。

示例：

| **实验分组** | **实验流量** | **Feature 变体比例** |
| --- | --- | --- |
| 实验组 A | 30% | 30% |
| 实验组 B | 70% | 70% |

**7.4.3 实验与 Feature 冲突说明**

页面必须展示提示：

实验和 Feature 是两个独立对象，可同时存在。若同一个参数既有实验运行中，又有 Feature 已发布，线上生效优先级为：实验 > Feature。

示例逻辑：

实验占用 20% 流量，Feature 全量发布到 100%。

命中实验的 20% 用户仍按实验策略生效。

未命中实验的 80% 用户按 Feature 策略生效。

**7.5 第二步：确认 Feature 信息**

页面结构：

左侧：实验参数信息，只读

右侧：Feature 信息，可编辑

可编辑内容：

| **内容** | **说明** |
| --- | --- |
| Feature 名称 | 默认根据实验名称生成 |
| Feature Key | 默认根据实验参数 key 生成，需唯一 |
| 描述 | 默认带入实验描述 |
| 标签 | 可编辑 |
| Owner | 默认实验创建人和当前操作人 |
| 变体名称 | 可编辑 |
| 变体值 | 默认带入实验参数值 |
| 发布受众 | 可编辑 |
| 默认规则 | 可编辑 |

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 上一步 | 返回选择全量组 |
| 下一步 | 校验当前信息，进入发布 |
| 取消 | 退出固化流程 |

**7.6 第三步：发布 Feature**

进入标准 Feature 发布流程。

发布前展示：

1. 本次固化来源实验。
2. 固化实验分组。
3. Feature key。
4. 变体映射关系。
5. 生效受众。
6. 与实验冲突优先级提示。

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 提交发布 | 创建 Feature 版本并进入发布计划 |
| 返回修改 | 回到第二步 |
| 取消 | 放弃固化 |

**10.4.1 手动发布**

字段：

| **字段** | **说明** |
| --- | --- |
| 初始发布流量 | 本次发布开始时流量 |
| 是否定时下线 | 是否在指定时间自动回滚 |

规则：

1. 初始发布流量最小 1%，最大 100%。

3. 初始发布流量小于 100% 时，状态为灰度中。
4. 如果开启定时下线，到时自动回滚。
5. 如果无上一个全量版本，回滚后关闭 Feature，使用本地默认值。

字段：

| **字段** | **必填** | **说明** |
| --- | --- | --- |
| 首次发布时间 | 是 | 自动发布开始时间 |
| 发布频率 | 是 | 每次扩量间隔 |
| 每次增加流量 | 是 | 每次扩量比例 |
| 目标流量 | 是 | 最终发布到多少流量，默认 100% |
| 一键设置 | 否 | 自动生成发布计划 |
| 发布计划列表 | 是 | 每次发布时间和流量 |

“一键设置”逻辑：

用户输入：

1. 首次发布时间。
2. 发布频率。
3. 每次增加流量。
4. 目标流量。

点击“一键设置”后：

1. 系统生成多条发布计划。
2. 最后一条流量必须等于目标流量。
3. 用户可手动调整每条计划的时间和流量。
4. 调整后系统重新校验流量递增。

发布计划校验：

| **校验** | **说明** |
| --- | --- |
| 时间递增 | 每条发布时间必须晚于上一条 |
| 流量递增 | 每条流量必须大于上一条 |
| 流量范围 | 1%-100% |
| 最后一条 | 必须等于目标流量 |
| 不能早于当前时间 | 首次发布时间必须晚于当前时间 |

**10.5 发布流量运行逻辑**

当新版本发布流量未达到 100% 时：

1. 系统先通过稳定哈希判断用户是否进入新版本发布流量。
2. 命中新版本发布流量的用户，按新版本发布受众规则决策。
3. 未命中新版本发布流量的用户：
   * 如果存在上一个已全量版本，则按上一个全量版本规则决策。
   * 如果不存在上一个全量版本，则不下发参数值，使用本地默认值。

发布流量哈希因子：

appId + featureKey + targetVersionId + userId

同一用户在同一版本发布阶段应稳定命中。

| --- | --- |
| 手动发布 100% | 版本状态变为已全量 |
| 手动发布 <100% | 版本状态变为灰度中 |
| 定时自动发布未到开始时间 | 版本状态变为待发布 |
| 定时自动发布已到开始时间 | 按计划进入灰度中 |

Feature 权限分为两类：

| **权限** | **能力** |
| --- | --- |
| 查看权限 | 查看 Feature 列表、详情、操作历史 |
| 协作者权限 | 新建、编辑、发布、回滚、关闭、关联实验、删除、权限管理 |

**13.2 角色权限**

预置角色：

| **角色** | **权限** |
| --- | --- |
| 集团管理员 | 查看权限、协作者权限 |
| 应用管理员 | 查看权限、协作者权限 |
| Feature 创建者 | 查看权限、协作者权限 |
| 普通用户 | 默认仅查看公共 Feature |
| 无权限用户 | 不可见 |

**13.3 操作权限矩阵**

| **操作** | **查看权限** | **协作者权限** |
| --- | --- | --- |
| 查看 Feature 列表 | 支持 | 支持 |
| 查看 Feature 详情 | 支持 | 支持 |
| 查看操作历史 | 支持 | 支持 |
| 查看发布历史 | 支持 | 支持 |
| 新建 Feature | 不支持 | 支持 |
| 编辑 Feature | 不支持 | 支持 |
| 发布 Feature | 不支持 | 支持 |

| 关闭 Feature | 不支持 | 支持 |
| 创建关联实验 | 不支持 | 支持 |

| 删除 Feature | 不支持 | 支持 |

**13.4 公共 Feature 与私有 Feature**

Feature 类型：

| **类型** | **说明** |
| --- | --- |
| 公共 Feature | 当前应用下有访问权限的普通用户可查看 |
| 私有 Feature | 仅集团管理员、应用管理员、Feature 创建者、Owner 可见 |

默认规则：

新创建的 Feature 默认为公共 Feature。

权限关系：

| **类型** | **集团管理员** | **应用管理员** | **Feature 创建者 / Owner** | **普通用户** |
| --- | --- | --- | --- | --- |
| 公共 Feature | 协作者权限 | 协作者权限 | 协作者权限 | 查看权限 |
| 私有 Feature | 协作者权限 | 协作者权限 | 协作者权限 | 不可见 |

**13.5 权限管理弹窗**

入口：

Feature 列表 > 操作 > 权限管理

Feature 详情页 > 权限设置

弹窗字段：

| **字段** | **说明** |
| --- | --- |
| Feature 类型 | 公共 Feature / 私有 Feature |
| 当前权限说明 | 根据选择类型展示解释 |
| 确定 | 保存设置 |
| 取消 | 关闭弹窗 |

切换为私有 Feature 时提示：

切换为私有 Feature 后，普通用户将无法在列表和详情中看到该 Feature。确认切换吗？

切换为公共 Feature 时提示：

切换为公共 Feature 后，当前应用下有访问权限的用户将可查看该 Feature。确认切换吗？

**14. Runtime 决策逻辑**

当业务代码请求 Feature 值时，服务端或 SDK 按以下顺序决策。

1. 判断 Feature 是否存在

2. 判断是否命中有效白名单测试

3. 判断是否命中运行中的 A/B 实验

4. 判断 Feature 是否开启

5. 判断是否存在可生效发布版本

6. 判断发布流量是否命中新版本

7. 按受众规则自上而下匹配

8. 命中规则后按发布范围返回变体值

9. 未命中规则进入 else 默认规则

10. 仍无值则返回本地默认值

**17. 状态机**

**17.1 Feature 开关状态**

enabled 开启

disabled 关闭

deleted 已删除

状态变化：

enabled -> disabled

disabled -> enabled

disabled -> deleted

删除限制：

enabled 状态不可删除。

**17.2 发布状态**

unpublished 未发布

pending\_publish 待发布

gray 灰度中

publish\_confirm 发布确认

full 已全量

rolled\_back 已回滚

disabled 已禁用

状态变化：

unpublished -> pending\_publish

unpublished -> gray

unpublished -> full

pending\_publish -> gray

pending\_publish -> canceled

gray -> full

gray -> rolled\_back

publish\_confirm -> gray

publish\_confirm -> rolled\_back

full -> rolled\_back

unpublished -> disabled

rolled\_back -> disabled

**18. 异常与边界场景**

| **场景** | **处理** |
| --- | --- |
| Feature Key 重复 | 创建失败，提示 key 已存在 |
| 编辑时线上版本变化 | 保存前提示当前 Feature 已被他人修改，请刷新后重试 |
| 发布计划时间早于当前 | 不允许提交 |
| 定时发布执行失败 | 状态标记失败，通知 Owner |
| 回滚无历史全量版本 | 关闭 Feature，使用本地默认值 |
| 白名单过期 | 自动失效 |
| 私有 Feature 普通用户访问 URL | 返回无权限页面 |
| Feature 关闭后 SDK 请求 | 返回本地默认值 |
| 删除 Feature 后 SDK 请求 | 返回本地默认值 |
| 多变体比例不等于 100% | 不允许保存并发布 |
| JSON 变体格式错误 | 不允许保存 |
| 参数校验规则变化导致旧变体不合法 | 保存时阻断，要求修正变体值 |

**19. 验收标准**

**19.1 Feature 列表**

1. 用户可以按应用、状态、标签、Owner、名称、Key 筛选 Feature。
2. 无权限用户看不到私有 Feature。
3. 点击 Feature 名称可进入详情。
4. 协作者可创建、编辑、发布、回滚、删除、权限管理。
5. 查看权限用户只能查看，不能执行写操作。

**19.2 创建 Feature**

1. Key 必须全局唯一，创建后不可修改。
2. Feature 名称必须全局唯一。
3. boolean、string、number、json 四种变体类型必须按规则校验。
4. 发布受众必须按 if / else 逻辑配置。
5. 多条 if 规则必须按顺序匹配，命中第一条后停止。
6. else 默认规则必须存在。
7. 保存草稿不影响线上。
8. 保存并发布必须进入发布流程。

**19.3 实验固化**

1. 可以从实验详情页固化 Feature。
2. 可以选择单个实验分组固化。
3. 可以选择多个实验分组按流量比例固化。
4. 固化生成的 Feature 信息可编辑。
5. 页面必须展示实验优先级高于 Feature 的提示。
6. 固化后必须通过发布流程才线上生效。

**19.4 白名单测试**

1. 白名单无需发布即可生效。
2. 白名单失效时间最多 7 天。
3. 白名单用户不能在同一测试内重复出现在多个规则。
4. 提交后约 1 分钟内生效。
5. 过期或终止后不再影响 Feature 决策。

**19.5 发布与回滚**

1. 支持手动发布。
2. 支持定时自动发布。
3. 支持一键生成灰度发布计划。
4. 发布流量未达 100% 时状态为灰度中。
5. 发布流量达到 100% 时状态为已全量。
6. 灰度中和已全量版本可以回滚。
7. 回滚后优先恢复上一个已全量版本。
8. 无历史全量版本时，回滚后关闭 Feature。
9. 已回滚版本不能直接再次发布。

**19.6 版本管理**

1. 每次核心配置变更都必须生成新版本。
2. 未发布版本不影响线上。
3. 禁用版本不可编辑、不可发布、不可恢复。
4. 版本详情必须展示基本信息、变体、发布受众、代码、版本差异。
5. Feature 关闭后所有流量使用本地默认值。

**19.7 发布历史**

1. 发布、回滚、取消发布、关闭 Feature 都必须进入发布历史。
2. 支持按应用、状态、时间、名称、key、标签筛选。
3. 支持查看发布详情和版本差异。
4. 发布历史不可删除。

**19.8 生命周期**

1. 生命周期 Timeline 必须展示创建、编辑、发布、开启实验、回滚等关键事件。
2. 操作时间精确到分钟。
3. 展示操作人。
4. 展示最近一次变更时间。
5. 展示 Feature 使用趋势和变体使用占比。
6. 对长期无使用 Feature 给出清理提示。

**19.9 权限管理**

1. 支持查看权限和协作者权限。
2. 公共 Feature 对普通用户可见。
3. 私有 Feature 对普通用户不可见。
4. 只有协作者可修改 Feature 类型。
5. 无权限访问 Feature URL 时必须展示无权限页面。
