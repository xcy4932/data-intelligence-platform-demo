**数据脱敏 PRD**

**1. 产品定位**

**1.1 功能目标**

数据脱敏用于对数据集中包含敏感信息的字段进行掩码、模糊化、变形展示，降低敏感数据在分析、看板、下载、订阅、嵌出、监控等场景中的泄露风险。

本模块需要解决以下问题：

1. 数据集创建或编辑时，必须明确该数据集是否涉敏。
2. 涉敏数据集必须配置敏感字段和脱敏规则。
3. 不同字段可使用不同脱敏规则。
4. 脱敏规则可以是系统预设规则，也可以是用户自定义规则。
5. 脱敏规则可以配置生效范围，即哪些用户看到脱敏值，哪些用户看到原始值。
6. 脱敏后的字段在可视化查询、仪表盘、下载、导出、订阅、监控、嵌出等场景中必须统一生效。
7. 涉敏字段在分析能力上需要受到限制，避免通过字段别名、分组、格式化、计算字段等方式绕过脱敏。
8. 关联数据集需要继承子数据集的脱敏规则。
9. 可视化建模输出的新数据集不自动继承输入数据集脱敏配置，需要重新定级和配置。
10. 数据脱敏必须和数据行列权限、资源权限、数据集列表状态、数据集详情状态联动。

**2.1 本 PRD 覆盖范围**

**3. 用户角色与权限**

**3.1 用户角色**

| **角色** | **说明** | **数据脱敏能力** |
| --- | --- | --- |
| 项目管理员 | 管理项目内全部数据集和权限 | 可查看和配置全部数据集脱敏 |
| 数据集创建者 | 创建数据集的人 | 可对自己创建的数据集进行涉敏定级和脱敏配置 |
| 数据集所有者 | 当前数据集 Owner | 可编辑数据集脱敏配置 |
| 数据集管理员 | 拥有该数据集管理权限的人 | 可配置脱敏字段、规则和生效范围 |
| 数据集使用者 | 有数据集查看或使用权限的人 | 使用数据时按规则看到脱敏或原始值 |
| 仪表盘查看者 | 查看基于数据集制作的仪表盘的人 | 只能看到权限规则处理后的展示值 |
| 普通访客 | 仅有查看权限 | 无法修改脱敏配置 |

**3.2 权限模型**

type DesensitizationPermission = {

canViewMaskingConfig: boolean;

canEditSensitivityLevel: boolean;

canAddMaskingField: boolean;

canRemoveMaskingField: boolean;

canEditMaskingRule: boolean;

canEditEffectiveScope: boolean;

canPreviewMaskedData: boolean;

canViewOriginalValue: boolean;

};

**3.2.1 权限计算规则**

用户进入数据集详情

→ 后端根据用户角色、数据集资源权限、所有者关系计算脱敏权限

→ 返回 DesensitizationPermission

→ 前端根据权限控制按钮显示、置灰和可编辑状态

**3.2.2 原始值查看权限**

用户能否看到原始值由两层共同决定：

第一层：数据集资源权限

第二层：脱敏生效范围

规则：

1. 没有数据集查看权限时，用户不能访问数据。
2. 有数据集查看权限，但命中脱敏规则控制范围时，只能看到脱敏值。
3. 有数据集查看权限，且未命中脱敏规则控制范围时，可以看到原始值。
4. 数据集管理员是否默认可看原始值由产品配置决定，建议默认不豁免，必须由生效范围明确控制。
5. 后端不能只依赖前端判断，所有查询、下载、订阅、导出接口都必须执行脱敏计算。

**4. 核心状态模型**

**4.1 数据集涉敏状态**

数据集需要新增字段：

type DatasetSensitivityStatus =

| "unclassified"

| "sensitive\_unmasked"

| "sensitive\_masked"

| "non\_sensitive";

| **状态** | **中文** | **含义** |
| --- | --- | --- |
| unclassified | 未定级 | 数据集尚未判断是否涉敏 |
| sensitive\_unmasked | 涉敏未脱敏 | 数据集已标记涉敏，但未完成脱敏字段和规则配置 |
| sensitive\_masked | 涉敏已脱敏 | 数据集已标记涉敏，并完成至少一个脱敏字段和规则配置 |
| non\_sensitive | 不涉敏 | 数据集明确不包含敏感字段 |

**4.2 状态流转**

新建数据集保存

→ 必须选择：涉敏 / 不涉敏

选择不涉敏

→ non\_sensitive

选择涉敏

→ sensitive\_unmasked

→ 添加脱敏字段并配置规则

→ sensitive\_masked

存量数据集启用脱敏模块后

→ unclassified

→ 数据集所有者或管理员完成定级

**4.3 状态流转规则**

**4.3.1 新建数据集**

用户点击保存数据集

→ 系统检查是否已选择涉敏等级

→ 未选择

→ 阻止保存

→ 提示必须完成涉敏定级

→ 选择不涉敏

→ 保存数据集

→ sensitivityStatus = non\_sensitive

→ 选择涉敏

→ 保存数据集

→ sensitivityStatus = sensitive\_unmasked

→ 详情页展示异常提醒

→ 引导用户进入数据脱敏页签配置规则

**4.3.2 存量数据集**

当系统新增数据脱敏模块后，历史数据集默认进入：

sensitivityStatus = unclassified

页面表现：

1. 左侧数据集目录显示未定级图标。
2. 数据集列表显示未定级状态。
3. 数据集详情标题后显示未定级标识。
4. 数据脱敏页签展示提示：当前数据集尚未完成涉敏定级，请先判断是否涉敏。
5. 若系统要求强制治理，可限制未定级数据集进入下载、导出、订阅等功能。

**4.3.3 涉敏未脱敏**

如果数据集标记为涉敏，但没有配置脱敏字段或字段规则不完整：

sensitivityStatus = sensitive\_unmasked

页面表现：

1. 数据集列表显示 涉敏未脱敏。
2. 详情页标题后显示异常标识。
3. 数据脱敏页签顶部显示告警条。
4. 可视化查询是否允许继续使用由系统策略决定。

推荐策略：

允许查询，但持续提示风险；

禁止下载和导出；

禁止订阅和嵌出；

直到配置完成。

**4.3.4 涉敏已脱敏**

满足以下条件后状态变为 sensitive\_masked：

1. 数据集已标记为涉敏。
2. 至少添加一个脱敏字段。
3. 每个脱敏字段均配置脱敏规则。
4. 每个脱敏字段均配置生效范围。
5. 所有规则校验通过。

**4.3.5 不涉敏**

如果用户选择不涉敏：

sensitivityStatus = non\_sensitive

规则：

1. 不展示添加脱敏字段入口，或展示但需先切换为涉敏。
2. 所有字段按原始值展示。
3. 下载、导出、订阅、监控均不做脱敏处理。
4. 用户仍可重新编辑涉敏等级，将其改为涉敏。

**9.2 预设脱敏规则**

**9.2.1 姓名脱敏**

适用字段：

姓名、联系人、客户姓名、用户姓名等

规则：

保持前 1 位不脱敏，其余字符替换为 \*

示例：

| **原值** | **脱敏值** |
| --- | --- |
| 张三 | 张\* |
| 王小明 | 王\*\* |
| Alexandar | A\*\*\*\*\*\*\*\* |

实现逻辑：

function maskName(value: string): string {

if (!value) return value;

return value.slice(0, 1) + "\*".repeat(Math.max(value.length - 1, 0));

}

**9.2.2 邮箱脱敏**

规则：

保留 @ 后面的真实信息

@ 前面的部分使用 \* 脱敏

如果没有 @，则全脱敏

示例：

| **原值** | **脱敏值** |
| --- | --- |
| zhangsan@example.com | \*\*\*\*\*\*\*\*@example.com |
| a@example.com | \*@example.com |
| invalidEmail | \*\*\*\*\*\*\*\*\*\*\*\* |

实现逻辑：

function maskEmail(value: string): string {

if (!value) return value;

const atIndex = value.indexOf("@");

if (atIndex < 0) return "\*".repeat(value.length);

const prefix = value.slice(0, atIndex);

const suffix = value.slice(atIndex);

return "\*".repeat(prefix.length) + suffix;

}

**9.3 自定义脱敏规则**

**9.3.1 脱敏中间字符**

配置项：

保留前 M 位

保留后 N 位

其余字符替换为 \*

表单：

type CustomMiddleForm = {

keepPrefixLength: number;

keepSuffixLength: number;

};

校验：

| **字段** | **规则** |
| --- | --- |
| keepPrefixLength | 必填，整数，>= 0 |
| keepSuffixLength | 必填，整数，>= 0 |
| M + N | 可以超过字符串长度，超过时直接返回原值或按实际长度处理 |
| replacementChar | 固定为 \* |

推荐逻辑：

function maskMiddle(value: string, prefix: number, suffix: number): string {

if (!value) return value;

const len = value.length;

if (prefix + suffix >= len) return value;

return (

value.slice(0, prefix) +

"\*".repeat(len - prefix - suffix) +

value.slice(len - suffix)

);

}

**9.3.2 脱敏头尾字符**

配置项：

保留从 M 位至 N 位

其余字符替换为 \*

表单：

type CustomHeadTailForm = {

keepStartIndex: number;

keepEndIndex: number;

};

交互规则：

1. 位次从 1 开始。
2. M 必须小于等于 N。
3. M、N 必须为正整数。
4. N 超过字符串长度时，按字符串长度处理。
5. 除 M 到 N 之间的字符外，其他字符全部替换为 \*。

**9.3.3 特殊字符前脱敏**

配置项：

特殊字符 X 之前的字符替换为 \*

表单：

type CustomBeforeSpecialCharForm = {

specialChar: string;

};

示例：

| **原值** | **特殊字符** | **脱敏值** |
| --- | --- | --- |
| zhangsan@example.com | @ | \*\*\*\*\*\*\*\*@example.com |
| abc-12345 | - | \*\*\*-12345 |

如果找不到特殊字符：

按全脱敏处理

**9.3.4 特殊字符后脱敏**

配置项：

特殊字符 X 之后的字符替换为 \*

示例：

| **原值** | **特殊字符** | **脱敏值** |
| --- | --- | --- |
| zhangsan@example.com | @ | zhangsan@\*\*\*\*\*\*\*\*\*\*\* |
| abc-12345 | - | abc-\*\*\*\*\* |

如果找不到特殊字符：

按全脱敏处理

**10. 生效范围配置**

**10.1 功能目标**

生效范围用于决定哪些用户看到脱敏后的数据，哪些用户看到原始数据。

支持两种配置模式：

适用成员受规则控制，成员以外的用户不受规则控制

适用成员不受规则控制，成员以外的用户受规则控制

**10.2 生效范围模式**

**10.2.1 适用成员受规则控制**

mode = "members\_masked\_others\_unmasked"

含义：

被添加为生效成员的用户、用户组、角色看到脱敏值；

其他用户看到原始值。

适用场景：

只对普通员工脱敏；

管理员、数据负责人、审计人员可看原始值。

**10.2.2 适用成员不受规则控制**

mode = "members\_unmasked\_others\_masked"

含义：

被添加为生效成员的用户、用户组、角色看到原始值；

其他用户看到脱敏值。

适用场景：

仅少数授权人员可看原始敏感值；

大多数用户只能看到脱敏值。

推荐默认模式：

适用成员不受规则控制，成员以外的用户受规则控制

因为该模式更符合安全默认原则。

**10.3 生效成员选择**

支持成员类型：

用户组

角色

私有化环境中，需要支持按角色设置生效范围。

| --- | --- |

| 用户 | 必须是当前项目有效用户 |

**10.5 运行时判断逻辑**

function shouldMaskUser(

scope: MaskingEffectiveScope,

currentUser: {

userId: string;

userGroupIds: string[];

roleIds: string[];

}

): boolean {

const matched = scope.members.some(member => {

if (member.memberType === "user") {

return member.memberId === currentUser.userId;

}

if (member.memberType === "user\_group") {

return currentUser.userGroupIds.includes(member.memberId);

}

if (member.memberType === "role") {

return currentUser.roleIds.includes(member.memberId);

}

return false;

});

if (scope.mode === "members\_masked\_others\_unmasked") {

return matched;

}

if (scope.mode === "members\_unmasked\_others\_masked") {

return !matched;

}

return true;

}

function calculateSensitivityStatus(

): DatasetSensitivityStatus {

if (!isSensitive) return "non\_sensitive";

if (maskingFields.length === 0) {

**12. 关联数据集脱敏规则**

**12.1 功能目标**

关联数据集由多个子数据集组合生成。只要任一子数据集涉敏，关联数据集就必须继承涉敏状态和脱敏字段规则，避免通过关联数据集绕过脱敏。

**12.2 继承规则**

当关联数据集的子数据集中存在至少一个 sensitive\_masked 或 sensitive\_unmasked 数据集：

关联数据集状态 = 涉敏已脱敏 或 涉敏未脱敏

具体规则：

| **子数据集状态** | **关联数据集状态** |
| --- | --- |
| 任一子数据集 sensitive\_unmasked | sensitive\_unmasked |
| 子数据集均非未脱敏，且至少一个 sensitive\_masked | sensitive\_masked |
| 所有子数据集 non\_sensitive | non\_sensitive |
| 任一子数据集 unclassified | unclassified 或需强制重新定级 |

**12.3 脱敏字段合集**

关联数据集的脱敏字段为全部子数据集脱敏字段的合集。

子数据集 A 脱敏字段：手机号、身份证

子数据集 B 脱敏字段：邮箱

关联数据集脱敏字段：手机号、身份证、邮箱

字段映射逻辑：

1. 如果关联数据集字段直接来源于子数据集脱敏字段，则继承原规则。
2. 如果关联数据集字段为原字段改名，则按字段血缘映射继承原规则。
3. 如果关联数据集字段由涉敏字段计算产生，则按计算字段规则处理。
4. 如果多个子字段合并成一个输出字段，只要任一来源字段涉敏，则输出字段涉敏。

**12.4 子数据集规则变更同步**

子数据集修改脱敏规则

→ 系统查找所有依赖该子数据集的关联数据集

→ 更新关联数据集脱敏字段映射

→ 清理关联数据集查询缓存

→ 下游图表、仪表盘下次查询按新规则展示

**13. 可视化查询中的脱敏效果**

**13.1 基本展示规则**

在可视化查询中：

1. 涉敏字段支持作为维度。
2. 涉敏字段支持作为指标。
3. 涉敏字段支持作为筛选项。
4. 图表、表格、明细表中展示的值均需要按脱敏规则处理。
5. 字段列表需要对涉敏字段增加标识。
6. 鼠标悬浮字段时展示：该字段已配置脱敏规则。

**13.2 涉敏维度字段限制**

当涉敏字段作为维度时，不支持：

字段值别名

地理角色

创建组

前端处理：

1. 字段右键菜单中隐藏这些功能。
2. 如果历史图表已经配置这些功能，打开时展示异常提示。
3. 用户保存图表时阻止保存非法配置。

提示文案：

当前字段为涉敏字段，不支持字段值别名、地理角色和创建组。

**13.3 涉敏指标字段限制**

当涉敏字段作为指标时：

支持的聚合方式仅包括：

计数

计数不同（快速）

计数不同

最大值

最小值

不支持：

求和

平均值

中位数

百分位

自定义格式

设置数据格式

创建组

原因是脱敏字段的真实值不能在多数数值计算中直接暴露或被反推。

前端逻辑：

用户拖入涉敏字段到指标区

→ 聚合方式下拉只展示允许项

→ 如果默认聚合方式不在允许项内

→ 自动切换为计数

**13.4 涉敏字段筛选限制**

当涉敏维度字段作为筛选条件时：

仅支持精确筛选

不支持：

模糊搜索

范围筛选

条件筛选

文本包含

正则匹配

筛选值展示：

1. 筛选值列表中的维度值需要脱敏展示。
2. 用户选择的是脱敏后的展示值。
3. 后端需要映射到真实值或基于真实值查询后返回脱敏结果。
4. 不允许通过筛选项暴露原始值。

**13.5 计算字段规则**

**13.5.1 表达式中包含涉敏字段**

当用户创建计算字段，表达式中引用了涉敏字段：

1. 被引用的涉敏字段在表达式编辑器中用红色标识。
2. 右侧说明区展示该字段脱敏规则。
3. 计算字段需要继承涉敏字段规则。
4. 保存计算字段时，系统记录字段血缘。

**13.5.2 完全不加工表达式**

如果计算字段只是直接引用涉敏字段，不做加工：

[手机号]

规则：

按原数据源字段的脱敏规则执行

**13.5.3 加工表达式**

如果计算字段对涉敏字段做了加工：

concat([手机号], '-', [客户名称])

或：

substring([身份证号], 1, 6)

规则：

按全脱敏字段规则执行

即输出字段整体全脱敏，避免通过加工绕过原脱敏规则。

**13.5.4 多涉敏字段表达式**

如果计算字段引用多个涉敏字段：

1. 只要任一涉敏字段被加工，计算字段全脱敏。
2. 如果多个字段均为直接透传，则按输出字段对应来源规则。
3. 如果无法明确判断透传关系，则按全脱敏处理。

**14. 仪表盘中的脱敏效果**

**14.1 图表展示**

仪表盘中所有图表查询结果必须执行脱敏。

用户打开仪表盘

→ 后端识别图表依赖数据集

→ 计算当前用户是否命中脱敏范围

→ 对涉敏字段结果进行脱敏

→ 返回前端展示

前端不得自行脱敏真实值，避免原始值出现在浏览器网络请求中。

**14.2 全局筛选器**

当全局筛选器包含涉敏字段：

1. 筛选器候选值脱敏展示。
2. 用户选择脱敏后的值。
3. 后端基于真实值执行筛选。
4. 前端不能获取真实值。
5. 筛选器导出、分享、订阅时展示脱敏值。

**14.3 仪表盘导出**

仪表盘导出包括：

图片导出

PDF 导出

Excel 导出

截图订阅

规则：

1. 涉敏字段均按脱敏结果展示。
2. 导出文件中不得包含原始值。
3. 即使导出人有查看原始值权限，也需要按当前用户脱敏规则执行。
4. 如果系统需要支持“导出原始值”，必须走单独审批，不在默认导出中开放。

**15.1 数据下载**

仪表盘订阅发送内容包括：

数据摘要

图表链接

监控结果

规则：

1. 截图中的数据按订阅接收人权限脱敏。
2. 如果一个订阅有多个接收人，不能只按创建人权限渲染一次截图。
3. 推荐按接收人分别计算权限并渲染。
4. 如果系统无法按接收人分别渲染，则必须按最严格规则脱敏。

**15.3 监控**

监控触发内容中若包含涉敏字段：

1. 监控判断可以基于真实值执行。
2. 监控通知展示必须按接收人权限脱敏。
3. 告警消息正文中不得出现原始敏感值。

**15.4 嵌出**

嵌出场景中：

1. 嵌出图表或仪表盘必须根据访问身份计算脱敏。
2. 如果是匿名嵌出，默认按最严格规则脱敏。
3. 如果是带用户身份的嵌出，按对应用户脱敏范围计算。
4. 嵌出接口返回数据不能包含原始敏感值。

**16. 可视化建模输出数据集**

**16.1 规则**

从可视化建模输出的数据集：

不继承输入数据集的脱敏字段控制

输出成新数据集后：

sensitivityStatus = unclassified

用户需要重新进行：

1. 涉敏定级。
2. 脱敏字段选择。
3. 脱敏规则配置。
4. 生效范围配置。

**16.2 原因**

可视化建模可能改变字段结构、字段含义、聚合粒度和字段血缘。如果自动继承输入数据集脱敏规则，可能出现：

1. 输出字段已不再包含敏感信息，但仍被错误脱敏。
2. 输出字段由多个字段加工而来，原规则不适用。
3. 输出字段改变了业务含义，需要重新判断。
4. 模型输出数据集作为新数据集，应由创建者重新负责定级。

**17. 后端脱敏执行逻辑**

**17.1 执行位置**

脱敏必须在后端查询结果返回前完成。

推荐执行链路：

SQL 查询执行

→ 行列权限处理

→ 查询结果生成

→ 字段级脱敏处理

→ 返回前端

注意：

1. 行权限应在查询前拼接条件。
2. 列权限应在查询字段选择阶段裁剪字段。
3. 脱敏应在结果返回前进行值替换。
4. 前端只接收脱敏后的值。

**17.2 查询结果脱敏**

function applyMaskingToRows(

rows: Record<string, any>[],

fields: DatasetField[],

maskingConfig: DatasetSensitivityConfig,

currentUser: CurrentUser

): Record<string, any>[] {

const shouldMask = shouldMaskUser(maskingConfig.effectiveScope, currentUser);

if (!shouldMask) return rows;

const fieldRuleMap = buildFieldRuleMap(maskingConfig.maskingFields);

return rows.map(row => {

const nextRow = { ...row };

for (const field of fields) {

const rule = fieldRuleMap.get(field.id);

if (!rule) continue;

nextRow[field.name] = maskValue(nextRow[field.name], rule);

}

return nextRow;

});

}

**17.3 空值处理**

| **原值** | **脱敏结果** |
| --- | --- |
| null | null |
| undefined | undefined |
| 空字符串 | 空字符串 |
| 0 | 按字符串 "0" 或数值规则处理，建议不脱敏数值本身，除非字段配置为涉敏 |
| boolean | 不建议配置脱敏；若配置则转字符串后全脱敏 |

**17.4 类型处理**

脱敏结果一般为字符串。

如果涉敏字段原本为 number：

1. 展示时可以返回字符串。
2. 图表计算时不能把脱敏值作为数值计算。
3. 指标聚合必须走受限聚合。
4. 明细表展示按字符串展示。

**20. 异常与边界场景**

**20.1 字段被删除**

如果已配置脱敏的字段被删除：

1. 数据脱敏页显示字段异常。
2. 保存时阻止提交。
3. 提示：字段已不存在，请删除该脱敏配置。
4. 数据集状态重新计算。

**20.2 字段类型变化**

如果字段类型变化：

1. 原规则仍保留。
2. 页面提示规则可能不再适用。
3. 用户需要确认或重新选择规则。
4. 对于不支持脱敏的字段类型，必须删除配置或切换为全脱敏。

**20.3 用户组或角色被删除**

如果生效范围中的用户组或角色不存在：

1. 页面显示异常成员。
2. 保存时要求移除异常成员。
3. 运行时忽略已删除成员。
4. 操作日志记录配置异常。

**20.4 规则参数异常**

如用户配置：

保留前 5 位，保留后 -1 位

前端阻止保存：

保留位数必须为大于等于 0 的整数。

**20.5 并发保存**

两个管理员同时编辑：

管理员 A 打开页面 version = 1

管理员 B 打开页面 version = 1

管理员 A 保存成功 version = 2

管理员 B 保存时版本冲突

→ 提示配置已被他人修改，请刷新后重新编辑

**22. 验收标准**

**22.1 涉敏定级**

1. 新建数据集保存时必须选择涉敏或不涉敏。
2. 存量数据集默认进入未定级状态。
3. 未定级数据集在列表和详情页有明确标识。
4. 标记为不涉敏后，字段按原始值展示。
5. 标记为涉敏后，若未配置脱敏字段，状态为涉敏未脱敏。
6. 涉敏字段和规则配置完整后，状态为涉敏已脱敏。

**22.2 脱敏字段配置**

1. 用户可以添加一个或多个脱敏字段。
2. 已添加字段不能重复添加。
3. 字段被删除后，脱敏配置显示异常。
4. 删除脱敏字段后，数据集状态能重新计算。
5. 无权限用户不能添加、删除、修改脱敏字段。

**22.3 脱敏规则**

1. 支持姓名脱敏。
2. 支持邮箱脱敏。
3. 支持联系方式脱敏。
4. 支持中国证件号码通用规则。
5. 支持中国公民身份证脱敏。
6. 支持全脱敏。
7. 支持脱敏中间字符。
8. 支持脱敏头尾字符。
9. 支持特殊字符前脱敏。
10. 支持特殊字符后脱敏。
11. 自定义规则参数非法时不能保存。
12. 规则保存后数据预览立即生效。

**22.4 生效范围**

1. 支持适用成员受规则控制。
2. 支持适用成员不受规则控制。
3. 支持用户作为生效成员。
4. 支持用户组作为生效成员。
5. 私有化环境支持角色作为生效成员。
6. 当前用户是否看到脱敏值由生效范围正确判断。
7. 生效范围修改后，可视化查询、仪表盘、下载、订阅均生效。

**22.5 可视化查询**

1. 涉敏字段在表格和图表中按规则脱敏展示。
2. 涉敏字段支持作为维度。
3. 涉敏字段支持作为指标。
4. 涉敏字段支持作为筛选项。
5. 涉敏维度字段不支持字段值别名、地理角色、创建组。
6. 涉敏指标字段仅支持计数、计数不同、最大值、最小值等受限聚合。
7. 涉敏字段作为筛选项时，仅支持精确筛选。
8. 筛选值列表中的涉敏维度值需要脱敏展示。
9. 计算字段引用涉敏字段时，需要继承脱敏规则。
10. 加工后的涉敏计算字段按全脱敏执行。

**22.6 仪表盘和导出**

1. 仪表盘图表展示值按脱敏规则处理。
2. 全局筛选器中的涉敏字段值按脱敏规则处理。
3. 数据下载中的涉敏字段必须脱敏。
4. 仪表盘导出中的涉敏字段必须脱敏。
5. 仪表盘订阅中的涉敏字段必须脱敏。
6. 监控通知中的涉敏字段必须脱敏。
7. 嵌出场景中的涉敏字段必须脱敏。
8. 前端网络请求中不得出现应被脱敏的原始值。

**22.7 关联数据集与可视化建模**

1. 关联数据集需要继承子数据集脱敏字段合集。
2. 子数据集脱敏规则变化后，关联数据集同步变化。
3. 任一子数据集涉敏未脱敏时，关联数据集应标记为涉敏未脱敏。
4. 可视化建模输出数据集不继承输入数据集脱敏规则。
5. 可视化建模输出数据集状态为未定级。
6. 输出数据集需要创建者重新定级和配置脱敏规则。

**22.8 安全和审计**

1. 脱敏必须在后端执行。
2. 前端不得接收需要脱敏的原始值。
3. 脱敏配置变更需要记录操作日志。
4. 下载和导出包含脱敏字段时需要记录审计日志。
5. 并发保存时需要版本控制。
6. 无权限用户访问脱敏配置接口返回 403。
7. 异常字段、异常成员、异常规则必须有明确提示。
