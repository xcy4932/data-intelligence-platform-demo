**触达营销-用户运营与微信运营 PRD**

**1. 文档范围**

本文覆盖触达营销中的两个业务域：

1. 用户运营
   包含：用户发送明细、分群营销旅程。
2. 微信运营
   包含：微信标签、个性化菜单、微信公众号二维码。

本文目标不是列功能点，而是把每个页面、按钮、状态、校验、交互、数据逻辑写到前端和后端可以直接拆任务开发的程度。

**2. 通用产品规则**

**2.1 权限规则**

系统采用“菜单权限 + 操作权限”的组合控制。

| **模块** | **菜单权限** | **操作权限** |
| --- | --- | --- |
| 用户发送明细 | 用户运营-用户发送明细-查看 | 查询、查看、重发 |
| 分群营销旅程 | 用户运营-分群营销旅程-查看 | 查看分群旅程、跳转分群详情 |
| 微信标签 | 微信运营-微信标签-查看 | 新增标签、删除标签、导入分群、修改单用户标签 |
| 个性化菜单 | 微信运营-微信个性化菜单-查看 | 新增、编辑、发布、下线、删除 |
| 微信公众号二维码 | 微信运营-微信公众号二维码-查看 | 新增、编辑、查看、下载、删除、批量删除 |

权限控制逻辑：

1. 用户无菜单权限时，左侧导航不展示对应菜单。
2. 用户有菜单权限但无操作权限时，页面可查看，但对应按钮不展示。
3. 用户通过 URL 直接访问无权限页面时，返回 403 页面。
4. 所有写操作后端必须再次校验权限，不能只依赖前端隐藏按钮。
5. 所有新增、编辑、删除、发布、重发操作必须写入操作日志。

**2.2 微信公众号前置条件**

微信运营相关功能必须满足以下前提：

1. 当前租户已在「管理中心 - 通道管理 - 微信公众号」完成公众号授权。
2. 当前用户拥有对应微信运营模块权限。
3. 当前公众号授权状态为“有效”。
4. 如果公众号授权失效，微信标签、个性化菜单、微信公众号二维码页面仍可进入，但所有写操作禁用，并展示提示：
   “当前公众号授权已失效，请前往管理中心重新授权后再操作。”

**2.3 公众号切换规则**

微信运营页面顶部统一提供“公众号选择器”。

字段：

| **字段** | **说明** |
| --- | --- |
| 公众号名称 | 展示已授权公众号名称 |
| app\_id | 后端实际查询和调用微信接口的唯一标识 |
| 授权状态 | 有效、失效、未授权 |
| 最近同步时间 | 当前公众号最近一次同步微信数据时间 |

交互规则：

1. 页面首次进入时，默认选中用户最近一次使用的公众号。
2. 若用户没有历史选择，默认选中列表中的第一个有效公众号。
3. 切换公众号后，当前页面所有列表、筛选条件、表单数据清空并重新加载。
4. 切换公众号时，如果当前页面有未保存表单，弹出确认框：
   “当前页面存在未保存内容，切换公众号后内容将丢失，是否继续？”
5. 确认后切换；取消后保持原公众号。

**2.4 异步任务规则**

以下操作必须按异步任务处理：

1. 微信标签批量导入用户。
2. 微信标签批量删除或批量更新用户关系。
3. 用户发送明细批量重发。
4. 微信二维码批量删除。
5. 微信菜单发布到微信后台。

异步任务统一状态：

| **状态** | **含义** |
| --- | --- |
| 待执行 | 用户已提交，任务进入队列 |
| 执行中 | 系统正在处理 |
| 成功 | 全部数据处理成功 |
| 部分成功 | 部分数据失败，部分成功 |
| 失败 | 全部处理失败 |
| 已取消 | 用户删除标签、删除资源或系统中断导致任务取消 |

异步任务必须记录：

task\_id

task\_type

tenant\_id

operator\_id

related\_object\_id

status

total\_count

success\_count

failed\_count

failed\_reason\_file\_url

created\_at

started\_at

finished\_at

**3. 用户运营模块**

**3.1 用户发送明细**

**3.1.1 功能定位**

用户发送明细用于查看系统对单个用户的触达发送记录，覆盖以下触达来源：

1. 消息触达。
2. 流程画布。
3. 智能触达。

页面支持按用户、任务、通道、状态、时间等条件查询发送记录，并支持对部分失败记录执行重发。

**3.1.2 页面入口**

导航路径：

左侧导航-智能运营-营销触达-用户运营 / 用户发送明细

**3.1.3 页面结构**

页面从上到下分为四个区域：

1. 筛选区。
2. 操作区。
3. 发送明细表格。
4. 分页区。

**3.1.4 筛选区**

**字段设计**

| **字段** | **类型** | **是否必填** | **说明** |
| --- | --- | --- | --- |
| 用户 ID | 输入框 | 否 | 支持输入 baseid 或发送 ID |
| 任务类型 | 下拉单选 | 否 | 消息触达、流程画布、智能触达 |
| 任务名称 | 输入框 | 否 | 支持模糊搜索 |
| 任务 ID | 输入框 | 否 | 精确搜索 |
| 子任务 ID | 输入框 | 否 | 精确搜索 |
| 触达任务通道 | 下拉多选 | 否 | 短信、邮件、微信、Webhook、App Push 等 |
| 发送状态 | 下拉多选 | 否 | 待发送、发送中、发送成功、发送失败、已取消 |
| 到达状态 | 下拉多选 | 否 | 未回执、到达成功、到达失败、未知 |
| 时间 | 时间范围选择器 | 否 | 默认最近 7 天，最大跨度 366 天 |

**查询逻辑**

1. 用户填写多个条件时，所有条件之间为 AND 关系。
2. 任务名称使用模糊匹配。
3. 任务 ID、子任务 ID、用户 ID 使用精确匹配。
4. 时间字段默认作用于“发送时间”。
5. 如果用户清空时间条件，系统允许查询，但后端最多返回最近一年数据。
6. 查询时必须分页请求，默认每页 20 条。
7. 查询结果按发送时间倒序排列。

**按钮**

| **按钮** | **位置** | **逻辑** |
| --- | --- | --- |
| 查询 | 筛选区右侧 | 根据当前筛选条件刷新列表，页码重置为第 1 页 |
| 重置 | 查询按钮旁 | 清空所有筛选项，时间恢复为最近 7 天，刷新列表 |
| 展开/收起 | 筛选区右上 | 当筛选字段超过一行时展示，收起后只展示用户 ID、任务类型、时间 |

**3.1.5 操作区**

操作区位于表格上方。

**按钮**

| **按钮** | **展示条件** | **可点击条件** | **逻辑** |
| --- | --- | --- | --- |
| 重发 | 用户有重发权限 | 至少选择 1 条可重发记录 | 打开重发确认弹窗 |
| 刷新 | 始终展示 | 始终可点 | 保持当前筛选条件，重新请求列表 |

**重发按钮可点击规则**

记录满足以下条件才可重发：

1. 任务类型为“消息触达”。
2. 发送状态为“发送失败”或到达状态为“到达失败”。
3. 原任务未被删除。
4. 原任务通道仍然可用。
5. 当前触达内容仍然可读取。
6. 当前用户有重发权限。

以下情况不可重发：

1. 流程画布记录不可重发。
2. 智能触达记录不可重发。
3. 发送成功且到达成功的记录不可重发。
4. 原通道被禁用时不可重发。
5. 原任务内容被删除时不可重发。

当用户勾选了不可重发记录时：

1. 重发按钮仍可点击。
2. 弹窗内展示可重发数量和不可重发数量。
3. 系统只对可重发记录执行重发。
4. 不可重发记录展示原因。

**3.1.6 表格字段**

| **字段** | **说明** |
| --- | --- |
| 复选框 | 用于选择需要重发的发送记录 |
| 基准 ID baseid | 用户在 GMP 内部的统一用户 ID |
| 发送 ID | 实际触达用户时使用的 ID 值，例如手机号、openid、邮箱 |
| 触达任务类型 | 消息触达、流程画布、智能触达 |
| 触达通道 | 短信、邮件、微信、Webhook、App Push 等 |
| 触达内容 | 展示内容摘要，超过 30 字省略，鼠标悬停展示完整内容 |
| 子任务 ID | 触达执行批次或子任务 ID |
| 任务名称 | 支持点击进入任务详情；无权限时只展示文本 |
| 发送状态 | 待发送、发送中、发送成功、发送失败、已取消 |
| 发送时间 | 该条记录最近一次发送时间 |
| 发送失败原因 | 仅发送失败时展示；成功时展示“-” |
| 到达状态 | 未回执、到达成功、到达失败、未知 |
| 到达时间 | 到达成功或失败的回执时间 |
| 到达失败原因 | 仅到达失败时展示 |
| 重发次数 | 展示该记录被重发的次数 |
| 最近操作人 | 最近一次重发操作人 |
| 操作 | 查看详情 |

**行状态规则**

1. 发送失败行使用红色状态标签。
2. 到达失败行使用橙色状态标签。
3. 发送中行展示 loading 状态。
4. 已取消行置灰。
5. 不可重发记录复选框仍可勾选，但弹窗内会提示不可重发原因。

**3.1.7 查看详情**

点击“查看详情”后打开右侧抽屉。

**抽屉内容**

1. 用户信息
   baseid、发送 ID、ID 类型。
2. 任务信息
   任务类型、任务名称、任务 ID、子任务 ID、触达通道。
3. 内容信息
   触达标题、触达正文、模板 ID、变量值。
4. 发送结果
   发送状态、发送时间、发送失败原因、通道返回码。
5. 到达结果
   到达状态、到达时间、到达失败原因、回执原始内容。
6. 重发记录
   每次重发时间、操作人、重发结果、失败原因。

**按钮**

| **按钮** | **逻辑** |
| --- | --- |
| 关闭 | 关闭抽屉，不刷新列表 |
| 重发 | 如果当前记录可重发，点击后打开重发确认弹窗 |
| 复制发送 ID | 将发送 ID 写入剪贴板 |
| 复制任务 ID | 将任务 ID 写入剪贴板 |

**3.1.8 重发确认弹窗**

**触发方式**

用户在列表中勾选记录后点击“重发”。

**弹窗内容**

弹窗标题：

确认重发

弹窗展示：

| **信息** | **说明** |
| --- | --- |
| 已选择记录数 | 用户勾选的总记录数 |
| 可重发记录数 | 满足重发条件的记录数 |
| 不可重发记录数 | 不满足条件的记录数 |
| 不可重发原因 | 按原因聚合展示 |
| 风险提示 | 定时型消息触达重发将忽略原任务限制条件并立即发送；触发型消息触达重发可能与原触发条件不一致，请谨慎操作 |

**按钮**

| **按钮** | **逻辑** |
| --- | --- |
| 取消 | 关闭弹窗，不执行操作 |
| 确认重发 | 创建重发任务，只处理可重发记录 |

**重发执行逻辑**

1. 用户确认后，后端创建 resend\_job。
2. 系统逐条校验当前记录是否仍可重发。
3. 对定时型消息触达，系统忽略原任务中的频控、发送时间、受众限制，立即对该用户发送。
4. 对触发型消息触达，系统使用原触达内容和原通道立即发送，不重新校验触发条件。
5. 流程画布不执行重发。
6. 重发完成后，原发送记录更新以下字段：
   发送状态、发送时间、发送失败原因、到达状态、到达时间、到达失败原因、重发次数、最近操作人。
7. 系统同时保留 resend\_attempt 明细，便于审计和问题排查。

**3.2 分群营销旅程**

**3.2.1 功能定位**

分群营销旅程用于回答三个问题：

1. 这是怎样的一个分群。
2. 这个分群经历过哪些触达和营销动作。
3. 触达后，该分群相关业务指标发生了什么变化。

该页面不是归因分析页面，只提供趋势观察和运营参考。若需要判断营销动作是否造成指标变化，应使用 A/B 测试或其他归因模型。

**3.2.2 页面入口**

推荐入口：

1. 用户分群详情页中的“查看营销旅程”。
2. 触达任务详情页中的“查看关联分群旅程”。
3. 用户运营菜单中的“分群营销旅程”。

页面路由建议：

/marketing/cohorts/{cohort\_id}/journey

**3.2.3 页面结构**

页面由以下区域组成：

1. 头部区域。
2. 核心指标趋势。
3. 营销旅程时间线。
4. 分群数据。
5. 分群标签。

页面采用左右布局：

* 左侧：核心指标趋势 + 营销旅程。
* 右侧：分群数据 + 分群标签。

**3.2.4 头部区域**

**展示字段**

| **字段** | **说明** |
| --- | --- |
| 分群名称 | 正常展示分群名称 |
| 分群 ID | 鼠标悬停展示，可复制 |
| 时间段 | 默认最近 30 天，最大可选择过去一年 |
| 最近更新时间 | 当前页面数据最近刷新时间 |

**控件与按钮**

| **控件/按钮** | **逻辑** |
| --- | --- |
| 时间段选择器 | 支持快捷选择最近 7 天、最近 30 天、最近 90 天、过去一年、自定义 |
| 刷新 | 重新拉取当前分群旅程数据 |
| 查看分群详情 | 跳转至客户数据平台分群详情页 |
| 复制分群 ID | 复制 cohort\_id |

**时间段规则**

1. 最大可查询跨度为 366 天。
2. 如果用户选择超过 366 天，保存按钮置灰，并提示“最多只能选择过去一年”。
3. 时间选择后，核心指标趋势、营销旅程、分群数据、分群标签全部刷新。
4. 刷新期间保留旧数据，并在对应模块展示 loading。

**3.2.5 核心指标趋势**

**数据来源**

核心指标趋势数据来源于增长分析平台 DataFinder。GMP 后端需要预先配置可展示指标，前端不允许用户临时自由选择任意 DataFinder 指标。

**展示内容**

| **内容** | **说明** |
| --- | --- |
| 指标 Tab | 展示已配置的核心指标，例如活跃用户、转化用户、支付金额等 |
| 趋势图 | 按日期展示指标趋势 |
| 触达活动标记 | 当天存在触达任务或流程画布执行时，在趋势图上标记活动数量 |
| tooltip | 鼠标悬停展示日期、指标值、当天触达活动数量 |

**交互逻辑**

1. 默认选中配置中的第一个核心指标。
2. 切换指标 Tab 后，只刷新图表，不刷新页面其他模块。
3. 鼠标悬停在折线点上，展示当天指标值。
4. 鼠标悬停在触达活动标记上，展示当天触达活动数量。
5. 点击触达活动标记，营销旅程时间线自动滚动到对应日期。
6. 如果当天有多个任务，营销旅程中按执行时间倒序展示。

**3.2.6 营销旅程时间线**

**数据范围**

营销旅程只展示当前分群关联的：

1. 触达任务。
2. 流程画布。

**数据粒度**

营销旅程按执行粒度展示，不按任务粒度展示。

规则如下：

| **任务类型** | **展示规则** |
| --- | --- |
| 定时-单次型 | 只展示一次 |
| 定时-重复型 | 按天展示每个子任务；如果一天有 X 个子任务，则展示 X 个 item |
| 触发型 | 按实际执行过程按天展示 |
| 流程画布 | 按流程画布节点实际执行时间展示 |

**排序规则**

1. 以日期为主轴。
2. 日期按倒序排列，越新的日期越靠前。
3. 同一天内按执行时间倒序排列。
4. 如果执行时间相同，按任务创建时间倒序排列。

**时间线卡片字段**

| **字段** | **说明** |
| --- | --- |
| 执行日期 | 当前 item 所属日期 |
| 任务名称 | 可点击进入任务详情 |
| 任务类型 | 触达任务、流程画布 |
| 执行类型 | 单次、重复、触发 |
| 触达通道 | 短信、微信、邮件、Webhook、Push 等 |
| 子任务 ID | 用于定位具体执行批次 |
| 计划发送人数 | 本次计划触达人群数 |

**4.2.5 菜单优先级规则**

一个微信用户可能同时拥有多个微信标签，因此可能命中多个个性化菜单。系统必须提供确定性规则：

1. 已发布的个性化菜单才参与匹配。
2. 菜单按优先级从高到低匹配。
3. 用户命中第一个菜单后，不再继续匹配后续菜单。
4. 如果用户未命中任何个性化菜单，则展示默认菜单。
5. 草稿、已下线、发布失败菜单不参与匹配。

优先级调整逻辑：

1. 点击“调整优先级”后，列表进入拖拽模式。
2. 用户拖动菜单行调整顺序。
3. 点击“保存排序”后提交。
4. 排序保存成功后，如果有已发布菜单，系统提示：
   “优先级已更新，需要重新发布菜单后才会在微信端生效。”
5. 点击“取消排序”恢复原顺序。

**4.2.9 菜单结构规则**

菜单结构遵循公众号菜单结构：

1. 最多 3 个一级菜单。
2. 每个一级菜单最多 5 个二级菜单。
3. 一级菜单如果有二级菜单，则一级菜单本身不能配置动作。
4. 没有二级菜单的一级菜单必须配置动作。
5. 二级菜单必须配置动作。
6. 菜单名称不能为空。
7. 菜单名称不能只包含空格。
8. 同级菜单名称允许重复与否由产品统一决定；本 PRD 规定同级菜单名称不允许重复，避免用户混淆。

**4.2.12 手机预览区**

手机预览区实时展示当前菜单结构。

交互：

1. 点击预览中的菜单项，右侧动作配置区自动切换到该菜单。
2. 菜单名称修改后，预览实时更新。
3. 添加、删除、排序菜单后，预览实时更新。
4. 预览仅用于展示，不真正触发发送消息、跳转页面、打标签。

**4.2.13 保存草稿逻辑**

点击“保存草稿”后：

1. 前端校验菜单结构。
2. 后端保存菜单组、菜单项、动作配置、自动打标签配置。
3. 不调用微信发布接口。
4. 状态更新为“草稿”。
5. 保存成功后提示“保存成功”。
6. 保存失败时停留当前页面并展示失败原因。

**4.2.14 发布逻辑**

点击“发布”后：

1. 校验公众号授权有效。
2. 校验菜单结构完整。
3. 校验所有菜单动作配置完整。
4. 校验自动标签均为当前公众号有效标签。
5. 保存当前配置。
6. 生成微信菜单 payload。
7. 调用微信接口发布。
8. 发布成功后状态变为“已发布”。
9. 发布失败后状态变为“发布失败”，保留草稿配置并展示失败原因。

**4.2.15 下线逻辑**

1. 仅已发布菜单可下线。
2. 点击“下线”弹出确认框。
3. 确认后调用微信接口删除或停用对应菜单。
4. 下线成功后状态变为“已下线”。
5. 下线默认菜单前必须校验是否存在已发布个性化菜单。
   如果存在，拦截并提示：
   “当前存在已发布个性化菜单，请先下线个性化菜单后再下线默认菜单。”

**4.3.12 二维码扫码行为追踪**

**上报事件**

用户扫描公众号二维码后，系统需要上报 DataFinder 事件：

gmp\_wechat\_qrcode\_scan

**事件属性**

建议至少包含：

| **属性** | **说明** |
| --- | --- |
| gmp\_qrcode\_id | GMP 内部二维码 ID |
| qrcode\_name | 二维码名称 |
| qrcode\_type | 临时 / 永久 |
| open\_id | 微信 openid |
| app\_id | 公众号 app\_id |
| scene\_key | 自定义参数 key |
| scene\_value | 自定义参数 value |
| scan\_time | 扫码时间 |
| is\_subscribe | 扫码前是否已关注 |
| subscribe\_status\_after\_scan | 扫码后的关注状态 |

**分析入口逻辑**

点击“查看扫码分析”后：

1. 打开 左侧导航-数据洞察-事件分析页面。
2. 自动选择事件 gmp\_wechat\_qrcode\_scan。
3. 自动添加筛选条件：
   gmp\_qrcode\_id = 当前二维码 ID
4. 如果当前二维码配置了关键参数，也自动带入 key-value 筛选。
5. 用户可在 DataFinder 中继续分析扫码用户行为明细。

**5. 后端数据模型建议**

**5.1 用户发送明细**

**6. 验收标准**

**6.1 用户发送明细**

1. 能按用户 ID、任务类型、任务名称、任务 ID、子任务 ID、通道、发送状态、到达状态、时间组合查询。
2. 多个筛选条件必须为 AND 关系。
3. 列表字段完整展示。
4. 可对消息触达失败记录执行重发。
5. 流程画布记录不可重发。
6. 重发后发送状态、发送时间、到达状态、到达时间必须更新。
7. 重发操作必须有二次确认和操作日志。

**6.2 分群营销旅程**

1. 页面能展示分群名称、时间段、核心指标趋势、营销旅程、分群数据、分群标签。
2. 时间范围最大不超过过去一年。
3. 营销旅程必须按执行粒度展示。
4. 定时单次任务只展示一次。
5. 定时重复任务按天展示每个子任务。
6. 触发型任务按实际执行过程展示。
7. 核心指标趋势能标记当天触达活动数量。
8. 分群基本信息可跳转到客户数据平台分群详情。

**6.3 微信标签**

1. 能按公众号切换标签列表。
2. 能新增微信标签。
3. 标签名称同一公众号下不可重复。
4. 能删除微信标签，删除需二次确认。
5. 能将行为圈选分群、已有分群、上传 openid 导入标签。
6. 上传文件只能导入当前公众号 openid。
7. 能查询单个用户当前标签。
8. 能为单个用户新增或删除微信标签。
9. 用户微信标签达到 20 个时，继续打标必须失败并展示原因。

**6.4 个性化菜单**

1. 创建个性化菜单前必须先创建默认菜单。
2. 菜单支持发送消息、跳转页面、跳转小程序。
3. 菜单支持自动打标签。
4. 菜单结构必须满足一级最多 3 个、二级最多 5 个。
5. 有子菜单的一级菜单不能配置动作。
6. 发布前必须校验菜单结构和动作配置完整。
7. 多个个性化菜单命中时必须按优先级匹配。
8. 未命中个性化菜单时展示默认菜单。
9. 发布失败必须保留草稿并展示失败原因。

**6.5 微信公众号二维码**

1. 二维码列表支持名称、关键参数、创建人、状态、创建时间筛选。
2. 列表每页展示 10 条。
3. 默认按创建时间倒序。
4. 能新增临时二维码和永久二维码。
5. 临时二维码必须配置失效时间。
6. 编辑二维码时不允许修改二维码类型。
7. 支持查看二维码图片。
8. 支持下载二维码图片。
9. 支持单个删除和批量删除。
10. 删除二维码必须二次确认。
11. 删除系统记录不影响已经下载图片的扫码行为。
12. 二维码失效后，用户无法继续扫描。
13. 扫码事件必须上报到 DataFinder，并支持按二维码参数追踪用户行为。
