**权限与策略中心 PRD**

**1. 模块定位**

**1.1 模块名称**

权限与策略中心，英文名称为 Permission & Policy Center。

**1.2 产品定位**

权限与策略中心是统一数据平台左侧导航的核心安全控制模块，负责管理平台内所有“谁可以访问什么、可以做什么、可以看到哪些数据、权限从哪里来、为什么没有权限”的规则。

本模块不负责创建用户、部门、项目和业务资源本身，而是负责在这些基础对象之上建立统一权限模型。

权限与策略中心需要为以下业务产品提供统一权限能力：

1. BI / 智能数据洞察。
2. 增长分析。
3. A/B 测试。
4. 客户数据平台。
5. 增长营销平台。
6. 数据准备与可视化建模。
7. 标签平台。
8. 分群平台。
9. 数据输出与数据开放。
10. 后续扩展的数据开发、指标平台、智能问数、AI Agent 数据应用。

**1.3 模块目标**

权限与策略中心需要解决以下问题：

1. 用户能否进入某个项目。
2. 用户能否看到某个菜单、页面、按钮。
3. 用户能否创建、查看、编辑、删除、管理某类资源。
4. 用户能否访问某个具体资源，例如仪表盘、数据集、图表、实验、标签、分群、营销任务。
5. 用户能否下载、复制、导出数据。
6. 用户能否查看敏感字段原文。
7. 用户能否看到数据集中的某些行或某些列。
8. 用户的权限来自个人授权、角色、用户组、部门、项目管理员、资源所有者，还是系统预置权限。
9. 用户为什么没有权限。
10. 管理员如何批量授权、批量回收权限。
11. 管理员如何查看某个资源的完整权限清单。
12. 管理员如何模拟某个用户访问某个资源时的最终权限。
13. 项目管理员和资源管理员的授权范围如何被约束。
14. 权限变更后如何实时或准实时生效。
15. 权限如何与审批流、操作日志、资源中心、安全中心联动。

**1.4 设计原则**

1. **统一权限引擎**
   所有业务产品共享同一套权限模型、权限计算逻辑、权限解释逻辑和审计日志结构。
2. **权限分层**
   权限至少分为项目权限、功能权限、资源权限、数据权限、操作权限、安全权限六层，不同层解决不同问题。
3. **先判断空间，再判断资源，再判断数据**
   权限判定顺序必须稳定：用户状态 -> 项目权限 -> 功能权限 -> 资源权限 -> 数据权限 -> 安全策略。
4. **显式拒绝优先于允许**
   如果某条策略明确拒绝访问，则即使其他策略允许，也应优先拒绝，除非该拒绝策略被管理员关闭或被更高优先级系统策略覆盖。
5. **最高权限合并，拒绝策略例外**
   用户通过多个角色、用户组、个人授权获得权限时，允许权限取并集；但屏蔽组授权、显式拒绝、数据行列限制、系统冻结、项目冻结等限制性策略优先。
6. **资源权限不等于数据权限**
   用户拥有数据集权限，不代表可以看到全部行列数据。行列权限、脱敏策略、网络区策略仍需单独判断。
7. **权限可解释**
   所有权限结果都必须能解释来源，例如“来自角色 A”“来自用户组 B”“来自项目管理员权限”“被行权限规则 C 限制”。
8. **授权操作必须可审计**
   所有授予、回收、修改、批量授权、模板配置、权限模拟、权限导出操作必须记录日志。
9. **权限配置面向开发可落地**
   页面上的每个锁、按钮、开关、复选框、树节点，都必须对应明确的数据结构和接口行为。

**2. 功能范围**

权限与策略中心包含以下功能：

10. 资源权限管理。
11. 数据权限管理。
12. 行权限配置。
13. 列权限配置。
14. 数据脱敏权限配置。

16. 权限模板。
17. 快捷配置。

25. 权限生效状态查看。

**2.2 本期不包含**

以下功能不在权限与策略中心直接实现：

1. 用户账号创建、禁用、删除，由组织与身份中心负责。
2. 项目创建、归档、冻结，由项目与空间中心负责。
3. 资源本身的创建、编辑、删除，由各业务产品负责。
4. 权限申请审批流程配置，由申请审批与流程中心负责。

6. 资产归属迁移、资源健康度，由资源与资产中心负责。
7. 操作日志检索与下载总入口，由审计与可观测中心负责。

权限与策略中心可以展示相关状态和提供跳转入口，但不承担这些模块的主流程。

**3. 权限模型设计**

**3.1 权限对象**

权限中心涉及以下核心对象：

1. 主体 Principal。
2. 角色 Role。
3. 用户组 UserGroup。
4. 项目 Project。
5. 功能点 FunctionPermission。
6. 资源 Resource。
7. 操作 Action。
8. 授权 Grant。
9. 策略 Policy。
10. 行权限 RowPolicy。
11. 列权限 ColumnPolicy。
12. 脱敏权限 MaskingPolicy。
13. 权限结果 PermissionDecision。
14. 权限来源 PermissionSource。

**3.2 主体 Principal**

主体指可以被授权的对象。

支持主体类型：

| **主体类型** | **说明** |
| --- | --- |
| user | 单个用户 |
| user\_group | 用户组 |
| department | 部门 |
| role | 角色 |
| external\_group | 外部群组，例如飞书群、企业微信群 |
| system | 系统预置主体 |

**3.2.1 主体授权规则**

1. user 主体授权只对单个用户生效。
2. user\_group 主体授权对组内所有成员生效。
3. department 主体授权对部门当前成员生效。
4. role 主体授权对角色当前成员生效。
5. external\_group 主体授权对已完成授信和绑定的外部群成员生效。
6. system 主体由系统内置，不允许普通管理员修改。

**3.3 资源 Resource**

资源指平台内可被授权和访问控制的对象。

本期支持资源类型：

| **资源类型** | **说明** |
| --- | --- |
| project | 项目 |
| dashboard | 仪表盘 |
| dashboard\_folder | 仪表盘文件夹 |
| chart | 图表 |
| dataset | 数据集 |
| dataset\_folder | 数据集文件夹 |
| data\_connection | 数据连接 |
| visual\_model | 可视化建模任务 |
| experiment | A/B 实验 |
| feature\_flag | Feature Flag |
| metric | 指标 |
| segment | 用户分群 |
| tag | 标签 |
| campaign | 营销活动 |
| touch\_task | 触达任务 |
| landing\_page | 落地页 |
| webhook\_template | Webhook 模板 |
| sms\_template | 短信模板 |
| data\_output\_task | 数据输出任务 |
| api\_token | API Token |
| system\_config | 系统配置项 |

**3.3.1 资源注册机制**

每个业务产品接入权限中心时，必须注册资源类型。

注册内容包括：

1. resource\_type。
2. resource\_display\_name。
3. 支持的操作 action。
4. 支持的权限等级 permission\_level。
5. 是否支持文件夹继承。
6. 是否支持行列权限。
7. 是否支持脱敏权限。
8. 是否支持权限申请。
9. 是否支持授权给角色。
10. 是否支持授权给用户组。
11. 是否支持权限清单下载。
12. 是否支持权限模拟。

**3.4 操作 Action**

操作表示用户对资源执行的具体行为。

通用操作包括：

| **Action** | **说明** |
| --- | --- |
| list | 列表可见 |
| read | 读取详情 |
| view | 查看内容 |
| create | 新建 |
| edit | 编辑 |
| delete | 删除 |
| manage | 管理 |
| grant | 授权 |
| transfer | 转移所有者 |
| download | 下载 |
| copy | 复制 |
| export | 导出 |
| embed | 嵌出 |
| subscribe | 订阅 |
| monitor | 配置监控 |
| execute | 执行 |
| approve | 审批 |
| debug | 调试 |
| publish | 发布 |
| offline | 下线 |
| decrypt | 解密查看 |
| api\_call | OpenAPI 调用 |

不同资源类型可支持不同 action。

**3.5 权限等级 PermissionLevel**

不同资源的权限等级需要统一抽象。

**3.5.1 项目权限等级**

项目权限等级：

none < viewer < editor < global\_viewer < admin

含义：

1. none：无项目访问权限。
2. viewer：可进入项目，可查看自己有资源权限的内容。
3. editor：包含 viewer，可创建部分项目资源。
4. global\_viewer：包含 editor，可查看项目内全部公共资源，但仍受数据权限限制。
5. admin：项目最高权限，可管理项目成员、项目设置和项目内资源授权。

**3.5.2 资源权限等级**

通用资源权限等级：

none < browse < view < edit < manage

其中：

1. browse：仅列表可见或仅阅览。
2. view：可查看资源内容，可按规则下载或复制。
3. edit：可编辑资源内容。
4. manage：可管理资源权限、删除、移动、转移所有者。

**3.5.3 功能权限等级**

功能权限不按等级，而按操作点控制：

1. 查看页面。
2. 新建。
3. 编辑。
4. 删除。
5. 下线。
6. 发布。
7. 全部操作。

**3.5.4 数据权限等级**

数据权限包括：

1. 行权限。
2. 列权限。
3. 脱敏权限。
4. 解密权限。
5. 下载解密权限。
6. API 解密权限。

数据权限不直接等同于资源权限，必须单独计算。

**3.6 授权 Grant**

授权表示某个主体对某个资源或功能拥有某种权限。

**4. 权限判定总流程**

**4.1 总判定顺序**

当用户访问任意资源或执行任意操作时，必须按以下顺序判断：

1. 用户是否存在。
2. 用户状态是否 active。
3. 用户是否占用必要 License。
4. 项目是否存在。
5. 项目状态是否允许访问。
6. 用户是否有项目进入权限。
7. 用户是否有对应功能权限。
8. 用户是否有资源权限。
9. 操作是否被系统或项目设置禁止。
10. 是否存在显式拒绝策略。
11. 是否存在行权限限制。
12. 是否存在列权限限制。
13. 是否存在脱敏策略。
14. 是否满足网络区、时间、设备、API 等安全策略。
15. 输出最终权限结果。

**4.2 项目冻结时的优先级**

如果项目状态为 frozen：

1. read、view 可按规则允许。
2. create、edit、delete、grant、download、copy、export、embed、execute 默认拒绝。
3. 系统管理员可执行解除冻结相关操作。
4. 项目管理员不可绕过冻结限制。

**4.3 系统全局开关优先级**

如果系统全局关闭某功能：

1. 即使用户有功能权限，也不展示入口。
2. 即使用户有资源权限，也不能通过接口执行该操作。
3. 权限解释中必须说明：“系统全局开关已关闭该功能”。

例如：

1. 系统关闭下载，则项目允许下载也不生效。
2. 系统关闭监控，则图表监控按钮不展示。
3. 系统关闭移动端，则移动端入口不展示。

**4.4 项目设置优先级**

项目设置不能突破系统全局限制，但可以进一步收紧权限。

例如：

1. 系统允许下载，项目可以禁止下载。
2. 系统禁止下载，项目不能允许下载。
3. 系统允许嵌出，项目可以关闭嵌出。
4. 系统关闭嵌出，项目不能开启嵌出。

**4.5 权限合并规则**

用户最终权限来自多个来源：

1. 个人授权。
2. 用户组授权。
3. 部门授权。
4. 角色授权。
5. 项目权限。
6. 文件夹继承。
7. 资源所有者身份。
8. 系统管理员身份。
9. 审批自动授权。
10. 系统预置权限。

合并规则：

1. allow 权限取最高等级。
2. actions 权限取并集。
3. 显式 deny 优先于 allow。
4. 屏蔽组授权会排除用户组、部门、角色来源的权限。
5. 过期权限不参与计算。
6. 已撤销权限不参与计算。
7. disabled 用户不参与任何权限计算。

**5. 用户角色与操作权限**

**5.1 系统管理员**

系统管理员拥有权限与策略中心全部能力。

可操作：

1. 查看所有权限配置。
2. 创建、编辑、删除角色。
3. 管理所有角色成员。
4. 给任意用户、用户组、角色授权。
5. 配置全部项目、资源、功能、数据权限。
6. 创建、编辑、删除行列权限。
7. 创建、编辑、删除脱敏权限。
8. 使用权限模拟。
9. 下载权限清单。
10. 查看权限变更日志。
11. 配置权限模板。
12. 配置系统级功能权限。

**5.2 项目管理员**

项目管理员可管理其项目范围内的权限。

可操作：

1. 查看自己管理项目的权限配置。
2. 给项目内用户授权项目资源。
3. 给项目内用户组授权资源。
4. 给项目内角色授权资源。
5. 配置项目内行列权限。
6. 配置项目内脱敏查看权限。
7. 下载项目内资源权限清单。
8. 使用项目范围内权限模拟。
9. 查看项目权限变更日志。

不可操作：

1. 修改系统级功能权限。
2. 给项目外用户授权，除非系统允许。
3. 创建系统级角色。
4. 修改自己无管理权限的资源。
5. 授权超出自己权限范围的权限。

**5.3 资源管理员**

资源管理员只能管理自己拥有 manage 权限的资源。

可操作：

1. 查看自己管理资源的权限清单。
2. 给项目内用户授予该资源权限。
3. 给项目内用户组授予该资源权限。
4. 回收该资源权限。
5. 下载该资源权限清单。
6. 查看该资源权限来源。

不可操作：

1. 授权项目权限。
2. 授权自己没有 manage 权限的资源。
3. 创建角色。
4. 修改行列权限，除非资源类型允许资源管理员配置。
5. 授予高于自身权限的权限。

**5.4 角色管理员**

角色管理员负责角色成员与角色资源权限维护。

可操作：

1. 查看自己负责的角色。
2. 编辑角色基本信息。
3. 维护角色成员。
4. 为角色配置自己有权限管理的资源。
5. 查看角色权限清单。
6. 下载角色权限清单。

不可操作：

1. 创建系统管理员角色。
2. 授予角色超出自己资源管理范围的权限。
3. 删除系统预置角色。
4. 修改默认系统角色身份。

**5.5 普通用户**

**8.7 新建角色**

**8.7.1 入口**

**8.7.2 创建角色步骤**

新建角色使用分步抽屉：

1. 基本信息。
2. 作用范围。
3. 功能权限。
4. 资源权限。
5. 数据权限。
6. 成员配置。
7. 确认创建。

**8.7.3 第一步：基本信息**

字段：

1. 角色名称。
2. 角色描述。
3. 角色类型。
4. 角色负责人。
5. 状态。

校验：

4. 不允许使用系统预置角色名称。
5. 角色负责人必填。
6. 负责人必须为 active 用户。
7. 项目级角色必须选择所属项目。

**8.7.4 第二步：作用范围**

字段：

1. 开放项目。
2. 开放产品。
3. 成员范围。
4. 是否允许角色负责人维护成员。

开放项目可选：

1. 全部项目。
2. 部分项目。

规则：

1. 系统管理员可选择全部项目。
2. 项目管理员只能选择自己管理的项目。
3. 如果选择全部项目，后续新增项目默认也开放该角色。
4. 如果选择部分项目，后续新增项目不自动开放。

开放产品可选：

1. BI。
2. 增长分析。
3. A/B 测试。
4. CDP。
5. 营销平台。
6. 数据准备。
7. 系统管理。
8. 项目中心。

**8.7.5 第三步：功能权限**

页面展示功能权限树。

功能权限树结构：

1. 产品。
2. 一级菜单。
3. 二级菜单。
4. 功能点。
5. 操作点。

操作点包括：

1. 查看。
2. 新建。
3. 编辑。
4. 删除。
5. 发布。
6. 下线。
7. 下载。
8. 导出。
9. 全部操作。

交互规则：

1. 勾选父节点时，默认勾选所有子节点。
2. 取消父节点时，取消所有子节点。
3. 子节点部分勾选时，父节点显示半选。
4. 必备权限不可取消，展示锁图标。
5. 鼠标悬停锁图标提示“该权限为角色基础权限，不可取消”。
6. 搜索功能点时，树节点自动展开匹配结果。
7. 勾选“全部操作”时，同级其他操作点自动勾选。
8. 取消任一单独操作点时，“全部操作”自动取消。

**8.7.6 第四步：资源权限**

资源权限配置支持两种方式：

1. 暂不配置资源权限。
2. 立即配置资源权限。

如果选择立即配置：

1. 选择资源类型。
2. 搜索资源。
3. 勾选资源。
4. 选择权限等级。
5. 配置是否继承子资源。
6. 设置有效期。
7. 添加到授权清单。

资源类型包括：

1. 项目。
2. 仪表盘。
3. 仪表盘文件夹。
4. 数据集。
5. 数据集文件夹。
6. 数据连接。
7. 可视化建模任务。
8. 实验。
9. Feature。
10. 标签。
11. 分群。
12. 营销任务。

权限等级根据资源类型动态展示。

例如仪表盘：

1. 仅阅览。
2. 查看。
3. 编辑。
4. 管理。

例如项目：

1. 查看。
2. 编辑。
3. 全局查看。
4. 管理。

**8.7.7 第五步：数据权限**

数据权限配置支持：

1. 不配置。
2. 添加行权限。
3. 添加列权限。
4. 添加脱敏权限。

创建角色时只允许选择已有数据权限规则，不在角色创建流程中创建新规则。新规则应在数据权限页面创建。

字段：

1. 数据集。
2. 行权限规则。
3. 列权限规则。
4. 脱敏规则。
5. 生效范围。

**8.7.8 第六步：成员配置**

支持成员配置方式：

1. 手动选择用户。
2. 选择部门。
3. 选择用户组。
4. 动态规则加入。

手动选择用户：

1. 支持按用户名、姓名、邮箱搜索。
2. 仅可选择 active 用户。
3. 支持多选。

选择部门：

1. 选择部门后，该部门当前成员加入角色。
2. 后续部门成员变化是否同步，由“动态同步”开关决定。

选择用户组：

1. 选择用户组后，组内成员加入角色。
2. 后续用户组成员变化是否同步，由“动态同步”开关决定。

动态规则加入：

规则条件支持：

1. 部门等于。
2. 职位包含。
3. 用户属性等于。
4. 用户类型等于。
5. 邮箱后缀等于。

动态规则必须支持预览命中用户。

1. 角色名称。

6. 资源权限数量。
7. 数据权限数量。

9. 负责人。

3. 创建角色。

6. 写入操作日志。
7. 跳转角色详情页。
8. 展示“角色创建成功”。

**8.8 角色详情**

点击角色名称进入角色详情页。

详情页标签：

1. 基本信息。

3. 功能权限。
4. 资源权限。
5. 数据权限。

顶部按钮：

**8.9 编辑角色**

编辑规则：

1. 系统预置角色不可修改名称。
2. 系统管理员角色不可修改权限。
3. 普通自定义角色可修改名称、描述、负责人、作用范围、权限、成员。
4. 角色权限修改后，成员权限在 1 分钟内生效。
5. 修改开放项目范围时，如果移除某项目，则角色成员失去该项目下由该角色带来的权限。
6. 修改前必须展示影响范围。

保存按钮逻辑：

1. 检查必填字段。
2. 检查是否会导致用户失去关键管理权限。
3. 展示权限变更差异。
4. 用户确认后保存。
5. 写入操作日志。

**8.10 复制角色**

点击“复制角色”：

弹窗字段：

1. 新角色名称。
2. 新角色描述。
3. 是否复制成员。
4. 是否复制功能权限。
5. 是否复制资源权限。
6. 是否复制数据权限。

规则：

1. 默认复制权限，不复制成员。
2. 新角色名称必填且唯一。
3. 系统预置角色可被复制为自定义角色。
4. 复制后新角色状态为 active。

**8.11 禁用角色**

点击禁用：

弹窗展示影响：

1. 该角色成员将不再通过此角色获得权限。
2. 角色不会被删除。
3. 角色成员关系保留。
4. 可后续重新启用。

点击确认：

1. 角色状态变为 disabled。
2. 权限计算时忽略该角色。
3. 写入操作日志。

**8.12 删除角色**

删除条件：

1. 系统预置角色不可删除。
2. 角色存在成员时可以删除，但必须提示影响。
3. 角色被审批流、系统配置引用时不可删除。
4. 删除后角色成员关系和角色授权关系全部失效。

删除确认：

1. 展示成员数量。
2. 展示权限数量。
3. 展示影响资源数量。
4. 用户输入角色名称。
5. 点击确认删除。

删除后：

1. 角色状态变为 deleted。
2. 权限计算不再使用该角色。
3. 写入操作日志。

1. 白名单模式。
2. 黑名单模式。

白名单模式：

1. 只有规则命中的主体可见对应数据。
2. 不在规则中的用户看不到任何受控数据。

黑名单模式：

1. 规则命中的主体受到限制。
2. 不在规则中的用户默认可见全部数据。

**16.6 列权限规则**

**16.6.1 列权限定义**

列权限用于控制某些用户是否可以看到数据集中的某些字段。

**16.6.2 列权限列表字段**

字段：

1. 规则名称。
2. 数据集。
3. 字段范围。
4. 授权主体。
5. 控制方式。
6. 状态。
7. 更新时间。
8. 操作。

**16.6.3 新建列权限**

字段：

1. 规则名称。
2. 数据集。
3. 字段选择。
4. 授权主体。
5. 控制方式。
6. 备注。

字段选择支持：

1. 模型字段。
2. 数据集字段。

控制方式：

1. 仅允许所选主体查看字段。
2. 禁止所选主体查看字段。

规则：

1. 模型字段受控时，其衍生数据集字段也受影响。
2. 数据集字段受控时，不影响底层模型字段。
3. 字段被用于 group by、where、join 时，如果用户无列权限，则查询应失败或图表不显示。
4. 表格中字段仅在 select 中时，无列权限用户不能看到该列。

**23. 权限生效机制**

**23.1 生效方式**

权限变更后采用准实时生效机制。

要求：

1. 新增授权 1 分钟内生效。
2. 回收授权 1 分钟内生效。
3. 高危权限回收，例如解密权限、下载权限，必须立即失效。
4. 用户禁用后权限立即失效。
5. 项目冻结后权限立即受限。
6. 系统开关关闭后相关权限立即失效。

**23.2 缓存机制**

权限引擎可使用缓存提升性能。

缓存键：

1. tenant\_id。
2. user\_id。
3. project\_id。
4. resource\_type。
5. resource\_id。
6. action。

缓存失效场景：

1. 用户状态变更。
2. 用户加入或移除角色。
3. 用户组成员变更。
4. 角色权限变更。
5. 资源授权变更。
6. 项目状态变更。
7. 项目设置变更。
8. 行列权限变更。
9. 脱敏权限变更。
10. 系统开关变更。

**23.3 权限变更通知**

权限变更后，系统发布权限变更事件：

事件内容：

1. event\_id。
2. event\_type。
3. tenant\_id。
4. project\_id。
5. affected\_user\_ids。
6. affected\_resource\_ids。
7. changed\_by。
8. changed\_at。

消费方：

1. 各业务产品。
2. 缓存服务。
3. 审计中心。
4. 通知中心。
5. 权限风险检测服务。

**24.5 与数据安全与合规中心**

权限中心负责谁有解密权限、行列权限，安全中心负责实际脱敏、加密、网络区策略执行。

**24.6 与审计中心**

所有权限操作日志同步至审计中心。

**27. 异常与边界规则**

**27.1 禁用用户权限不生效**

如果用户状态为 disabled：

1. 所有权限结果为拒绝。
2. 不删除授权记录。
3. 权限解释显示“用户已禁用”。

**27.2 删除用户权限不生效**

deleted 用户：

1. 不参与权限计算。
2. 不展示在新增授权主体搜索结果。
3. 历史授权清单中可展示为“用户已删除”。

**27.3 角色禁用**

角色 disabled：

1. 成员关系保留。
2. 角色权限不参与计算。
3. 权限来源中展示为“角色已禁用，不生效”。

**27.4 资源删除**

资源 deleted：

1. 不允许新增授权。
2. 已有授权不生效。
3. 权限清单可查看历史。
4. 权限解释显示“资源已删除”。

**27.5 权限过期**

授权 expires\_at 到期后：

1. status 自动变为 expired。
2. 不参与权限计算。
3. 权限清单中保留。
4. 可由管理员续期。

**27.6 授权不能高于自身权限**

资源管理员授权时：

1. 只能授予不高于自己拥有的权限。
2. 自己只有 edit 时不能授予 manage。
3. 自己没有 download 权限时不能授予 download。
4. 系统管理员不受此限制。

**27.7 必备权限不可取消**

某些功能是产品正常使用所需，例如：

1. 我的收藏。
2. 查看个人资料。
3. 查看自己有权限资源。
4. 基础首页入口。

这些权限不可取消，页面展示锁图标。

**27.8 行列权限与资源权限同时缺失**

如果用户既无数据集权限，又无行列权限：

1. 权限解释优先提示缺少数据集权限。
2. 行列权限提示作为补充说明。
3. 不泄露具体敏感字段规则。

**27.9 外部群授权未授信**

外部群组未完成授信时：

1. 授权按钮禁用。
2. 提示“该外部群尚未完成授信，无法用于授权”。
3. 提供“去授信”按钮。

**28. 验收标准**

**28.1 角色管理验收**

1. 系统管理员可创建角色。
2. 角色名称租户内唯一。
3. 系统预置角色不可删除。
4. 系统管理员角色不可编辑权限。
5. 角色可配置功能权限、资源权限、数据权限和成员。
6. 禁用角色后，成员不再通过该角色获得权限。
7. 删除角色后，角色授权不再生效。
8. 复制角色时可选择是否复制成员和权限。

**28.2 按用户授权验收**

1. 可搜索 active 用户。
2. disabled 用户权限显示为不生效。
3. 可给用户授予项目权限。
4. 可给用户授予资源权限。
5. 回收个人授权不影响角色或用户组授权。
6. 用户权限来源展示完整。
7. 权限变更写入日志。

**28.3 按用户组授权验收**

1. 可给用户组授予资源权限。
2. 用户加入用户组后自动继承权限。
3. 用户移出用户组后自动失去该用户组权限。
4. 屏蔽组授权生效。
5. 取消屏蔽后重新继承组权限。

**28.4 按角色授权验收**

1. 可为角色配置功能权限。
2. 可为角色配置资源权限。
3. 可为角色配置数据权限。
4. 快捷模板可预填权限。
5. 提交前展示权限差异。
6. 提交后角色成员权限生效。

**28.5 按模块授权验收**

1. 可查看某模块已授权主体。
2. 可给多个主体授予模块权限。
3. 授权子功能时自动补齐父级查看权限。
4. 系统开关关闭的模块不可新增授权。
5. 必备权限不可回收。

**28.6 资源权限验收**

1. 可按资源名称、ID 搜索资源。
2. 可查看资源完整权限清单。
3. 可授权用户、用户组、角色、部门。
4. 文件夹继承权限生效。
5. 屏蔽组授权生效。
6. 权限清单可下载。
7. 无 manage 权限用户不可管理资源权限。

**28.7 数据权限验收**

1. 可创建行权限规则。
2. 可创建列权限规则。
3. 固定值规则生效。
4. 动态用户属性规则生效。
5. 白名单和黑名单模式逻辑正确。
6. 列权限限制字段展示和查询。
7. 模拟验证可返回命中规则和样例结果。

**28.8 脱敏权限验收**

1. 可查看敏感字段列表。
2. 可授予解密权限。
3. 解密权限必须设置有效期。
4. 外部用户默认不可授予解密权限。
5. 下载解密和 API 解密必须单独授权。
6. 回收解密权限后立即失效。

**28.9 权限模拟验收**

1. 可选择用户、项目、资源、操作进行模拟。
2. 模拟结果包含允许或拒绝。
3. 模拟结果包含权限来源。
4. 模拟结果包含拒绝原因。
5. 模拟结果包含修复建议。
6. 模拟操作不产生实际授权。

**28.10 权限解释验收**

1. 管理员可查看完整权限解释。
2. 普通用户只看到简化原因。
3. 无权限页面可跳转权限申请。
4. 不泄露用户无权查看的敏感策略信息。

**28.11 权限清单验收**

1. 可按项目、主体、资源筛选权限。
2. 可查看权限来源。
3. 可下载权限清单。
4. 下载包含行列权限和脱敏权限选项。
5. 超大数据量导出走异步任务。

**28.12 权限日志验收**

1. 所有授权、回收、修改操作记录日志。
2. 日志包含原值和新值。
3. 日志包含操作人、时间、IP。
4. 日志支持筛选和下载。
5. 权限清单下载操作也记录日志。
