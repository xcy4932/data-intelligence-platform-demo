**触达营销-数据分析 PRD**

**1. 文档定位**

本文定义「触达营销-数据分析」模块的完整产品功能逻辑，覆盖以下能力：

1. DataFinder 分析能力集成
   包含：触达行为事件回流、事件属性映射、转化分析、事件分析、留存分析、看板能力、元数据与权限依赖。
2. 用户发送明细
   包含：查询发送记录、查看发送与到达状态、查看失败原因、查看上行回复关联、选中项重发、按当前筛选条件批量重发、查看重发记录。
3. 用户回复明细
   包含：Webhook 上行消息查询、回复内容查看、回复含义识别、72 小时内最优下行任务追溯。
4. 分群营销旅程
   包含：从分群视角查看触达活动、流程画布执行记录、分群数据。
5. 数据导出
   包含：面向客户 BI 平台的数据导出字段、导出任务配置、导出记录、导出权限与安全规则。

本文按“可以直接开发”的粒度描述页面、按钮、字段、交互、校验、状态、接口与数据逻辑。

**3.2 权限交互规则**

1. 用户没有菜单查看权限时，左侧菜单不展示。
2. 用户通过 URL 访问无权限页面时，展示 403 页面。
3. 用户只有查看权限时，可以查看数据，但不能执行保存、导出、重发、新建看板等操作。

6. 涉及用户 ID、手机号、openid、发送 ID 等敏感字段时，按数据权限决定是否脱敏展示。

**5. 数据洞察及元数据管理 分析能力集成**

**5.1 功能定位**

GMP 需要将触达行为和后链路行为统一交给 数据洞察和元数据管理 分析，支持运营人员直接在 GMP 内完成：

1. 单个任务转化分析。
2. 自主转化分析。
3. 触达行为事件分析。
4. 留存分析。
5. 将分析图表保存到看板。
6. 通过看板长期监控触达效果。
7. 通过元数据管理的行为数据管理查看事件、属性、虚拟事件、圈选事件。
8. 通过权限管理控制用户是否可使用高级分析和看板能力。

**6. 转化分析 PRD**

**6.1 功能定位**

转化分析用于分析用户在 GMP 触达后的行为转化情况。系统将转化路径拆成多个步骤，并计算用户从上一步到当前步骤、从第一步到当前步骤的转化率。

典型使用场景：

短信发送成功 -> 短链点击 -> 落地页访问 -> 提交表单 -> 支付成功

**6.2 页面入口**

入口一：任务详情页指标入口

消息触达详情 / 数据分析 / 转化分析（跳转到数据洞察的漏斗分析）

流程画布详情 / 数据分析 / 转化分析（跳转到数据洞察的漏斗分析）

入口二：自主分析入口

触达营销 / 数据分析 / 分析工具 / 转化分析（跳转到数据洞察的漏斗分析）

**6.3 路由**

/marketing-analysis/conversion

任务带入分析参数时：

/marketing-analysis/conversion?source=task&task\_id=xxx&task\_type=task

/marketing-analysis/conversion?source=canvas&task\_id=xxx&task\_type=canvas

直接使用数据洞察的漏斗分析

**7. 事件分析 PRD**

**7.1 功能定位**

事件分析用于通过构建指标、配置分组和筛选条件，对 GMP 触达行为及后链路用户行为进行多维分析。

常见问题：

1. 某个触达任务发送量、送达量、点击量是多少。
2. 不同通道的到达率是否不同。
3. 不同实验组的点击率是否不同。
4. 手动重发数据占比多少。
5. 某个活动下不同分组的发送表现如何。

**7.2 页面入口**

触达营销 / 数据分析 / 分析工具 / 事件分析（跳转到数据洞察的事件分析）

也可从任务详情、看板图表、用户发送明细跳转。

直接使用数据洞察的事件分析已有的功能，不做开发

**8. 留存分析 PRD**

**8.1 功能定位**

留存分析用于分析用户在完成起始事件后，在后续时间周期内是否完成回访事件。

典型场景：

收到触达消息的用户，在第 2 天、第 7 天、第 30 天是否再次访问、购买或登录。

**8.2 页面入口**

触达营销 / 数据分析 / 分析工具 / 留存分析（跳转到数据洞察的留存分析）

直接使用数据洞察的留存分析已有的功能，不做开发

**9. 看板 PRD**

**9.1 功能定位**

看板用于管理常用分析图表，支持日常监控触达营销核心指标。

**9.2 页面入口**

触达营销 / 数据分析 / 分析工具 / 看板（跳转到可视化分析的仪表盘）

直接使用可视化分析的仪表盘已有的功能，不做开发

**10. 用户发送明细 PRD**

**10.1 功能定位**

用户发送明细用于查看过往消息触达、流程画布、智能触达中，每个用户每一条触达发送记录，包含：

1. 什么时间发送。
2. 发送了什么内容。
3. 是否发送成功。
4. 是否送达。
5. 失败原因是什么。
6. 是否有用户回复。
7. 是否进行过重发。
8. 重发进度如何。

**10.2 页面入口**

触达营销 / 数据分析 / 明细查询 / 用户发送明细

路由：

/marketing-analysis/user-send-details

**10.3 页面结构**

1. 筛选区。
2. 批量操作区。
3. 发送明细表格。
4. 分页区。

**10.4 筛选区**

**筛选字段**

| **字段** | **类型** | **查询方式** |
| --- | --- | --- |
| 用户 ID | 输入框 | 精确搜索 baseid 或 current\_id |
| 触达任务类型 | 下拉多选 | 消息触达、流程画布、智能触达 |
| 任务名称 | 输入框 | 模糊搜索 |
| 任务 ID | 输入框 | 精确搜索 |
| 策略器名称 | 输入框 | 模糊搜索 |
| 策略器 ID | 输入框 | 精确搜索 |
| 触达任务通道 | 下拉多选 | sms、wechat、push、webhook 等 |
| 发送状态 | 下拉多选 | 发送成功、发送失败、未发送 |
| 到达状态 | 下拉多选 | 到达成功、到达失败、未收到通道回执 |
| 发送失败原因 | 下拉多选 | 支持搜索 |
| 到达失败原因 | 下拉多选 | 支持搜索 |
| 开始时间 | 日期时间 | 发送时间起点 |
| 结束时间 | 日期时间 | 发送时间终点 |

**查询规则**

1. 多个筛选条件之间为 AND。
2. 任务名称、策略器名称支持模糊搜索。
3. 任务 ID、策略器 ID、用户 ID 精确搜索。
4. 默认时间范围为最近 7 天。
5. 最大查询跨度为 366 天。
6. 查询结果默认按发送时间倒序排列。
7. 点击“查询”后页码重置为第 1 页。
8. 点击“重置”后清空筛选条件，并恢复默认最近 7 天。

**10.11 重发方式一：对选中项重发**

**适用场景**

少量用户反馈未收到消息，运营手动勾选这些用户后重发。

**流程**

1. 用户勾选一条或多条记录。
2. 点击“对「选中项」重发”。
3. 系统打开确认弹窗。
4. 弹窗展示可重发数、不可重发数、不可重发原因。
5. 用户点击“确认重发”。
6. 系统创建重发任务。
7. 列表刷新，并可查看重发记录。

**10.12 重发方式二：对当前筛选条件全部重发**

**适用场景**

批量发送失败，例如 5000 个用户因为同一失败原因未发送成功，运营筛选失败原因后批量重发。

**流程**

1. 用户配置筛选条件。
2. 点击“对「当前筛选条件」全部重发”。
3. 系统先计算当前筛选条件命中的记录数量。
4. 打开确认弹窗。
5. 用户确认后创建异步重发任务。
6. 重发任务按批次执行。
7. 用户可在重发记录中查看进度。

**必须校验**

1. 当前筛选条件不能为空，避免误重发全量数据。
2. 如果筛选命中数量超过系统阈值，例如 10 万条，需要二次强提示。
3. 用户需输入确认文案，例如“确认重发”，才能继续。
4. 后端必须在任务执行时保存本次筛选快照，避免筛选条件后续变化影响执行范围。

**10.14 重发内容生成逻辑**

重发时：

1. 使用任务当前配置中的发送内容。
2. 如果任务内容中插入用户标签、用户属性、券码、权益等变量，系统在重发时获取最新数据。
3. 如果变量获取失败，该用户重发失败，并记录失败原因。
4. 如果任务内容已删除或不可读取，该记录不可重发。
5. 重发产生的数据需要在任务数据分析中的“手动重发数据”体现。

**10.15 不可重发规则**

以下情况不可重发：

1. 触达通道为弹窗类型。
2. 消息触达-触发型任务，过滤原因为“进入条件不符合”。
3. 消息触达-触发型任务，过滤原因为“完成B”。
4. 流程画布策略器，过滤原因为“分群不匹配”。
5. AB 分流实验设置了“实验组不触达”。
6. 任务已删除。
7. 通道已停用。
8. 当前用户缺少高级操作权限。

| **原始内容** | **标准含义** |
| --- | --- |

**逻辑规则**

5. 未命中规则时展示“未识别”。

**11.8 最优下行任务追溯**

**追溯条件**

1. 当前回复 ID 与下行发送 ID 一致。
2. 当前回复 ID 类型与下行发送 ID 类型一致。
3. 下行发送时间早于或等于回复时间。
4. 下行发送时间与回复时间间隔不超过 72 小时。
5. 优先选择距离回复时间最近的一条下行消息。

**15. 验收标准**

**15.1 DataFinder 集成**

1. GMP 触达日志必须回流为 gmp\_sdk\_logs。
2. 事件属性必须包含任务、用户、通道、发送、到达、点击、重发、实验组等信息。
3. 用户从任务详情进入转化分析时，系统必须自动带入任务事件条件。
4. 用户从菜单进入转化分析时，页面应为空白自主分析配置。
5. 事件分析、留存分析、看板必须受 DataFinder 开通状态和权限控制。

**15.2 转化分析**

1. 可以正常跳转。

**15.3 事件分析**

1. 可以正常跳转。

**15.4 留存分析**

1. 可以正常跳转。

**15.5 看板**

1. 可以正常跳转。

**15.6 用户发送明细**

1. 支持按用户 ID、任务类型、任务名称、任务 ID、策略器、通道、发送状态、到达状态、时间筛选。
2. 表格必须展示 baseid、发送 ID、任务、内容、发送状态、到达状态、失败原因、上行消息、重发记录。
3. 支持对选中项重发。
4. 支持对当前筛选条件全部重发。
5. 重发前必须二次确认。
6. 弹窗通道、特定触发型过滤原因、流程画布分群不匹配、实验组不触达等场景不可重发。
7. 重发变量必须取最新数据。
8. 重发记录必须展示进度和操作人。

**15.7 用户回复明细**

1. 当前仅支持 Webhook 上行消息。
2. 支持按 baseid、回复 ID、回复内容、回复含义、回复时间、最优下行任务筛选。
3. 系统必须将用户回复归一为标准含义。
4. 系统必须在回复时间前 72 小时内追溯最优下行消息。
5. 无匹配下行消息时展示“-”。
6. 支持查看详情和跳转发送明细。

**15.8 分群营销旅程**

1. 支持选择分群。
2. 触达活动必须按执行粒度展示。
3. 定时单次只展示一次。
4. 定时重复按天展示每个子任务。
5. 触发型按实际执行过程展示。
6. 时间线按天倒序。
7. 分群数据展示最近用户数、更新频次、类型。
8. 可跳转用户发送明细和转化分析。

**15.9 数据导出**

1. 支持消息触达、流程画布、资源位三类导出对象。
2. 每类对象字段必须按 PRD 字段清单提供。
3. 支持字段选择和字段排序。
4. 支持异步导出。
5. 支持导出记录查看、下载、删除。
6. 敏感字段必须按权限脱敏。
7. 导出操作必须记录操作日志。
