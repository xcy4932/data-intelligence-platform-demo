**业务归因分析PRD**

**1. 产品定位与模块边界**

归因决策是智能数据洞察中的自动化数据归因与智能报告模块。它的目标不是让用户手动做一次临时分析，而是让分析生产者预先配置核心指标、业务日期、归因方式、检测算法、下钻维度、分组维度、订阅方式等参数，系统按日、周、双周、月或双月自动运行，生成可查看、可推送、可嵌入仪表盘、可通过 WebHook 同步的归因报告。

模块需要覆盖四类核心分析能力：

1. 异动分析：发现核心指标是否出现异常波动，并解释异常发生在哪些子指标或维度项上。
2. 维度归因：从维度项角度解释核心指标变化，由哪些维度、哪些维度值贡献最大。
3. 指标归因：从相关指标或指标公式角度解释核心指标变化，由哪些过程指标或公式因子贡献最大。
4. 指标分析树：将异动检测、维度归因、指标归因等能力节点化，组成可执行的业务分析树，并支持 WebHook 两阶段同步。

模块还需要包含通用支撑能力：归因配置管理、报告列表、报告查看、历史报告切换、自定义运算、例行运算暂停与恢复、订阅推送、WebHook 推送、权限管理、报告嵌入仪表盘、嵌出参数控制。

本 PRD 按照前端和后端可以直接实现的粒度描述，不按功能清单罗列，而是拆成页面、状态、数据结构、交互规则、校验逻辑、运算逻辑和验收标准。

**2.5 FilterGroup：筛选条件**

筛选条件采用 AND + OR 分组结构。

type FilterGroup = {

andGroups: OrConditionGroup[];

};

type OrConditionGroup = {

id: string;

conditions: FilterCondition[];

};

type FilterCondition = {

fieldId: string;

fieldName: string;

fieldType: "STRING" | "NUMBER" | "DATE" | "BOOLEAN";

operator:

| "EQ"

| "NE"

| "IN"

| "NOT\_IN"

| "GT"

| "GTE"

| "LT"

| "LTE"

| "BETWEEN"

| "IS\_NULL"

| "IS\_NOT\_NULL"

| "CONTAINS"

| "NOT\_CONTAINS";

value?: unknown;

};

页面上“添加”按钮新增一个 AND 条件组；当前组右上角的 OR 按钮在该组内新增 OR 条件。最终 SQL 逻辑为：

(group1\_condition1 OR group1\_condition2)

AND

(group2\_condition1 OR group2\_condition2)

每个归因配置必须指定分区日期 p\_date 的筛选范围。保存时后端校验：

function validatePartitionFilter(filterConfig: FilterGroup): boolean {

return filterConfig.andGroups.some(group =>

group.conditions.some(condition =>

condition.fieldName === "p\_date" &&

["EQ", "IN", "BETWEEN", "GTE", "LTE"].includes(condition.operator)

)

);

}

如果未配置 p\_date，保存按钮不可用，并在筛选区下方提示：“必须指定分区日期 p\_date 的查询范围，否则无法进行归因运算。”

**5. 异动分析配置 PRD**

**5.1 功能目标**

异动分析用于自动检测核心指标在观察日期是否显著偏高或偏低，并可附带子指标拆解与维度拆解。系统按照配置的粒度在数据就绪后运行，生成报告并推送订阅。

**5.2 异动检测配置**

type AnomalyConfig = {

detectionMode: "ALGORITHM" | "RULE";

algorithmConfig?: {

algorithm: "HOLT\_WINTERS" | "PROPHET";

sensitivity: number;

observationWindow: number;

smoothingWindow?: number;

ignoreSmallShareMetric?: {

enabled: boolean;

metricId?: string;

threshold: number;

};

};

ruleConfig?: {

compareTarget: "LAST\_PERIOD" | "LAST\_WEEK\_SAME\_DAY";

upperThresholdPercent?: number;

lowerThresholdPercent?: number;

};

dimensionDrilldowns?: DimensionDrilldownPath[];

metricDisassemblies?: MetricDisassemblyFormula[];

};

**5.3 算法模式**

算法模式通过历史数据学习正常波动区间，输出预测值、上界、下界和实际值。

字段逻辑：

1. algorithm=HOLT\_WINTERS 时，适用于周期性不强、近期趋势更重要的时间序列。
2. algorithm=PROPHET 时，适用于周期性强、波动较规律的时间序列。
3. sensitivity 越高，正常波动区间越窄，异常更容易被触发。
4. observationWindow 表示用于观察和建模的历史时间窗口。
5. smoothingWindow 用于移动平均平滑。
6. ignoreSmallShareMetric.enabled=true 时，需要选择一个衡量占比指标，并且后端忽略占比低于 2% 的异常项。

异常判断：

function judgeAnomaly(actual: number, lower: number, upper: number): AnomalyStatus {

if (actual < lower) {

return {

isAnomaly: true,

direction: "LOWER",

summary: "显著偏低",

deviationDegree: Math.abs((actual - lower) / lower),

};

}

if (actual > upper) {

return {

isAnomaly: true,

direction: "HIGHER",

summary: "显著偏高",

deviationDegree: Math.abs((actual - upper) / upper),

};

}

return {

isAnomaly: false,

direction: "NORMAL",

summary: "没有显著变化",

deviationDegree: null,

};

}

**5.4 规则模式**

规则模式不训练时间序列模型，而是直接基于环比或同比百分比判断异常。

type RuleConfig = {

compareTarget: "LAST\_PERIOD" | "LAST\_WEEK\_SAME\_DAY";

upperThresholdPercent?: number;

lowerThresholdPercent?: number;

};

判断逻辑：

const changePercent = (compareValue - baseValue) / baseValue;

if (upperThresholdPercent !== undefined && changePercent > upperThresholdPercent) {

return "HIGHER";

}

if (lowerThresholdPercent !== undefined && changePercent < -Math.abs(lowerThresholdPercent)) {

return "LOWER";

}

return "NORMAL";

如果 baseValue=0，不能计算百分比。后端返回 INVALID\_BASE\_ZERO，前端在试运算结果中展示：“基准值为 0，无法使用百分比规则判断异常，请调整指标或规则。”

**5.5 维度拆解配置**

type DimensionDrilldownPath = {

id: string;

name?: string;

dimensions: {

fieldId: string;

fieldName: string;

displayName?: string;

}[];

};

交互逻辑：

1. 点击“+ 维度拆解”新增一个下钻路径。
2. 每条路径至少选择 1 个维度，最多建议 5 个维度。
3. 路径内维度按顺序构成层级下钻，例如 省份 > 城市 > 区县。
4. 报告中仅展示存在异常的维度路径；如果某路径所有维度项都无异常，则该路径不展示。
5. 若用户选择重复维度，前端禁止保存，并提示：“同一下钻路径中不能重复选择维度。”

报告生成时，系统对每条路径按层级计算每个维度项的趋势和异常状态。父节点无异常但子节点有异常时，父节点仍可展示，并在“显著子项”字段中显示异常子节点数量。

**7. 维度归因配置 PRD**

**7.1 功能目标**

维度归因用于解释核心指标从基准期到观察期的变化，是由哪些维度、哪些维度值贡献造成的。它输出贡献率、贡献值、同向贡献因子、反向贡献因子、根因维度定位、趋势图、瀑布图或拆解树。

**7.2 核心指标与算法自动选择**

维度归因在选择核心指标后，系统需要根据表达式自动识别贡献率算法。

type DimensionAttributionAlgorithm =

| "ADTRIBUTOR"

| "PROPORTION"

| "DROP";

算法映射：

function inferDimensionAlgorithm(metricExpression: string): DimensionAttributionAlgorithm {

if (containsLOD(metricExpression)) {

return "DROP";

}

if (isAdditiveRatio(metricExpression)) {

return "PROPORTION";

}

return "ADTRIBUTOR";

}

映射规则：

1. 普通加法类、计数类、去重计数类、聚合表达式、常见除法表达式默认使用定基法。
2. 分子分母均可加和的比率指标可使用占比加权法。
3. 表达式中使用 LOD 函数时使用剔除法。
4. 系统自动推断算法后，前端展示“系统已根据指标公式选择算法”，高级用户可在允许范围内切换算法。
5. 如果公式无法解析，禁止保存，并提示用户检查指标表达式。

type CoreMetricImpactRow = {

metricValueAfterRemoval: number;

impactDiff: number;

};

加法指标逻辑：

占比 = 当前维度项数值 / 核心指标值

占比越高，对核心指标当期值影响越大

除法指标逻辑：

剔除维度项后的核心指标值 =

(父层级分子 - 当前维度项分子) / (父层级分母 - 当前维度项分母)

影响差值 = 原核心指标值 - 剔除后核心指标值

散点图象限：

1. 左上角：维度项自身低于大盘，并拉低大盘，表现差。
2. 右下角：维度项自身高于大盘，并拉高大盘，表现好。
3. 其余象限用于识别自身表现与大盘影响方向不一致的维度项。

**9.1 功能目标**

指标归因用于解释核心指标变化是由哪些相关指标、公式因子或过程指标造成的。它支持乘法公式、复合公式和相关性归因。

一个报告可以包含多个归因公式，一个公式可以包含多个因子。

**9.3 乘法指标归因**

适用场景：

成交额 = 点击UV \* 访购率 \* 平均客单价

成单率 = 渲染成功率 \* 提交订单率 \* 生单成功率 \* 支付成功率

配置结构：

type MultiplicativeFormulaConfig = {

factors: MetricFactorConfig[];

};

type MetricFactorConfig = {

id: string;

metricName: string;

datasetId: string;

metricId: string;

aggregate: CoreMetricConfig["aggregate"];

dateField: string;

displayFormat: CoreMetricConfig["displayFormat"];

};

保存校验：

1. 至少配置 2 个因子。
2. 因子名称在同一报告内不可重复。
3. 因子的日期粒度必须与核心指标一致。
4. 后端试运算时校验因子相乘是否近似等于核心指标。如果误差超过阈值，试运算警告：“乘法因子与核心指标不满足乘积关系，请检查配置。”
5. 除法指标可通过为分母建立倒数字段实现，例如满意度 = 满意量 × 1/参评量。

贡献率计算逻辑：

贡献率\_i =

[ln(本期因子\_i) - ln(上期因子\_i)]

/

[ln(本期核心指标) - ln(上期核心指标)]

如果任一因子值小于等于 0，不能取对数，后端返回错误，前端提示：“乘法归因要求核心指标和所有因子在基准期、观察期均大于 0。”

**9.4 复合公式归因**

适用场景：核心指标由多个指标通过乘法、除法、加法、减法组合得到。

示例：

DAU看播时长 = (看播UV \* 看播UV人均看播时长) / DAU

配置结构：

type CompositeFormulaConfig = {

factors: MetricFactorConfig[];

};

公式编辑器规则：

1. 用户从左侧指标列表插入因子。
2. 支持 + - \* / ( )。
3. 不允许出现未声明变量。
4. 不允许空括号。
5. 不允许连续运算符。
6. 除法分母在试运算中不能为 0。

**9.5 相关性归因**

适用场景：核心指标与过程指标之间没有明确公式，但存在相关性，需要用模型解释贡献。

4. 每个过程指标必须配置数据集、指标、聚合方式、日期字段和数据格式。
5. 模型训练时将历史数据切分为训练集和测试集。
6. 如果模型在测试集上表现不佳，后端返回低质量模型警告，并提示用户增加更相关的因子指标或增加历史数据量。
7. 使用 XGBoost 建模，使用 SHAP 计算过程指标贡献值。
8. 贡献值为本期和上期 SHAP 回归值之差。
9. 贡献率为贡献值除以核心指标本期与上期差值。

**11.4 运行逻辑**

async function runAnalysisTree(tree: AnalysisTreeConfig) {

const sortedNodes = topologicalSort(tree.nodes, tree.edges);

for (const node of sortedNodes) {

if (!areParentsFinished(node)) {

node.status = "unready";

continue;

}

node.status = "running";

try {

const result = await runNode(node);

node.status = result.status;

node.nlg = result.nlg;

node.params = result.params;

} catch (error) {

node.status = "failed";

node.msg = error.message;

}

}

}

前端需要防止形成循环依赖。用户连接节点时，如果新边会导致有向图出现环，禁止连接并提示：“分析树节点不能形成循环依赖。”

**15. 报告嵌入仪表盘 PRD**

**15.1 嵌入归因报告**

用户在归因报告页面复制 URL，然后在仪表盘中添加网页控件并填入 URL。

为了让仪表盘每次打开时加载最新报告，系统需要支持参数：

CalculationDay=Latest

用户复制嵌入链接时，前端自动做以下处理：

1. 将 CalculationDay 替换为 Latest。
2. 删除 GenerateType=Trial。
3. 删除 ReportId。
4. 保留 SceneId 或配置标识。
5. 根据用户选择追加展示控制参数。

嵌入参数：

type AttributionEmbedQuery = {

OnlyRootCause?: "True" | "False";

Algorithms?: "Adtributor" | "Drop" | "Proportion";

Advance?: "True" | "False";

Inline?: "true" | "false";

};

规则：

1. OnlyRootCause=True 时，归因分析报告只展示分析详情，不展示报告头部指标卡和趋势图。
2. OnlyRootCause 需要配合 Algorithms 使用，单独使用不生效。
3. Algorithms 仅当报告中包含多个算法时生效。
4. Advance=False 时，隐藏表格上方 TopN 筛选和下载功能。
5. Inline=true 时隐藏 DataWind 导航。

**19. 验收标准**

**19.1 配置创建验收**

1. 用户可以从归因报告首页新建配置。
2. 未填写名称不能创建。
3. 名称重复时后端拒绝保存。
4. 选择归因类型后可进入对应配置表单。
5. 已保存配置不允许直接切换归因类型。
6. 保存配置后自动触发试运算。
7. 试运算失败时展示明确失败原因。

**19.2 异动分析验收**

1. 支持算法模式和规则模式。
2. 算法模式可选择 Holt-Winters 或 Prophet。
3. 敏感度越高，异常更容易触发。
4. 规则模式按阈值判断显著偏高或显著偏低。
5. 维度拆解只展示存在异常的路径。
6. 指标拆解展示子指标显著性和异常程度。
7. 趋势图正确展示实际值、预测值、上下界。
8. 报告可按历史观察日期切换。

**19.3 维度归因验收**

1. 支持下钻、组合、自动发现三种视角。
2. 下钻视角可逐层展开。
3. 组合视角按叉乘维度项计算贡献。
4. 自动发现视角展示根因维度和 Surprise 值。
5. 表格基础模式展示基准值、观察值、差值、差异百分比、贡献率、贡献值。
6. 高级模式按算法展示 EP 值、剔除法得分、种类内/种类间贡献。
7. 支持表格、瀑布图、拆解树切换。
8. 支持 TopN 筛选、趋势图、下载。
9. 支持自定义运算，自定义报告未保存时 7 天后过期。

**19.4 指标归因验收**

1. 支持乘法公式、复合公式、相关性归因。
2. 乘法归因要求因子值大于 0。
3. 同一报告内指标名称不能重复。
4. 相关性归因至少添加 2 个过程指标。
5. 相关性归因模型质量不足时给出警告。
6. 支持按贡献率排序或按配置顺序展示。
7. 报告展示因子自身变化、贡献值和贡献率。

**19.5 订阅与 WebHook 验收**

1. 新建配置成功后自动创建默认订阅。
2. 用户可以新建、编辑、停用、立即推送订阅。
3. WebHook 接收方返回 code=0 视为成功。
4. WebHook 失败后每 10 秒重试一次，最多 5 次。
5. 归因报告 WebHook 包含公共字段、报告链接、完整报告 URL、token、detail。
6. 指标分析树 WebHook 分阶段推送元信息和节点明细请求参数。

**19.6 权限验收**

1. 查看权限只能查看配置和报告。
2. 编辑权限可以编辑配置、试运算、重跑和新建订阅。
3. 管理权限可以授权他人。
4. 用户组权限和个人权限同时存在时取最高权限。
5. 归因报告权限与数据集权限相互独立。

**19.7 嵌入与嵌出验收**

1. 复制嵌入链接时可将 CalculationDay 设置为 Latest。
2. 嵌入链接自动删除 GenerateType=Trial 和 ReportId。
3. URL 参数可控制归因报告各区域显示隐藏。
4. navigation=false 时报告 Tab 也隐藏。
5. 指标分析树支持 URL 嵌入和仪表盘分析树控件嵌入。
6. 结论区点击行为可通过参数控制是否打开节点详情抽屉。
