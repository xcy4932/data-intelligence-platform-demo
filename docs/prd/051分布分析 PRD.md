**分布分析 PRD**

**1. 功能定位**

分布分析用于回答：

用户在某段时间内，对某个事件、属性或行为指标的数值分布是什么样的？

有多少用户处在低频、中频、高频区间？

不同分布区间的人数和占比如何变化？

不同用户群、渠道、系统版本、城市之间的分布结构是否不同？

某个指标是否出现长尾、集中、异常偏移？

典型例子：

过去 7 天，每个用户启动 App 的次数分布

过去 30 天，每个用户观看广告次数分布

过去 1 天，每个用户游戏局数分布

过去 30 天，每个用户累计付费金额分布

过去 7 天，每个用户活跃天数分布

过去 1 天，每个用户活跃小时数分布

过去 30 天，每个用户订单金额总和分布

本功能的核心不是简单统计事件次数，而是：

先按统计主体聚合出每个用户的指标值

再把指标值归入分布区间

最后统计每个区间的人数、占比、趋势和明细

**3. 核心概念**

**3.1 分析指标**

分析指标是分布分析的核心对象。

它表示：

对每个统计主体，在指定时间范围内计算出的一个数值。

例如：

用户 A 在 2026-05-01 启动 App 5 次

用户 B 在 2026-05-01 启动 App 2 次

用户 C 在 2026-05-01 启动 App 0 次

如果分布区间是：

1 次

2 次

3 次

4 次

5 次

6-10 次

10 次以上

则用户 A 进入“5 次”区间，用户 B 进入“2 次”区间。

**3.2 统计主体**

统计主体用于决定“人数”里的“人”是什么。

支持：

用户 ID

设备 ID

账号 ID

匿名 ID

自定义主体 ID

字段结构：

type AnalysisSubject = {

subjectType: "user\_id" | "device\_id" | "account\_id" | "anonymous\_id" | "custom\_id";

displayName: string;

};

默认使用：

user\_id

切换统计主体后：

1. 当前事件配置保留。

2. 查询结果清空。

3. 再次点击查询后，按新主体重新聚合。

4. 如果某个事件不支持该主体，事件选择器中置灰并提示。

**3.3 分布区间**

分布区间是把指标值划分成多个连续或离散区间的规则。

例如：

0 次

1 次

2 次

3-5 次

6-10 次

10 次以上

或：

0-100 元

100-500 元

500-1000 元

1000 元以上

支持默认、预置、等分、自定义等分和自定义区间：默认分组由系统根据 Sturges 算法计算；预置分组可按 1 次、2 次、3 次、4 次、5 次、6-10 次、11-20 次、20-50 次、50-100 次、大于 100 次划分；也支持 5 等分、10 等分、15 等分和自定义区间。

**4. 指标配置**

**4.1 选择分析事件**

用户在指标配置区选择一个事件作为分布分析的基础事件。

支持事件类型：

一般事件

虚拟事件

圈选事件

字段结构：

type DistributionMetricEvent = {

eventName: string;

eventDisplayName: string;

eventType: "normal" | "virtual" | "visual";

filters?: FilterGroup;

};

事件选择器支持：

1. 按事件中文名搜索

2. 按事件英文名搜索

3. 按事件描述搜索

4. 按事件分类筛选

5. 展示最近使用事件

6. 展示收藏事件

7. 展示事件是否可用于当前主体

选择事件后，系统自动加载该事件可用的计算方式。

**4.2 事件过滤条件**

每个分析事件可以配置过滤条件。

例如：

事件：支付成功

过滤条件：商品类型 = 会员

过滤条件：支付金额 > 0

字段结构：

type FilterGroup = {

relation: "AND" | "OR";

conditions: Array<FilterCondition | FilterGroup>;

};

type FilterCondition = {

fieldType:

| "event\_property"

| "user\_property"

| "user\_tag"

| "cohort"

| "subject\_property";

fieldName: string;

operator:

| "eq"

| "neq"

| "in"

| "not\_in"

| "contains"

| "not\_contains"

| "gt"

| "gte"

| "lt"

| "lte"

| "between"

| "is\_null"

| "not\_null";

value: any;

};

交互规则：

1. 点击“添加过滤条件”。

2. 默认添加一条 AND 条件。

3. 支持切换 AND / OR。

4. 支持最多两层嵌套。

5. 未完整配置的条件不允许查询。

6. 删除事件时，同步删除事件过滤条件。

**4.3 计算方式**

计算方式决定如何把事件数据聚合成每个主体的指标值。

支持以下类型：

| **计算方式** | **含义** | **示例** |
| --- | --- | --- |
| 总次数 PV | 统计主体触发事件的次数 | 每个用户启动 App 几次 |
| 总天数 Active Days | 统计主体在多少个自然日触发过事件 | 每个用户过去 30 天活跃几天 |
| 总小时数 Active Hours | 统计主体在多少个自然小时触发过事件 | 每个用户当天活跃几个小时 |
| 属性求和 SUM | 对事件属性求和 | 每个用户累计支付金额 |
| 属性均值 AVG | 对事件属性求平均 | 每个用户平均订单金额 |
| 属性最大值 MAX | 取事件属性最大值 | 每个用户最大单笔支付金额 |
| 属性最小值 MIN | 取事件属性最小值 | 每个用户最小单笔支付金额 |
| 去重属性数 DISTINCT | 统计事件属性去重数量 | 每个用户浏览过多少个商品 |
| 首次属性值 FIRST | 取时间范围内首次事件属性值 | 首次启动来源 |
| 末次属性值 LAST | 取时间范围内末次事件属性值 | 最近一次版本号 |

字段结构：

type DistributionMetric = {

event: DistributionMetricEvent;

aggregator:

| "PV"

| "ACTIVE\_DAYS"

| "ACTIVE\_HOURS"

| "SUM"

| "AVG"

| "MAX"

| "MIN"

| "DISTINCT"

| "FIRST"

| "LAST";

propertyName?: string;

propertyType?: "number" | "string" | "datetime" | "boolean" | "list";

};

校验规则：

| **场景** | **校验** |
| --- | --- |
| PV | 不需要选择属性 |
| ACTIVE\_DAYS | 不需要选择属性 |
| ACTIVE\_HOURS | 不需要选择属性 |
| SUM / AVG / MAX / MIN | 必须选择数值属性 |
| DISTINCT | 可以选择 string、number、datetime 属性 |
| FIRST / LAST | 可以选择任意可展示属性 |
| 指标结果非数值 | 不允许进入数值区间分布，只允许枚举分布 |

**5. 指标计算逻辑**

**5.1 基础计算单位**

每次查询先生成主体粒度的中间表。

结构：

type SubjectMetricValue = {

subjectId: string;

timeBucket: string;

metricValue: number | string | null;

eventCount: number;

};

示例：

| **subjectId** | **timeBucket** | **metricValue** |
| --- | --- | --- |
| u\_001 | 2026-05-01 | 5 |
| u\_002 | 2026-05-01 | 2 |
| u\_003 | 2026-05-01 | 0 |

**5.2 总次数 PV**

COUNT(event\_id)

按主体和时间粒度聚合：

SELECT

subject\_id,

time\_bucket,

COUNT(\*) AS metric\_value

FROM events

WHERE event\_name = :eventName

GROUP BY subject\_id, time\_bucket

**5.3 活跃天数**

定义：

在查询时间范围内，主体至少触发一次事件的自然日数量。

用户只要在一天内触发一次，就记这一天有发生。

SQL 示例：

SELECT

subject\_id,

COUNT(DISTINCT DATE(event\_time, timezone)) AS metric\_value

FROM events

WHERE event\_name = :eventName

GROUP BY subject\_id

**5.4 活跃小时数**

定义：

在查询时间范围内，主体至少触发一次事件的自然小时数量。

用户至少在某一小时触发一次，就记这一小时有发生。

SQL 示例：

SELECT

subject\_id,

COUNT(DISTINCT DATE\_TRUNC('hour', event\_time)) AS metric\_value

FROM events

WHERE event\_name = :eventName

GROUP BY subject\_id

**5.5 属性求和 SUM**

SUM(CAST(property\_value AS DOUBLE))

规则：

1. 仅统计属性存在且可转为数值的事件。

2. 属性为空的事件默认忽略。

3. 如果主体没有任何有效属性值，则 metricValue = null。

4. null 默认不进入任何区间，除非用户开启“包含空值区间”。

**5.6 属性均值 AVG**

AVG(CAST(property\_value AS DOUBLE))

规则：

1. 分母是有效属性值事件数。

2. 空值不进入分母。

3. 如果没有有效值，结果为 null。

**5.7 去重属性数 DISTINCT**

COUNT(DISTINCT property\_value)

例如：

每个用户浏览过多少个不同商品

每个用户参与过多少个不同活动

每个用户使用过多少个不同功能

**6. 分布区间配置**

**6.1 区间模式**

支持 5 种区间模式：

type BucketMode =

| "sturges\_auto"

| "preset\_frequency"

| "equal\_width"

| "custom\_equal\_width"

| "custom\_ranges"

| "enum\_values";

页面展示：

分布区间：默认 / 预置 / 等分 / 自定义等分 / 自定义区间

**6.2 默认分组：Sturges 自动分组**

默认分组由系统根据指标值分布自动生成。

公式：

bucketCount = ceil(log2(n) + 1)

其中：

n = 有效主体数

规则：

1. 如果有效主体数 < 2，则只生成 1 个区间。

2. 如果最大值 = 最小值，则只生成 1 个区间。

3. 区间边界保留 2 位小数。

4. 支持用户点击“恢复默认分组”重新计算。

字段结构：

type SturgesBucketConfig = {

mode: "sturges\_auto";

includeNullBucket: boolean;

};

**6.3 预置频次分组**

适用于 PV、活跃天数、活跃小时数等非负整数指标。

默认区间：

1 次

2 次

3 次

4 次

5 次

6-10 次

11-20 次

21-50 次

51-100 次

100 次以上

字段结构：

type PresetFrequencyBucketConfig = {

mode: "preset\_frequency";

ranges: Array<{

id: string;

label: string;

min?: number;

max?: number;

leftClosed: boolean;

rightClosed: boolean;

}>;

};

默认配置：

[

{ "label": "1次", "min": 1, "max": 1, "leftClosed": true, "rightClosed": true },

{ "label": "2次", "min": 2, "max": 2, "leftClosed": true, "rightClosed": true },

{ "label": "3次", "min": 3, "max": 3, "leftClosed": true, "rightClosed": true },

{ "label": "4次", "min": 4, "max": 4, "leftClosed": true, "rightClosed": true },

{ "label": "5次", "min": 5, "max": 5, "leftClosed": true, "rightClosed": true },

{ "label": "6-10次", "min": 6, "max": 10, "leftClosed": true, "rightClosed": true },

{ "label": "11-20次", "min": 11, "max": 20, "leftClosed": true, "rightClosed": true },

{ "label": "21-50次", "min": 21, "max": 50, "leftClosed": true, "rightClosed": true },

{ "label": "51-100次", "min": 51, "max": 100, "leftClosed": true, "rightClosed": true },

{ "label": "100次以上", "min": 101, "leftClosed": true, "rightClosed": false }

]

**6.4 等分分组**

等分分组用于把最小值到最大值平均切分成固定数量区间。

支持快捷选项：

5 等分

10 等分

15 等分

字段结构：

type EqualWidthBucketConfig = {

mode: "equal\_width";

bucketCount: 5 | 10 | 15;

includeNullBucket: boolean;

};

计算规则：

intervalWidth = (maxValue - minValue) / bucketCount

区间规则：

1. 默认左闭右开：[a, b)

2. 最后一个区间右闭：[a, b]

3. 如果 maxValue = minValue，则只生成一个区间。

**6.5 自定义等分**

用户可以自行设定：

起始值

结束值

区间宽度

字段结构：

type CustomEqualWidthBucketConfig = {

mode: "custom\_equal\_width";

start: number;

end: number;

width: number;

includeBelowRange: boolean;

includeAboveRange: boolean;

includeNullBucket: boolean;

};

示例：

{

"mode": "custom\_equal\_width",

"start": 0,

"end": 100,

"width": 10,

"includeBelowRange": true,

"includeAboveRange": true,

"includeNullBucket": false

}

生成区间：

小于 0

0-10

10-20

...

90-100

大于 100

校验规则：

| **字段** | **规则** |
| --- | --- |
| start | 必须小于 end |
| width | 必须大于 0 |
| 区间数量 | 默认最多 100 个 |
| 超出数量 | 禁止保存，提示减少区间数量 |

**6.6 自定义区间**

用户可以完全自定义每个区间。

字段结构：

type CustomRangeBucketConfig = {

mode: "custom\_ranges";

ranges: Array<DistributionRange>;

includeNullBucket: boolean;

};

type DistributionRange = {

id: string;

label: string;

min?: number;

max?: number;

leftClosed: boolean;

rightClosed: boolean;

};

示例：

[

{

"id": "r1",

"label": "低价值用户",

"min": 0,

"max": 100,

"leftClosed": true,

"rightClosed": false

},

{

"id": "r2",

"label": "中价值用户",

"min": 100,

"max": 500,

"leftClosed": true,

"rightClosed": false

},

{

"id": "r3",

"label": "高价值用户",

"min": 500,

"leftClosed": true,

"rightClosed": false

}

]

交互规则：

1. 点击“自定义区间”。

2. 默认生成两行：[ -∞, +∞ )。

3. 用户可点击“+”添加区间。

4. 用户可删除区间。

5. 用户可编辑区间名称。

6. 区间按 min 升序自动排序。

7. 支持 -∞ 和 +∞。

8. 点击“校验区间”检查重叠和遗漏。

-∞ 和 +∞ 表示所选指标的最小值到最大值的指代，用户按需填写需要分段的数值即可。

**6.7 区间校验规则**

| **校验项** | **规则** |
| --- | --- |
| 区间为空 | 禁止查询 |
| min >= max | 禁止保存 |
| 区间重叠 | 默认禁止，提示重叠区间 |
| 区间遗漏 | 允许，但展示提示 |
| 区间名称重复 | 自动追加序号 |
| 非数值输入 | 禁止保存 |
| 区间数量过多 | 默认最多 100 个 |
| null 值 | 根据 includeNullBucket 决定是否进入“空值”区间 |

**7. 用户筛选**

**7.1 功能说明**

用户筛选用于限定参与分布分析的目标用户范围。

例如：

新老用户 = 老用户

城市 = 深圳

操作系统 = Android

用户分群 = 高价值用户

过去 7 天做过支付

分布分析可以在细分筛选区域配置目标用户范围，支持按用户群、按事件/用户属性过滤，并支持多个条件之间的逻辑关系。

**7.2 支持筛选类型**

| **类型** | **示例** |
| --- | --- |
| 用户属性 | 城市 = 深圳 |
| 用户标签 | 生命周期 = 成熟用户 |
| 用户分群 | 属于 高价值用户 |
| 事件属性 | 操作系统 = Android |
| 行为圈选 | 过去 7 天做过支付 |
| 行为排除 | 过去 30 天没做过登录 |
| 动态匹配 | 按查询日期匹配当天用户分群 |

字段结构：

type UserFilterConfig = {

relation: "AND" | "OR";

conditions: Array<FilterCondition | FilterGroup>;

};

交互规则：

1. 默认展示“全部用户”。

2. 点击“添加筛选”后选择筛选类型。

3. 多个条件默认 AND。

4. 支持切换为 OR。

5. 支持二级过滤。

6. 未完整配置的筛选条件置红，不允许查询。

**8. 属性分组**

**8.1 功能说明**

属性分组用于在分布区间之外，再按某个属性拆分结果。

例如：

按操作系统查看各启动次数区间人数

按渠道查看各付费金额区间人数

按会员等级查看各活跃天数区间人数

字段结构：

type DistributionGroupBy = {

id: string;

fieldType:

| "event\_property"

| "user\_property"

| "user\_tag"

| "cohort"

| "subject\_property";

fieldName: string;

displayName: string;

valueLimit: number;

includeOthers: boolean;

includeUnknown: boolean;

};

默认规则：

1. 最多支持 2 个属性分组。

2. 每个分组默认展示 Top 20 属性值。

3. 超出 Top 20 的值合并为“其他”。

4. 属性为空的主体进入“未知”。

5. 图表默认最多展示 10 个分组值，其余可在图例中展开。

**8.2 分组与分布区间的关系**

结果维度为：

时间 × 分布区间 × 属性分组值

例如：

| **日期** | **分布区间** | **操作系统** | **人数** |
| --- | --- | --- | --- |
| 2026-05-01 | 1 次 | Android | 1200 |
| 2026-05-01 | 1 次 | iOS | 900 |
| 2026-05-01 | 2 次 | Android | 800 |
| 2026-05-01 | 2 次 | iOS | 700 |

**9. 对照组**

**9.1 功能说明**

对照组用于比较不同用户群体的分布差异。

例如：

新用户 vs 老用户

iOS 用户 vs Android 用户

自然流量用户 vs 投放用户

高付费用户 vs 普通用户

字段结构：

type ComparisonGroup = {

id: string;

name: string;

filter: UserFilterConfig;

};

交互规则：

1. 点击“添加对照组”。

2. 系统创建一个新的筛选组。

3. 默认名称为“对照组 1”。

4. 用户可修改名称。

5. 每个对照组独立配置筛选条件。

6. 最多支持 10 个对照组。

7. 开启对照组后，属性分组默认禁用，避免维度爆炸。

**10. 时间配置**

**10.1 时间粒度**

分布分析默认支持：

天

分布分析设置查询时间时，分析时间粒度为天级，时间段可以按最近 xx 天、最多 120 天，或指定时间范围设置。

本产品建议扩展支持：

小时

天

周

月

V1 只实现天级，字段预留其他粒度。

字段结构：

type DistributionTimeConfig = {

granularity: "hour" | "day" | "week" | "month";

startTime: string;

endTime: string;

timezone: string;

weekStartDay?: 1 | 2 | 3 | 4 | 5 | 6 | 7;

};

**10.2 时间范围**

支持两种模式：

| **模式** | **示例** |
| --- | --- |
| 相对时间 | 最近 7 天、最近 30 天、最近 120 天 |
| 固定时间 | 2026-05-01 至 2026-05-10 |

校验规则：

| **粒度** | **最大范围** |
| --- | --- |
| 小时 | 7 天 |
| 天 | 120 天 |
| 周 | 104 周 |
| 月 | 60 月 |

V1 采用 DataFinder 规则：

天级，最大 120 天。

| **权限** | **说明** |
| --- | --- |
| distribution:view | 查看分布分析页面 |
| distribution:query | 执行查询 |
| distribution:save | 保存分析 |

| distribution:dashboard | 保存到看板 |

| distribution:user\_detail | 查看用户列表 |

权限拦截：

1. 没有 distribution:view：不可进入页面。

2. 没有事件权限：事件选择器不展示该事件。

3. 没有属性权限：属性选择器不展示该属性。

4. 非本用户创建或者保存的：无分享权限

5. 打开保存分析时，如果部分字段无权限，则置灰并提示。

6. 没有 user\_detail：隐藏“查看用户列表”。

7. 没有 export：隐藏导出按钮。

**18. 异常状态**

**18.1 无事件**

当前项目暂无可用于分布分析的事件，请先完成事件接入。

**18.2 无数据**

当前条件下暂无分布数据。

可能原因：

1. 所选事件在当前时间范围内无人触发

2. 事件过滤条件过窄

3. 用户筛选条件过窄

4. 所选属性为空或无法转为数值

5. 分布区间未覆盖当前指标值

**18.3 区间未覆盖**

部分指标值未落入任何分布区间，建议开启“小于最小值 / 大于最大值”区间或调整区间边界。

**18.4 区间重叠**

分布区间存在重叠，同一个用户可能被重复计入，请调整区间边界。

**18.5 查询超时**

当前查询范围较大，建议缩短时间范围、减少属性分组或减少区间数量。
