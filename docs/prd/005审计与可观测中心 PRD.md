**审计与可观测中心 PRD**

**1. 模块定位**

审计与可观测中心用于统一记录、查询、追踪和分析数据平台内所有关键行为与系统运行状态，覆盖用户操作审计、身份登录审计、权限变更审计、数据访问审计、审批流程审计、系统健康监控、运行日志查询、链路追踪、任务运行监控、告警管理和合规导出。

该中心不是单纯的“日志列表”，而是面向平台安全、合规、排障、运维和管理决策的统一控制台。

核心目标包括：

1. 所有关键操作可追溯。
2. 所有数据访问行为可审计。
3. 所有权限、策略、审批变化可还原。
4. 系统运行异常可发现、可定位、可处理。
5. 告警规则可配置，异常事件可闭环。
6. 审计日志不可随意篡改，支持合规留存和导出。

**2. 功能边界**

**2.1 本模块负责的内容**

审计与可观测中心负责以下能力：

1. 审计总览。
2. 操作审计日志。
3. 登录与身份审计。
4. 权限与策略变更审计。
5. 数据访问审计。
6. 申请审批流程审计。
7. 系统健康观测。
8. 指标监控与趋势分析。
9. 运行日志查询。
10. 链路追踪。
11. 任务运行监控。
12. 告警规则配置。
13. 告警事件处理。
14. 审计报告导出。
15. 审计数据留存与归档策略。

**2.2 本模块不负责的内容**

以下内容不在本模块内直接维护，只在本模块内展示、查询或引用：

1. 用户、角色、组织、空间的基础配置，由组织与身份中心负责。
2. 权限策略的创建和修改，由权限与策略中心负责。
3. 审批流程模板配置，由申请审批与流程中心负责。
4. 系统参数配置，由系统配置中心负责。
5. 资产、资源、数据源、数据集的主数据维护，由资源与资产中心负责。
6. 数据脱敏规则配置，由数据安全与合规中心负责。

本模块可以跳转到上述模块查看源对象，但不在本模块内直接修改源对象。

**3. 用户角色与权限**

**3.1 角色定义**

**3.1.1 平台超级管理员**

拥有本模块全部权限，包括查看全部审计日志、配置告警规则、配置留存策略、导出审计报告、查看系统运行日志和链路追踪。

**3.1.2 安全管理员**

可查看安全相关审计数据，包括登录审计、权限变更审计、数据访问审计、审批审计、异常行为分析和合规报告。可配置审计留存策略。不可查看服务运行日志中的敏感业务参数。

**3.1.3 运维管理员**

可查看系统健康、运行日志、链路追踪、任务监控、告警事件。可配置告警规则。默认不可查看用户数据访问的明细结果内容。

**3.1.4 空间管理员**

仅可查看自己管理空间范围内的操作审计、数据访问审计、任务运行记录、审批流程记录。不可查看其他空间数据。

**3.1.5 审计查看员**

仅可查询和导出被授权范围内的审计日志。不可配置告警规则、不可配置留存策略、不可处理告警事件。

**3.1.6 普通用户**

默认不可进入审计与可观测中心。若被授予特定空间的审计查看权限，则只能查看与自己或所在空间相关的审计记录。

**6. 审计事件统一模型**

**6.1 审计事件产生规则**

平台内所有关键业务模块在发生重要行为时，都必须向审计中心写入审计事件。

审计事件写入方式采用后端统一审计 SDK 或统一审计服务 API，不允许各业务系统直接写入审计库。

每条审计事件必须包含：

1. 谁操作。
2. 在哪个租户、组织、空间内操作。
3. 操作了什么对象。
4. 做了什么动作。
5. 操作前是什么状态。
6. 操作后是什么状态。
7. 操作是否成功。
8. 来源 IP、设备、客户端信息。
9. 请求 ID、链路 ID。
10. 发生时间。
11. 不可篡改校验字段。

**6.3 审计事件不可篡改规则**

审计日志写入后不可编辑。

普通用户、空间管理员、安全管理员、平台管理员均不能通过前端删除单条审计日志。

系统仅允许通过留存与归档策略进行批量过期归档或销毁。

每条审计日志生成 current\_hash。

计算逻辑：

current\_hash = SHA256(previous\_hash + audit\_payload + occurred\_at + audit\_id)

如果审计日志被篡改，重新计算的 hash 与 current\_hash 不一致，系统在审计完整性校验中标记为异常。

**28. 验收标准**

**28.1 审计日志验收标准**

1. 用户进行关键操作后，系统必须生成审计日志。
2. 审计日志必须包含操作人、对象、动作、结果、时间、IP、request\_id 和 trace\_id。
3. 权限变更类操作必须展示操作前后差异。
4. 审计日志写入后不可编辑。
5. 审计列表支持按时间、用户、模块、对象、结果、风险等级筛选。
6. 审计详情中的复制、跳转、查看链路功能可正常使用。
7. 无权限用户不能查看超出授权范围的审计数据。

**28.2 数据访问审计验收标准**

1. 用户预览、查询、下载、导出数据时必须生成数据访问审计。
2. 涉及敏感字段时必须记录敏感字段列表和脱敏状态。
3. 下载数据必须记录下载行数和文件大小。
4. 查看完整 SQL 参数必须进行二次确认。
5. 高风险访问必须自动标记风险等级。
6. 标记风险可生成告警事件。

**28.3 可观测验收标准**

1. 系统健康页面能展示服务状态和实例状态。
2. 服务异常时全局健康状态能正确变化。
3. 指标监控支持按时间、服务、指标、聚合方式查询。
4. 运行日志支持关键词、级别、服务、trace\_id 查询。
5. 链路追踪能展示调用拓扑和 Span 时间轴。
6. 任务运行监控能查看任务详情、日志、链路和重试记录。

**28.4 告警验收标准**

1. 用户可创建、编辑、复制、启用、停用告警规则。
2. 告警规则测试不发送真实通知。
3. 满足触发条件时生成告警事件。
4. 告警事件支持认领、转派、恢复、关闭和静默。
5. 告警通知失败时可重新发送。
6. 所有告警处理动作必须写入审计日志。

**28.5 导出与留存验收标准**

1. 审计日志、数据访问记录、告警记录支持异步导出。
2. 导出任务可查看状态、下载、重新生成和取消。
3. 下载导出文件必须写入数据访问审计。
4. 留存策略修改必须二次确认。
5. 归档任务必须进入任务运行监控。
6. 审计完整性校验发现异常时必须生成严重告警。

**29. 异常场景处理**

**29.1 审计写入失败**

如果业务操作成功但审计写入失败：

1. 后端不得直接忽略。
2. 必须写入本地失败队列。
3. 系统异步重试。
4. 重试失败超过阈值后生成系统告警。
5. 审计写入失败不应阻塞普通低风险业务操作。
6. 高风险操作可配置为审计写入失败时阻断业务。

**29.2 日志服务不可用**

运行日志查询服务不可用时：

1. 页面提示日志服务异常。
2. 不影响审计日志查询。
3. 系统健康页面将日志服务标记为异常。
4. 自动生成服务异常告警。

**29.3 指标数据延迟**

如果指标数据延迟超过 5 分钟：

1. 指标图表显示数据延迟提示。
2. 系统健康状态可能变为未知。
3. 告警规则检测使用最近可用数据。
4. 若连续多个周期无数据，触发数据缺失告警。

**29.4 导出文件过期**

用户点击过期文件下载时：

1. 禁止下载。
2. 提示文件已过期。
3. 提供重新生成按钮。
4. 重新生成时必须重新校验当前权限。

**30. 非功能要求**

**30.1 性能要求**

1. 审计列表普通查询响应时间不超过 3 秒。
2. 最近 24 小时数据查询响应时间不超过 2 秒。
3. 导出任务必须异步执行。
4. 单次前端分页最大 page\_size 为 100。
5. 实时日志追踪刷新间隔不得低于 5 秒。
6. 指标查询默认最多返回 5000 个点。

**30.2 安全要求**

1. 审计数据传输必须通过 HTTPS。
2. 敏感字段必须默认打码。
3. 导出文件必须带权限校验。
4. 下载链接必须有过期时间。
5. 审计日志不允许普通删除。
6. 查看敏感参数必须二次确认并记录原因。

**30.3 可用性要求**

1. 审计查询和可观测查询服务应相互隔离。
2. 指标、日志、链路查询失败不应影响审计日志查询。
3. 告警服务异常时必须在系统健康中体现。
4. 审计写入失败必须可重试。

**30.4 可扩展要求**

1. 新模块接入审计时必须使用统一事件模型。
2. 新指标接入指标监控时必须注册指标元数据。
3. 新告警类型必须通过 AlertService 扩展。
4. 新日志类型必须通过统一日志采集规范接入。

**32. 总结**

审计与可观测中心需要同时满足安全审计、合规追踪、系统排障、任务监控和告警闭环五类需求。

开发时必须坚持以下原则：

1. 审计日志不可篡改。
2. 数据访问必须可追溯。
3. 权限变更必须能还原。
4. 系统异常必须可发现。
5. 告警事件必须可处理。
6. 导出和敏感查看必须二次审计。
7. 前端展示范围不能代替后端权限校验。
8. 所有高风险操作必须有完整记录。

该模块完成后，平台将具备面向企业级数据平台所需的安全追责能力、运行可观测能力和合规支撑能力。
