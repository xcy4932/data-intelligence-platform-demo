**营销触达-首页与消息触达 PRD**

**1. 产品定位与范围**

**1.1 产品目标**

营销触达模块用于让运营人员在统一平台内完成以下工作：

1. 在首页查看营销业务整体运行情况；
2. 创建不同通道的消息触达任务；
3. 对触达任务进行审批、启动、暂停、取消、复制、删除；
4. 对触达任务配置人群、触发时机、触达内容、频控、勿扰、互斥、A/B 实验和关注指标；
5. 对触达任务进行测试发送；
6. 在任务执行后查看发送、送达、点击、转化、过滤原因、执行记录和重发明细；
7. 通过跨任务频控、跨任务配额、非交易日规则控制营销触达风险。

**1.2 功能范围**

本 PRD 覆盖以下页面与功能：

| **模块** | **页面 / 功能** |
| --- | --- |
| 首页 | 业务总览默认看板、嵌入看板入口 |
| 消息触达 | 消息触达任务列表、筛选、状态管理、新增任务 |
| 任务创建 | 选择触达方式、基础信息、受众用户、触发条件、触达配置、关注指标 |
| 通道类型 | 短信、Webhook、服务号模板消息、公众号活跃消息、公众号群发消息、小程序订阅消息、Telegram、WhatsApp |
| 辅助能力 | 触达测试、A/B 实验、审批、非交易日、跨任务频控及配额、效果评估 |
| 数据分析 | 漏斗图、关注指标、执行记录、详细数据、过滤明细、发送明细、重发 |

不在本 PRD 内详细展开的内容：

1. 通道配置本身，例如短信通道密钥配置、微信公众号授权、Telegram 通道配置、WhatsApp 通道配置；
2. 内容中心模板管理本身，例如短信模板审核、Webhook 模板对接、微信模板创建；
3. CDP / DataFinder 分群编辑器本身；
4. 审批流程管理后台本身；
5. 权益中心、素材中心、物料中心、活动落地页中心的内部管理功能。

这些功能在本 PRD 中只作为依赖能力出现。

**2. 角色、权限与全局规则**

**2.1 用户角色**

| **角色** | **权限范围** |
| --- | --- |
| 普通运营人员 | 查看授权页面、创建触达任务、编辑本人草稿、提交审批、查看本人有权限的任务、复制任务、查看数据分析 |
| 任务创建人 | 可编辑草稿、提交审批、查看审批结果、查看任务数据、对异常任务执行重启 |
| 审批人 | 查看待审批任务、审批通过、审批驳回、填写驳回原因 |
| 项目管理员 | 配置功能权限、配置分组、查看项目内任务、配置部分全局能力 |
| 集团管理员 | 拥有跨项目或集团级管理权限，可管理任务分组、审批、频控等配置 |

**2.2 权限控制**

**2.2.1 首页权限**

用户访问「首页 - 业务总览」时，系统必须校验：

permission.home\_business\_overview.view = true

无权限时：

1. 页面不展示业务总览菜单；
2. 若用户通过 URL 直接访问，展示无权限页面；
3. 无权限页面文案为：暂无「首页-业务总览」查看权限，请联系项目管理员开通。

**2.2.2 消息触达权限**

用户访问「智能运营 - 消息触达」时，系统必须校验：

permission.message\_touch.task.view = true

用户创建、编辑、删除、审批、暂停、取消等操作分别校验：

permission.message\_touch.task.create

permission.message\_touch.task.edit

permission.message\_touch.task.delete

permission.message\_touch.task.approve

permission.message\_touch.task.pause

permission.message\_touch.task.cancel

permission.message\_touch.task.analysis

无权限按钮处理规则：

1. 若用户无该操作权限，按钮不展示；
2. 若按钮因状态可见但用户无权限，按钮置灰并展示 tooltip；
3. tooltip 文案格式：暂无「{权限名称}」权限，请联系管理员开通。

**2.2.3 通道权限**

不同触达通道需要单独校验通道查看 / 使用权限：

| **通道** | **权限标识** |
| --- | --- |
| 短信 | permission.channel.sms.view |
| Webhook | permission.channel.webhook.view |
| 微信公众号 | permission.channel.wechat\_official\_account.view |
| 微信小程序 | permission.channel.wechat\_mini\_program.view |
| Telegram | permission.channel.telegram.view |
| WhatsApp | permission.channel.whatsapp.view |

用户在「新增触达任务」选择触达方式时，只展示已开通且有权限的通道卡片。

未开通但产品支持的通道可展示为置灰卡片，文案为：当前项目未开通该通道，请联系管理员配置。

**4. 首页：业务总览**

**4.1 页面入口**

路径：

左侧导航-智能运营-营销触达-业务总览

页面打开逻辑：

1. 用户进入系统后，默认进入营销触达首页；
2. 若用户有「营销触达首页-业务总览」权限，则展示业务总览默认看板；
3. 若无权限，则不展示该页面入口；
4. 若项目未购买相关依赖产品，部分报表展示空值或无数据提示。

**4.2 页面布局**

页面分为两类看板：

1. 默认看板；
2. 嵌入看板。

默认看板为系统预置，不允许用户删除。

嵌入看板仅在私有化部署且购买「智能营销洞察」或「增长分析」能力时展示入口。

**4.3 默认看板**

默认看板包含 6 个报表：

1. 总用户数趋势图；
2. 活动数量通道分布图；
3. 消息触达任务数量趋势图；
4. 流程画布任务数量趋势图；
5. 个性化 Push 文案数量趋势图；
6. 个性化短信文案数量趋势图。

**4.3.1 总用户数趋势图**

展示内容：

| **字段** | **逻辑** |
| --- | --- |
| 昨日总用户 | 昨日累计 baseid 数量 |
| 昨日新增 | 昨日新增 baseid 数量 |
| 趋势图 | 最近 14 天，不含今日，总用户数趋势 |

数据依赖：

1. 数据来自 VeCDP；
2. 若项目未购买 VeCDP，报表展示无权限 / 无数据；
3. 若用户无 VeCDP 项目查看权限，报表展示无权限提示；
4. 若数值为 0，页面不自动判断为无用户，应展示为 0，并在 tooltip 中提示：若数据刚更新完成前可能为 0。

交互逻辑：

1. 鼠标 hover 折线点时，展示日期和用户数；
2. 日期横轴按自然日升序排列；
3. 若接口返回空数组，图表区域展示空状态：暂无用户趋势数据；
4. 若接口异常，展示错误状态并提供「刷新」按钮。

**4.3.2 活动数量通道分布图**

展示内容：

| **字段** | **逻辑** |
| --- | --- |
| 累计消息触达任务数 | 按通道统计历史消息触达任务数量 |
| 累计流程画布数量 | 按通道统计历史流程画布中使用该通道的数量 |
| 通道占比 | 各通道任务数量占比 |

统计规则：

1. 消息触达任务按任务选择的触达通道计数；
2. 流程画布任务中，只要有任一策略器使用该通道，该流程画布计入该通道；
3. 同一个流程画布如果使用多个通道，则分别计入多个通道；
4. 饼图占比 = 当前通道任务数量 / 所有通道任务数量。

交互逻辑：

1. hover 饼图扇区时展示通道名称、数量、占比；
2. 点击图例可隐藏 / 显示对应通道；
3. 所有通道数量为 0 时，展示空状态。

**4.3.3 消息触达任务数量趋势图**

展示内容：

| **字段** | **逻辑** |
| --- | --- |
| 总任务数 | 当前项目下所有人近 30 天创建的消息触达任务数量 |
| 昨日新增 | 昨日当前项目下所有人创建的消息触达任务数量 |

**4.4 嵌入看板**

**4.4.1 展示条件**

同时满足以下条件时展示「+」按钮：

deploymentType = PRIVATE

AND (hasDatawind = true OR hasDataFinder = true)

AND permission.home\_embedded\_dashboard.manage = true

**4.4.2 「+」按钮逻辑**

按钮名称：

+ 添加看板

点击后：

1. 打开「嵌入看板」弹窗；
2. 用户选择来源系统；
3. 用户选择已有看板；
4. 用户确认后，系统保存嵌入配置；
5. 首页新增一个嵌入看板卡片。

| **字段** | **类型** | **必填** | **逻辑** |

| 看板 | Select | 是 | 根据来源系统加载用户有权限的看板 |
| 看板名称 | Input | 是 | 默认带入原看板名称，允许修改 |
| 展示顺序 | Number | 否 | 默认追加到末尾 |

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 取消 | 关闭弹窗，不保存 |
| 确认 | 校验必填项，通过后保存嵌入看板 |
| 刷新 | 重新拉取来源系统看板列表 |

**5. 消息触达管理页**

**5.1 页面入口**

路径：

左侧导航-智能运营-营销触达-消息触达

页面功能：

1. 查看当前项目下消息触达任务；
2. 按多个维度筛选任务；
3. 新增触达任务；
4. 管理已有任务；
5. 进入任务数据分析；
6. 进入触达测试；
7. 查看审批相关入口。

**5.2 页面结构**

页面从上到下分为：

1. 顶部操作区；
2. 筛选区；
3. 状态统计区；
4. 任务列表；
5. 分页区。

**5.3 顶部操作区**

**5.3.1 「新增触达任务」按钮**

展示条件：

permission.message\_touch.task.create = true

点击逻辑：

1. 打开「选择触达方式」页面或弹窗；
2. 加载当前项目已开通且用户有权限的触达通道；
3. 用户选择通道后进入任务创建向导。

**5.3.2 「触达测试」按钮**

展示条件：

permission.message\_touch.test.view = true

点击逻辑：

1. 跳转到「触达测试」页面；
2. 默认打开 App Push 测试 Tab；
3. 若用户无 App Push 权限，则默认打开第一个有权限的测试 Tab。

**5.3.3 「我的申请」入口**

点击逻辑：

1. 打开当前用户提交的审批申请列表；
2. 列表展示申请状态、任务名称、审批人、提交时间、当前节点；
3. 支持按审批状态筛选；
4. 点击任务名称进入任务详情。

**5.3.4 「我的审批」入口**

点击逻辑：

1. 打开需要当前用户审批的任务列表；
2. 待审批数量每 5 分钟刷新一次；
3. 点击「审批」进入审批详情弹窗；
4. 审批人可以通过或驳回。

**5.4 筛选区**

筛选字段：

| **字段** | **控件** | **逻辑** |
| --- | --- | --- |
| 任务类型 | Select | 定时型单次、定时型重复、触发型完成 A、触发型完成 A 未完成 B |
| 触达通道 | Select | 短信、Webhook、服务号模板消息、公众号活跃消息、公众号群发消息、小程序订阅消息、Telegram、WhatsApp |
| 所属分组 | Select | 加载当前项目消息触达任务分组 |
| 任务名称 | Input | 支持模糊搜索 |
| 创建人 | Select / Input | 支持按创建人搜索 |
| 审批状态 | Select | 草稿、审批中、审批驳回、审批通过 |
| 任务状态 | Select | 运行中、已暂停、已取消、已结束、异常等 |
| 创建时间 | DateRangePicker | 按任务创建时间筛选 |

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 查询 | 使用当前筛选条件请求列表 |
| 重置 | 清空筛选条件，恢复默认查询 |
| 展开 / 收起 | 控制高级筛选项展示 |
| 刷新 | 保留筛选条件，重新请求列表 |

查询规则：

1. 多个筛选条件之间为 AND；
2. 空字段不参与查询；
3. 任务名称支持模糊匹配；
4. 创建时间按闭区间处理；
5. 查询后分页回到第 1 页。

展示任务数量聚合，例如：

3. 若开通多主体，只展示当前任务主体对应分群；

3. 若均未购买，不展示按钮；
4. 从分群创建页返回后，刷新分群列表。

**9.4 上传分群**

**9.4.1 使用限制**

1. 仅支持定时型任务；
2. 不支持触发型任务；
3. 不支持任务排除功能；
4. 分群上传入口在「触达配置」步骤，不在受众用户步骤完成；
5. 上传 ID 类型必须为当前通道发送目标 ID 类型；
6. 上传分群中的 ID 即使不存在于 VeCDP / DataFinder，也允许发送；
7. 若触达内容中插入了标签、属性、ID 信息，而上传 ID 不存在于系统，则该用户发送失败。

**9.4.2 页面表现**

在受众用户步骤选择「上传分群」后：

1. 页面展示说明文案；
2. 不展示分群上传控件；
3. 提示用户将在触达配置步骤上传 CSV；
4. 下一步进入触发条件。

**9.5 全部用户**

**9.5.1 使用限制**

全部用户仅支持：

1. 触发型 - 完成 A；
2. 触发型 - 完成 A 未完成 B。

含义：

用户触发事件后，不再做受众过滤，所有满足事件条件的用户均可触达。

**9.5.2 提交校验**

若用户选择全部用户但触发条件为定时型：

禁止提交

提示：全部用户仅支持触发型任务，请调整触发条件

**9.6 微信标签分群**

仅公众号群发消息支持。

逻辑：

1. 微信标签同步自微信公众号平台；
2. 用户选择一个微信标签；
3. 系统针对该标签下全部用户进行群发；
4. 若标签为空或已删除，提交时提示重新选择。

**10.2 定时型 - 单次**

**10.2.1 字段**

| **字段** | **控件** | **必填** | **逻辑** |
| --- | --- | --- | --- |
| 触达时间 | DateTimePicker | 是 | 指定唯一触达时间点 |
| 审批超时策略 | Radio | 是 | 到触达时间仍未审批时如何处理 |
| 执行前刷新分群 | Checkbox | 条件展示 | 是否在执行前刷新按需分群 |
| 刷新分群失败策略 | Radio | 条件展示 | 失败后发送或不发送 |
| 非交易日处理 | Radio | 条件展示 | 证券行业开关打开后展示 |

**10.2.2 触达时间校验**

1. 必须晚于当前时间；
2. 不允许选择过去时间；
3. 若保存草稿允许过去时间，但提交审批时必须重新校验；
4. 若审批通过时触达时间已过，根据审批超时策略处理。

**10.2.3 审批超时策略**

可选：

1. 取消该任务；
2. 审批通过后立即执行。

规则：

1. 若到触达时间时任务仍未审批通过，执行该策略；
2. 即使选择审批通过后立即执行，若 72 小时内仍未审批完成，任务自动取消；
3. 自动取消后任务状态变为已取消；
4. 执行记录中记录取消原因。

**10.2.4 执行前刷新分群**

展示条件：

hasVeCDP OR hasDataFinder

规则：

1. 若分群为按需更新，勾选后默认提前 15 分钟刷新；
2. 例如 15:00 执行，14:45 刷新；
3. 若分群为按天更新，按分群自身更新时间更新；
4. 若分群为实时更新，实时生效；
5. 若未购买 VeCDP / DataFinder，不展示该选项。

**10.2.5 刷新分群失败策略**

按需更新分群可选：

1. 使用系统当前获取到的分群数据发送；
2. 不发送。

按天更新分群：

1. 刷新失败默认使用系统当前获取到的分群数据发送。

**10.3.1 字段**

| 起止时间 | DateTimeRangePicker | 是 | 设置任务运行区间 |
| 审批超时策略 | Radio | 是 | 同定时型单次 |
| 执行前刷新分群 | Checkbox | 条件展示 | 同定时型单次 |
| 刷新分群失败策略 | Radio | 条件展示 | 同定时型单次 |
| 非交易日处理 | Radio | 条件展示 | 证券行业开关打开后展示 |

**10.3.2 循环周期逻辑**

支持示例：

1. 每日 10:00；
2. 每周五 16:00；
3. 指定日期范围内每天执行；
4. 指定日期范围内按周执行。

校验：

1. 起始时间必须早于结束时间；
2. 循环周期生成的首次执行时间必须落在起止时间内；
3. 若无任何有效执行点，禁止提交。

**10.4 触发型 - 完成 A**

**10.4.1 字段**

| **字段** | **控件** | **必填** | **逻辑** |
| --- | --- | --- | --- |
| 触发事件 A | EventSelector | 是 | 用户完成该事件后触发 |
| 完成次数规则 | Radio + Number | 是 | 累计完成 A / 每完成 A |
| 触达时机 | Radio | 是 | 立即、延迟、延迟到指定时间、延迟到周几 |
| 事件 A 起止时间 | DateTimeRangePicker | 是 | 仅该时间段内 A 事件触发任务 |
| 触达任务结束时间 | DateTime | 系统生成 | 到达后任务结束 |
| 执行前刷新分群 | 条件展示 | 否 | 触发型下按天或实时更新 |
| 刷新分群失败策略 | 条件展示 | 是 | 失败后使用最新数据判断 |

**10.4.2 触发事件 A**

逻辑：

1. 用户选择数据源；
2. 选择事件；
3. 可添加事件属性筛选条件；
4. 完成事件的用户还需满足受众用户条件才会真正触达。

**10.4.3 完成次数规则**

| **规则** | **示例** | **含义** |
| --- | --- | --- |
| 累计完成 A | 累计完成 A 3 次 | 用户累计完成 3 次后，仅触达 1 次 |
| 每完成 A | 每完成 A 3 次 | 用户每完成 3 次触发一次 |

**10.4.4 触达时机**

| **选项** | **逻辑** |
| --- | --- |
| 立即触达 | 事件发生后立即触达 |
| 延迟触达 | 延迟相对时间，例如 1 天 = 24 小时，最多 365 天 |
| 延迟指定时间 | 事件发生后等待到指定时间点触达 |
| 延时到周几 | 等待到最近一个指定星期几触达 |

延时到周几示例：

1. 设置周二，周一发生事件，本周二触达；
2. 设置周二，周三发生事件，下周二触达。

**10.5 触发型 - 完成 A 未完成 B**

**10.5.1 字段**

| **字段** | **控件** | **必填** | **逻辑** |
| --- | --- | --- | --- |
| 完成事件 A | EventSelector | 是 | 用户完成 A 后进入等待判断 |
| 未完成事件 B | EventSelector | 是 | 等待期内未完成 B 才触发 |
| B 判断时间 | DurationPicker | 是 | 完成 A 后等待多久判断 B |
| 完成次数规则 | Radio + Number | 是 | 累计完成 A / 每完成 A |
| 触达时机 | Radio | 是 | 立即、延迟、指定时间、周几 |
| 事件 A 起止时间 | DateTimeRangePicker | 是 | 仅该时间段内 A 事件参与判断 |
| 触达任务结束时间 | DateTime | 系统生成 | 到达后任务结束 |
| 执行前刷新分群 | 条件展示 | 否 | 同触发型完成 A |
| 刷新分群失败策略 | 条件展示 | 是 | 失败后使用最新数据判断 |

**10.5.2 执行逻辑**

1. 用户完成事件 A；
2. 系统记录 A 事件时间；
3. 等待配置的 B 判断时间；
4. 若用户在等待期内完成 B，则不触达；
5. 若用户在等待期内未完成 B，则进入触达流程；
6. 进入触达流程后仍需经过受众过滤、频控、勿扰、黑白名单、互斥、配额等判断。

**10.6 GMP 回传事件选择逻辑**

当用户希望基于 GMP 触达行为触发后续任务时：

1. 在事件选择框搜索 GMP；
2. 选择 GMP 回传事件；
3. 系统自动加载 3 个属性：
   1. 活动类型 / 任务类型；
   2. 活动 ID / 任务 ID；
   3. 指标名称。
4. 用户需填写对应值；
5. 例如想在短信发送成功后触发，可选择指标名称为发送量或成功触达量。

3. 点击确认后：
   1. 清空 contentConfig；
   2. 重置通道相关字段；
   3. 保留基础信息、受众、触发条件、关注指标；

**11.3 任务类型与优先级**

任务类型：

1. 普通活动；
2. 紧急活动；
3. 通知活动。

优先级：

通知活动 > 紧急活动 > 普通活动

执行逻辑：

1. 当多个任务同时触发且发送队列积压时，优先执行优先级高的任务；
2. 每个任务完成一次触发，对应通道频控次数消耗一次；
3. 通知活动在通道频控次数消耗完后，仍允许触发；
4. 普通活动和紧急活动必须满足频控限制。

**11.4 任务信息同步到外部系统**

展示条件：

project.openPlatform.taskChangeWebhookConfigured = true

开启后：

1. 任务创建、提交审批、审批通过、审批驳回、暂停、重启、取消、结束、异常等状态变更时，向外部系统发送任务变更通知；
2. 外部系统来自「项目中心 - 开放平台 - 业务集成」中已对接的任务变更通知系统；
3. 发送失败时记录日志，不阻断任务主流程；
4. 数据分析页可展示同步失败告警。

**11.5 上传文件**

展示条件：

audienceType = UPLOAD\_SEGMENT

按钮：

| **按钮** | **逻辑** |
| --- | --- |
| 模板下载 | 下载当前通道上传模板 |
| 上传文件 | 上传 CSV |
| 删除文件 | 删除已上传文件 |
| 重新上传 | 替换当前文件 |

上传规则：

1. 仅支持 CSV；
2. 文件必须包含当前通道发送 ID 列；
3. 文件大小需受系统配置限制；
4. 表头不可为空；
5. ID 空值行自动过滤，并在上传结果中展示过滤数量；
6. 重复 ID 去重；
7. 若内容中插入上传文件参数，参数名必须与 CSV 表头一致；
8. 若字段不存在，提交时提示：上传文件中不存在字段 {fieldName}。

**11.6 测试发送**

点击「测试发送」后：

1. 打开测试发送弹窗；
2. 根据通道展示目标 ID 输入框；
3. 若内容包含变量，展示变量值填写区；
4. 用户填写后点击发送测试；
5. 系统不改变任务状态；
6. 测试发送结果不计入正式任务数据分析；
7. 测试失败展示通道返回错误。

**11.7 发送黑白名单**

开启后：

1. 仅对白名单用户触达；
2. 黑名单用户不触达；
3. 若同一用户同时在白名单和黑名单，黑名单优先；
4. 黑白名单来自通道配置；
5. 点击「去查看」跳转到通道管理对应黑白名单页面。

**11.8 勿扰设置**

**11.8.1 任务勿扰**

开启后配置勿扰时段。

字段：

| **字段** | **逻辑** |
| --- | --- |
| 勿扰开始时间 | 每日时间点 |
| 勿扰结束时间 | 每日时间点 |
| 勿扰期间触达规则 | 放弃本次触达 / 勿扰结束后继续触达 |

执行逻辑：

1. 若计划发送时间命中勿扰时段；
2. 若选择放弃本次触达，则该用户本次过滤；
3. 若选择勿扰结束后继续触达，则延迟到勿扰结束后发送；
4. 延迟后仍需再次校验频控、配额、任务状态；
5. 若任务已取消或结束，不再发送。

**11.8.2 通道勿扰**

通道勿扰来自通道管理。

页面逻辑：

1. 若通道配置了勿扰时段，任务配置页展示通道勿扰摘要；
2. 点击「去设置」跳转通道勿扰配置页；
3. 通道勿扰与任务勿扰同时生效；
4. 任一命中即按勿扰规则处理。

**11.9 全局触达限制**

开启时：

1. 任务受通道频控限制；
2. 任务受跨通道频控限制；
3. 触达成功后消耗对应频控次数。

关闭时：

1. 本次发送不受通道频控、跨通道频控限制；
2. 触达成功后不消耗通道频控次数；
3. 页面需展示风险提示：关闭全局触达限制可能导致用户收到过多消息，请谨慎操作。

**11.10 任务内频控**

展示条件：

triggerType in ["SCHEDULE\_REPEAT", "EVENT\_A", "EVENT\_A\_NOT\_B"]

配置项：

| **字段** | **逻辑** |
| --- | --- |
| 是否开启 | 开启后生效 |
| 时间窗口 | 例如每天、每 7 天、任务周期内 |
| 次数限制 | 用户在窗口内最多触达 N 次 |
| 统计口径 | 按当前任务统计 |

执行逻辑：

1. 每次准备发送前判断用户是否达到当前任务频控限制；
2. 达到限制则过滤；
3. 未达到则发送；
4. 发送成功后计数 +1；
5. 发送失败不计入成功触达频控次数。

**11.11 互斥 / 排除任务**

配置逻辑：

1. 用户开启互斥；
2. 选择一个或多个任务；
3. 系统根据任务名称或 ID 搜索；
4. 默认展示前 50 条，更多任务必须搜索；
5. 若目标用户已被互斥任务成功触达，则当前任务不再触达该用户；
6. 当前任务成功触达后，互斥任务后续也不再触达该用户。

限制：

1. 上传分群不支持任务排除；
2. 若受众选择上传分群，互斥配置入口不展示。

**12.3 地区与签名逻辑**

**12.3.1 国内短信**

1. 国内短信由签名 + 正文组成；
2. 签名符号为全角【】；
3. 国内短信必须选择签名；

**12.3.2 国际 / 港澳台短信**

1. 签名符号为半角 []；
2. 可以选择带签名或不带签名；
3. 若选择签名，则发送内容中拼接签名；
4. 若不选择签名，直接发送正文。

**12.4 模板内容变量**

变量类型：

1. 用户属性；
2. 用户 ID；
3. 用户标签；
4. 事件属性；
5. 上传文件参数；
6. 多主体关联标签 / 属性 / ID。

变量规则：

1. 插入变量后建议填写默认值；
2. 若系统无法取到变量值且有默认值，使用默认值；
3. 若无默认值，取消该用户发送；
4. 变量长度超过短信模板限制时，按通道规则处理；
5. 上传文件参数必须匹配 CSV 表头。

**12.5 短链插入逻辑**

支持短链类型：

1. 通用短链；
2. 带参长链转短链；
3. 小程序短链。

**12.5.1 通用短链**

字段：

| **字段** | **逻辑** |
| --- | --- |
| 原始链接 | 必填 |
| 有效期 | 到期失效 / 永久有效 |
| 到期时间 | 到期失效时必填 |
| 统计点击 UV | 统计 / 不统计 |

规则：

1. 统计点击 UV 时，触达时给不同用户生成不同短链；
2. 不统计点击 UV 时，所有用户使用同一短链；
3. 到期后访问短链展示 404。

**12.5.2 带参长链转短链**

支持在原始链接中插入用户属性、ID、标签等变量。

规则：

1. 原始链接后追加参数时必须先输入 ?；
2. 参数格式为 key=value；
3. 多个参数用 & 连接；
4. 变量前必须填写参数名和 =；
5. 示例：userid={user\_id}&username={user\_name}。

**12.5.3 小程序短链**

支持：

1. 随 GMP 任务生成；
2. 通用小程序短链。

规则：

1. 到期时间最多 3 个月；
2. 随 GMP 任务生成可统计点击 UV；
3. 通用小程序短链不支持统计 UV；
4. 微信小程序原始短链每天最多 50 万条；
5. 超过限制会导致任务发送失败；
6. 小程序页面路径不可携带 query；
7. query 参数支持固定值和变量；
8. 兜底链接用于调微信接口失败时跳转。

**12.6 短信字数统计**

1. 系统实时统计短信字数；
2. 超过 70 字提示将拆分多条；
3. 字数统计应包含签名；
4. 变量按占位符展示时，统计预估字数；
5. 测试发送时按实际变量值统计。

**20. A/B 实验**

**20.1 入口**

在「触达配置」步骤中，用户打开「开启分流实验」。

开启后，发送策略可选：

1. 分流实验；
2. 赛马实验。

**20.2 分流实验**

**20.2.1 使用场景**

运营人员无法判断哪个触达内容更好时，使用分流实验。

系统按比例将待触达用户分成多个实验组，每组使用不同内容触达。

**20.2.2 字段**

| **字段** | **必填** | **逻辑** |
| --- | --- | --- |
| 随机命中 | 是 | 定时重复场景中，同一用户多次触达是否重新随机命中 |
| 实验组数量 | 是 | 至少 2 组，最多 10 组 |
| 对照组 | 是 | 系统默认第一组为对照组 |
| 新增实验 | 否 | 新增实验组 |
| 实验组不触达 | 否 | 命中该组的用户不触达 |
| 实验组触达内容 | 是 | 每组配置独立内容 |
| 分流比例 | 是 | 所有组比例之和必须等于 100% |
| 关注指标 | 否 | 用于分析各组效果 |
| 核心指标 | 条件展示 | 购买 A/B Test 后可设置 |

**20.2.3 随机命中逻辑**

1. 选择是：同一用户在多次子任务中可能随机命中不同文案；
2. 选择否：同一用户多次被触达时保持同一实验组内容。

**20.2.4 分流比例校验**

提交时：

sum(group.ratio) === 100

否则提示：

各实验组分流比例之和必须为 100%

**20.2.5 分流运行逻辑**

1. 到达触发时间后，系统获取本次待触达分群；
2. 根据用户 ID hash 进行分桶；
3. 根据配置比例分配实验组；
4. 各组使用对应内容触达；
5. 数据分析按对照组和实验组分别展示。

说明：

比例不会严格等于配置值，尤其样本较小时会存在差异。

**20.3 赛马实验**

赛马用于先用小流量测试多组内容，再将剩余流量给优胜组。

赛马类型：

1. 手动决策；
2. 基于转化率自动决策。

**20.3.1 手动决策赛马**

字段：

| **字段** | **必填** | **逻辑** |
| --- | --- | --- |
| 赛马实验组 | 是 | 配置多个赛马文案 |
| 赛马期流量比例 | 是 | 例如 10%、30% |
| 赛马期结束方式 | 是 | 到指定时间或人工判断 |
| 优胜组选择 | 后置必填 | 人工选择全量组 |

运行逻辑：

1. 到触达时间后，先选取赛马比例用户；
2. 多个赛马文案均分赛马流量；
3. 用户触达后进入数据分析；
4. 运营人员观察效果；
5. 选择优胜组；
6. 剩余流量按优胜组触达。

不同任务类型下剩余流量处理：

| **任务类型** | **逻辑** |
| --- | --- |
| 定时型单次 | 剩余用户立即使用优胜组触达 |
| 定时型重复 | 后续每个子任务都使用优胜组触达 |
| 触发型完成 A | 后续满足条件的用户使用优胜组触达 |
| 触发型完成 A 未完成 B | 后续满足条件的用户使用优胜组触达 |

**20.3.2 自动决策赛马**

前提：

1. 购买 A/B Test 产品；
2. 配置核心指标；
3. 核心指标为率指标。

逻辑：

1. 系统在赛马期统计核心指标；
2. 按转化率选择最优组；
3. 剩余流量自动使用最优组；
4. 若各组指标均为 0，使用系统默认实验设置。

**20.3.3 赛马指标时间要求**

若指标为实时回执：

1. 系统可实时计算；
2. 赛马开始时间需早于剩余流量发送时间，至少留出统计窗口。

若指标为异步回执：

1. 系统无法实时计算；
2. 需要预留数据回执延迟；
3. 例如数据回执需要 2 天，则赛马开始时间至少应比剩余流量发送时间提前 2 天以上。

**23. 跨任务频控及配额**

**23.1 概念**

| **概念** | **含义** |
| --- | --- |
| 频控 | 对单个用户在某个时间窗口内的触达次数限制 |
| 配额 | 对某个通道或分组在某个时间窗口内的总触达次数限制 |

**23.2 跨通道频控**

配置位置：

管理中心 / 频控触达及配额 / 跨任务频控 / 跨通道频控

规则示例：

选择通道 A、通道 B，每天 1 次，表示用户通过 A 或 B 任一通道每天最多触达 1 次。

任务中使用逻辑：

1. 默认开启跨通道频控；
2. 若任务所选通道配置了频控策略，发送前判断是否超过策略；
3. 超过任一策略则不触达；
4. 未超过则触达；
5. 触达成功后计数 +1；
6. 若任务关闭跨通道频控，则不受限制且不计数。

**23.3 任务分组频控**

配置位置：

管理中心 / 频控触达及配额 / 跨任务频控 / 任务分组频控

规则示例：

选择分组 A、分组 B，每天 1 次，表示用户通过分组 A 或 B 的任务每天最多触达 1 次。

任务中使用逻辑：

1. 默认开启按分组频控；
2. 若任务所属分组配置了频控策略，发送前判断；
3. 超过则不触达；
4. 未超过则触达；
5. 触达成功后该分组计数 +1；
6. 关闭后不受限制且不计数。

**23.4 跨通道配额**

配置位置：

管理中心 / 频控触达及配额 / 跨任务配额 / 跨通道配额

规则示例：

选择通道 A、通道 B，每天 100 次，表示通过 A 或 B 每天最多触达 100 次。

任务中使用逻辑：

1. 默认开启跨通道配额；
2. 若任务通道配置了配额策略，发送前判断剩余额度；
3. 超过任一配额策略则不触达；
4. 未超过则触达；
5. 触达成功后消耗额度；
6. 关闭后不受限制且不消耗配额。

**23.5 任务分组配额**

规则示例：

1. 不限制通道，仅选择分组 A、B 每天 100 次，则通过 A 或 B 分组每天最多 100 次；
2. 限制通道 1 且选择分组 A、B 每天 100 次，则通过通道 1 且分组为 A 或 B 的触达每天最多 100 次。

**23.6 任务配置页展示**

触达配置页需要展示：

1. 当前通道剩余额度；
2. 当前分组剩余额度；
3. 命中的频控策略；
4. 命中的配额策略；
5. 「查看」入口跳转配置详情。

**24. 非交易日设置**

**24.1 展示条件**

industry = SECURITIES

AND feature.nonTradingDay = true

弹窗类通道暂不支持非交易日设置。

**24.2 字段**

当发送日期是非交易日时，可选：

1. 顺延到下个交易日发送；
2. 不发送；
3. 正常发送。

**24.3 执行逻辑**

**24.3.1 顺延到下个交易日发送**

1. 系统查询企业日历；
2. 若触达日为非交易日，找到下一个交易日；
3. 将本次发送计划移动到下一个交易日同一时间；
4. 若顺延后与下个循环周期重复，是否重复触达由任务频控控制；
5. 若任务已结束，不再顺延。

**24.3.2 不发送**

1. 若触达日为非交易日；
2. 本次触达直接过滤；
3. 执行记录记录原因：非交易日不发送。

**24.3.3 正常发送**

忽略非交易日，按原计划发送。

| --- | --- |
| 通道被删除 | 提示通道不可用，请重新选择 |
| 模板被删除 | 清空模板字段并提示 |
| 分群无权限 | 禁止提交，提示无分群权限 |
| 分群发送 ID 为 0 | 允许保存草稿，提交时二次确认 |
| 触达时间已过 | 禁止提交 |
| A/B 比例不等于 100 | 禁止提交 |
| 上传文件格式错误 | 禁止下一步 |
| 变量无默认值 | 允许配置，但执行时对应用户取消发送；提交时给出风险提示 |

**28. 验收标准**

**28.1 首页验收**

1. 有权限用户可看到 6 个默认报表；
2. 无权限用户无法访问首页业务总览；
3. VeCDP 未购买时，总用户数报表展示无数据或无权限状态；
4. 消息触达任务趋势统计最近 30 天含今日；
5. 总用户趋势统计最近 14 天不含今日；
6. 私有化且购买 Datawind / DataFinder 时可添加嵌入看板。

**28.2 消息触达列表验收**

1. 支持按任务类型、通道、分组、名称、创建人、审批状态、任务状态筛选；
2. 不同任务状态展示不同操作按钮；
3. 草稿可编辑、复制、删除；
4. 运行中可暂停、取消、数据分析；
5. 已暂停可重启、取消、数据分析；
6. 审批中可审批或催审；
7. 发送量、送达量按任务类型正确累计。

**28.3 任务创建验收**

1. 支持所有指定通道创建；
2. 不同通道展示正确字段；
3. 不同通道限制正确，例如公众号活跃仅支持触发型，公众号群发仅支持定时型；
4. 标签与行为圈选、已有分群、上传分群、全部用户、微信标签分群按通道正确展示；
5. 保存草稿不强制完整校验；
6. 提交审批必须完成全量校验；
7. 审批通过前任务不会执行。

**28.4 触达配置验收**

1. 修改触达通道会清空触达内容但保留其他步骤配置；
2. 任务类型影响优先级；
3. 上传分群仅定时型可用；
4. 互斥任务在上传分群场景不展示；
5. 勿扰、频控、配额按配置正确过滤；
6. 测试发送不计入正式数据。

**28.5 A/B 实验验收**

1. 分流实验至少 2 组，最多 10 组；
2. 分流比例之和必须为 100%；
3. 每个实验组可配置独立内容；
4. 赛马实验先发送小流量；
5. 手动赛马可选择优胜组；
6. 自动赛马按核心指标决策；
7. 数据分析按实验组展示效果。

**28.6 审批验收**

1. 提交审批时可确认审批人；
2. 发起人自选节点可选择审批候选人；
3. 指定成员节点不可修改审批人；
4. 审批驳回必须填写原因；
5. 我的审批待办数量每 5 分钟刷新；
6. 审批通过后任务才进入执行流程。

**28.7 数据分析验收**

1. 数据分析页展示漏斗图、关注指标、执行记录、详细数据；
2. 支持人数 / 人次切换；
3. 支持查看过滤明细；
4. 支持发送明细筛选与重发；
5. 异常任务可根据执行记录定位原因；
6. 分群准备失败类异常可重启执行。
